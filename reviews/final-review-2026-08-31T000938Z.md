### Minor

- **Tokenizer treats backslash inside single quotes as an escape**
  (`packages/cli/src/commands/gate/configured-command.ts:29`)
  - Issue: The backslash check at line 29 runs before the quote-state check at
    line 34, so `\` escapes the next character even inside single quotes, where
    POSIX shells treat it as a literal. A pathological command such as
    `oat --json gate review 'a\' | other'` is one quoted token to the
    tokenizer but a pipeline to the shell, so the validator can classify a
    shell-pipeline command as `valid` instead of `not-applicable`. The
    persisted command still executes byte-for-byte, gate commands are authored
    by the trusted config owner, and every trailing-token divergence is
    confined to prompt content — the fixed `oat --json gate review` prefix
    match is unaffected — so this is a classification-fidelity nuance, not a
    security or execution defect.
  - Suggestion: In `tokenizeCommand`, skip escape processing while
    `quote === "'"` (treat `\` as a literal character inside single quotes) so
    quote boundaries match POSIX behavior, and add a regression case for a
    single-quoted token containing `\'`. Acceptable to defer; the design
    explicitly scopes full shell parsing out of this project.
