  (`packages/cli/src/commands/gate/configured-command.ts:29`)
  - Issue: `tokenizeCommand` consumes a backslash before checking whether it is
    inside single quotes, even though POSIX shells preserve every character
    literally inside single quotes. Consequently
    `oat --json 'g\ate' review` and `oat '--j\son' gate review` both return
    `{ kind: 'valid', command: 'gate-review' }`, while `/bin/sh` passes `g\ate`
    and `--j\son` as distinct argv tokens. This disproves the prior deferral's
    claim that direct-prefix classification is unaffected. The impact remains
    Minor because the config owner is trusted, ordinary canonical commands are
    unaffected, and these malformed commands fail later rather than creating a
    security boundary, but the defect is inside the approved direct-command
    classifier and no general shell-AST redesign is needed.
  - Suggestion: Handle the single-quote branch before generic backslash escape
    processing so backslashes are appended literally while `quote === "'"`.
    Add both false-positive forms as `not-applicable` regression cases plus a
    literal-backslash prompt case.
