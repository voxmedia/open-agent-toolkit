### Important

- **Supported value-taking global options bypass lifecycle-command validation** (`packages/cli/src/commands/gate/configured-command.ts:90`)
  - Issue: `isDirectGateReview` assumes every token before `gate` starts with
    `-`. OAT's documented `--cwd <path>` global option has a separate value
    token, so direct commands such as `oat --cwd /tmp gate review` and
    `oat --cwd /tmp --json gate review` return `not-applicable` instead of the
    required `invalid` result. This bypasses the phase's core configuration-time
    rejection contract for recognized direct lifecycle commands with missing or
    non-canonical global `--json` placement.
  - Fix: Parse the known OAT global-option grammar sufficiently to locate the
    command path, including consuming the value for `--cwd` (both split and
    `--cwd=...` forms), and then require the exact canonical
    `oat --json gate review` prefix. Add regression cases for missing, late, and
    displaced `--json` when `--cwd` is present.
  - Requirement: p01-t01; design responsibilities “Recognize direct `oat`
    invocations whose command path is `gate review`” and “Accept only the
    canonical lifecycle prefix `oat --json gate review`.”

### Medium

- **Shell-newline and backtick forms are reported as validated commands** (`packages/cli/src/commands/gate/configured-command.ts:46`)
  - Issue: The conservative scanner rejects `|;&<>` and `$(`, but treats a shell
    newline as ordinary whitespace and backticks as ordinary token characters.
    Consequently, `oat --json gate review\necho trailing` and
    ``oat --json gate review `echo trailing` `` return `valid` rather than
    `not-applicable`. These compound/substitution shapes contradict the design's
    conservative shell-parsing boundary and can make downstream code believe a
    shell-heavy declaration was positively validated.
  - Fix: Treat unquoted command-separating newlines and executable backtick
    substitutions as unsupported shell syntax (while respecting literal single
    quotes), return `not-applicable`, and add focused cases alongside the
    existing pipe and `$()` coverage.
