# Wrap-up: 2026-05-27 to 2026-09-15

## TL;DR

Over this long summer window, OAT moved from being a set of per-repo workflow skills to a scope-portable toolkit. Every tool pack can now be installed at user scope, projects can live on Git-native synced refs, and skill and agent references resolve across loaded, user, and project installs. The biggest new workflow surface is **cross-runtime workflow gates**: another model or provider reviews a plan or implementation, and the gate fails closed. Four more dispatch projects let OAT route subagents across Claude, Codex, and Cursor to exact model and effort pins. New entry points also shipped: the **Lite** workflow, **project retros**, **`recon` evidence packets**, **remote project management** (GitHub Issues, Linear, and Jira), and a rebuilt **`oat-doctor`**. A seven-wave execution program, plus an earlier four-wave defect program, spent September on truthfulness and hardening fixes across the CLI, skills, and release tooling.

## Features introduced

### Workflow and lifecycle

- **Cross-runtime workflow gates.** A skill can now require that a configured external runtime (Codex `codex exec`, Claude `claude -p`, or Cursor `cursor-agent -p`) passes before the skill counts as done. Gates are configured through `workflow.gates.skills` and `workflow.gates.execTargets`. The later gate projects added:

  - target-neutral lifecycle guidance, with no hardcoded Codex target;
  - immutable run, target, and model provenance, and fail-closed project and artifact correlation;
  - scope-aware time budgets and transcript liveness probes;
  - a mandatory, resumable implementation exit gate;
  - write-time validation of gate commands;
  - durable `gate-receipts/` recovery;
  - per-project gate overrides.
