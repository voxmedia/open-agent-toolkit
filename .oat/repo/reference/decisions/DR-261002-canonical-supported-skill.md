# Canonical supported-skill guides

## Context

Supported user-facing skills were not uniformly discoverable, and pack membership does not describe prerequisites or the reader task.

## Decision

Map every eligible shipped user-facing skill to a canonical family guide and per-skill anchor with verified invocation, prerequisites, a realistic scenario and output/next step. Generate the committed catalog from canonical metadata and the audited guide mapping; check eligibility and parity without adding a runtime metadata schema.

## Consequences

The current 71 eligible skills have useful owner sections without duplicating full skill specifications. Source-verification evidence and mechanical catalog/anchor checks remain distinct; eligibility counts are not permanent constants or semantic proof. Evidence: .oat/projects/shared/docs-improvement-overhaul/references/skill-inventory-matrix.md and conservation-closeout.md.
