## Executive summary

- The reusable OAT/Fumadocs contract is centered on authored `docs/**/index.md` files with `## Contents` sections, plus a generated app-root `index.md` manifest. The wrapper should teach this as tooling-critical, not stylistic.
- `.md`-suffixed relative links in `## Contents` are the desired OAT direction because `@open-agent-toolkit/docs-transforms` normalizes them for Fumadocs routing while agents can follow file paths directly. Newer apps follow this; older apps such as `vox-mobile` still contain extensionless authored links.
- Every inspected app shares the Fumadocs/OAT script spine: `predev` and `prebuild` run `fumadocs-mdx` plus `oat docs generate-index`; all use `@open-agent-toolkit/docs-config`, `docs-theme`, and `docs-transforms` packages.
- The docs app root is not stable across repos. It may be `apps/oat-docs`, `documentation`, `apps/honeycomb-docs`, `apps/duet-docs`, or `apps/documentation`. The wrapper must detect the root from config and files instead of assuming a path.
- OAT config is useful but not always complete or perfectly normalized. Most repos declare `documentation.root`, `tooling: fumadocs`, `index`, and `requireForProjectCompletion`; `vox-mobile` currently has only `documentation.index` in repo-root config.
- Generated app-root indexes should not be hand-edited, but warning banners are not universal. `cyclone`'s root generated `index.md` lacks the `AUTOGENERATED` header even though scripts and instructions say it is generated.
- Agent-instruction surfaces vary. The current template appears in OAT/Duet/Cyclone-like forms, while Gizmo, Honeycomb, Vox Mobile, and Stoa have shorter or specialized local guidance. The wrapper should read local guidance and not replace it with a generic template during authoring.
- The wrapper should route lifecycle-sized work to existing skills: bootstrap for setup, analyze for read-only audits, apply for approved bulk changes, and project-document for OAT project-derived deltas.
- Universal documentation writing rules belong in the agnostic `authoring-docs` baseline; `oat-docs-authoring` should only add OAT/Fumadocs contract, discovery, workflow, validation, and migration pointers.
- Repo-specific improvements and migrations should remain evidence-backed. The wrapper should warn about known pitfalls such as stale generated indexes, generated manifests masking local `## Contents` drift, missing `## Contents`, extensionless links, `overview.md`, README-derived migration artifacts, MkDocs syntax residue, formatter hazards, and metadata/chrome confusion.

## Existing OAT/Fumadocs contract

Authoritative OAT references establish these rules:

- Plain Markdown is the default for content pages; `.mdx` is only for pages that need embedded JSX or custom components. OAT states this in `apps/oat-docs/AGENTS.md:11`, and the bootstrap template repeats it in `.agents/skills/oat-docs-bootstrap/assets/AGENTS.md.template:11`.
- Each page needs at least `title` and `description` frontmatter. OAT states this in `apps/oat-docs/AGENTS.md:12`, and the bootstrap template repeats it in `.agents/skills/oat-docs-bootstrap/assets/AGENTS.md.template:12`.
- The nearest authored `index.md` `## Contents` section is the machine-readable local map. OAT instructs agents to add new pages there and use `.md`-suffixed links in `apps/oat-docs/AGENTS.md:13`; the template repeats the same in `.agents/skills/oat-docs-bootstrap/assets/AGENTS.md.template:13`.
- Every content directory must have an authored `index.md`; new subdirectories must get their own `index.md` and `## Contents`. OAT states this in `apps/oat-docs/AGENTS.md:14`; the template repeats it in `.agents/skills/oat-docs-bootstrap/assets/AGENTS.md.template:14`.
- Generated navigation artifacts must not replace authored `## Contents`. OAT says derived artifacts are generated from `## Contents` in `apps/oat-docs/AGENTS.md:15` and warns not to hand-edit generated files in `apps/oat-docs/AGENTS.md:46-47`.
- Navigation restructuring belongs in authored `## Contents`, not sidebar config or separate nav YAML. OAT states this in `apps/oat-docs/AGENTS.md:17-23` and the template repeats it in `.agents/skills/oat-docs-bootstrap/assets/AGENTS.md.template:17-23`.
- Bulk audits and content changes should flow through analyze/apply. OAT instructs agents to use `oat-docs-analyze` and `oat-docs-apply` in `apps/oat-docs/AGENTS.md:25-31`.
- Project-derived documentation should flow through `oat-project-document`, which reads project artifacts and proposes evidence-backed changes. OAT states this in `apps/oat-docs/AGENTS.md:39-43`.
- `overview.md` is deprecated in favor of `index.md` with `## Contents`. OAT states this in `apps/oat-docs/AGENTS.md:52` and the template repeats it in `.agents/skills/oat-docs-bootstrap/assets/AGENTS.md.template:52`.
- The generated app-root `index.md` is regenerated by `oat docs generate-index` and should not be edited. OAT references the command in `apps/oat-docs/AGENTS.md:63` and root instructions call the generated index out in `AGENTS.md:159-161`.

## Observed implementation patterns

### Authored local maps drive navigation and discovery

- **Seen in:** all seven repos, strongest in OAT, Gizmo, Honeycomb, Duet, Cyclone, Stoa.
- **Evidence:** OAT docs root `docs/index.md` links direct children with `.md`/`index.md` targets in `oat-docs:docs/index.md:16-24`; Honeycomb does the same in `honeycomb:docs/index.md:15-24`; Duet does the same at larger scale in `duet:docs/index.md:13-32`; Stoa uses top-level area links in `stoa:docs/index.md:10-16`. Local guidance states the contract in `gizmo:AGENTS.md:29-33`, `honeycomb:AGENTS.md:33-38`, `cyclone:AGENTS.md:13-17`, and `stoa:AGENTS.md:44-59`.
- **Pattern:** Repos treat each `index.md` as both a rendered section landing page and a machine-readable map for the directory's direct children.
- **Assessment:** Good and core to OAT tooling, though not perfectly applied everywhere.
- **Wrapper implication:** `oat-docs-authoring` should start navigation work by finding the nearest `docs/**/index.md`, reading `## Contents`, and updating it in the same change as any page add/move/delete.

### Generated root index is a committed machine-readable manifest

- **Seen in:** all seven repos.
- **Evidence:** Generated warnings exist in `oat-docs:index.md:1`, `gizmo:index.md:1`, `honeycomb:index.md:1`, `duet:index.md:1`, `vox-mobile:index.md:1`, and `stoa:index.md:1`; Cyclone's scripts generate the same root file in `cyclone:package.json:8-10`, and Cyclone warns not to edit it in `cyclone:AGENTS.md:49` and `cyclone:AGENTS.md:63`.
- **Pattern:** The app-root `index.md` outside `docs/` rolls up authored `## Contents` into a single map used by OAT tools and agents.
- **Assessment:** Good, with one drift case: Cyclone lacks the warning banner despite being generated.
- **Wrapper implication:** The wrapper should never edit app-root `index.md` directly. It should regenerate or request regeneration through the repo's package script or `oat docs generate-index`, and it should flag missing generated warnings as scaffold/lifecycle drift.

### Generated manifests can mask local navigation drift

- **Seen in:** Duet, potentially any app with generated manifest output.
- **Evidence:** Duet's generated root index includes a README-only Vox app entry in `duet:index.md:15-16`, while the local parent contents in `duet:docs/apps/index.md:10-13` lists Duet Docs and The Verge but omits Vox. The generated root index also includes migrated pages such as runtime theme switching and module system entries that can be absent from local parent maps.
- **Pattern:** The generated app-root manifest may discover files from the filesystem even when the nearest authored parent `## Contents` no longer represents the local navigation contract.
- **Assessment:** Risky. A generated map is useful for global discovery but is not sufficient proof that authored local maps are healthy.
- **Wrapper implication:** Validate nearest parent `## Contents` directly after authoring or restructuring; do not treat a generated-root entry as evidence that the local navigation contract is satisfied.

### `.md`-suffixed links are the desired OAT direction but not universal

- **Seen in:** OAT, Gizmo, Honeycomb, Duet, Cyclone, Stoa; partially missing in Vox Mobile authored docs.
- **Evidence:** OAT uses `.md`/`index.md` targets in `oat-docs:docs/index.md:18-24`; Honeycomb does so in `honeycomb:docs/index.md:17-24`; Duet does so in `duet:docs/index.md:14-32`; Cyclone does so in `cyclone:docs/index.md:12-21`; Stoa does so in `stoa:docs/index.md:10-16`. Vox Mobile authored docs use extensionless targets in `vox-mobile:docs/index.md:12-18`, while the generated root manifest uses `.md` targets in `vox-mobile:index.md:3-29`.
- **Pattern:** Newer and generated surfaces normalize to `.md`-suffixed links; older authored pages may still have extensionless links.
- **Assessment:** Mixed. `.md` links are required for current OAT authoring guidance, but existing drift should be handled carefully.
- **Wrapper implication:** Require `.md` links for new work. Treat existing extensionless links as an audit/migration finding unless the user approved normalization or the change is local and safe.

### Fumadocs app shell is thin but has repo-specific customizations

- **Seen in:** all seven repos.
- **Evidence:** `source.config.ts` delegates to `createSourceConfig()` and `defineDocs` in each app, for example `honeycomb:source.config.ts:1-12`, `duet:source.config.ts:1-12`, and `cyclone:source.config.ts:1-12`. Layouts use `DocsLayout`, for example `honeycomb:app/layout.tsx:33-41`, `duet:app/layout.tsx:33-42`, and `cyclone:app/layout.tsx:34-43`. Vox Mobile uses a direct `createMDX()` config with static export, base path, images, and Turbopack root in `vox-mobile:next.config.js:1-21` rather than the newer shared wrapper.
- **Pattern:** Most apps use OAT wrappers for source/theme/transforms; some preserve local needs such as base path handling, image overrides, or direct MDX config.
- **Assessment:** Good but repo-specific. App shell edits are higher risk than content edits.
- **Wrapper implication:** Authoring should usually stay under `docs/`. If shell/config changes are needed, preserve local customizations and route larger scaffold/config repairs to lifecycle skills or explicit user approval.

### Site metadata and chrome title are separate and inconsistently wired

- **Seen in:** Honeycomb, Duet, Vox Mobile, Cyclone; older ambiguity in OAT, Gizmo, Stoa.
- **Evidence:** Honeycomb comments that `createDocsConfig` title/description are not wired to the HTML head and exports metadata in `honeycomb:app/layout.tsx:11-13`; Duet notes metadata belongs in layout and config only forwards framework settings in `duet:next.config.js:5-7` and exports metadata in `duet:app/layout.tsx:12`; Cyclone repeats the same in `cyclone:next.config.js:5-7` and `cyclone:app/layout.tsx:12`. OAT passes title/description to config in `oat-docs:next.config.js:3-8` and uses branding in `oat-docs:app/layout.tsx:23-30`.
- **Pattern:** Newer migrations learned that browser metadata and `DocsLayout.branding` are separate concerns.
- **Assessment:** Mixed and easy to get wrong.
- **Wrapper implication:** For authoring, ensure page frontmatter is present. For site-wide renames or metadata fixes, point to bootstrap/migration guidance and avoid suggesting `createDocsConfig({ title, description })` as sufficient.

### Validation commands are local, not universal

- **Seen in:** all seven repos.
- **Evidence:** OAT uses markdownlint and prettier in `oat-docs:package.json:11-13`; Honeycomb and Duet use markdownlint plus oxfmt in `honeycomb:package.json:13-16` and `duet:package.json:13-16`; Gizmo, Vox Mobile, Cyclone, and Stoa disable lint or formatting differently in `gizmo:package.json:13-15`, `vox-mobile:package.json:13-15`, `cyclone:package.json:13-15`, and `stoa:package.json:14-16`.
- **Pattern:** The package script names are consistent, but their behavior ranges from real lint/format to no-op echo commands.
- **Assessment:** Good enough for wrapper use if scripts are read first.
- **Wrapper implication:** The wrapper should discover and run the local scripts that exist; it should not invent `pnpm docs:build` or fail because lint is intentionally disabled.

### Three instruction surfaces are useful but unevenly implemented

- **Seen in:** all seven repos, with different maturity.
- **Evidence:** OAT root points to docs root, framework, and generated index in `AGENTS.md:155-161`; OAT docs-app guidance defines runtime authoring tasks in `apps/oat-docs/AGENTS.md:9-63`; OAT human docs authoring contract lives in `oat-docs:docs/contributing/documentation.md:10-77`. Gizmo's local docs app guidance points humans to an authoring contract in `gizmo:AGENTS.md:5`; Stoa has a top-level area router in `stoa:AGENTS.md:78-94`. Cyclone has a generated bootstrap-style docs-app `AGENTS.md` in `cyclone:AGENTS.md:1-63`.
- **Pattern:** Root `AGENTS.md` is a signpost, docs-app `AGENTS.md` is runtime agent guidance, and contributing docs are human authoring conventions. Some repos also add nested per-area `AGENTS.md` files.
- **Assessment:** Good pattern, uneven implementation.
- **Wrapper implication:** The wrapper should read all applicable local instruction surfaces before editing, then preserve their audience boundaries instead of duplicating runtime agent rules into human docs.

### Repo-specific IA routers improve authoring decisions

- **Seen in:** Stoa, Honeycomb, Gizmo; partially in larger monorepos.
- **Evidence:** Stoa's docs-app `AGENTS.md` routes top-level areas by audience and scope in `stoa:AGENTS.md:78-94` and has a cross-cutting user-facing update rule in `stoa:AGENTS.md:91-94`. Honeycomb's authoring doc describes monorepo Apps/Packages taxonomy in `honeycomb:docs/apps/honeycomb-docs/contributing/documentation.md:56-77`. Gizmo splits User Guide and Engineering at `gizmo:docs/index.md:12-15`.
- **Pattern:** Mature docs apps encode destination choice in local IA rules, not only in global authoring principles.
- **Assessment:** Good but repo-specific.
- **Wrapper implication:** The wrapper should teach agents to read local routers and nearest `index.md` scopes before deciding placement. It should not hard-code one global IA beyond the OAT contract.

### Optional Fumadocs `meta.json` can coexist with OAT `## Contents`

- **Seen in:** Gizmo.
- **Evidence:** Gizmo local guidance says `meta.json` is optional and additive, only for sidebar separators and explicit ordering, and does not replace `## Contents` in `gizmo:AGENTS.md:33`. Gizmo's authoring doc repeats this in `gizmo:docs/engineering/contributing/documentation.md:18`.
- **Pattern:** `meta.json` can refine Fumadocs sidebar presentation while authored `## Contents` remains the source of truth.
- **Assessment:** Useful but optional.
- **Wrapper implication:** Do not require `meta.json`; if present, preserve it and keep it consistent with `## Contents` after structural changes.

### Asset-only directories should not be forced into the content contract

- **Seen in:** Honeycomb.
- **Evidence:** The Honeycomb helper scan found `docs/assets` and `docs/assets/images` without `index.md`, but those directories are asset-only/image-only rather than Markdown-bearing content directories. Honeycomb still states source pages live under `docs/` and every docs directory has `index.md` in `honeycomb:AGENTS.md:20` and `honeycomb:AGENTS.md:24-28`.
- **Pattern:** The OAT index contract applies to content directories, not generated/artifact/asset-only folders.
- **Assessment:** Good qualification; otherwise audits produce noisy false positives.
- **Wrapper implication:** Require `index.md` and `## Contents` for Markdown-bearing content directories. Exempt asset-only directories unless local guidance explicitly requires otherwise.

### Legacy and migration drift is common even in good docs apps

- **Seen in:** OAT, Vox Mobile, Cyclone, Duet, Stoa.
- **Evidence:** OAT's own tree has index files without `## Contents` and `overview.md` files despite anti-pattern guidance, based on local structural scan and OAT's anti-pattern in `apps/oat-docs/AGENTS.md:52`. Vox Mobile authored root uses extensionless links in `vox-mobile:docs/index.md:12-18`. Cyclone has `docs/integrations/wordpress-content-sync/index.md` with no `## Contents`, from `cyclone:docs/integrations/wordpress-content-sync/index.md:6-12`. Duet has generated entries for a README-only app directory in `duet:index.md:15-16`. Stoa generated root index can drift relative to current docs when not regenerated; its package scripts show regeneration should happen in `stoa:package.json:8-10`.
- **Pattern:** Scaffolds and migrations leave partial adoption states; a build can pass while authoring contract drift remains.
- **Assessment:** Risky if treated as desired convention.
- **Wrapper implication:** The wrapper should separate “current repo state” from “OAT contract,” and should report drift rather than copy it into new pages.

### README-derived pages are migration artifacts, not the default content model

- **Seen in:** Duet.
- **Evidence:** Duet's generated root index includes README-derived entries such as `duet:index.md:15-16`; the inspected README page `duet:docs/apps/duet-network-vox/README.md:1-8` has frontmatter and content but lives without a sibling `index.md`, while local parent navigation omits it in `duet:docs/apps/index.md:10-13`.
- **Pattern:** Large migrations may preserve package or app READMEs as docs pages to avoid losing existing knowledge, but this can conflict with the ordinary OAT `index.md` section-entrypoint model.
- **Assessment:** Mixed. Useful for preservation, risky as a pattern to copy.
- **Wrapper implication:** Support existing README-derived pages during migrations, but do not create new README pages by default. Prefer `index.md` section entrypoints and explicit parent `## Contents` coverage.

### Render fidelity is a separate validation axis from build success

- **Seen in:** Honeycomb/Duet lesson artifacts and Honeycomb guidance.
- **Evidence:** Prior gotcha analysis records that Duet builds passed while MkDocs figures rendered zero images until conversion in `.oat/repo/reference/brainstorms/docs-authoring-skill/oat-docs-bootstrap-gotchas.md`; Honeycomb warns that a green build is not proof of rendering and says to inspect `out/` for callouts, images, tabs, and Mermaid in `honeycomb:AGENTS.md:39-41` and `honeycomb:AGENTS.md:53-54`.
- **Pattern:** Migration correctness requires rendered HTML spot checks, especially for MkDocs syntax, images, tabs, Mermaid, and callouts.
- **Assessment:** Required for migrations, recommended for ordinary authoring when render-affecting syntax changed.
- **Wrapper implication:** `oat-docs-authoring` should include render spot-check guidance and route larger MkDocs migrations to lifecycle/migration docs rather than only running `next build`.

## Wrapper skill boundary

### Belongs in `authoring-docs`

Universal documentation guidance that should stay agnostic:

- Ground facts in repository sources and do not invent commands, env vars, APIs, deployment steps, owners, or guarantees.
- Classify documentation type: tutorial, how-to, reference, explanation, or runbook.
- Use reader-first structure, explicit prerequisites, task steps, expected output, verification, rollback for risky operations, and clear handoff summaries.
- Maintain universal Markdown hygiene: one H1, no skipped heading levels, fenced code language identifiers, descriptive links, active voice, and explicit uncertainty.
- Prefer improving existing docs over creating parallel docs.
- Separate public/internal assumptions and avoid leaking secrets or sensitive operational details.
- Review docs for purpose, accuracy, task support, reference quality, operational safety, agent usefulness, maintainability, and navigation quality.

### Belongs in `oat-docs-authoring`

OAT/Fumadocs-specific rules and workflow guidance:

- Resolve the docs app root and authored docs root from `.oat/config.json`, package scripts, and Fumadocs files instead of assuming a location.
- Distinguish authored `docs/index.md` and nested `docs/**/index.md` files from generated app-root `index.md`.
- Apply the `index.md`/`## Contents` contract to Markdown-bearing content directories, while exempting asset-only directories unless local guidance says otherwise.
- Treat `## Contents` as the OAT local-map contract for navigation, generated manifests, and agent discovery.
- Require `.md`-suffixed links for new `## Contents` entries and `subdir/index.md` for child directories.
- Require `title` and `description` frontmatter for new or touched pages, while preserving local frontmatter style.
- Prefer `.md` over `.mdx`; allow `.mdx` only for component/JSX needs already supported by the app.
- Preserve local Fumadocs shell customizations in `next.config.js`, `source.config.ts`, `app/layout.tsx`, `lib/source.ts`, image components, search options, and base paths.
- Read root `AGENTS.md`, docs-app `AGENTS.md`, nested area `AGENTS.md`, and human contributing/Markdown feature docs before authoring.
- Use local package scripts for format, lint, build, type-check, and generation; do not assume one command shape.
- Validate generated root manifest freshness and warn when generated files lack the expected autogen warning.
- Warn about OAT-specific anti-patterns: hand-editing generated root index, omitting `## Contents`, extensionless `## Contents` links, `overview.md`, unapproved bulk edits, and metadata/chrome confusion.

### Belongs in lifecycle skills

Guidance that should remain in `oat-docs-bootstrap`, `oat-docs-analyze`, `oat-docs-apply`, or `oat-project-document`:

- `oat-docs-bootstrap`: repo preflight, framework choice, site/package/target-dir input gathering, `oat docs init`, scaffold post-patches, build verification, `.oat/config.json` inspection, educational walkthrough, and initial content kickoff. Its scope is explicit in `.agents/skills/oat-docs-bootstrap/SKILL.md:13-47`.
- `oat-docs-analyze`: read-only docs inventory, index-contract checks, quality/coverage assessment, substantive claim verification, navigation/drift findings, and analysis artifact writing. Its analyze/apply boundary is explicit in `.agents/skills/oat-docs-analyze/SKILL.md:34-45` and its index-contract process in `.agents/skills/oat-docs-analyze/SKILL.md:102-112`.
- `oat-docs-apply`: branch-based application of approved recommendations from an analysis artifact, deterministic nav sync, verification, commit, and optional PR. Its boundary is explicit in `.agents/skills/oat-docs-apply/SKILL.md:30-56`.
- `oat-project-document`: OAT project artifact and implementation-code scanning, documentation delta planning, approval, and docs updates for shipped project work. Its scope is explicit in `.agents/skills/oat-project-document/SKILL.md:3-52`.

## Proposed `oat-docs-authoring` contents

Recommended wrapper skill structure:

- **Mode or purpose statement:** “OAT MODE: Docs Authoring Wrapper” — author, migrate, audit, or restructure content inside an existing OAT/Fumadocs docs app while preserving the OAT `index.md`/`## Contents` contract and delegating lifecycle-sized work to existing OAT docs skills.
- **When to use:** Use for targeted docs authoring, page moves, local structure edits, Markdown/Fumadocs troubleshooting, small migrations, or reviewer guidance inside an existing OAT/Fumadocs docs app. Do not use for initial scaffold, bulk unapproved audits, project-derived docs deltas, or full apply workflows.
- **What to read first:** `.oat/config.json`, docs app `package.json`, docs app `AGENTS.md`, root `AGENTS.md` documentation section, target-area `AGENTS.md` if present, nearest `docs/**/index.md`, human contributing docs, `source.config.ts`, `next.config.js`, and `app/layout.tsx` only if the task touches shell/config.
- **OAT/Fumadocs contract:** Authored `docs/**/index.md` maps, `## Contents`, `.md` links, generated root index, frontmatter, `.md` default, no `overview.md`, no hand-editing generated files.
- **Authoring workflow:** Resolve target, classify page type via agnostic baseline, gather repo evidence, edit authored docs only, update nearest and higher-level `## Contents`, preserve local IA/router rules, regenerate the manifest, run local validation scripts, and summarize sources/uncertainties.
- **Migration/refactor workflow pointers:** For MkDocs syntax, `overview.md` conversion, generated-file warnings, metadata/chrome fixes, large structural moves, or repo-wide coverage gaps, point to `oat-docs-analyze`/`oat-docs-apply` or migration guides rather than doing broad rewrites ad hoc.
- **Restructuring guidance:** Move source files and update source/destination `## Contents` in one change; check generated root manifest; search for links to old paths; preserve local `meta.json` if present; do not hand-edit derived navigation.
- **Validation checklist:** Verify every touched directory has `index.md`; every touched index has `## Contents`; links use `.md` or `subdir/index.md`; frontmatter exists; generated root index was regenerated; local `docs:format:check`, `docs:lint`, `build`, and type-check scripts were run when meaningful; render spot checks were done for syntax/render changes.
- **Anti-patterns:** Hand-editing app-root `index.md`; adding pages without `## Contents`; copying extensionless link style into new OAT docs; creating `overview.md`; using `.mdx` without JSX need; bypassing analyze/apply for bulk edits; passing site metadata to `createDocsConfig` and assuming it affects HTML head; overwriting local Fumadocs customizations.
- **Handoff summary expectations:** Files changed, authored maps updated, generated files regenerated or intentionally not run, commands run, evidence sources inspected, uncertainties/owner-review items, and whether lifecycle skills should follow.

Likely reference files for the wrapper skill:

- `references/oat-fumadocs-contract.md` — concise canonical contract with examples.
- `references/authoring-workflow.md` — step-by-step targeted authoring workflow.
- `references/restructure-checklist.md` — moves, links, generated index, local routers, validation.
- `references/migration-pitfalls.md` — MkDocs syntax, `overview.md`, metadata/chrome, generated-file banners, formatter hazards, render checks.
- `references/lifecycle-boundaries.md` — when to invoke bootstrap/analyze/apply/project-document instead.

## Candidate wrapper rules

- **Rule:** Resolve the docs app root before editing.
  - **Why:** The docs app may live at `apps/oat-docs`, `documentation`, `apps/honeycomb-docs`, `apps/duet-docs`, or `apps/documentation`.
  - **Evidence:** Repo config roots differ in `open-agent-toolkit:.oat/config.json:22-28`, `gizmo-slack-app:.oat/config.json:20-25`, `duet:.oat/config.json:20-25`, `cyclone-app:.oat/config.json:22-27`, and `stoa:.oat/config.json:24-30`; `vox-mobile:.oat/config.json:20-22` only records the generated index.
  - **Strength:** required.

- **Rule:** Edit authored files under `docs/`, not the generated app-root `index.md`.
  - **Why:** The generated root manifest is clobbered by `predev`/`prebuild`.
  - **Evidence:** Generated warnings in `oat-docs:index.md:1`, `gizmo:index.md:1`, `honeycomb:index.md:1`, `duet:index.md:1`, `vox-mobile:index.md:1`, and `stoa:index.md:1`; Cyclone warning in `cyclone:AGENTS.md:49` and `cyclone:AGENTS.md:63`.
  - **Strength:** required.

- **Rule:** Every content directory you create or touch must have an `index.md` with `## Contents` unless local guidance explicitly scopes an exception.
  - **Why:** OAT analyze/generate tooling treats `## Contents` as the machine-readable local map.
  - **Evidence:** OAT guidance in `apps/oat-docs/AGENTS.md:13-15`; analyze checks in `.agents/skills/oat-docs-analyze/SKILL.md:102-112`; Stoa contract in `stoa:AGENTS.md:44-59`.
  - **Strength:** required.

- **Rule:** Apply the index contract to content directories, not asset-only directories.
  - **Why:** Asset-only folders should not be forced into rendered section pages or noisy audit findings.
  - **Evidence:** Honeycomb's asset-only `docs/assets` and `docs/assets/images` directories lack `index.md`, while content-directory rules are still explicit in `honeycomb:AGENTS.md:20` and `honeycomb:AGENTS.md:24-28`.
  - **Strength:** required for audits and authoring placement.

- **Rule:** New `## Contents` links use `.md` for leaf pages and `subdir/index.md` for child directories.
  - **Why:** The docs-transform plugin strips `.md` for routing while preserving agent-friendly file paths.
  - **Evidence:** OAT guidance in `apps/oat-docs/AGENTS.md:13` and anti-pattern in `apps/oat-docs/AGENTS.md:49`; Stoa contract in `stoa:AGENTS.md:50-56`; Honeycomb explanation in `honeycomb:docs/apps/honeycomb-docs/contributing/documentation.md:50-54`.
  - **Strength:** required for new work, recommended migration target for existing drift.

- **Rule:** Do not trust the generated root manifest as proof of local navigation health.
  - **Why:** Generated manifests can surface filesystem pages that are missing from nearest parent `## Contents`.
  - **Evidence:** Duet's generated manifest includes a Vox README entry in `duet:index.md:15-16`, while the local parent contents in `duet:docs/apps/index.md:10-13` omit the Vox app.
  - **Strength:** required for audits and restructures.

- **Rule:** Treat extensionless `## Contents` links as drift, not precedent.
  - **Why:** Older authored docs may contain extensionless links that should not be copied forward.
  - **Evidence:** Vox Mobile authored root links are extensionless in `vox-mobile:docs/index.md:12-18`, while generated manifest output uses `.md` in `vox-mobile:index.md:3-29`.
  - **Strength:** recommended.

- **Rule:** Add or preserve `title` and `description` frontmatter on every page touched.
  - **Why:** Fumadocs metadata, nav display, search previews, and sibling summaries depend on these fields.
  - **Evidence:** OAT instruction in `apps/oat-docs/AGENTS.md:12`; Honeycomb authoring expectations in `honeycomb:docs/apps/honeycomb-docs/contributing/documentation.md:84-87`; Cyclone instruction in `cyclone:AGENTS.md:14`.
  - **Strength:** required.

- **Rule:** Prefer `.md`; use `.mdx` only for real JSX/component needs.
  - **Why:** Plain Markdown is easier for agents, linters, grep, and link rewrites.
  - **Evidence:** OAT instruction in `apps/oat-docs/AGENTS.md:11`; Gizmo instruction in `gizmo:AGENTS.md:35`; Honeycomb authoring expectation in `honeycomb:docs/apps/honeycomb-docs/contributing/documentation.md:92-93`.
  - **Strength:** required for new plain-content pages.

- **Rule:** Do not create `overview.md` as a directory entrypoint.
  - **Why:** OAT directory entrypoints are `index.md` files with `## Contents`.
  - **Evidence:** OAT anti-pattern in `apps/oat-docs/AGENTS.md:52`; Gizmo instruction in `gizmo:AGENTS.md:36`; Stoa authoring doc in `stoa:docs/engineering/contributing/documentation.md:16`.
  - **Strength:** required.

- **Rule:** Read local docs-app and target-area instructions before placing or changing content.
  - **Why:** Larger apps add area-specific audience, scope, and cross-area update rules.
  - **Evidence:** Stoa top-level router in `stoa:AGENTS.md:78-94`; Gizmo docs boundary in `gizmo:AGENTS.md:39-45`; Vox Mobile docs boundary in `vox-mobile:AGENTS.md:32-36`.
  - **Strength:** required.

- **Rule:** Preserve local Fumadocs shell customizations unless the task explicitly targets the app shell.
  - **Why:** Apps have custom base paths, search behavior, image handling, static export settings, and API-version differences.
  - **Evidence:** OAT base path and search in `oat-docs:app/layout.tsx:8-19`; Gizmo image/search overrides in `gizmo:app/layout.tsx:6-30`; Vox Mobile direct MDX config in `vox-mobile:next.config.js:1-21`; Stoa uses `source.pageTree` in `stoa:app/layout.tsx:13-18`.
  - **Strength:** required.

- **Rule:** Use local package scripts for validation and generation; do not assume universal commands.
  - **Why:** Script bodies differ and some are intentionally disabled.
  - **Evidence:** OAT scripts in `oat-docs:package.json:6-13`; Honeycomb scripts in `honeycomb:package.json:8-16`; Cyclone no-op lint/format scripts in `cyclone:package.json:13-15`; Stoa type-check in `stoa:package.json:12`.
  - **Strength:** required.

- **Rule:** Route bulk audits and broad restructures through `oat-docs-analyze` and `oat-docs-apply`.
  - **Why:** Analyze/apply provide evidence, approval, branch isolation, nav sync, and verification.
  - **Evidence:** OAT guidance in `apps/oat-docs/AGENTS.md:25-31`; analyze/apply boundary in `.agents/skills/oat-docs-analyze/SKILL.md:34-45`; apply approval boundary in `.agents/skills/oat-docs-apply/SKILL.md:30-56`.
  - **Strength:** required for bulk changes.

- **Rule:** Use `oat-project-document` for docs derived from active OAT project artifacts.
  - **Why:** It preserves provenance from discovery/spec/design/plan/implementation and avoids speculative project docs.
  - **Evidence:** OAT guidance in `apps/oat-docs/AGENTS.md:39-43`; project-document purpose and allowed activities in `.agents/skills/oat-project-document/SKILL.md:23-52`.
  - **Strength:** required for project-derived docs deltas.

- **Rule:** Render-check migration-sensitive syntax, not only build success.
  - **Why:** MkDocs syntax, images, callouts, tabs, and Mermaid can compile while rendering incorrectly.
  - **Evidence:** Honeycomb warns not to treat a green build as proof in `honeycomb:AGENTS.md:39-41` and `honeycomb:AGENTS.md:53-54`; prior gotcha artifact documents Duet/Honeycomb render pitfalls in `.oat/repo/reference/brainstorms/docs-authoring-skill/oat-docs-bootstrap-gotchas.md`.
  - **Strength:** required for migrations, recommended for render-affecting authoring.

- **Rule:** Prefer durable source-code links when rendered docs need code references.
  - **Why:** GitHub blob links work in rendered docs, GitHub reviews, and external docs surfaces without ambiguity about repository or branch.
  - **Evidence:** Honeycomb recommends blob URLs and line anchors in `honeycomb:docs/apps/honeycomb-docs/contributing/documentation.md:106-115`; Duet recommends the same in `duet:docs/contributing/documentation.md:61-68`.
  - **Strength:** recommended.

- **Rule:** Keep rendered docs focused on shipped behavior and local audience boundaries.
  - **Why:** Some repos explicitly separate durable rendered docs from `.oat` provenance, planning detail, and repo reference artifacts.
  - **Evidence:** Gizmo boundary in `gizmo:AGENTS.md:39-45`; Vox Mobile boundary in `vox-mobile:AGENTS.md:32-36`; Stoa area audience table in `stoa:AGENTS.md:78-90`.
  - **Strength:** recommended, required when local guidance states it.

## Candidate updates to existing lifecycle skills

- `oat-docs-bootstrap`
  - **Priority:** High.
  - **Recommendation:** Ensure generated root `index.md` always gets the `AUTOGENERATED` warning after build/generate, even when a scaffold or older package version omits it.
  - **Evidence:** Cyclone is generated by scripts in `cyclone:package.json:8-10` and warns not to edit root `index.md` in `cyclone:AGENTS.md:49`, but `cyclone:index.md:1` starts directly with content rather than an autogenerated warning.
  - **Recommendation:** Strengthen FP-16 or walkthrough guidance so older extensionless authored `## Contents` links are reported as drift/migration targets, not silently normalized without approval.
  - **Evidence:** Vox Mobile authored `docs/index.md` uses extensionless links in `vox-mobile:docs/index.md:12-18`, while newer Cyclone uses `.md` in `cyclone:docs/index.md:12-21`.
  - **Recommendation:** Keep site metadata/chrome education prominent and avoid implying `createDocsConfig({ title, description })` is sufficient.
  - **Evidence:** Honeycomb and Duet comments explicitly distinguish metadata from config in `honeycomb:app/layout.tsx:11-13`, `duet:next.config.js:5-7`, and `cyclone:next.config.js:5-7`.

- `oat-docs-analyze`
  - **Priority:** High.
  - **Recommendation:** Add explicit checks for generated root index freshness and missing generated targets, not only authored `index.md` contract.
  - **Evidence:** Generated root indexes are committed and used across repos; Stoa and Cyclone examples show generated-output drift can exist even when package scripts are correct.
  - **Recommendation:** Report missing autogenerated banner as a scaffold hygiene finding.
  - **Evidence:** Most generated root indexes have a banner at line 1; Cyclone does not.
  - **Recommendation:** Distinguish “existing repo drift” from “recommended OAT target convention” in analysis wording.
  - **Evidence:** OAT's own tree has legacy `overview.md` and index gaps despite `apps/oat-docs/AGENTS.md:52`; Vox Mobile has extensionless authored links despite newer link guidance.

- `oat-docs-apply`
  - **Priority:** Medium.
  - **Recommendation:** When normalizing link style, provide a scoped recommendation type for `.md` link normalization with owner approval, and avoid mixing it into unrelated content edits.
  - **Evidence:** Vox Mobile has broad extensionless link usage in authored docs; normalizing all links would be a structural migration, not a local authoring fix.
  - **Recommendation:** Preserve optional `meta.json` and local sidebar ordering when applying structural changes.
  - **Evidence:** Gizmo says `meta.json` is additive and does not replace `## Contents` in `gizmo:AGENTS.md:33`.
  - **Recommendation:** After apply changes, verify generated root index has the warning and does not contain stale paths, then separately verify local parent `## Contents` coverage.
  - **Evidence:** Generated indexes are committed in every inspected app and regenerated by scripts; Duet shows generated entries can exist even when local parent contents omit the same pages.

- `oat-project-document`
  - **Priority:** Medium.
  - **Recommendation:** Before proposing docs placement, read docs-app and target-area `AGENTS.md` routers when present.
  - **Evidence:** Stoa's top-level area router and cross-cutting rule in `stoa:AGENTS.md:78-94` determine whether user-facing behavior needs `user-guide/`, `reference/`, `operations/`, `agent-guide/`, or `engineering/` updates.
  - **Recommendation:** Treat local docs boundaries as evidence when deciding whether project-provenance details belong in rendered docs.
  - **Evidence:** Gizmo and Vox Mobile explicitly keep planning/provenance details out of rendered docs in `gizmo:AGENTS.md:39-45` and `vox-mobile:AGENTS.md:32-36`.
  - **Recommendation:** Include generated manifest regeneration and `## Contents` update status in project-document handoff summaries.
  - **Evidence:** OAT project docs flow is expected to preserve the same docs-app contract described in `apps/oat-docs/AGENTS.md:39-43`.

## Open design questions

- Should `oat-docs-authoring` be a pure wrapper over `authoring-docs`, or should it include compact copies of core universal docs rules for convenience when the agnostic skill is unavailable?
- Should existing extensionless links be automatically normalized when a nearby `## Contents` is touched, or should normalization always require an explicit migration/audit recommendation?
- Should missing `## Contents` in a single-page Markdown-bearing directory be treated as required drift, or can the wrapper allow local exceptions for topic pages that happen to be named `index.md`?
- Should `oat-docs-authoring` invoke `oat-docs-analyze` automatically for broad terms like “audit docs,” or only recommend it unless the user explicitly asks for an audit?
- How much Fumadocs shell troubleshooting belongs in the wrapper versus lifecycle references? Examples include `source.getPageTree()` versus `source.pageTree`, `PlainImg`, base paths, static export, and Turbopack root.
- Should the wrapper define a standard generated-root-index freshness check plus local-parent coverage check, or should that remain an analyze/apply responsibility?
- Should `meta.json` support be documented only as a preservation rule, or should the wrapper include guidance for adding/updating it when local style uses it?
- Should rendered-doc boundaries about `.oat/` provenance and planning artifacts become a general OAT rule, or remain repo-local unless explicitly stated?
- Should the wrapper instruct agents to run render spot checks on every docs build, or only when migration syntax, images, Mermaid, tabs, callouts, or MDX components changed?

6. After the wrapper exists, test it against two contrasting apps: `cyclone` for a newer scaffold with small drift and `vox-mobile` for older partial adoption with extensionless links.
