Why this project existed

Make the ordinary recap path dependable

The former implementation-tail path asked a normal host for custom authoring, critique, planning, browser, and visual-review providers before it could produce a page. The ordinary lifecycle often produced no recap.

Requested result

Produce one standalone, navigable HTML recap from approved project evidence, verify it honestly with the best available browser capability, and preserve archive-safe proof without adding a new command surface.

Choices that shaped the result

Put editorial judgment in the host; keep assurance in the core

One authoring owner

The host agent writes the page. The installed core constrains sources, narrative anchors, scripts, and traceable facts.

One recipe-selected flow

Bundle, author, verify, and record serve lifecycle callers and direct users without custom callback modules.

Honest visual assurance

Browser inspection is preferred. Playwright is the next rung. Static checks still run when neither browser path is available.

Archive export owns durability

The project removed a second publication and attestation system. The archive copy remains the durable handoff.

Delivered system

A thin adapter around a destination-neutral core

The OAT adapter resolves intent, theme, approved lifecycle sources, and the canonical run location. The installed core owns the package stages and their machine checks.
