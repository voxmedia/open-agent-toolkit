Key agent decisions

Four design choices shaped the delivered behavior. Quick mode went straight to a plan, because every item already had concrete acceptance criteria and these choices were recorded during discovery.

Accept alwaysApply as an alias

Choice Canonical rule parsing reads alwaysApply: true as activation: always, as the Cursor importer already did. Every other parse error names the file.

Why Warn-and-skip would drop a rule its author clearly meant to apply. File-naming errors still catch the rules that are truly invalid.

Label the gate audit stamp as the policy view

Choice Gate-originated reviews label the resolver's stamp **Dispatch audit (policy view):** instead of building a second stamp from the gate invocation. Validation rejects an unlabeled stamp that disagrees with the gate.

Why The label keeps the Dispatch: token, so the audit line still has a single extraction path.

Cost After release, reviews from older installed copies of oat-project-review-provide can trip the new check until oat tools update runs.

Keep config key order and skip no-op writes

Choice Writes to .oat/config.json keep the existing key order. A write that changes nothing leaves the file untouched, and a real change never reorders keys it did not touch.

Why Config churn from reordering or rewriting identical content disappears from diffs.

One redacted message for dispatch-record problems

Choice Managed Claude dispatch-record validation gathers every violation into a single scrubbed multi-line error rather than adding a new violations JSON field. The published example is pinned by validating it as-is.

Why One run now surfaces every independent input problem, and each line is scrubbed of secret-shaped values.

Where the build departed from the plan

  • p01-t03 took the backlog item's labeling branch. Review then widened stamp recognition to every section that is not a finding section.
  • After p02-t02, nothing depended on the sync conjunct that guarded the no-change line beside a failed scope, so review removed it as dead code. A test that cannot fail is not a pin.
  • p02-t06 added an export to providers/shared/registry.ts, outside the declared write set, so sync evidence reuses the registry's check. The parallel phase never touched that file.
  • p03-t07 placed the per-line scrub in providers/claude/dispatch-envelope.ts, which owns the report error class, outside the task's listed files.
  • Recovery p03-rec-01 handled a field-list line in record-schema.md that matched the autonomy-gate inventory's prompt-site scan. One recovery attempt mapped it in the autonomy contract.
