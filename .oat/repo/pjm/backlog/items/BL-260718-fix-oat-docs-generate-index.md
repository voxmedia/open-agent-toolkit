## Description

Bare 'oat docs generate-index' resolves its defaults (--docs-dir 'docs', --output index.md) against the invoking cwd. In a monorepo whose docs app lives elsewhere (this repo: apps/oat-docs), a bare invocation from repo root silently generates a stray ./index.md from the wrong tree instead of failing or locating the docs app. Evidence: 2026-07-18 wave-skills-promotion p04-t02 - the phase implementer ran the bare command per docs conventions ('regenerated by oat docs generate-index' in apps/oat-docs/AGENTS.md), got a stray repo-root index.md, and had to delete it and re-run with explicit --docs-dir apps/oat-docs/docs --output apps/oat-docs/index.md. Suggested fix: detect the docs app root (config key or marker file) or hard-fail when --docs-dir does not exist / contains no docs surface; align the AGENTS.md convention text with the exact flagged invocation.

## Acceptance Criteria

- A bare `oat docs generate-index` from the repository root either locates the
  configured docs app or fails closed. It must never silently generate an index
  from the wrong tree.
- The command does not mutate `documentation.index` in `.oat/config.json` as a
  side effect of generating. Regenerating a configured artifact must not
  re-point the configuration that names it.
- `apps/oat-docs/AGENTS.md`'s "regenerated by `oat docs generate-index`" wording
  matches the exact invocation that is actually safe to run.

## Additional evidence (2026-08-29, portable-agent-references)

Recurred, and worse than first recorded. Running `oat docs generate-index` from
the repository root during that project's docs-delta step produced the known
stray root `index.md` (4 lines, indexing `research/`) **and additionally
rewrote `documentation.index` in `.oat/config.json` from `apps/oat-docs/index.md`
to `index.md`**. The real `apps/oat-docs/index.md` was untouched.

That second symptom is new relative to the 2026-07-18 evidence and is the more
damaging one: the stray file is obvious in `git status`, whereas the config
rewrite is a one-line change that would have shipped inside an unrelated PR had
the commit happened two minutes earlier. It was caught in a post-commit status
check and reverted.

This broadens the item's scope from "wrong default output path" to "wrong
default output path, and persists that wrong path into repository config."
Scope broadening approved by the operator at retro filing time.
