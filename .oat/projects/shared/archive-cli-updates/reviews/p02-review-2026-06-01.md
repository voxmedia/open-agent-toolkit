### Important

- **Missing local-only worktree guard before mutating archive push** (`packages/cli/src/commands/project/archive/push-runner.ts:251`)
  - Issue: `runArchivePushCommand()` delegates straight into `archiveProjectOnCompletion()` once dry-run is false. The quick-mode discovery and plan require preserving the worktree-durability guard and surfacing the local-only warning when the primary-repo archive path is unavailable. The existing helper resolves the primary repo when archive contents are ignored, but if that primary path cannot be resolved it falls back to the current `repoRoot` without returning a warning or requiring confirmation. Because this new command is mutate-by-default and has no additional preflight, a linked worktree with ignored `.oat/projects/archived/**` can copy the project into a local-only ignored archive and remove the active project without the required warning/confirmation when the primary checkout is unavailable.
  - Fix: Add a pre-mutation planner/preflight shared with `archive-utils.ts` that detects ignored archive contents, whether the primary archive root is available, and the final archive target. In the unavailable-primary case, fail before mutation with an actionable `CliError` or implement an explicit confirmation path consistent with the documented guard; do not silently continue into a local-only worktree archive. Add a regression test for a linked worktree where `git check-ignore --no-index .oat/projects/archived/<project>` succeeds and the primary repo archive root is unavailable.
  - Requirement: p02-t01; discovery Key Decision 4; plan Phase 2 `--dry-run`/worktree-durability bullets.

### Medium

- **Dry-run previews a different archive path than apply mode in linked worktrees** (`packages/cli/src/commands/project/archive/push-runner.ts:143`)
  - Issue: `buildDryRunReport()` builds `archivePath` from `repoRoot` directly, while apply mode uses `archiveProjectOnCompletion()`, whose archive path can switch to the primary checkout when archive contents are gitignored in the current worktree. In this repo, `.oat/projects/archived/**` is ignored, so `pnpm run cli -- project archive --dry-run .oat/projects/shared/archive-cli-updates` previews the worktree-local archive path even though apply mode should archive under the primary checkout when available. That violates the Phase 2 dry-run requirement to preview the resolved archive target.
  - Fix: Reuse the same pure archive-target resolution as apply mode for dry-run, including primary-checkout selection and unique-path suffix handling. Add a push-runner dry-run test for the linked-worktree path already covered by `archive-utils.test.ts`.
