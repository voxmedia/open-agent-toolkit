### Medium

- **The guard's fenced-example exclusion is defeated by heterogeneously nested

    `/^[[:space:]]*([`][`][`]|~~~)/ { fence = 1 - fence; next }`, which treats
` ``` ` and `~~~`as interchangeable delimiters and does not remember which
one opened the block. A backtick fence nested inside a tilde fence therefore
flips the toggle to "outside", so content that is plainly inside a fenced
example is scanned as the record. Predicate condition 4 at`:883-887`
    explicitly promises the opposite ("never inside a fenced example").

    example placed _before_ the real `## Reviews` section returns `not-ready`
    only because `tail -1` happens to pick the real row — the outcome depends on
    document order, not on the fence semantics the predicate claims.
  - The shipped tests do exercise ` ``` ` and `~~~` fences, but only
    non-nested ones, so this class passes today.
  - Fix: track the opening delimiter, e.g. capture the fence marker on open and
    only close on a matching marker:
    `/^[[:space:]]*(```|~~~)/ { if (!fence) { fence = 1; mark = substr($0,1,3) } else if (substr($0,1,3) == mark) fence = 0; next }`.
    Add a nested-fence fixture in both directions (example before and after the
    real section) to
