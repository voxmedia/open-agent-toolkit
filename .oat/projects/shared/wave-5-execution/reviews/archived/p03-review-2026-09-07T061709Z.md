### M1 — the CommonMark trace is correct; the Codex case was rightly rejected

I did not take the trace on faith. I cross-checked the guard against
`micromark@4.0.2` (the CommonMark reference implementation, resolved from this
worktree's `node_modules`), asking for each fixture whether the example
`| plan | artifact | passed |` row lands inside a `<pre><code>` block or leaks
into document content, and compared that to the guard's verdict:

| Case                                                | micromark says                                                 | Guard says                  | Agree   |
| --------------------------------------------------- | -------------------------------------------------------------- | --------------------------- | ------- |
| `~~~yaml` inside `~~~text` (the Codex case)         | **leaks outside code** — the bare `~~~` closes the outer fence | `ready` (row is the record) | **yes** |
| `~~~~text` outer, `~~~yaml` inner (shipped fixture) | inside code                                                    | `not-ready`                 | yes     |
| ` ``` ` inside `~~~` (my round-1 attack A1b)        | inside code                                                    | `not-ready`                 | yes     |
| ` ``` ` inside ` ```` ` (my new n11)                | inside code                                                    | `not-ready`                 | yes     |
| indented `~~~` inside `~~~` (my new n12)            | inside code                                                    | `not-ready`                 | yes     |

Six-for-six agreement with the reference parser, in both directions. The Codex
finding was correctly rejected: in CommonMark you cannot nest a same-marker fence
of equal length, so the inner bare `~~~` genuinely terminates the outer block and
the row that follows genuinely is document content. A guard that treated it as an
example would diverge from every renderer that displays the file. The awk
implementation at `:955-969` and `:993-1007` records the opening marker character
and run length, closes only on a bare run of the same marker at least as long,
and ignores markers indented four spaces or more — which is what CommonMark
specifies.
