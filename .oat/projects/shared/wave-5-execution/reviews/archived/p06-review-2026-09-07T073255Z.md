  - Issue: `PLACEHOLDER_SYNTAX = /[<{}$*?]/` is applied to the whole token
    after only a single trailing prose mark is dropped, so an emphasis marker
    that survives in the token discards the reference instead of reporting it.
    Measured on the shipped build:

    | Input                                          | Extracted |
    | ---------------------------------------------- | --------- |
    | `**.oat/scripts/missing.sh**`                  | (none)    |

    | `_.oat/scripts/missing.sh_`                    | (none)    |
    | `Run .oat/scripts/missing.sh**`                | (none)    |
    | `` `**.oat/scripts/missing.sh**` ``            | (none)    |
    | `**.oat/scripts/resolve-tracking.sh**` (valid) | (none)    |

    Two distinct causes. For the `*` forms the token retains the trailing
    `**`, and `*` is in `PLACEHOLDER_SYNTAX`, so `skill-script-references.ts:155`
    `continue`s. For `_.oat/…` the start pattern
    `SCRIPT_REFERENCE_START` at `:41` never matches at all, because its
    lookbehind `(?<![A-Za-z0-9_.-])` excludes a preceding `_`.

    This is live-reachable, not merely a unit-level curiosity. Appending
    `Run **.oat/scripts/bold-missing.sh** now.` to
    `.agents/skills/oat-docs-analyze/SKILL.md` (a shipped, docs-pack skill)
    and running the contract case gave `exit=0` with zero violations, while
    the same line without the `**` gives exactly one violation. The module's
    own rationale comment at `:53-54` — "a fail-open integrity check is worse
    than none" — is the standard this misses.

  - Severity rationale: not Critical. Ruling 7's Critical trigger is a shape
    the plan's test plan requires to be caught; every plan-named shape
    (`$SCOPE_ROOT`-prefixed, backticked, link-form, bare-prose negative) is
    handled correctly in its plain spelling. Nothing previously rejected is
    now accepted — the prior state had no general check at all, only a
    substring gate on `resolve-tracking.sh` — so the weaker-anywhere rule does
    not fire either. There are zero live instances (all 11 live references are
    `$SCOPE_ROOT`-prefixed, backticked, or inside fenced shell blocks; the repo
    consistently backticks paths, and ``**`path`**`` extracts correctly

    real fail-open on an authored Markdown spelling that this repo does use for
    other paths (for example `.agents/skills/oat-docs-bootstrap/SKILL.md:961`).
  - Fix: before the `PLACEHOLDER_SYNTAX` test in `extractScriptReferences`,
    strip a leading and trailing run of `*` from the token. `*` is not a legal
    path character, so a boundary run is unambiguously emphasis, while a `*`

    (`skill-script-references.test.ts:148-152`). Cover the `_`-italic form by
    documenting the lookbehind limitation rather than widening the lookbehind.
