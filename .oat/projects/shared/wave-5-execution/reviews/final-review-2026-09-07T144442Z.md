### Important

- **Concurrent gate finalizations can report success after committing another writer's event and dropping their own** (`packages/cli/src/commands/project/log/append.ts:848`)
  - Issue: `appendEntry` reads and rewrites the whole log before the synthesis
    section without coordinating with another writer. The idempotency scan is
    also separate from that mutation (`append.ts:893-925`). If writers A and B
    both read the same log, B can overwrite A's entry; A can then stage and
    commit B's bytes, and `commitProjectLog` immediately returns `committed`
    without verifying A's supplied identity (`append.ts:364-371`). Both
    processes can settle successfully while A's `runId` is absent. This
    violates p04's stable-identity and replay-safety outcome for the exact
    concurrent Git-writer condition the feature handles.
  - Fix: make the append/idempotency mutation concurrency-safe without deleting
    another process's Git lock, and verify the caller's identity after every
    nominally successful commit. Add a deterministic overlapping-writer control
    proving two distinct run IDs both survive and a same-ID replay remains
    singular, including a log with an end-of-run synthesis section.
  - Requirement: p04 outcome and done criterion that retries never lose or
    duplicate the `runId`-identified finalization event.

- **The public project-status recommender bypasses quick-plan readiness** (`packages/control-plane/src/recommender/router.ts:62`)
  - Issue: the p03 predicate requires ready frontmatter, a durable review
    disposition, and a substantive task. The control-plane router instead maps
    every quick plan at boundary tier 2 directly to
    `oat-project-implement` (`router.ts:62-69`), while boundary tier 2 checks
    only `oat_status: in_progress`, template state, and placeholders
    (`recommender/boundary.ts:20-30`). A completed artifact's `oat_ready_for` is
    also followed without checking the review/task conditions
    (`router.ts:105-120`). `oat project status` publishes this recommendation,
    so an interrupted or hand-edited quick plan that all four lifecycle skills
    reject can still be told to implement.
  - Fix: give the control-plane artifact reader a shared executable equivalent
    of Quick Plan Readiness and route not-ready quick plans to
    `oat-project-quick-start`; add public `project status` controls for a
    substantive but pre-review plan and for ready frontmatter missing either a
    disposition or a substantive task.
  - Requirement: p03's “incomplete quick-workflow project never dead-ends”
    outcome and the repository workflow-change inventory's recommender/router
    consumer requirement.

- **`oat config unset` omits the documentation key that p05 explicitly waited for p02 to add** (`packages/cli/src/commands/config/index.ts:97`)
  - Issue: p05's dependency and refresh clauses require its family-coverage
    test to include p02's `documentation.*` opt-out. The live catalog and
    `KEY_ORDER` contain `documentation.excludes` but omit
    `documentation.instructionPointerExcludes` (`index.ts:97-111,225-240`),
    and the test codifies that omission as deliberate
    (`index.test.ts:4470-4475`). Operators therefore cannot remove the newly
    introduced opt-out with the new unset surface, and the enumerated family
    test never exercises it.
  - Fix: expose `documentation.instructionPointerExcludes` through the config
    catalog with set/unset validation and family coverage, or revise and
    re-review the p02/p05 product contract before claiming p05 complete. Add a
    negative control that fails when the key is removed from `KEY_ORDER`.
  - Requirement: p05 dependency row, refreshed boundary statement, and step 2
    requirement to cover every documentation key landed by p02.

### Medium

- **A pending receipt is labeled stale before its log entry is committed** (`packages/cli/src/commands/gate/index.ts:3045`)
  - Issue: p04 reserves `stale` for a receipt whose run entry is already
    committed. The warning checks only the working-tree `project-log.md`; that
    is the normal state immediately after exhausted commit retries, so the next
    gate labels unfinished finalization stale. The test seeds its entry before
    repository setup and therefore covers a committed entry, not the pending
    working-tree case (`index.test.ts:6213-6240`).
  - Fix: classify staleness against `HEAD:project-log.md` (with exact identity),
    and add a control whose log entry is dirty and whose receipt remains
    `pending` until recovery commits it.

- **The readiness guard treats a tab-indented fence marker as CommonMark syntax** (`.agents/skills/oat-project-quick-start/SKILL.md:973`)
  - Issue: the guard counts raw leading whitespace characters and accepts any
    count below four. A tab counts as one character to AWK but expands to a
    four-column code indentation in CommonMark, so a tab-indented apparent
    closer can end the guard's fence while remaining example code. Subsequent
    example review rows or tasks can then make a non-ready plan pass. The same
    logic is duplicated for review and task extraction (`SKILL.md:1011-1023`).
  - Fix: measure indentation in columns with tab expansion or reject leading
    tabs as indented code; add tab-indented opener/closer fixtures that prove
    example dispositions and tasks cannot satisfy readiness.

- **The executable external-plan contract does not protect the required plan-to-source backlink** (`packages/cli/src/commands/init/tools/shared/skills-bundled-docs-contract.test.ts:2303`)
  - Issue: p07 requires bidirectional links and says its executable backstop
    covers that contract. The skill and template currently contain the rule,
    but the template assertions cover headings, provenance, statuses, and
    legacy mode without asserting a source backlink. `evaluateExternalPlan`
    likewise checks no link (`skills-bundled-docs-contract.test.ts:525-665`). A
    template regression can therefore remove half of the tracking relationship
    while all p07 tests stay green.
  - Fix: add a template assertion and a prospective-fixture rule for the
    plan-body source link, with a mutation control that removes it and fails.

- **A newly scaffolded consolidation writes through the pre-creation project path** (`.agents/skills/oat-project-quick-start/SKILL.md:123`)
  - Issue: quick-start resolves `PROJECT_PATH` before `oat project new`, then
    creates and activates the project at lines 155-159 without resolving the
    variable again. The new p11 consolidation branch immediately directs
    `absorbed_projects` and `absorbed_backlog_ids` into
    `"$PROJECT_PATH/state.md"` (`SKILL.md:167-184`). The contract test checks
    only that this prose exists, so it cannot prove the fields reach the newly
    created project; completion can consequently skip the ownership sweep for
    lack of inputs.
  - Fix: re-resolve and validate `PROJECT_PATH` immediately after scaffolding,
    before any Step 1 or consolidation write, and add an executable create-path
    control that reads both fields back from the created `state.md`.
