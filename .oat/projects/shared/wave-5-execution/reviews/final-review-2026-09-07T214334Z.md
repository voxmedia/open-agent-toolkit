### Medium

- **The backlog matcher validates only the first character of an extension segment** (`packages/cli/src/commands/init/tools/shared/skills-bundled-docs-contract.test.ts:284`)
  - Issue: `BACKLOG_ID_MATCH_END` accepts as soon as the declared ID is
    followed by `-[A-Za-z0-9]`; it never consumes the extension or checks its
    final boundary. Consequently a declaration of `BL-123` accepts links to
    `BL-123-other_more`, `BL-123-otheré`, and `BL-123-other--tail`, even though
    the adjacent comments and p12-t09 require one or more complete
    hyphen-delimited alphanumeric segments and nothing else. The focused suite
    stays green because it tests malformed characters only at the first
    extension position.
  - Fix: match either the exact declared ID at a Unicode-aware token boundary
    or consume the complete `(?:-[A-Za-z0-9]+)+` extension before enforcing
    that boundary. Add negative controls for malformed suffixes after an
    initially valid extension segment while retaining the valid multi-segment
    case.
  - Requirement: p12-t09's exact-or-validated-extension contract.

- **Fence parsing still runs before HTML comments are removed** (`packages/cli/src/commands/init/tools/shared/skills-bundled-docs-contract.test.ts:342`)
  - Issue: both `linkDefinitions()` and `sourceDeclarations()` call
    `withoutFences(section)` before removing comments (the second call is at
    line 505). A fence opener inside an HTML comment therefore changes parser
    state and can hide a valid declaration or definition after the comment.
    The independent control `<!--` / ` ```markdown ` / `-->` followed by a
    linked source declaration produced `current-order-retains-declaration=false`;
    removing comments first produced `true`. This contradicts p12-t09's
    explicit instruction to strip comments before scanning definitions and
    declarations.
  - Fix: remove HTML comments before passing the section to the fence scanner,
    share that ordering between definition and declaration extraction, and add
    controls with fence-looking lines inside terminated and unterminated
    comments followed by valid source content.
  - Requirement: p12-t09's comment-before-definition/declaration contract.
