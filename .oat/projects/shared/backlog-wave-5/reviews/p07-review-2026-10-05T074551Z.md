### Low

- **Fragment-target scan can skip real ids after an inline script, stripping a valid link** (`packages/cli/src/commands/project/archive/archive-utils.ts:1620`)
  - Issue: the new target scan iterates `html.matchAll(markup)` and skips matches that start inside a raw-text body (`match.index < targetCursor`, line 1621). Skipping a match does not move the scan back to the closing tag, so a match that starts inside the body and runs past `</script>` swallows the markup after it. The main walk avoids this by resetting `markup.lastIndex = cursor` (line 1761); the target scan has no equivalent, so the two walks disagree despite the comment saying they use the same readers. Confirmed against the real exporter through `archiveProjectOnCompletion`: for `<a href="#later">go</a><script>var i = s.indexOf('<!--');</script><h2 id="later">Later</h2>` the exported page contains `<a data-probe="p">go</a>` with the `href` removed, while the same page without the script keeps it. The comment alternative in `markup` matches from `<!--` to the next `-->` or to end of input, so every id between the script and that point is missed. The pre-fix check tested the whole page text and kept this link, so this is a regression from p07-t11. It needs an inline script, style, or textarea body containing an unterminated comment opener (or similar overrunning markup) ahead of the target, so it is uncommon; the effect is a dead navigation link in the derived page, with the original recap bytes untouched.
  - Suggestion: drive the target scan with the same `exec` loop shape as the main walk and set `lastIndex` to the end of the raw-text element after each one, or collect targets inside the main walk's own traversal in a first pass. Add one keeper next to `ignores fragment targets described only in raw text, comments, or attribute values` (`archive-utils.test.ts:377`) with a script body containing `<!--` followed by a real target.
