### Low

- **Pending-retry ownership evidence silently drops files larger than 1 MiB** (`packages/cli/src/commands/backlog/rewrite-references.ts:710`, `packages/cli/src/commands/backlog/archive.ts:179`)
  - Issue: Both `git show HEAD:…` reads use `execFile`'s default 1 MiB output limit and swallow every error as "no evidence". On a pending Git retry, a reference file over 1 MiB that the first pass rewrote is no longer reported. Reproduced: a 59-byte reference is claimed on retry (5 paths); the same reference at 1,248,059 bytes is not (4 paths). A caller that commits from the retry result would leave that rewritten reference uncommitted. The same limit applies to `completed.md` and `index.md` in HEAD. The first-pass result is unaffected, and the largest tracked Markdown under `.oat/repo` today is 355 KB, hence Low.
  - Suggestion: Pass an explicit `maxBuffer` (the file lister in the same module already uses 64 MiB), and treat only "path absent in HEAD" as missing evidence rather than every failure.

- **`affectedPaths` names the old item path even when it was never tracked, and the helper then rejects the whole list** (`packages/cli/src/commands/backlog/archive.ts:209`, `apps/oat-docs/docs/reference/config-and-local-state.md:91`)
  - Issue: An item created and archived before its first commit still reports `items/<id>.md`. Passing the list verbatim to `oat internal commit-paths` fails closed with `Absent path is not a tracked removal` (exit 2, nothing committed, user literals intact; reproduced). The long-form guidance in `.oat/repo/pjm/AGENTS.md`, its template and `oat-pjm-update-repo-reference` tells the caller to omit a never-tracked source. The shorter call sites (`oat-doctor`, `oat-pjm-review-backlog`, `oat-wave-execute`, `cli-reference.md`) and the result description ("old item path (a tracked deletion)") do not.
  - Suggestion: Either state the never-tracked omission rule wherever the result contract is described, or have the short call sites defer to the Backlog Lifecycle text for it. No data is at risk; the cost is a stopped close-out with a clear error.

- **A rewritten untracked reference is reported, so an exact-path commit captures the whole untracked file** (`packages/cli/src/commands/backlog/rewrite-references.ts:703`)
  - Issue: The scanner rewrites untracked, non-ignored Markdown under `.oat/repo` (existing behavior), and such a file now appears in `affectedPaths` (reproduced with an untracked `reference/draft.md`). Guidance tells callers to commit the complete list, which adds the user's entire uncommitted draft to the close-out commit. This matches the S1 wording ("every … rewritten reference path"), so I am reporting it as a product choice rather than a defect: whether callers should commit, skip or flag untracked references is not stated anywhere.
  - Suggestion: Decide the intended disposition and say so in the Backlog Lifecycle guidance. I have not chosen one.

- **The knowledge prepare snippet hides its report from the consumer** (`.agents/skills/oat-repo-knowledge-index/SKILL.md:65`)
  - Issue: Step 2 redirects the JSON report into a `mktemp` file held only in a shell variable and prints nothing. An agent that runs Step 2 and Step 10 as separate shell calls has neither the variable nor the content, yet Step 10 requires the report's removed paths. The owning test has to append its own `cat "$KNOWLEDGE_REFRESH_REPORT"` to read it (`tests/refresh-owned.test.mjs:156`). The eight expected outputs are documented and recoverable; a marked generated file outside that set would be deleted on disk and left out of the commit (visible in `git status`, not lost). The temp file is also never removed.
  - Suggestion: Have the snippet print the report (or its path) so the retained list survives between steps.
