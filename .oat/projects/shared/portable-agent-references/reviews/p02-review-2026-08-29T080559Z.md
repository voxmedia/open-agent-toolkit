### Judgment call: the conditional `tool-packs.md` edit

The plan made `tool-packs.md` conditional on the existing mixed-scope section
being unable to express the agent fallback without ambiguity. **The condition
was met and the edit is correct and minimal.** The pre-existing paragraph
(`tool-packs.md:82-84`) states exactly one resolution order — "Lifecycle skills
resolve each required sibling independently from the loaded scope, then user
scope, then project scope" — and that section is the canonical explainer for
mixed-scope `workflows`/`utility` placement. The `workflows` pack ships three
materialized agents through that same install path
(`pack-manifest.ts:225-229`), and those agents _cannot_ use the loaded-scope
step. Leaving the section unchanged would present a single three-step order in
the one place a reader goes to reason about mixed-scope resolution, with no
signal that the agents shipped by the same pack use a different order. The edit
adds 8 lines, states the exception plus its rationale, links to the full
contract instead of duplicating it, and restructures nothing. Only the "these
packs" attribution is loose (Minor m1).
