### Medium

- **Template rendering interprets `$` replacement patterns, corrupting authored metadata and Contents** (`packages/cli/src/commands/docs/init/markdown.ts:84`)
  - Issue: `renderMarkdownTemplate` calls `content.replaceAll(token, value)` with string `value`s derived from user input (`siteName`, `siteDescription`), `basename(repoRoot)`, and adopted filenames (via `{{CONTENTS}}` labels). JavaScript treats `$&`, `` $` ``, `$'` and `$$` in a string replacement as special patterns. Reproduced against the branch source: `oat --json docs init --framework markdown --adopt --yes --site-name "Acme \$' Docs" --description 'Pay $& more'` on a tree containing `docs/price-$&-notes.md` returned `status: ok`/exit 0 but wrote a `docs/index.md` whose frontmatter is `title: "Acme ` followed by the entire remaining template (unterminated YAML string), whose description is `"Pay '{{DESCRIPTION_METADATA}}' more"`, whose body duplicates the template several times, and whose Contents label reads `Price {{CONTENTS}} Notes`. This violates the design's meaningful title/description metadata and useful-index contract and the success criteria for authored entrypoints, and the result is reported as successful. `$$` silently collapses to `$` (e.g. a title like `Pricing $$ tiers`).
  - Fix: Use a replacer function so values are inserted literally, e.g. `content.replaceAll(token, () => value)` (or `split(token).join(value)`). Add a public `docs init` regression (existing `integration.test.ts` harness) with `$&`, `$'`, `$$` in `--site-name`/`--description` and an adopted filename containing `$&`; parse the frontmatter with the independent YAML reader and assert exact title/description and a single Contents section. Show the regression failing on the current encoder and passing after the fix.
