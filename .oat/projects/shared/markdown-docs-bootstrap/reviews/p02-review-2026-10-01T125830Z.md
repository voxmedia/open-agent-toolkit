### Medium

- **M1: Encode URI delimiters in generated filename links** (`packages/cli/src/commands/docs/init/markdown.ts:203`)
  - Issue: `encodeURI(path)` preserves `#` and `?`. When explicit adoption creates a missing root index for existing `docs/deploy#prod.md` and `docs/how?to.md`, it reports `ok` and writes `[Deploy#prod](deploy#prod.md)` and `[How?to](how?to.md)`. Relative URI resolution addresses `/docs/deploy` with fragment `#prod.md` and `/docs/how` with query `?to.md`; neither addresses the actual page. The same helper handles child-directory index links, so names such as `operations#prod/` also produce a broken Contents destination. This violates the p02-t02 requirement to map actual sibling pages and authored child indexes with working relative Markdown links.
  - Fix: Encode each path segment as filename data, retaining `/` separators and escaping characters that terminate Markdown destinations. For these controls, emit literal destinations `deploy%23prod.md` and `how%3Fto.md`. Add a public adoption regression with existing special-character filenames and a child index; verify generated destinations resolve to the existing files, without changing those files.
