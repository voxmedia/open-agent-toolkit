## Findings

### Critical

- **The persistence schema accepts unsuppressed signaled content**
  (`packages/cli/src/commands/pjm/remote/schema.ts:342`)
  - Issue: The new refinement validates `contentRedacted` against the supplied
    evidence and validates evidence-to-marker references, but it never checks
    retained core or extension values for the same sensitive-content signal.
    Consequently, `RemoteSnapshotRecordSchema.parse()` accepts a description
    such as `password private-tail` with `contentRedacted: false` and no
    redactions. `RemoteBindingStateSchema` nests that snapshot, and
    `RemoteSyncStore.writeBindingState()` persists it after only schema parsing.
    This bypasses the P0 requirement that every signaled inbound field be
    suppressed before either storage class is written.
  - Fix: Enforce the field-suppression invariant at the persistence boundary.
    Reject any retained core or adapter-extension field whose bounded content
    triggers the signal unless the complete top-level field is the suppression
    marker with exactly one matching evidence record. Also reject an unpaired
    marker/evidence state, and add direct schema and store tests proving that a
    caller cannot bypass `sanitizeRemoteSnapshot()`.
  - Requirement: FR12, NFR1

### Important

- **The incompatible snapshot shape still identifies itself as schema version 1**
  (`packages/cli/src/commands/pjm/remote/schema.ts:290`)
  - Issue: At the base commit, schema-v1 snapshots used a string `field`, the
    `credential` reason, and no `representation`. The reviewed commit changes all
    three while retaining `schemaVersion: 1`; those previously valid records now
    fail parsing when nested binding state is read through `RemoteSyncStore`.
    A direct parse of a base-shape record fails on all three changed properties.
    This makes restart behavior depend on when the record was written and leaves
    no safe treatment for snapshots produced by the retired, known-incomplete
    parser.
  - Fix: Introduce an independently versioned snapshot/binding-state schema and
    an explicit migration or compatibility parser. Legacy redaction evidence
    must cause the complete affected field to become unavailable, or the legacy
    snapshot must be invalidated and refreshed; do not preserve or trust the old
    parser's partially retained field text. Add read/store fixtures for the
    prior shape and the chosen migration behavior.
  - Requirement: NFR3

- **The allowlist bound exceeds the suppression-evidence bound**
  (`packages/cli/src/commands/pjm/remote/snapshot.ts:143`)
  - Issue: `validateExtensionAllowlist()` accepts as many as 64 unique extension
    keys, while `RemoteSnapshotRecordSchema` permits only 16 redaction records.
    Seventeen allowlisted extensions containing the signal are all correctly
    replaced by markers, but final schema parsing rejects the 17th record instead
    of retaining the bounded incomplete snapshot.
    Four signaled core fields reduce the usable extension-evidence capacity
    further.
  - Fix: Use one shared bound that accounts for all four core fields plus the
    maximum accepted extension keys, or reduce the accepted allowlist bound so
    every allowed input can produce valid evidence. Add a boundary test at the
    maximum with all fields signaled.
  - Requirement: FR12
