  (`packages/cli/src/commands/pjm/remote/providers/linear.ts:1196`)
  - Issue: The read branch of `linearAdapter.verify()` validates the action,
    provider, exact context, and stable identity, but it does not compare
    `issue.extensions.capabilityEvidenceDigest` with
    `action.intent.capabilityEvidenceDigest`. A live probe normalized a
    same-identity, same-context readback carrying `sha256:stale` instead of the
    planned capability digest. `validateObservation()` correctly returned
    `capability-evidence-mismatch`, while the exported `verify()` method
    independently returned `{ field: 'stable-identity', status: 'verified' }`.
    Mutation verification already enforces this capability binding at
    `linear.ts:1219`.
  - Impact: The public adapter exposes contradictory verdicts for the same
    evidence. The current fake persistence lifecycle requires both gates and
    therefore does not persist this probe, but any generic consumer that treats
    `ProviderAdapter.verify()` as an independently authoritative field-verdict
    surface can ratify stale or misattributed read evidence.
  - Fix: Require the normalized issue capability-evidence digest to equal the
    read action's planned digest before returning `verified`; return
    `unavailable` on capability mismatch. Add public conformance and
    persistence-boundary regressions for stale, missing, and misattributed
    read capability evidence, asserting that validation and verification agree.
  - Requirement: p05-t04, p05-t06, p05-t07, FR11, FR16, NFR2, NFR8
