### Important

- **The documented provider policy hierarchy contradicts the implemented authority contract** (`apps/oat-docs/docs/cli-utilities/remote-project-management.md:96`)
  - Issue: The guide says repository, provider, purpose, and operation policy combine by intersection and cannot broaden one another; `configuration.md:110` repeats that provider policy is tightening-only. The normative specification instead permits provider policy to broaden repository authority (`spec.md:208`), the design explicitly makes provider policy a replacement layer (`design.md:468-477`), and `resolveEffectiveRemotePolicy()` plus its test replace a repository `read-only` operation with provider `autonomous` authority (`packages/cli/src/commands/pjm/remote/authority.ts:429-466`, `authority.test.ts:29-47`). A repository operator can therefore rely on the docs' claimed read-only ceiling while the configured provider override produces a more permissive effective authority.
  - Fix: Describe repository default/operation resolution followed by provider replacement, with binding restrictions and purpose field grants as the tightening/intersection layers. Retain the hard approval floors and caller-owned authority evidence requirements. Update both the main guide and configuration reference together.
  - Requirement: FR8, NFR2, NFR6.

- **The documented host loop cannot prepare its first durable action as written** (`apps/oat-docs/docs/workflows/skills/index.md:58`)
  - Issue: The new workflow says to run the requested remote command first, wait for `pending` plus `externalAction`, and only then inspect live connectors. The canonical skill repeats this ordering (`.agents/skills/oat-pjm-remote/SKILL.md:49-56`), and the main guide's copyable lifecycle examples omit `--capability-evidence-stdin` (`apps/oat-docs/docs/cli-utilities/remote-project-management.md:33-45`). In the production runner, intake, refresh, publish/reconcile, closeout, and relink/recreate all require current capability evidence before they can persist and emit the initial semantic action (for example `service.ts:2092-2106`, `2315-2329`, and `2844-2860`). Following the published loop therefore produces a failed envelope rather than the promised durable handoff.
  - Fix: Move live connector/configured-CLI discovery before the first remote command, construct only the bounded provider-neutral capability evidence object, and pass it through `--capability-evidence-stdin`. Then process the emitted `externalAction` at most once and return the bounded observation through `operation continue`. Align the canonical skill and docs; because the canonical skill would materially change, apply its required one-per-PR version bump and add a contract test that covers the capability-evidence handoff/order.
  - Requirement: FR16, NFR2, NFR8; p08-t03.
