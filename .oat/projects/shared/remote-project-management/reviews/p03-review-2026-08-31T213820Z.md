## Findings

### Critical

- **Mutation action fields are not bound to the gated projection** (`packages/cli/src/commands/pjm/remote/external-action.ts:243`)
  - Issue: `buildExternalAction()` validates the supplied projection and its
    safety result, then parses `intent` independently. The create/update intent
    schema allows an arbitrary scalar `fields` record and never compares that
    record with `input.projection`. A direct reproduction built a valid update
    action whose gated projection was `{title: "Safe title"}` while its emitted
    intent also contained `nativeRequest: "opaque-command"`. The production
    create path additionally puts `sourceRevision` into `intent.fields` and the
    expected remote observation even though it is OAT-owned source evidence,
    not a shared remote planning field.
  - Fix: Define the closed runtime field schema for each mutation intent and
    require canonical equality between its remote-write fields and the exact
    normalized projection covered by the safety result. Keep supporting source
    evidence outside writable fields. Reject every extra key before computing
    the action digest, and add a default-run regression that attempts a
    mismatched/native-shaped extra field.
  - Requirement: FR6, FR16, NFR1, NFR2, NFR8

- **Whole-field suppression is broken across observation ingress and snapshot persistence** (`packages/cli/src/commands/pjm/remote/external-action.ts:336`)
  - Issue: Observation acceptance replaces a signaled text value with the
    suppression marker but returns no field-specific suppression evidence. The
    production intake/refresh path then passes that marker through
    `sanitizeRemoteSnapshot()`, which cannot reconstruct why it was suppressed;
    the strict snapshot schema rejects it as an unpaired marker. A direct
    reproduction of the resulting sanitizer input reports an unpaired
    whole-field suppression marker. Therefore the default lifecycle fails
    instead of retaining an incomplete bounded snapshot when the conservative
    signal fires.
  - Fix: Carry bounded field-specific suppression evidence in the sanitized
    observation contract (without retaining the original value), and teach the
    snapshot boundary to consume that evidence exactly once. Add default-run
    intake and refresh tests proving the complete field is replaced, the
    snapshot is persisted, and `contentRedacted`/redaction evidence identify
    the unavailable field.
  - Requirement: FR12, NFR1, NFR4

- **Authoritative read-back is not pinned to the planned identity or execution evidence** (`packages/cli/src/commands/pjm/remote/service.ts:971`)
  - Issue: `acceptExternalObservation()` checks operation, step, provider, and
    context but does not compare the returned stable identity or capability
    evidence digest with the action/operation contract. A read planned for
    `issue-1` directly accepted `issue-2` and a different capability digest.
    In the create path, the final verifier derives both the expected and
    observed identity hash from that returned identity, so any non-null
    identity verifies; mutation read-back similarly follows the mutation
    response's identity rather than the durable binding identity. Intake also
    fixes the action context to `{}`, preventing the host from returning the
    discovered account/workspace context that the binding must retain.
  - Fix: Persist the expected stable identity and selected capability reference
    before each read, require the observation to match both, and compare create
    read-back with the identity returned by the recorded create attempt. Set the
    expected identity hash before observation, never from the same observation
    being verified. For intake, support a bounded discovered context and bind
    it before materialization rather than requiring an empty context.
  - Requirement: FR5, FR11, FR14, FR16, NFR2, NFR3

- **The production runner does not implement the configured authority modes or durable invocation evidence** (`packages/cli/src/commands/pjm/remote/service.ts:416`)
  - Issue: Default create and update execution proceed only when policy resolves
    to `user-authorized`; `user-approved` and `autonomous` always throw, and the
    command request has no approval, active-workflow, workflow-revision, or
    instruction-evidence fields. For `user-authorized`, the record persists the
    policy digest as `authority.sourceDigest` but no evidence binding the exact
    user instruction. The robust checks in `publishBinding()` are exercised
    only through injected helper tests and are not used by
    `createProductionRemoteRunner()`.
  - Fix: Compose the production path through one authority validator. Persist
    exact current-invocation evidence for `user-authorized`, validate and retain
    fresh preview-bound approval for `user-approved`, and validate active
    workflow ID/revision for `autonomous`. Recheck all of it after pre-read and
    before action emission. Add temporary adopted-repository/default-run tests
    for all four modes and their drift cases, not only injected lifecycle tests.
  - Requirement: FR8, FR9, FR11, NFR2, NFR3

- **Mutation attempts and observations are not journaled, leaving replay and recovery state false** (`packages/cli/src/commands/pjm/remote/store.ts:386`)
  - Issue: `transitionOperation()` can update only state, selected execution,
    outcome, verification, and an optional substep. It never appends an attempt
    or observation or advances `lastSafeStep`/`retryDisposition`. The production
    continuation consequently overwrites the current mutation action with the
    read action and can finish `verified` or `uncertain` while `attempts` and
    `observations` remain empty and `retryDisposition` remains
    `safe-before-attempt`. Accepted action digests are never supplied to the
    duplicate detector, so a terminal read observation can be replayed and
    accepted again. A restarted process cannot reconstruct whether the effect
    ran or which evidence established the result.
  - Fix: Use the canonical state reducer and append-only operation evidence in
    the default runner. Persist `attempt-started` and the immutable mutation
    action before handoff, append each accepted sanitized observation/action
    digest, retain mutation and verification actions separately, advance
    last-safe-step and retry disposition, and reject every already-accepted
    digest. Add crash/restart and duplicate-continuation tests against the real
    filesystem store and default runner.
  - Requirement: FR11, FR14, NFR2, NFR3

### Important

- **Shared-storage preview paths and config target remain caller-authored labels** (`packages/cli/src/commands/pjm/remote/service.ts:206`)
  - Issue: The runner verifies the repository fingerprint and current mode but
    accepts `configTarget` and `proposedPaths` directly from CLI arguments. It
    never compares them with the actual config path or the locations that
    `resolveRemoteStorageLocations()` will use after switching to shared mode.
    Apply always writes the repository config through `writeOatConfig()`
    regardless of the previewed target. A caller can therefore approve a
    truthful digest over false path labels and enable retention at unpreviewed
    paths.
  - Fix: Derive the config target and exact shared operational paths from the
    adopted repository and storage locator inside the runner. Either remove
    these CLI inputs or require exact equality with the derived values before
    persisting the preview and again before apply. Cover mismatched target/path
    inputs in the default-run tests.
