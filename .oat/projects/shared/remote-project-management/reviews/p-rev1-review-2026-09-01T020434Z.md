- **`user-approved` authority still has no persisted preview/apply workflow** (`packages/cli/src/commands/pjm/remote/service.ts:772`)
  - Issue: The runner validates approval before it creates an operation or returns a
    command envelope. With no approval it throws from `authority.ts:203`; the success
    test explicitly catches that exception and regex-extracts the preview digest from
    the error string at `index.test.ts:469`. That is not the required first invocation
    that persists and emits a preview, and it gives the public CLI no structured,
    restart-safe approval handoff. It also means the declared `user-approved` mode is
    only reachable through an undocumented error-scraping protocol.
  - Fix: Split preview preparation from apply. Persist the planned operation and exact
    preview first, return a structured `needs-review`/pending envelope with its digest,
    and accept the caller-owned fresh approval on a subsequent invocation that
    re-reads and revalidates all load-bearing inputs before host execution. Replace
    the error-regex test with a two-command default-CLI regression.
  - Requirement: FR8, FR9, FR11, NFR2, NFR3

  - Issue: `prepareCreate()` always places `local.description` in the outbound
    projection before resolving policy, and the effective description mode computed
    at `service.ts:520` is never applied to that projection. A repository configured
    with `description: none` therefore still publishes the full backlog/project
    description, while `managed-section` does not construct the managed boundary.
    The projection then passes safety, preview, and host execution as if it were
    policy-compliant. Existing description-mode tests cover only the bound-update
    projection helper, not production create.
  - Fix: Resolve policy before constructing the create projection. Omit description
    in `none`, construct only the managed region in `managed-section`, and enforce
    the fresh-approval floor for `replace`; then bind that exact projection through
    safety, preview, action, verification, and baseline materialization. Add
    default-run backlog and project create tests for all three modes.
  - Requirement: FR7, FR8, NFR1, NFR2

    baseline-advancement test, and this is a P0 recovery/correctness path from the
    source Critical finding.
  - Fix: Extend a production-run fixture through update observation, verification
