### Important

- **Resolution approvals still depend on reading private operation files**
  (`packages/cli/src/commands/pjm/remote/service.ts:1787`)
  - Issue: Closeout substeps and the recreate create substep now persist and
    return `approvalPreview`, and apply validates the submitted approval against
    that persisted object. The initial relink, detach, and recreate-search
    previews still return only an operation ID in recovery text
    (`service.ts:1792-1816`), not the required preview digest or a standard
    `approvalPreview`; the operation itself does not persist an
    `approvalPreview` at preparation time. The new production E2E test works
    around this by opening `RemoteSyncStore` and copying
    `operation.preview.digest` into the approval
    (`packages/cli/src/e2e/pjm-remote.test.ts:876-905`, `:937-967`). A real
    operator cannot construct the exact fresh approval from public CLI output.
    In addition, the public approval-preview type exposes rendered fields and
    revision evidence but omits the persisted target/baseline/capability/policy/
    projection/safety component digests (`output.ts:32-47`) requested by the
    prior finding.
  - Fix: Persist a complete approval preview on initial relink/detach/recreate
    operations, return it through the same `approvalPreview` envelope used by
    closeout/create, and validate the submitted approval against that exact
    object. Expose the bounded component-digest evidence in JSON and human
    rendering so no private store read is needed; update E2E tests to build
    authority evidence solely from public command output.
  - Requirement: FR13, FR14, FR15, NFR6; p07-t02, p07-t05, p07-t06, p07-t10.
