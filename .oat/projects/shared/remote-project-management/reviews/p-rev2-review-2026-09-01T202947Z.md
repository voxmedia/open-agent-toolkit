## Findings

### Critical

1. **The handoff still permits create replay and a durable journal/action
   lifecycle mismatch**
   (`packages/cli/src/commands/pjm/remote/service.ts:1171`)
   - Issue: `acceptExternalObservation` completes at lines 1171-1179, but no
     durable state changes until `transitionOperation` at lines 1273-1304. A
     process failure after the observation is accepted but before that atomic
     write leaves the journal in `attempt-started` with the create action
     current. A no-observation restart takes the create-resume branch at lines
     1120-1125 and returns that create again at line 1801, rather than failing
     closed or emitting a durable verification read. The implemented later
     boundary also does not satisfy the approved invariant: the service first
     commits `verification-pending` plus the embedded handoff, then separately
     writes the verification action at lines 1305-1306. At the injected
     `after-verification-handoff` crash, the operation journal describes the
     verification-read lifecycle while the durable current-action file still
     describes the accepted create. Recovery at lines 1815-1829 explicitly
     tolerates and repairs that mismatch. The new tests exercise only the
     post-journal repair window (`service.test.ts:1302-1334`) and the
     pre-envelope window (`index.test.ts:540-560`); they do not inject a crash
     after observation acceptance but before the journal transition.
   - Impact: A remotely committed create can be presented for execution again
     after restart at an uncovered crash boundary. Even when restart repairs
     the later boundary safely, the durable journal and current action violate
     the phase's required single-lifecycle-step invariant. This leaves the P0
     no-blind-retry and restart-safety contract incomplete.
   - Fix: Make one durable record the canonical current-action and lifecycle
     authority, atomically storing accepted observation/attempt evidence and
     the exact verification-read action with the `verification-pending`
     transition. If a separate pointer remains, it must never be observably
     stale; schema/store validation must reject a `verification-pending` record
     whose canonical action is not that exact read. Also persist enough
     pre-envelope exposure state to distinguish a create that is safe to emit
     for the first time from an `attempt-started` create that may already have
     executed; the latter must fail closed to reconciliation rather than be
     re-emitted. Add service and real Commander crash injections immediately
     after observation acceptance and before the journal write, as well as at
     the journal/action boundary, asserting that restart returns only the exact
     durable read or an explicit reconcile-required result and never a create.
   - Requirement: `prev2-t01` criteria 1-3; FR11, FR14, NFR2, NFR3; design
     persist-before-effect and authoritative read-back recovery contract.
