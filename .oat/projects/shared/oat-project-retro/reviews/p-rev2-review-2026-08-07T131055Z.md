    `packages/cli/src/commands/project/log/append.ts:411-430`). The focused
    test at `retro-skill-contracts.test.ts:323-354` checks literal words, not
    outcome selection or command compatibility.
  - Fix: Define mutually exclusive semantics for all four outcomes for both
    actions, including no eligible items, absent non-interactive consent,
    interactive rejection, configured deferral, and child-skill failure.
    Specify the complete structural command shape, a stable producer/ref, and
    deterministic source-list serialization. Add table-driven scenarios that
    map run state to the exact receipt and validate the body through the
    append command contract.
  - Requirement: `prev2-t01`

- **The append-only correction route has no safe matcher or complete commit/recovery state machine**
  (`.agents/skills/oat-project-retro/references/apply-procedure.md:37`)
  - Issue: RP `Target` is a repository path, but the special case is phrased
    as a canonical path that "is `project-log.md`"; it does not define the
    required final-component/ends-with match, normalization, or rejection of
    lookalike paths. A normal project target such as
    `.oat/projects/shared/example/project-log.md` can therefore miss the route
    and fall through to direct docs editing. The procedure also omits the
    required judgment flags even though project-log corrections are judgment
    entries, gives the appended correction no stable RP identity for exact
    recovery, and says to record `Applied-ref` only after both correction and
    retro writeback are committed without defining whether those mutations are
    atomic or ordered. That conflicts with the generic same-commit guidance at
    lines 130-150 and leaves interruption points under-specified.
  - Fix: Trigger only for a `docs` item whose normalized target has the exact
    final path component `project-log.md`; fail closed on ambiguous paths.
    Define the full judgment append invocation and require a stable RP ID plus
    original-entry anchor in the correction. Specify an explicit transition
    sequence for append, semantic recovery, commit success/failure, status
    writeback, and `Applied-ref`, including what the reference names. Add
    transition tests for each interruption point and for positive/negative
    target-path matching.
  - Requirement: `prev2-t04`
