### Important

- **Receipt eligibility is sampled at contradictory times**
  (`.agents/skills/oat-project-retro/SKILL.md:207`)
  - Issue: The skill says to resolve outcomes “at receipt time” from items
    whose current status is unsettled and gives an empty eligible set
    precedence over every non-entry reason. A successful apply or filing
    action that settles every initially eligible item therefore has an empty
    receipt-time set and yields `skipped`, even though the same contract says
    an entered action that completes normally yields `performed`. The table
    instead defines `skipped` from an empty set “at decision time.” Mixed
    filing runs are also unresolved: an entered action can complete one lane
    while configured `none` leaves another lane eligible, satisfying both
    `performed` and `deferred`.
  - Test gap: `retro-skill-contracts.test.ts:365` checks that six prose rows
    exist, while `append.test.ts:205` proves Commander accepts already-chosen
    strings. Neither test evaluates pre-action state, post-action state, entry,
    completion, and remaining work to select one outcome.
  - Fix: Define one explicit pre-action eligibility snapshot and a total
    precedence function. At minimum distinguish initially empty (`skipped`),
    action-level interactive rejection (`declined`), non-entry or remaining
    eligible work caused by absent/configured consent or failure (`deferred`),
    and entered normal completion with no deferred eligible work
    (`performed`). State how mixed filing lanes resolve. Add table-driven
    transition fixtures that derive the outcome from before/after state,
    including “all items settled successfully” versus “initially empty,” then
    keep the executable parser tests for the resulting body.
  - Requirement: `prev2-t01`; final receipt portion of design alignment
