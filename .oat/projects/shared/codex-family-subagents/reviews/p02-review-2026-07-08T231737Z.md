### Important

- **Resolver reports selected Codex effort without a dispatchable role** (`packages/cli/src/commands/project/dispatch-ceiling/index.ts:1276`)
  - Issue: `buildProviderResolution` emits `effortAxis: selected:<value>` whenever `selection.selectedValue` is present, even if `adapter.compileToDispatchArgs(...)` returned `null`. In the current project state, `pnpm run cli -- project dispatch-ceiling resolve --provider codex --role reviewer --json --project-path .oat/projects/shared/codex-family-subagents` returns `dispatchArgs: null` with `effortAxis: "selected:xhigh"`. That contradicts the p02 skill contract, which says a selected Codex effort must use `providers.codex.dispatchArgs.variant` as `agent_type`, and no-variant fallback must be logged as provider-default.
  - Fix: Make Codex axes payload-derived: if no `dispatchArgs.variant` is returned, do not emit `effortAxis=selected:*`. Return `provider-default` for explicit base fallback paths and `unresolved` for incomplete or legacy/model-unaware paths. Add resolver tests for bare legacy caps and lower-preferred matrix cases where `dispatchArgs` is null.
  - Requirement: p02-t03, p02-t05

- **Sync only materializes targets from shared config, not the resolver's effective sources** (`packages/cli/src/providers/codex/codec/sync-extension.ts:223`)
  - Issue: `readCodexMaterializationTargets` calls `readOatConfig(scopeRoot)` and collects only `.oat/config.json` Codex matrix targets. The resolver can select matrix cells from user config, local config, and project-state `oat_dispatch_policy.matrix`, but `oat sync`/status will not generate those materialized role files and full sync can remove them as stale because they are absent from the planner's desired set.
  - Fix: Feed the sync extension the same effective dispatch matrix sources used by `dispatch-ceiling resolve`, including local/user/project-state layers, or centralize matrix target collection behind a shared resolver helper. Add tests for Codex materialization targets defined in local config and project state.
  - Requirement: p02-t02, p02-t03

- **Doctor still validates Codex dispatch cells against old effort-only role files** (`packages/cli/src/providers/identity/availability.ts:115`)
  - Issue: `validateCodexCell` only accepts `low|medium|high|xhigh` and checks for `.codex/agents/oat-phase-implementer-${value}.toml` plus `.codex/agents/oat-reviewer-${value}.toml`. Meanwhile doctor splits route-target objects into separate `.model` and `.effort` refs, so a valid Codex target like `{harness:"codex", model:"gpt-5.6-terra", effort:"xhigh"}` is checked as `model=gpt-5.6-terra` (unknown) and `effort=xhigh` (old role filenames). This leaves doctor inconsistent with p02 materialized role names.
  - Fix: Teach doctor/availability to validate Codex route targets as model+effort pairs and check the materialized implementer/reviewer role names produced by `buildCodexMaterializedRoleName`, or report preview model availability separately from role-file generation. Add doctor tests for valid materialized Codex targets and removed effort-only roles.
  - Requirement: p02-t04
