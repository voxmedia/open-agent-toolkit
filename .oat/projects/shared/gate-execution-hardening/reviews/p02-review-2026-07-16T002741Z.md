### Important

- **Valid gate children can be denied the required inline route** (`packages/cli/src/commands/gate/route.ts:30`)
  - Issue: Runtime detection accepts only `CODEX_THREAD_ID`, although the existing Codex host contract also accepts `CODEX_SESSION_ID`. It also rejects every environment containing more than one provider marker. `runReviewGate` deliberately preserves the parent environment when spawning a cross-provider target (`packages/cli/src/commands/gate/index.ts:3048`), so a Cursor→Claude, Claude→Codex, or similar child can contain both the inherited parent marker and its own current-runtime marker. The helper then delegates or refuses even though the gate child holds the configured reviewer runtime, contrary to the primary inline-when-identity-matches requirement.
  - Fix: Align route evidence with the existing host-detection contract, including `CODEX_SESSION_ID`, and establish a trustworthy way to distinguish the child's current-runtime marker from inherited parent markers (for example, gate-owned parent-runtime context plus expected-marker precedence, or selective provider-marker scrubbing at spawn). Add tests for every cross-provider parent→target combination and the `CODEX_SESSION_ID`-only case.
  - Requirement: Discovery requirement 1 / p02-t04

- **An unvalidated correlated path suppresses structured refusal classification** (`packages/cli/src/commands/gate/index.ts:3072`)
  - Issue: Refusal is classified only when `matchingArtifactPaths.length === 0`. One malformed correlated artifact, or multiple artifacts carrying the run ID, therefore suppresses refusal before target, invocation, and verdict validation has succeeded. The design requires only a validated run-correlated artifact to win; otherwise a refusal line must classify the outcome independently of exit code.
  - Fix: Defer artifact-wins precedence until a unique artifact has passed target/invocation/verdict validation, and classify the captured refusal when validation never establishes that winning artifact. Add regressions for refusal plus duplicate run-ID artifacts and refusal plus a malformed or invocation-mismatched artifact.
  - Requirement: Discovery requirement 1 / p02-t03

### Medium

- **Partial marker-write failures can leave an orphan after normal termination** (`packages/cli/src/commands/gate/index.ts:3013`)
  - Issue: The `finally` block removes the marker only when `writeGateRunMarker` returned `true`. A filesystem write can create or partially write the file and still fail (for example, an interrupted or out-of-space write), after which the helper returns `false` and normal gate termination skips cleanup. This falls outside the promised one-boundary cleanup across every write/terminal path.
  - Fix: Track that marker creation was attempted and perform one best-effort, ENOENT-tolerant removal from `finally` regardless of the write result. Add a test whose writer leaves a file but reports failure, then assert exactly one cleanup attempt and no orphan.
  - Requirement: Discovery requirement 4a / p02-t02
