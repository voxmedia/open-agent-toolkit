### High

- **Archive rewrites a hard-linked file outside `.oat/repo`** (`packages/cli/src/commands/backlog/rewrite-references.ts:134`)
  - Issue: `isRegularFileInside` accepts a regular file when its `realpath` is inside the scan root, but `realpath` does not reveal another hard link to the same inode outside that root. `writeNoFollow` then opens the accepted path with `O_TRUNC` and writes through the shared inode. In a scratch Git repository, I hard-linked `.oat/repo/reference.md` to an outside temporary file containing `./pjm/backlog/items/BL-test.md`. Calling the current TypeScript `rewriteInboundReferences` changed the outside file to `./pjm/backlog/archived/BL-test.md` and reported `.oat/repo/reference.md` as rewritten. `oat backlog archive` calls this rewriter after moving an item (`archive.ts:331-336`), so the advertised in-repository write boundary does not hold.
  - Fix: Replace changed files through a new temporary file and rename within a verified in-tree parent, rather than truncating the existing inode. Add a hard-link fixture asserting the outside alias remains byte-identical while a normal in-tree Markdown reference is rewritten. Verify path identity again at the write boundary.
