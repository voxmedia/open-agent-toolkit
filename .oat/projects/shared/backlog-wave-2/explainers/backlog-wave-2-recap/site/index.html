Original request

On 2026-09-27 the operator approved one tackle-backlog batch for wave-2 of the backlog review: the wave's queued items minus the recap-export lane, plus one new high-priority item to stop writing CLAUDE.md shims by default. The agreed shape was one quick-mode OAT project, five phases run in order, a single PR, Claude Opus implementing, and Codex codex-6-sol-xhigh as the independent reviewer for the plan gate, every phase gate, and the final review.

Why the shim item jumped the queue: Claude Code now reads AGENTS.md on its own, and its agents-md plugin stops reading AGENTS.md as soon as any CLAUDE.md, CLAUDE.local.md, or .claude/CLAUDE.md exists. The shims OAT used to generate were switching that plugin off.

What success meant

  • Every acceptance criterion of the closable items passes with recorded evidence, and those items are archived in the PR.
  • The bookkeeping-order item ships its change and contract tests but is not archived, because only a live multi-phase run can confirm it.
  • The full Definition of Done passes on the final head, and every independent gate passes or has its findings dispositioned.
  • Shim removal never deletes a hand-written instruction file.

As-built architecture

The wave put guards in front of commands that write to a repository or judge a gate. Each guard either proves a change is safe or reports the problem without touching the file. The map shows each entry point, the guard it passes through, and what it may change. Dashed boxes are the parts the revision reshaped.

Boundaries

  • Shim strategy. instructions.claude.shims takes none, pointer, symlink, or copy, with none as the default; instructions.claude.excludes lists directories sync leaves alone; --strategy overrides one run. Under none, sync creates no CLAUDE.md and removes only exact OAT-created shims (an @AGENTS.md pointer, a sibling symlink, an identical copy) after apply-time identity and content re-checks. A lone CLAUDE.md with no AGENTS.md is adopted into a new AGENTS.md and removed.
  • All or nothing. While any CLAUDE.md, CLAUDE.local.md, or .claude/CLAUDE.md with its own content exists anywhere in the repository, excluded trees included, sync removes no shim. sync and validate then report one claude_md_blocks_shim_removal finding that names the files with content, the shims kept, why any CLAUDE.md matters, and the fixes: move the content into AGENTS.md and remove the file, or set a shim strategy. Validate, oat-doctor, and the agent-instructions analyze and apply skills report the same finding.
  • Rules sync is independent of the shim setting. A test pins identical oat sync output for .claude/rules, skills, and agents under none and pointer, and oat sync never creates or removes a CLAUDE.md.
  • Append writer. An absent managed block is appended with O_WRONLY | O_APPEND | O_NOFOLLOW after fstat identity checks. Hard-linked, unwritable, swapped, or non-regular targets get the zero-write manual patch with the real cause. A new read-only oat tools guidance [--json] prints the block.
  • Reference rewriter. Handles .oat/repo Markdown links, repository-root path strings, and whole-span code citations. URLs, symlinks, fenced code, and working links are left alone; forms it cannot resolve produce a warning.
  • Recon. oat-reviewer no longer launches recon-worker; reviewer lanes use ordinary read-only sub-agents. Only the recon skill launches recon-worker, and that skill is unchanged from main.
  • Lifecycle skills. Quick-mode discovery routes straight to quick-start in next and progress. Lite records absorbed_projects and absorbed_backlog_ids. Implement commits the task ledger before the per-phase reviewer runs and keeps the phase row nonterminal until review fixes and gates settle.

What the reviews caught

  • p02 C1: shim removal nearly deleted a hand-written fileThe review reproduced default sync deleting a hand-written CLAUDE.md when AGENTS.md is a symlink to it: the copy check compared the file with itself. Fixes made any CLAUDE.md an AGENTS.md resolves to unmanaged, including cross-directory links checked at planning and apply time.
  • p04: the recon validator kept growingEach gate and review round found a new authority gap: unbounded reads, arbitrary schemas, mutating tool names, unbounded write paths. The gate budget ran out, and the operator later withdrew the component rather than hardening it further.
  • p05: the reference rewriter kept widening its reachReviews found a symlink escape outside .oat/repo, URL and unrelated-path rewrites, broken code-span citations, and footnote corruption. The rewriter now resolves every token and refuses symlinks and out-of-root paths.
  • Exit gate H1, fixed in p05-t12: writing through hard linksThe rewriter truncated files in place, so an in-tree file hard-linked to an outside file changed the outside file. Files are now replaced through an O_EXCL | O_NOFOLLOW temporary file and rename after an lstat device and inode re-check, proven with a hard-link fixture that fails when the guard is removed.

Known limits

  • BL-260829-order-phase-bookkeeping-before has not been observed live: gates and lifecycle skills run the installed release, so the item stays open until the next multi-phase project.
  • The p04 phase gate never passed on its own; the final review and the exit gate covered p04.
  • Case variants of CLAUDE.md are deliberately not flagged, because case-insensitive matching caught real provider docs such as tools/smoke/protocols/claude.md.
  • Whether Codex recon lanes launch as contract-enforced on the released CLI is a live check still to run, tracked in BL-260928-settle-codex-read-authority.

Outcome and follow-ups

What works now

  • oat instructions sync writes no shim by default, removes the shims OAT made when no hand-written CLAUDE.md remains, and otherwise removes none and explains why.
  • Rules, skills, and agents sync the same way whatever the shim setting.
  • OAT guidance lands in AGENTS.md automatically when it is safe, and names the reason when it is not.
  • Archiving a backlog item repoints the links to it across .oat/repo.
  • Exit gates no longer go stale when only project or repository records change.
  • Only the recon skill launches recon-worker; oat-reviewer uses ordinary read-only sub-agents.

Upgrade notes

After upgrading, oat instructions validate fails in a repository that still has old shims until oat instructions sync removes them, so CI that runs validate goes red until then. To keep shims, run oat config set instructions.claude.shims pointer and sync again.

A repository that set the released documentation.instructionPointerExcludes must re-set that list as instructions.claude.excludes before its first sync. The old key is ignored, so sync would otherwise adopt and remove a lone CLAUDE.md in the formerly excluded directories.
