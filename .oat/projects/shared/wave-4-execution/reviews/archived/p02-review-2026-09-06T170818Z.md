### Important

- **Restamp-only sync still prints `No changes required.` from the plan body**
  (`packages/cli/src/ui/output.ts:114`, reached via
  `packages/cli/src/commands/sync/apply.ts:495`)
  - Issue: the fix at `apply.ts:498-507` correctly replaces the _trailing_
    message, but it is not the only producer of that sentence.
    `formatAppliedOutput` (`apply.ts:267`) composes `formatCoreResults`, which
    calls `dependencies.formatSyncPlan`; that helper returns
    `` `${heading}\nNo changes required.` `` whenever the entry plan is empty
    (`ui/output.ts:110-115`), regardless of restamp state. Verified live against
    the built CLI in an isolated scratch repo (probe L2): a project whose
    manifest `oatVersion` was hand-edited to `0.0.1-probe` produced this exact
    stdout on `oat sync --scope project`:

    ```text
    Scope: project
    Sync plan (applied)
    No changes required.

    Manifest version refreshed; no content changes required.
    ```

    The external plan's Done criterion "Restamp-only sync no longer says no
    changes were required" and its Outcome sentence ("reports that fact instead
    of claiming that no changes were required") are therefore only partially
    satisfied: the corrected claim is present, but so is the contradicting one,
    two lines apart in the same run.

    The pinned test cannot observe this. `sync/index.test.ts:1361-1366` asserts
    `expect(capture.info).not.toContain('\nNo changes required.')`, which is
    array _element_ equality; the plan-body line is embedded inside the larger
    multi-line string logged at `apply.ts:495` and therefore never matches. The
    negative is real but structurally blind to composed output — which is why
    this escaped both Codex rounds and the implementer's probe 5.

  - Fix: keep the change local to the command layer rather than editing the
    shared formatter (`formatSyncPlan` is also used by dry-run and other
    callers). In `runSyncApply`, when
    `summary.plannedOperations === 0 && versionSkew.length > 0`, suppress or
    replace the plan body's empty-plan sentence before logging — e.g. thread the
    restamp-only state into `formatAppliedOutput` and have it emit the heading
    without the `No changes required.` line, letting the trailing message at
    `apply.ts:503-507` be the single claim. Then strengthen the assertion to
    operate on joined output rather than array membership, for example
    `expect(capture.info.join('\n')).not.toContain('No changes required.')` in
    the restamp-only test, and keep the existing exact-element positive for the
    new message.
  - Alternative (artifact alignment): if the wave decides the residue is
    acceptable because the external plan's step 4 named only `apply.ts:498-499`,
    record that decision explicitly against the Done criterion rather than
    leaving the criterion silently unmet. Do not close the criterion as fully
    satisfied without one of these two actions.
  - Requirement: external plan Done criterion 6; Review focus bullet 4.

- **init derives the restamp after the `!manifest.entries` fallback**
  (`packages/cli/src/commands/init/index.ts:1031-1042`)
  - Issue: `manifest = createEmptyManifest()` replaces the loaded manifest with
    one already stamped `OAT_VERSION`, and only then is
    `detectManifestVersionRestamp(scope, manifest)` computed. Any manifest that
    reached that branch would have its producing version discarded with no
    advisory and no JSON evidence — the exact failure mode this phase exists to
    close. This is latent rather than live: `ManifestSchema` requires `entries`
    on both V1 and V2 and `loadManifest` throws otherwise, so the branch is
    unreachable through the real loader (confirmed live by probes L5a-L5c, which
    all fail closed). It is reachable only through an injected
    `dependencies.loadManifest`.
  - Suggestion: compute `versionRestamp` from the manifest as loaded, before the
    `!manifest.entries` fallback, so the ordering is correct by construction
    rather than by the schema's current strictness. A one-line move; no
    behavior change today.
