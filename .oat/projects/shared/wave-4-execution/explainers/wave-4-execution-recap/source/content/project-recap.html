Wave 4: routing the Codex skill through live guidance

A skill that tells agents how to drive another coding CLI is a document, and documents rot quietly. This one named two models that had aged out of the provider guidance, passed a repository-check bypass on every example command, and used an approval flag the installed CLI no longer has.

What was asked for

Wave 4 is the last slice of the 2026-08-19 execution program, and like the wave before it, it carried a single bounded change, so the wrapper OAT project has exactly one lane. The subject is codex-skill: the repository-only skill that tells an agent how to hand work to the Codex CLI. It carried a fixed pair of model names, a bypass flag on every example, and a flag the installed CLI had dropped.

Before

Two hardcoded model names decided every route. --skip-git-repo-check rode along on ordinary commands, so the safety check it disables was off by default. Four examples used --full-auto, which the installed CLI does not accept.

After

The skill classifies the work by OAT task class and takes model and effort from the provider reference, named in the text as the source of truth. The bypass survives only for a target directory that is not a Git repository, with the reason stated and authorization asked for. Every example was re-checked against the CLI actually installed.

The distinction that mattered throughout: the skill was to stop holding an opinion about which model is current and start reading one. Named models become dated examples, compatibility snapshots are never defaults, and if the reference cannot be read the skill stops and asks rather than guessing from the examples.

The constraints the wrapper accepted

  1. The lane's entire implementation contract is its immutable external plan. The wrapper adds ordering, gates, review mapping and bookkeeping, and restates none of it.
  2. Run the source plan's drift check in the worktree before editing, extended by the wrapper to cover the release surfaces the plan writes, the live CLI help for every subcommand the skill drives, and the allowlist that keeps this skill out of the published bundle.
  3. Honour every source-plan STOP condition verbatim. One of them tripped: the flag four examples used is absent from live help. A tripped STOP parks the lane until an operator decides, and it is the operator, not the agent, who decides whether a fix is in scope.
  4. Confirm the source plan's own done criteria, then run the full definition of done, invoking each gate literally and capturing every exit code to a log — including the two gates continuous integration never runs, because this wave writes into the skills tree.
  5. Obtain an independent cross-model review of the uncommitted work before committing, and keep reviewed history append-only: fix rounds land as new commits and no reviewed SHA is amended.

Success meant the source plan's done criteria confirmed and recorded, every review row passed, and the full definition of done green on the wave branch.

Decisions that shaped the result

Four choices changed what shipped or how it got there. Each is recorded with the reason it was made and the consequence it carried.

  1. Send the tripped STOP to the operator, and take the wider fix

    Reason
    The plan required every command example to be valid and mutually consistent, but it was authored against a CLI that still had --full-auto. The live reread found the flag gone. Reading the plan narrowly would have shipped four examples that cannot run; reading it widely meant an agent deciding for itself that a plan means more than it says.
    Consequence
    The contradiction was reported at the drift refresh and reconciled by the operator, not by the agent, as an in-scope part of the plan’s own step: same file, no behaviour weakened, no undocumented flags. WHERE the fix lands changed; WHAT had to be true did not. It is recorded exactly once, in the drift record, and referenced by pointer everywhere else.

  2. Re-evaluate each example instead of swapping the flag

    Reason
    A dead flag has an obvious mechanical replacement, and the obvious replacement is wrong somewhere. The rows differed in what sandbox they were already asking for, so one substitution could not be correct for all of them.
    Consequence
    The cross-model reviewer caught exactly that before the commit: the mechanical mapping on the broadest-sandbox row would have paired it with the approvals bypass and weakened the posture the plan forbade weakening. The rows were split instead — network access inside a write sandbox through a documented configuration key, broad filesystem access kept separate, and the bypass reserved for automation already sandboxed elsewhere.

  3. Guard structurally, not by keyword

    Reason
    The contract test has to decide which lines of English are commands and which are prose about commands. Three rounds of widening a keyword allowlist each closed one hole and opened a narrower one: a bare word matched inside another word, a backtick-keyed rule missed fenced examples, and a keyword allowlist exempted the very sentences that prohibit the thing.
    Consequence
    The rule became structural — a line claiming the documented exception must not itself run the command — and soft-wrapped prose is normalised to logical lines before anything is matched. Wording dispositions got their own semantic assertion instead of riding on phrase co-location, so a clearer rewrite of the shipped text passes rather than failing.

  4. Stop at the cycle cap and hand verification onward

    Reason
    Both code scopes reached their third review cycle with the reviewer still finding new evasions of the guard. Each residual came with a verified patch, which is exactly the situation where an agent is tempted to grant itself another round.
    Consequence
    No fourth cycle was opened in either scope. The reviewer’s verified patch was applied as a bounded fix, the probe matrix was re-run by the root as the stored record, and independent verification was delegated onward — the phase scope to the final review, the final scope to the cross-family exit gate. The gate then reproduced both remaining residuals on its own, which is the evidence that the hand-off was real.

How the wave was built

One lane again, so the interesting structure is not fan-out but the loops a change had to survive. Three fired, one of them eighteen times, and a fourth path exists only because a STOP condition sent a question out of the machine entirely.

What the wrapper owns

  • Ordering, the drift-check addendum and the concurrency ceiling
  • The wrapper-level definition-of-done sequence and its captured exit codes
  • Review mapping, the mutation probes added to the phase checklist, and gate targets
  • Commit scope naming, backlog archival and all bookkeeping

What the external plan owns

  • Its drift check and STOP conditions
  • Its implementation steps and embedded verify gates
  • Its done criteria, review focus and test plan
  • The files it is allowed to write

How it was checked

Ten green gates never had an opinion about any of this. The shipped document was correct at the first commit and stayed correct; what took six rounds was proving that it would stay correct, because the test guarding it kept turning out to be readable around. Almost all the evidence below is about the guard, not the change.

The pattern worth carrying forward: a test over prose is a parser of English, and every widening of a keyword allowlist opened a narrower hole than the one it closed. Only the structural rule held, and only an adversary writing probes found the holes at all.

Where this leaves the repository

Works now

  • The skill classifies work by task class and reads model and effort from the provider reference, so a model retirement becomes an edit to the reference rather than a rewrite of the skill.
  • Ordinary Codex runs keep the repository check. The one surviving bypass path names its condition, states its reason and asks for authorization.
  • Every command example matches the installed CLI: unattended edits pair the approval flag with a write sandbox, and network access no longer implies the broadest sandbox available.
  • A contract test fails on the stale model pair, on any single retired slug, on a bypass added to any command-ish line including fenced blocks and table rows, on a removed authority sentence, and on a below-floor rule that starts blocking.

Did not ship

  • Two guard residuals stay open by decision: a broadened exception row can still re-exempt a bypass, and a blocking requirement in the clause after the below-floor clause escapes a per-clause filter. Both were reproduced independently by the exit gate; the shipped prose is correct as written.
  • The provider reference was out of scope and is already behind the live guidance — it lacks a new effort tier, and two model families retire from Codex before its own review date.
  • No documentation changed. The document step was recorded as skipped because no page referenced the old routing or the bypass, which is a real answer rather than an omission.
  • The wave PR has not been opened or merged; the recorded closeout stops after the summary and document steps.

For the next reader

  • The freshness obligation moved rather than disappeared. The skill now has no opinion of its own, so a stale provider reference is the failure mode, and refreshing it is already a filed follow-up.
  • Take the two residuals with the drafted backlog item as one piece of work: span-based prose guards, anchored probe records and a generalized probe runner are the same conversation.
  • When a plan and the live world disagree, the escalation is the deliverable. The one STOP that tripped here was answered by a person, recorded once, and referenced by pointer — which is why the wider fix stayed auditable instead of becoming scope creep.
  • This was the last wave. What remains is the wave PR, and the completion tail across all four wrapper projects is deliberately held for a human decision at program close.
