## Rules adopted from Waves 1–3 (applied to this wave)

- Every root command uses absolute paths / `git -C`; no bare `cd`; a rejected
  commit does not stop an `&&` chain — verify `git log` before any launch.
- Drift refresh intersects the lane's write surface with the release
  change-detection roots and states the planned bump up front.
- Implementer briefs invoke each gate literally and capture per-gate exit codes
  to log files, and re-run `git fetch origin && pnpm release:check-versions`
  after the task commit (committed-state-only gate).
- Focused-test Verify lines are checked against the repo's runner before
  dispatch (`node --test .agents/skills/codex-skill/tests/*.test.mjs` is the
  working form here).
- Reviewer briefs require reviewer-designed adversarial probes; for a prose
  contract test, mutation checks that the test rejects the stale model pair and
  a reintroduced blanket bypass; a cross-model or reviewer finding that names a
  class gets a repo-wide sweep.
- Configured gates launch detached (`nohup … & disown`) with a receipt file
  watched by the root; the selected target is verified in the `gate-start`
  line; a pre-child provider rejection is a boundary after one identical retry.
- `summary.md` is generated before any archive step; bookkeeping edits are
  asserted line transforms applied once per commit (never a `$1`-returning
  replace callback).
- Immutable explainer-kit packages are committed only with the formatter ignore
  in place (in `.oxfmtrc.jsonc`).
