### Critical

- **Successful recovery cannot satisfy the root's settled-ledger precondition**
  (`.agents/skills/oat-project-implement/references/phase-execution.md:361`)
  - Issue: The authoritative ledger contract defines a settled ledger as
    `pending_attempt: null` at lines 141-142, but requires the phase agent to
    mark the pending entry `completed` or `failed`, include the successful
    transition in the recovery commit, and leave clearing to root bookkeeping
    only after the root validates the matching report and event at lines
    155-158. The isolated phase-agent contract preserves the same order at
    `.agents/agents/oat-phase-implementer.md:247-253`. The root success branch
    then requires a “reconciled settled ledger” before it can accept the report
    at lines 361-363. A valid successful return therefore contains a committed
    `completed` pending marker and fails the `pending_attempt: null` condition;
    clearing it first would violate the explicit validate-before-clear rule.
  - Impact: The primary P0 outcome—an eligible post-commit defect producing one
    verified append-only recovery commit and continuing without another
    authorization prompt—has no valid end-to-end state transition. A compliant
    root must either reject every successful recovery report or mutate the
    ledger before the validation that authorizes that mutation. The event may
    also fail to reach durable root bookkeeping because report acceptance is
    blocked.
  - Correction boundary: Define a distinct validated pre-bookkeeping success
    state: a matching `completed` pending marker in the committed ledger is
    acceptable while the root validates the report, immutable history, event,
    exact target, attempt count, and verification. Only after validation may
    root bookkeeping clear `pending_attempt` while preserving `used_attempts`;
    reserve `pending_attempt: null` for the post-bookkeeping settled state.
    Define the analogous terminal handling for `failed`, and keep unreconciled
    or still-active markers fail-closed. Add a transition-matrix regression
    test spanning reservation → completed recovery commit → root validation →
    root clear, plus rejection cases for premature clear, mismatched status,
    and unreconciled pending state.
  - Requirement: Central bounded recovery, durable monotonic accounting,
    canonical event durability, and fail-closed root validation.
