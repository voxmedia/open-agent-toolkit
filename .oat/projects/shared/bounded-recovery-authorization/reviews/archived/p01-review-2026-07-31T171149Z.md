### Important

- **Fresh same-target recovery has no executable phase-agent mode**
  (`.agents/agents/oat-phase-implementer.md:29`)
  - Issue: The phase agent recognizes only `implement` and `fix`, rejects an
    unrecognized mode, replays all planned tasks in `implement`, and requires a
    review artifact plus Critical/Important findings in `fix`. The root contract
    nevertheless authorizes a fresh same-target recovery launch when the
    accepted handle cannot resume
    (`.agents/skills/oat-project-implement/references/phase-execution.md:173`).
    No mode, payload, base rule, or return contract can invoke that bounded
    post-commit recovery without replaying tasks or fabricating review inputs.
  - Fix: Define a dedicated recovery continuation mode and self-contained Phase
    Scope/report contract, including original task/commit, bounded defect,
    remaining attempts, immutable-history checks, and exact target; alternatively
    remove the fresh-launch promise and make handle loss an unconditional stop.
    Add a contract test that validates the phase-agent mode in isolation.
  - Requirement: p01-t02 exact-target continuity and fresh same-target recovery.

- **Recovery usage has no defined durable source or update protocol**
  (`.agents/skills/oat-project-implement/references/phase-execution.md:30`)
  - Issue: The root is told to start from a "durable count already recorded,"
    but neither this contract nor the state template identifies where that count
    lives or how it is derived and updated. The state template stores only limits
    (`.oat/templates/state.md:17`), while the agent says an attempt is consumed
    when editing starts and reports events only on return
    (`.agents/agents/oat-phase-implementer.md:140`). A resume or interruption
    can therefore reset or lose usage, violating the bounded-retry guardrail and
    the explicit "prior usage never resets" requirement.
  - Fix: Specify one authoritative per-phase usage ledger and a monotonic
    read/update protocol, including how an attempt consumed before an edit is
    preserved across interruption. Make root validation reject a resume when
    usage cannot be reconciled, and test resume/exhaustion from nonzero usage.
  - Requirement: p01-t02 attempt accounting and exhaustion preservation.

- **The emitting agent is not given the canonical recovery-event schema**
  (`.agents/agents/oat-phase-implementer.md:168`)
  - Issue: The phase agent receives only its Phase Scope and role contract, not
    root workflow references
    (`.agents/skills/oat-project-implement/SKILL.md:197`). Its role lists semantic
    fields but omits the canonical heading, labels, order, and authorization
    enum. The exact schema exists only in the root-only phase reference
    (`.agents/skills/oat-project-implement/references/phase-execution.md:193`),
    whose verifier blocks malformed events. The producer therefore cannot
    deterministically emit the record the consumer requires.
  - Fix: Put the exact event template and enum values in the phase-agent
    contract or include a versioned schema in every Phase Scope. Test the
    phase-agent contract independently instead of satisfying the assertion by
    concatenating root-only and agent-only files.
  - Requirement: p01-t02 canonical event observability and fail-closed report
    validation.

- **A valid `BLOCKED` recovery report conflicts with root verification**
  (`.agents/skills/oat-project-implement/references/phase-execution.md:222`)
  - Issue: Recovery stop boundaries and the phase agent allow
    `DONE_WITH_CONCERNS` or `BLOCKED`, but report verification says to require
    only `DONE` or `DONE_WITH_CONCERNS`; later it again calls `BLOCKED` terminal.
    A fail-closed `BLOCKED` report can therefore be rejected before its
    direction-required event and consumed attempt are validated and copied into
    bookkeeping, breaking the every-disposition observability contract.
  - Fix: Define separate accepted success and accepted terminal-stop report
    branches. For `BLOCKED`, validate provenance, attempt accounting, immutable
    history, and the canonical event before stopping, while still prohibiting
    continuation or fallback. Add a test over the root verifier's status matrix.
  - Requirement: p01-t02 fail-closed behavior and canonical event completeness.
