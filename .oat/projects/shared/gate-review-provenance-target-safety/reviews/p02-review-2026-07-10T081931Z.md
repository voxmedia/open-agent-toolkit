## Findings

### Critical

- **C1: Ambient review gates can pass a sibling project's artifact** (`packages/cli/src/commands/gate/index.ts:1824`)
  - Issue: The new scan includes every configured project's direct review files (`listReviewGateArtifactCandidates`, lines 1722-1743), but `corroborateReviewTarget` unconditionally reports `project: ambient` for `active-project` and `single-candidate` resolution. The only containment/frontmatter rejection is guarded by `reviewProject.source === 'declared'` at lines 2530-2533. Consequently, with active project A and sibling project B, a unique matching run ID written under B is parsed, severity-evaluated, and can return `status: ok` for A. Before this phase, the gate scanned only A's review directory, so this is a false-green backward-compatibility regression at the review-subject boundary.
  - Fix: Continue scanning across projects to detect duplicate run IDs, but require the unique match's `containingProject` to equal the resolved ambient project before parsing or handoff. Preserve `corroboration.project: ambient` to communicate that the subject was not explicitly declared; do not use `ambient` to waive containment. Add active-project and single-candidate tests where the only matching artifact is written under a sibling project and assert non-receive-eligible targeting failure.
  - Requirement: p02-t01 ambient backward compatibility; p02-t02 target correlation safety.

### Important

- **I1: Declared-project mismatch is checked after verdict parsing and artifact mutation** (`packages/cli/src/commands/gate/index.ts:2495`)
  - Issue: After unique run correlation, the gate calls `parseReviewGateVerdict(..., { normalizeMissingEmptySeveritySections: true })` at lines 2495-2502. That function parses finding counts and may rewrite the artifact before the declared containing-project/`oat_project` check at lines 2519-2550. A mismatched artifact with malformed findings therefore returns remediable `artifact_validation_failed` instead of the required non-remediable targeting outcome, while a mismatched artifact missing a zero-count severity heading can be modified before rejection. This contradicts the required ordering that path/frontmatter mismatches fail closed before invocation remediation, severity evaluation, or receive guidance.
  - Fix: Use the already parsed `artifactProject` and `containingProject` from the correlation candidate to reject declared-project mismatches immediately after unique run selection. Only then call `parseReviewGateVerdict`. Add a declared-mismatch test with malformed findings and another with a normalizable missing heading; both should return `targeting_correlation_failed`, remain non-receive-eligible, and leave artifact bytes unchanged.
  - Requirement: p02-t02 fail-closed targeting order.

- **I2: Generation metadata filtering can hide duplicate run-ID artifacts** (`packages/cli/src/commands/gate/index.ts:1616`)
  - Issue: `readReviewGateArtifactCandidate` returns `null` when `oat_generated_at` is missing or invalid (lines 1616-1623), before it parses `oat_gate_run_id` at lines 1627-1655. Thus, if two direct active artifacts carry the current run ID but one lacks valid generation metadata, the invalid-timestamp artifact is excluded and the other appears uniquely correlated; the gate may pass despite duplicate run identity. A single correctly run-correlated artifact with only a bad timestamp is likewise misclassified as a non-remediable missing-run failure rather than an artifact-format failure.
  - Fix: Retain every direct review candidate whose frontmatter can supply a run ID even when generation metadata is absent or invalid. Make generation time nullable or use a deterministic fallback for diagnostics/sorting, perform unique run-ID correlation first, and validate `oat_generated_at` afterward. Add tests for a valid artifact plus a same-run duplicate with missing/invalid generation time, and for a single same-run artifact with invalid generation time.
  - Requirement: p02-t02 unique direct-artifact correlation and duplicate-run fail-closed behavior.
