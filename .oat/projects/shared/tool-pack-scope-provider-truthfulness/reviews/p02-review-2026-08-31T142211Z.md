### Important

- **Provider scope resolution is still not a single authoritative production boundary**
  (`packages/cli/src/providers/shared/registry.ts:223`)
  - Issue: `resolveProviderScopeContext()` first calls
    `getConfigAwareAdapters()`, which detects every adapter, then calls every
    adapter's `detect()` again to populate `detectedProviders`. A filesystem
    transition between those reads can make activation and detection evidence
    contradict within one context. Doctor additionally calls its separate
    `checkProviders()` detector at `packages/cli/src/commands/doctor/index.ts:1213`
    and only resolves a context later for user managed-role inventory, so
    project doctor activation/detection does not come from the shared context.
    The explicit p02-t03 registry-only integration requirement is tested only
    for list and inspect, leaving init, sync, status, doctor, and set context
    consumption unpinned.
  - Fix: Detect each registered adapter exactly once per scope and derive
    active providers, raw detection, mismatches, and activation evidence from
    that one result. Route doctor's provider check through the resulting
    `ProviderScopeContext`, and add registry-only boundary tests for every
    p02-t03 consumer (including provider set validation) without restoring
    command-private provider arrays.
  - Requirement: FR4, NFR5

- **Removal still reports a retained target scope as a complete verified removal**
  (`packages/cli/src/commands/tools/remove/remove-tools.ts:464`)
  - Issue: `removalLifecycleOutcomes()` defines verification only as “inventory
    exists and has no unknown scopes.” It never verifies that requested removal
    scopes are absent. The new partial-removal fixture leaves user scope
    realized, yet the production branch at line 483 returns `status: complete`
    with no recovery. The so-called final inventory is also collected before
    `packages/cli/src/commands/tools/remove/index.ts:158` clears durable scoped
    intent, so successful JSON can retain stale `declared-only` evidence even
    after the command writes `enabled: false`.
  - Fix: Project removal lifecycle only after every canonical and intent
    mutation completes. For apply, require every requested removed scope to be
    proven absent; if any remains realized, return partial/failed with exact
    scope recovery. Preserve pre-mutation evidence for dry-run. Extend the
    partial-removal test to assert non-complete status and add a real
    command-level assertion that final evidence contains the post-write intent
    state.
  - Requirement: FR1, FR3, NFR2, NFR3
