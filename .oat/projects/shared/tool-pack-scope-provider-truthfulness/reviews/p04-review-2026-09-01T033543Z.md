## Findings

### Critical

- **Deferred directory copy can overwrite a user child created after the entry root is reserved**
  (`packages/cli/src/fs/io.ts:119`)
  - Issue: `copyDirectoryNoClobber` atomically rejects an entry root that already
    exists, but after `mkdir(dest)` it calls the ordinary `copyDirectory`.
    That copier writes each child with non-exclusive `writeFile` at
    `packages/cli/src/fs/io.ts:81`. A user file created inside the new entry
    root during the recursive copy window is therefore overwritten rather than
    producing `EEXIST`. An independent 32 MiB deferred-transition fixture
    injected `destination/SKILL.md` after root creation and observed
    `collectionStatus: changed`, `operationStatus: changed`,
    `userOwnedSurvived: false`, and a persisted `copy` manifest entry. This
    violates the P0 zero-unmanaged-loss boundary and leaves the round-4 fix
    incomplete even though all whole-destination fixtures pass.
  - Fix: Make deferred directory publication no-clobber for the complete tree,
    not only its root. Use recursively exclusive directory/file creation (or an
    equivalent identity-bound no-replace publication primitive), stop on any
    child collision, preserve the conflicting bytes/tree, report an actionable
    failed child, and persist no entry ownership. Add a deterministic hook after
    destination-root creation that injects same-name files and directories at
    nested levels and asserts byte/tree identity, failed evidence, and no
    manifest claim. If complete-tree no-replace semantics cannot be guaranteed,
    block deferred copy transitions and require a safe manual recovery path.
  - Requirement: FR5, FR10, NFR1, NFR2
