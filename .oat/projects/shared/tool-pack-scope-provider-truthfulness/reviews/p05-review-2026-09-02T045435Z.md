## Findings

### Critical

- **Guarded publication is non-atomic and still loses open-inode edits**
  (`packages/cli/src/commands/shared/agents-md.ts:463`)
  - Issue: For an existing direct file or contained-symlink target,
    `writePlannedContent()` renames the planned inode to a hidden rollback path,
    then hard-links the replacement at the public path, checks the rollback
    bytes once, and unlinks the rollback inode. This exposes a real `ENOENT`
    interval on every otherwise-successful update, so a contained `AGENTS.md`
    symlink is transiently broken and direct readers can observe a missing file.
    More seriously, the final rollback content check at line 478 is another
    check/use window: an editor that opened the original inode before the
    rename can write after that read but before line 482 removes the rollback
    inode. Deterministic injected-filesystem reproductions for both a direct
    file and a contained symlink returned `{action:"updated"}`, removed every
    rollback artifact, and left only the generated content; the late bytes
    written through the still-open original file descriptor disappeared. A
    separate reproduction observed `missingDuringPublish:true` during a
    successful update. This violates NFR1 unmanaged/user-content preservation,
    NFR2 failure atomicity, and p05-t01's explicit atomic-write contract.
  - Fix: Do not publish by moving the live inode out of the public path and
    later deleting it after a byte check. Use a primitive/protocol that gives a
    genuinely atomic public-path transition while retaining the original
    version until concurrent writers can no longer be silently discarded. If
    the runtime cannot provide the required conditional atomicity, fail closed
    before mutation or preserve both versions with an explicit recovery result;
    never return success after deleting a possibly edited original inode. Add
    deterministic direct-file and contained-symlink tests that keep the
    original file descriptor open, write at every publication/cleanup boundary,
    and assert the late bytes survive, the operation blocks, and no public-path
    absence is observable.
  - Requirement: NFR1 (P0), NFR2 (P0)

- **Crossed new/legacy marker ranges bypass preflight and delete user text**
  (`packages/cli/src/commands/shared/agents-md.ts:551`)
  - Issue: `findManagedSection()` validates the `tools` and legacy `workflows`
    pairs independently, but `upsertAgentsMdSection()` never verifies that the
    resulting ranges are disjoint. It then applies both edits using offsets
    from the original snapshot. A file whose unique ordered pairs cross
    (`tools` starts, `workflows` starts, `tools` ends, user text, `workflows`
    ends) is therefore accepted as valid. The exact helper path used by both
    aggregate and standalone guidance returned `{action:"updated"}` and changed
    the file from a crossed-marker fixture containing `interstitial user text`
    and `# Footer user text` to only the replacement `OAT tools` section; both
    unrelated trailing strings were deleted. A nested inverse fixture also
    returned success with a corrupted `lows -->` fragment. This means the
    round-1 malformed/duplicate-marker finding is not fully resolved: common
    unclosed/duplicate cases now block byte-for-byte, but aggregate structural
    validation remains incomplete and can still cause content loss.
  - Fix: Before computing any edit, validate the combined target/removal section
    set from the one snapshot: every pair must be unique, ordered, and mutually
    non-overlapping/non-crossing. Reject nested or crossed managed ranges as a
    blocked guidance outcome without writing. Apply validated edits without
    reusing stale offsets after any length-changing edit. Add shared-helper and
    actual aggregate/registered-workflows regressions for both nesting
    directions and crossing ranges, with unrelated prefix/interstitial/suffix
    bytes asserted exactly unchanged.
  - Requirement: FR6 (P0), NFR1 (P0), NFR2 (P0)
