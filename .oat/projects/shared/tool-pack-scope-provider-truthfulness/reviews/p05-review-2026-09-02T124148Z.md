## Findings

### Critical

- **Temporary publication source is not identity-bound before metadata mutation or commit** (`packages/cli/src/commands/shared/agents-md.ts:690`)
  - Issue: The helper creates the temporary pathname, then separately inspects
    it and performs path-based `chmod`/`chown` before treating the later
    observation as the source identity. A changed regular file or symlink at
    that boundary can therefore receive metadata changes and become the source
    of the final rename. Fresh checks reproduced foreign bytes replacing the
    public file and a foreign symlink becoming the direct or contained target;
    post-publication validation detects the mismatch only after the unsafe
    state is visible. This violates NFR1's unmanaged-content and containment
    guarantees and NFR2's fail-closed publication requirement.
  - Fix: Create and retain an open, exclusive file handle; apply and verify
    metadata through that handle; and publish only when the source identity is
    still the exact created object. If the platform cannot bind source identity
    through commit, preserve the artifact and return an explicit blocked
    recovery outcome without changing the public target. Add direct and
    contained-target regular-file/symlink boundary tests.
  - Requirement: NFR1 (P0), NFR2 (P0)

- **Final destination and retained-original identities are not protected at the publication boundary** (`packages/cli/src/commands/shared/agents-md.ts:733`)
  - Issue: The last public-target and recovery checks finish before the
    unconditional replacing rename at line 758. A changed destination is
    overwritten without a conditional identity check. Separately, if the
    retained-original pathname changes after its one validation, publication
    proceeds, the true original loses its durable name, the returned recovery
    identifier refers to unrelated content, and the next run can return
    `no-change`. Fresh four-case matrices reproduced both failures for direct
    and contained targets with regular-file and symlink boundary changes. This
    leaves raced user content unprotected and can lose the only retained
    original while claiming recovery evidence.
  - Fix: Use a commit primitive or fail-closed protocol that conditionally
    protects the expected destination identity and keeps the retained original
    identity bound through the commit result. Revalidate identity-bound
    recovery evidence after publication before returning it; ambiguity must
    remain blocked and must never become `no-change`. Cover every final
    destination/recovery boundary for direct and contained targets.
  - Requirement: NFR1 (P0), NFR2 (P0)

### Important

- **Recovery discovery treats a self-describing filename as ownership proof and ignores retained temporary artifacts** (`packages/cli/src/commands/shared/agents-md.ts:530`)
  - Issue: `discoverRecoveries()` accepts any regular file whose current
    device/inode matches values embedded in its own name; there is no
    independent durable evidence that OAT created that link. A user-owned file
    can therefore be misreported as OAT recovery evidence and recommended for
    removal. Conversely, temporary artifacts deliberately preserved after
    metadata, revalidation, or publication failures use random `.tmp` names and
    are never discovered by the recovery scan, so later runs can report normal
    state while retained OAT artifacts remain unresolved.
  - Fix: Store independent, identity-bound ownership evidence for both retained
    originals and retained temporary objects. Use deterministic repo-relative
    identifiers, rediscover all unresolved artifacts, distinguish foreign
    collisions, and require explicit reconciliation before ordinary success.
  - Requirement: FR6, NFR1, NFR2

- **Metadata restoration loses special permission bits** (`packages/cli/src/commands/shared/agents-md.ts:692`)
  - Issue: The implementation applies the complete mode before `chown`.
    On the reviewed platform, the ownership operation clears special mode bits;
    a fresh direct-file check changed mode `04666` to `0666` while returning
    `recovery-required`. Existing tests assert only `mode & 0777`, so the loss
    is not covered. Ordinary `0666` preservation under restrictive umask is
    fixed, but the full supported mode contract remains incomplete.
  - Fix: Restore ownership first, then apply the final validated mode, and
    verify both ownership and the full supported mode mask before publication.
    If exact restoration is unsupported, block with structured recovery rather
    than publishing altered metadata. Add direct and contained-target coverage
    for special bits and ownership failure.
  - Requirement: FR6 (P0), NFR1 (P0)

- **Post-scaffold filesystem failures are not carried as truthful structured partial outcomes across all consumers** (`packages/cli/src/commands/docs/init/index.ts:283`)
  - Issue: A returned `recovery-required` result now produces nonzero partial
    JSON for docs, PJM, and decision init, resolving the ordinary-success defect.
    Low-level helper failures after the primary scaffold/adoption has completed
    still fall through command error paths (`docs/init/index.ts:343`,
    `pjm/index.ts:210`, `decision/index.ts:203`) and emit `status: error`
    instead of a structured partial envelope that preserves the completed
    layer plus guidance code/action. Human PJM and decision recovery output also
    omits the repo-relative recovery identifiers/actions present in the result
    (`pjm/index.ts:203`, `decision/index.ts:193`). The tests cover generic
    sanitization and returned recovery values, but not every publisher stage
    through every registered consumer.
  - Fix: Propagate typed mutation code, target, retained identifiers, and safe
    action through aggregate, registered workflows, docs, PJM, and decision
    command outcomes. When primary work is complete, every guidance failure
    must produce exactly one nonzero partial human/JSON result, never ordinary
    success or a whole-command error that erases completed-state semantics.
    Add a registered consumer matrix for every low-level stage and both output
    modes, asserting redaction and scope/adoption preservation.
  - Requirement: FR6 (P0), NFR1 (P0), NFR2 (P0)
