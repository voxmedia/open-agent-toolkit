## Findings

### Critical

- **Production leaf workflows installs ignore the explicit guidance choice**
  (`packages/cli/src/commands/init/tools/index.ts:1907`)
  - Issue: With the default production dependencies, every leaf pack command,
    including `workflows`, is registered through `createReconciledPackCommand()`.
    That action installs and reports the pack but never resolves, applies, or
    reports project guidance. The guidance-aware
    `createInitToolsWorkflowsCommand()` is only used by the legacy dependency
    branch. An exact CLI reproduction of `oat tools install workflows` with
    project scope, explicit guidance, no sync, and JSON output exited 0 while
    leaving `AGENTS.md` absent; placing the option before the subcommand behaved
    identically. This violates FR6's P0 standalone
    workflow-install contract and contradicts the documented example at
    `apps/oat-docs/docs/cli-utilities/tool-packs.md:196`.
  - Fix: Make the production reconciled `workflows` leaf action run the shared
    guidance planner/apply/report path after verified capability installation,
    or register a lifecycle-compatible guidance-aware workflows command.
    Preserve the installed pack result when guidance is declined, and return a
    separate partial/blocked guidance result when an accepted update is unsafe.
    Add registered-program/e2e coverage for both option positions, project and
    user capability scopes, opt-in, decline, non-interactive default, human
    output, and JSON output. Do not rely only on direct tests of
    `createInitToolsWorkflowsCommand()`.
  - Requirement: FR6 (P0)

- **Atomic replacement clobbers a concurrent in-place user edit**
  (`packages/cli/src/commands/shared/agents-md.ts:368`)
  - Issue: `assertPlanUnchanged()` verifies path identity but not that the bytes
    read during planning are still current. An in-place edit retains the same
    device/inode, so the subsequent `rename(tempPath, targetPath)` overwrites it.
    A deterministic injected-filesystem reproduction wrote `# late user edit`
    after the temporary file was created; `upsertAgentsMdSection()` returned
    `{action: "updated"}`, `lateUserEditSurvived` was false, and the late edit
    disappeared. This violates the P0 unmanaged/user-content preservation and
    no-clobber requirements in NFR1/NFR2.
  - Fix: Use a commit protocol that detects content changes as well as identity
    changes and cannot publish over a changed target. If the runtime cannot
    provide a truly conditional atomic replacement, fail closed or use a
    recoverable guarded protocol that preserves both versions instead of
    claiming an atomic safe update. Add deterministic direct-file and
    contained-symlink target tests for in-place changes occurring after the
    planned read and immediately before publication; assert the late bytes
    survive and the operation reports blocked.
  - Requirement: NFR1 (P0), NFR2 (P0)

### Important

- **Malformed legacy markers block only after the new section has already been written**
  (`packages/cli/src/commands/init/tools/index.ts:852`)
  - Issue: Guidance migration is implemented as two independent mutations:
    upsert `OAT tools`, then remove `OAT workflows`. When the legacy section is
    malformed, the first mutation commits and the second rejects. An exact CLI
    reproduction seeded an unterminated `<!-- OAT workflows -->` section;
    aggregate install exited 1 as blocked, but `<!-- OAT tools -->` had already
    been appended. This conflicts with the design rule that malformed/duplicate
    marker pairs block automatic modification and with the phase's failure
    atomicity requirement. The same sequence is duplicated at
    `packages/cli/src/commands/init/tools/workflows/index.ts:121`.
  - Fix: Preflight both the replacement and legacy marker structures against
    one unchanged file snapshot, compute the complete migrated content once,
    and publish it with one safe commit. Add aggregate and standalone tests
    proving malformed or duplicate legacy markers leave the full file
    byte-for-byte unchanged and return a blocked guidance outcome.
  - Requirement: FR6, NFR2
