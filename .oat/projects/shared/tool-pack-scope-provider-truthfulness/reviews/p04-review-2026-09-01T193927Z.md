## Findings

### Critical

- **Deferred directory copy follows a race-swapped destination ancestry and writes outside the managed root**
  (`packages/cli/src/fs/io.ts:126`)
  - Issue: `copyDirectoryNoClobber` exclusively creates the destination root,
    but then addresses the entire publication tree by pathname. A concurrent
    actor can replace that root with a symlink before line 127, or replace a
    nested directory after line 145 and before its child is opened at line 158. `open(..., 'wx')` protects only the final filename; it follows parent
    symlinks. Two deterministic probes reproduced both forms. Replacing the
    post-create root with an external-directory symlink made the helper resolve
    successfully and create external `SKILL.md` with canonical bytes.
    Replacing the newly created `references` directory before its child filter
    returned likewise created external `guide.md`. Because the helper resolves,
    the executor adds a copy manifest entry at
    `packages/cli/src/engine/execute-plan.ts:280`, reports `changed` at line
    899, and can persist that false ownership at line 920. The new full-path
    test injects colliding children inside an unchanged root, so it does not
    exercise either ancestry replacement. This violates the P0 managed-root,
    apply-time-swap, and failure-atomicity guarantees even though ordinary
    same-name collisions are now preserved.
  - Fix: Fail closed for deferred directory-copy transitions on the current
    runtime unless publication can keep every destination ancestor
    identity-bound and non-following for the complete transaction. A safe
    implementation needs descriptor-relative/no-follow creation and writes (or
    an equivalent atomic no-replace publication primitive), not repeated
    pathname operations. If that primitive is unavailable, block this
    transition with manual recovery guidance, as collection alias creation and
    unlink already do. Add full `executeSyncPlan` regressions that replace the
    just-created root and a just-created nested directory with external
    symlinks; assert failed child evidence, byte-for-byte unchanged external
    trees, no provider or external canonical writes, and no per-entry manifest
    ownership.
  - Requirement: FR5, FR10, NFR1, NFR2
