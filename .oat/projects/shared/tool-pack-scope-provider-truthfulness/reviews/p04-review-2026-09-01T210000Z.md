### Critical

- **A failed deferred directory copy becomes an unsafe ordinary copy on the
  next sync** (`packages/cli/src/engine/execute-plan.ts:585`)
  - Issue: For an absent explicit-strategy transition, the collection
    transaction detaches ownership at lines 585-586 and persists that detached
    manifest at lines 650-657 before entry apply begins. The new directory-copy
    guard then correctly throws at lines 265-285, but the manifest already has
    neither the collection nor its inherited entries. On the next unchanged
    sync, `computeSyncPlan` finds no `existingCollection`, so its transition
    branch at `packages/cli/src/engine/compute-plan.ts:715-767` is skipped and
    the absent directory is classified as an ordinary `create_copy` at lines
    535-540. Because `deferredUntilCollectionDetached` is now false, apply calls
    the ordinary path-based `copyDirectory` at
    `packages/cli/src/engine/execute-plan.ts:309-312`. A direct two-run probe
    confirmed the first call returned the approved manual-recovery failure and
    persisted `collections: []`, `entries: []`; the retry planned
    `{ operation: "create_copy", deferred: false, isFile: false }` and invoked
    an injected ordinary copier once. Thus a routine retry silently escapes the
    fail-closed path and reintroduces the exact pathname publication class that
    can follow race-swapped destination ancestry.
  - Fix: Make the unsafe-copy block durable. Do not commit collection
    detachment when any associated deferred directory copy cannot safely run,
    or persist an explicit blocked-transition state that the planner must honor
    on later runs. An unchanged retry must remain blocked before every
    publication helper; only a safe strategy change or explicit external
    ownership disposition may release it. Add an integration regression that
    runs plan/apply twice with unchanged `copy` configuration, injects the
    ordinary copier on the second run, and proves zero calls, zero provider or
    external writes, preserved collection/block evidence, actionable human/JSON
    recovery, and no per-entry ownership.
