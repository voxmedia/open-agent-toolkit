## Findings

### Critical

- **Exclusive creation can be redirected through a swapped repository parent** (`packages/cli/src/commands/shared/agents-md.ts:450`)
  - Issue: `createMissingFile()` validates the repository directory identity at
    line 449 and then performs a path-based `writeFile(..., { flag: 'wx' })` at
    line 450. The exclusive flag protects only the final `AGENTS.md` name; it
    does not bind the already-validated parent directory to the create. A fresh
    injected check renamed the validated repository after
    `assertPlanUnchanged()`, replaced its old pathname with a symlink to a
    sibling foreign directory, and then allowed the real `writeFile` call to
    continue. OAT created `foreign/AGENTS.md`, left the original repository
    without the file, and returned `{ action: 'created' }`. This is an
    apply-time-swapped escaping path that mutates outside the validated root,
    contrary to NFR1 and the design's apply-time ancestry guarantee. The
    existing race test covers only a final target appearing at the unchanged
    parent; it cannot detect this parent swap.
  - Fix: Do not use pathname-only `writeFile(wx)` as sufficient containment
    proof. Either introduce a supported parent-relative, no-follow exclusive
    create primitive whose operation is bound to the validated parent identity,
    or extend the operator-selected fail-closed design so an absent file also
    returns manual guidance when that primitive is unavailable. Do not try to
    clean up after detecting the swap: path-based cleanup would add another
    identity race. Add direct-directory and directory-to-symlink swap tests at
    the final create boundary and assert zero writes outside the original
    validated root.
  - Requirement: NFR1 (P0), NFR2 (P0); design threat mitigation at
    `design.md:1300-1306`
