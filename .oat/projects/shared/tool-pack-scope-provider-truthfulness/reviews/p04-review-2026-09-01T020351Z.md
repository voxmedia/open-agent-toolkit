## Findings

### Critical

- **Collection creation still has a final ancestry-swap window** (`packages/cli/src/fs/io.ts:174`)
  - Issue: The new primitive validates each ancestor with separate `lstat`/`mkdir` calls through line 195, then creates the final link with a path-based `symlink` at line 201. An ancestor can be replaced with a symlink after its final `lstat` and before the `symlink` call, causing the kernel to resolve the destination through the replacement. The two new regressions swap ancestry before these checks; neither exercises nor eliminates this final syscall window. This leaves the original P0 guarantee that a race-swapped ancestor cannot redirect creation outside the managed root unproven and mechanically false.
  - Fix: Make the final creation relative to a securely opened, identity-verified parent with no-follow semantics (or use an equivalent platform primitive that makes ancestor identity and creation one guarded operation). If the current Node API cannot provide that guarantee, keep collection creation disabled for that path and report a safe per-entry/recovery outcome. Add a regression that swaps the parent after validation but before the final creation primitive and proves no out-of-scope path is created.
  - Requirement: FR5, NFR1, NFR2

- **An apply-time collection replacement is treated as a successful explicit transition and receives child writes** (`packages/cli/src/engine/execute-plan.ts:481`)
  - Issue: A transition detaches and persists manifest ownership before re-proving the alias. When the current proof no longer matches, lines 510-513 change only the reason while leaving the default status `changed`; `blockedTransitions` therefore permits deferred child operations at lines 641-679. An independent reproduction used `beforeFirstMutation` to replace the planned OAT-created alias with a real directory containing `user-owned.txt`. Apply reported the detach and child `create_symlink` as `changed` and created `.claude/skills/skill-one` inside that replacement directory. This violates the design rule that any apply-time identity mismatch invalidates the plan before mutation and NFR1's fail-closed boundary.
  - Fix: For `transitionToPerEntry`, re-prove the planned alias before detaching ownership and classify any mismatch/removal failure as a blocked transition. Do not run deferred child operations unless the exact durably identified alias was removed (or the destination was already absent under a separately revalidated plan). Add hook-time replacements with a real directory, foreign link, changed same-target link, missing path, and unavailable identity; every mismatched case must produce no child mutation.
  - Requirement: FR5, NFR1, NFR2

### Important

- **A zero-child collection never transitions from `auto` to explicit per-entry strategy** (`packages/cli/src/engine/compute-plan.ts:713`)
  - Issue: Existing-collection transition planning requires `collectionCandidates.length > 0` at lines 713-719. The later collection cleanup skips every active provider at lines 969-971. Starting from a real OAT-created collection, deleting its last canonical child, and selecting explicit `symlink` produced no collection plan; apply detached the inherited entry but left the provider directory as a symlink and retained the empty `oat-created` collection record. The configured explicit strategy therefore does not become authoritative until a future child happens to appear.
  - Fix: Reconcile an existing collection whenever it is no longer eligible, including an empty canonical collection. Safely detach/remove a still-proven OAT-created alias and collection record even when there are no per-entry operations, while preserving adopted, changed, legacy, and unverifiable paths with the existing conflict semantics. Add zero-child `auto -> symlink` and `auto -> copy` integration tests through apply and manifest reload.
  - Requirement: FR5, FR10, NFR2, NFR3

- **The design omits the durable identity fields now required for safe unlink** (`.oat/projects/shared/tool-pack-scope-provider-truthfulness/design.md:848`)
  - Issue: The defensible fix persists exact link text in `CollectionIdentityProof` and `{device, inode, linkText}` as `ManifestCollectionEntry.createdLink`, but the canonical design model at lines 848-899 defines neither field. The design still states that apply-time mismatch invalidates the plan and unchanged OAT-created aliases may be removed, yet it does not describe the durable authority that now makes that safe. This is load-bearing artifact drift, not a reason to remove the code.
  - Fix: Align the design data model and validation/migration text with `linkText` and optional `createdLink`, including the legacy-record rule that missing identity permits ownership detachment but never unlink. Keep the implementation's safe compatibility behavior.
  - Requirement: FR5, NFR1, NFR4
