## Findings

### Critical

- **Final path-based unlink can delete a race-swapped unmanaged file**
  (`packages/cli/src/fs/io.ts:240`)
  - Issue: `removeCollectionSymlinkIfUnchanged` proves device/inode and link
    text through separate `lstat` and `readlink` calls, then executes
    `unlink(linkPath)`. Another process can replace the proved link with a
    foreign symlink or regular file after the last read and before line 240.
    The path-based unlink then removes the replacement, returns success, and
    allows the explicit transition's deferred child writes to proceed. This
    leaves the round-2 transition fix incomplete and also affects disablement
    and rollback paths. Existing replacement tests swap the path before the
    function's proof or inject a false removal result; none controls the final
    syscall window.
  - Fix: Use an identity-bound, parent-relative no-follow removal primitive
    (for example, a securely held directory handle plus guarded unlink
    semantics). If the runtime cannot provide that primitive, fail closed by
    disabling automatic alias unlink/transitions, report manual recovery, and
    proceed with per-entry writes only after a separately revalidated absent
    destination. Add a deterministic test that swaps the final path after the
    last identity read but before removal and proves the replacement survives
    and every deferred child operation is blocked.
  - Requirement: FR5, NFR1, NFR2

### Important

- **The design still omits the transition identity fields used by the
  executor**
  (`.oat/projects/shared/tool-pack-scope-provider-truthfulness/design.md:531`)
  - Issue: The design's `CollectionProjectionPlan` omits
    `configuredStrategy`, `createdLink`, and `transitionToPerEntry`, while the
    implemented interface defines them at
    `packages/cli/src/engine/engine.types.ts:56`. `createdLink` and
    `transitionToPerEntry` are load-bearing inputs to the fixed identity proof,
    explicit transition, and deferred-child behavior. The design now describes
    manifest identity and legacy migration semantics, but its component
    contract still cannot express how the executor receives that evidence.
  - Fix: Align the design interface with the defensible implementation and
    document how configured strategy, durable creation identity, and explicit
    transition state control removal, child deferral, and reported outcomes.
  - Requirement: FR5, NFR1, NFR4

### Medium

- **A wholly failed apply can still rewrite a V1 manifest as V2**
  (`packages/cli/src/engine/execute-plan.ts:820`)
  - Issue: The design and plan require V1 to normalize in memory and write V2
    only after a successful sync apply. `loadManifest` performs the in-memory
    normalization, but entry failures are caught at lines 798-817 and manifest
    persistence still runs whenever operations exist. Consequently, an apply
    where every entry operation failed can silently persist the normalized V2
    manifest even though no sync change succeeded.
  - Fix: Persist a V1-to-V2 upgrade only after the executor establishes the
    specified successful-apply condition, or explicitly revise the artifacts
    if a different condition is intended. Add a regression with a V1 source
    manifest and all entry operations failing; assert the source manifest's
    bytes/version remain unchanged.
  - Requirement: NFR2, NFR4

- **User documentation describes alias creation that the current runtime does
  not offer**
  (`apps/oat-docs/docs/provider-sync/manifest-and-drift.md:44`)
  - Issue: Production sync does not pass
    `collectionAliasCreationAvailable`, so planning uses its safe `false`
    default and falls back per entry for an absent collection destination.
    Nevertheless, this page says OAT creates the final alias transactionally,
    while `config.md:106` and `commands.md:58` say configured `auto` may create
    one. That contradicts the safe production behavior introduced to resolve
    the round-2 creation race.
  - Fix: State that the current runtime may adopt an existing exact alias, but
    an absent destination falls back to per-entry sync until an identity-bound
    guarded creation primitive is available. Include the manual-adoption
    recovery path and preserve the fail-closed conflict wording.
  - Requirement: NFR3, Phase 4 task p04-t05
