## Findings

### Critical

- **Fallback validation accepts prohibited triggers, widened controls, and unrelated canonical role evidence** (`packages/cli/src/providers/identity/oat-dispatch-record.ts:289`)
  - Issue: The rejection schema accepts any non-empty `code`, and the fallback branch checks only provider/model/effort/reasoning/service-tier/route plus authority/deadline/retry. It does not reject timeout, `BLOCKED`, refusal, interruption, or runtime-mismatch reasons; compare the generic payload that owns sandbox/tool controls; or bind `roleInstructions` to the trigger's recorded `canonicalRole`. A direct production-module probe created a valid fallback whose rejection code was `timeout`, changed payload from `{sandbox: "read-only", tools: ["Read"]}` to `{sandbox: "danger-full-access", tools: ["Bash"]}`, and supplied `unrelated-role` instructions. The function returned all three as accepted evidence.
  - Fix: Model qualifying pre-start native-selection rejection as a closed event distinct from terminal outcome codes; explicitly reject every nonqualifying category. Compare or hash every immutable configured control, including the complete payload, before linking. Require the trigger to carry resolved canonical-role evidence and require the fallback role evidence to equal it exactly (dependency, role, tier, validation, paths, version, digest, and misses). Add negative tests for each prohibited reason, every control field, missing trigger role evidence, and unrelated/substituted role evidence.
  - Requirement: FR8, FR10, NFR3

- **The recorder cannot enforce exactly one fallback or preserve concurrent evidence updates** (`packages/cli/src/commands/project/dispatch/record.ts:150`)
  - Issue: Uniqueness is a read-all-files check followed by creation of a different fallback request path. Two callers can both observe no fallback and then create separate files. A concurrent production-module probe returned `fulfilled, fulfilled` and left `fallback-a.json`, `fallback-b.json`, and `native.json` for one trigger. Updates to one request have the same lost-update window: a second probe concurrently persisted rejection and runtime events, both fulfilled, but the final file retained the rejection and reverted runtime observation to `not-reported`.
  - Fix: Make fallback claiming and per-request update publication conditional on one shared, identity-bound state transition. Use a project/request lock or compare-and-swap revision/digest that is validated and advanced atomically; the trigger must durably claim its single fallback before the fallback record can publish. Concurrent stale updates must fail and preserve the winner rather than report success. Add deterministic barrier-based tests for two fallback IDs and two different events on the same request.
  - Requirement: FR8, NFR2, NFR3

- **Sensitive-content validation admits common credential and prompt aliases** (`packages/cli/src/providers/identity/generic-dispatch-record.ts:108`)
  - Issue: The recursive key denylist matches only a few exact spellings. Direct calls to the production validator accepted `apiKey`, `password`, `systemPrompt`, and `transcriptBody`; the strict record schema still allows them inside arbitrary `payload` or other unknown-valued generic fields. These values can therefore be written to the project journal despite the explicit prohibition on credentials, prompts, messages, transcript bodies, and role content.
  - Fix: Normalize key spelling/case/separators before classification and cover credential, token, password, prompt/message, transcript, and role-content families, including camelCase and common API-key forms. Prefer closed redacted payload/evidence projections at the recorder boundary where feasible. Add table-driven recursive tests at both parser and CLI persistence boundaries and verify rejected failures leave no journal or temporary file.
  - Requirement: FR8, NFR1, NFR3

- **Atomic journal publication has an unguarded final ancestor-swap window** (`packages/cli/src/fs/io.ts:385`)
  - Issue: The implementation rechecks `realpath(dirname(resolvedFile))`, then performs path-based `link` or `rename`. A privileged concurrent process can move the validated dispatch directory and replace its pathname with a symlink after the check but before publication. The final operation is not bound to the directory identity that was validated, so it can publish outside the project. NFR1's only accepted residual parent-swap exception is for exclusive creation of an absent root `AGENTS.md`, not dispatch journals.
  - Fix: Bind final create/replace to a no-follow directory handle and identity-checked relative operation (or fail closed when the runtime cannot provide that primitive). Add injected barrier tests immediately after the last ancestry check for both create-only `link` and update `rename`, proving no outside write and complete temporary-file cleanup.
  - Requirement: NFR1, NFR2

### Important

- **The generic validator does not enforce the canonical task-class field correlations** (`packages/cli/src/providers/identity/generic-dispatch-record.ts:77`)
  - Issue: `task_class`, `model_class_floor`, `classification_source`, `classification_reason`, and `floor_satisfaction` are independently optional. The canonical generic record contract requires the classification trio together, requires the floor to equal the requested class, and requires a corresponding satisfaction result. The current parser can persist partial or contradictory floor evidence while appearing schema-valid.
  - Fix: Add a `superRefine` correlation: legacy records omit all class fields; class-constrained records require all five, `classification_source: caller`, `model_class_floor === task_class`, and a valid satisfaction result. Pin partial and mismatched combinations in generic-record and recorder tests.
