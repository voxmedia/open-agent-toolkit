### Minor

- **Pre-start rejection cleanup is invoked on every refusal, including after
  the accepted handle is bound**
  (`packages/cli/src/commands/gate/index.ts:3415-3418`)
  - Issue: the new call site fires whenever `childResult.refusal` is set and no
    artifact was produced. `bindAcceptedHandle` runs inside
    `startPreparedValidationAuthorityBrokerInternal`
    (`packages/cli/src/review/validation-authority-broker.ts:236`), so every
    enforce-mode gate run that successfully completes `prepare-context` already
    has `acceptedHandleDigest !== null`. If such a run later emits
    `OAT_GATE_REFUSAL:` with no artifact,
    `deletePreStartRejectedGateRun` throws
    `accepted gate launch attempt cannot be replaced or deleted`
    (`packages/cli/src/review/validation-store.ts:1204-1211`), and
    `cleanupPreStartRejectedGateRun` re-throws because it tolerates only
    `ENOENT` and the missing-authority-key message
    (`packages/cli/src/commands/gate/index.ts:399-422`). Because the cleanup
    call precedes `writeRefusalFailure()`, the operator would receive
    `writeReviewGateUnexpectedFailure` instead of the
    `outcome: 'review_did_not_complete'` refusal envelope that skills branch
    on. This is bounded rather than incorrect: the canonical refusal contract
    emits the token only from Step 6.1 route validation, which runs before
    `prepare-context` (`.agents/skills/oat-project-review-provide/SKILL.md:709`
    and `:744-746`), so in-contract refusals are always genuinely pre-start;
    the store still refuses to delete accepted state, and the outer catch keeps
    the gate fail-closed at exit 1. Existing coverage cannot see the seam
    because the refusal test stubs the dependency with `async () => {}`
    (`packages/cli/src/commands/gate/index.test.ts:5363`).
  - Suggestion: either gate the call on genuinely pre-start state, or tolerate
    the `accepted gate launch attempt cannot be replaced or deleted` message in
    `cleanupPreStartRejectedGateRun` as an expected no-op, and move the call
    after `writeRefusalFailure()` so the refusal envelope is written first.
    Design already treats acceptance as the boundary — "Once a reviewer is
    accepted, replacement is prohibited and the pair remains fixed through
    translation" (`design.md:664-667`) — so tolerating it matches intent.

- **p05-t15 declares four symlinked contract copies as `Modify`**
  (`.oat/projects/shared/review-plan-workflow/plan.md:3315-3318`)

    `.agents/skills/*/references/docs/autonomy-contract.md` are symlinks to
