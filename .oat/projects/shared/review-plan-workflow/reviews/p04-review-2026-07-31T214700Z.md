- **Tier 1 coordinator rails have no dossier handoff to persist**
  (`.agents/skills/oat-project-review-provide/SKILL.md:818`)
  - Issue: the accepted primary reviewer owns each `WorkerDossierV1`, but its
    canonical output contract returns exactly one `ReviewerTerminalV1`, which
    contains only final accounting and dossier digests. The changed local and
    remote skills wait until the subagent completes and then tell the parent
    launcher to submit every full dossier; no terminal field, accepted-handle
    side channel, callback, or pre-terminal binding step transfers those
    dossiers to the parent. The launcher therefore cannot execute the new
    command on either Tier 1 rail, so valid delegated complete/partial reviews
    still reach `validate-output` with empty persisted worker coverage. The
    direct store and broker fixtures manufacture the dossier in the outer test
    process and do not exercise this missing producer-to-launcher boundary.
  - Fix: Keep full dossiers inside the accepted primary continuation and require
    that continuation to execute a supplied launcher-owned, receipt-bound
    binder invocation as each dossier is accepted, before returning its
    terminal. Alternatively, extend the typed accepted-handle result with a
    strictly parsed launcher-only dossier handoff. Update the canonical reviewer
    contract and both coordinator rails, then test an actual accepted reviewer
    result rather than outer-fixture dossier injection.
  - Requirement: FR6, FR7, FR9, NFR1, NFR2, NFR3

- **Direct phase reviews still validate delegated output before binding worker
  dossiers**
  (`.agents/skills/oat-project-implement/references/phase-execution.md:140`)
  - Issue: p04-t08 made direct phase review a first-class local artifact
    coordinator, and p04-t19 explicitly listed its integration test in scope.

  - Fix: Add a receipt-bound `bind-worker-dossier` step for every applicable
    complete/partial dossier between terminal return and output validation in

    `direct-phase-coordinator.integration.test.ts`, both direct-phase skill
    contract assertions, and the relevant canonical provider view/sync checks
