## Findings

### Critical

- **C1: A non-replayed deterministic lane can complete without any provenance evidence**
  (`packages/cli/src/review/worker-dossier.ts:608`)
  - Issue: `validateWorkerDossier` validates any command/evidence records that
    are present, but never requires records appropriate to the lane's
    `strategy` and `replay` contract. Its complete-outcome check only requires
    all lane paths and primary obligations to appear in the inspected arrays.
    A plan that passes `validateReviewPlan` with a deterministic
    `strategy: "command"` lane registered in `nonReplayedLaneIds` and using
    `replay: "accept-provenance"` therefore accepts a complete dossier with
    `commands: []` and `evidence: []`.
  - Reproduction: An independent `tsx` probe built a two-lane delegated plan
    satisfying all current plan checks, then submitted an empty-evidence
    complete dossier for the command lane. The result was
    `{"planErrors":[],"dossierErrors":[]}`.
  - Impact: The primary may skip semantic replay even though the worker
    produced no independently verifiable command or inventory result. This
    violates the binding FR5 requirement that at least one delegated lane
    actually produce provenance-verifiable output and weakens FR6/FR7 at the
    worker-data boundary.
  - Fix: When a lane uses `accept-provenance`, require a non-empty evidence set
    matching its provenance strategy. A `command` lane must include at least
    one bound command-evidence record with valid scope and result digest; an
    `inventory` lane must include non-empty inventory evidence with valid
    scope/provenance. Add positive and negative tests using a plan that itself
    passes `validateReviewPlan`.
  - Requirement: FR5, FR6, FR7, NFR1

- **C2: Self-declared traces still make the operation-savings fixture tautological**
  (`packages/cli/src/review/operation-metrics.ts:168`)
  - Issue: Trace provenance is established only by comparing the caller's
    mutable `producer` string to `review-operation-recorder/v1`. The selective
    JSON fixture writes that string and its low event count by hand, and no
    production strategy/evidence executor emits or signs the trace.
    `deriveOperationMetrics` therefore accepts an empty
    `selective-inline` trace marked `complete` and reports zero broad reads,
    zero semantic replay, and an improvement over the fixed baseline.
  - Reproduction: An independent `tsx` probe supplied the expected producer
    string, 237 changed files, `strategy: "selective-inline"`, and `events: []`.
    `deriveOperationMetrics` accepted it, and `compareOperationMetrics`
    returned `improvesBroadReview: true` with 238 broad operations and 237
    semantic replays claimed as saved.
  - Impact: NFR4's P0 fixture can still pass without the selective workflow
    performing or recording any operation. Replacing aggregate counters with
    freely authored events changes the representation but does not establish
    that Phase 3 reduced actual evidence or replay operations.
  - Fix: Generate the candidate trace by executing a production-owned
    deterministic strategy/evidence harness over the fixed ChangeMap and plan,
    or bind a validated trace to immutable producer output that fixture JSON
    cannot self-assert. Enforce strategy/completion invariants, including
    rejecting a complete non-empty-scope selective trace with no evidence
    operations, and retain the broad/replay-heavy negative case.
  - Requirement: FR4, FR5, NFR4
