### Important

- **I1: A single non-terminating connection prevents broker shutdown and keeps
  the state-signing key resident indefinitely**
  (`packages/cli/src/review/validation-authority-broker.ts:184`)
  - Issue: `closeBroker` resolves only through the `server.close` callback
    (lines 184-193), and Node fires that callback only once every accepted
    connection has ended. `readSocketJson` waits on the socket `'end'` event
    with no idle or read deadline (lines 100-122) and the server is created
    with `allowHalfOpen: true` (line 183), so a connection that sends a partial
    frame and never half-closes stays open forever. Both terminal shutdown
    paths depend on that same callback: the `begin` branch awaits
    `closeBroker()` (lines 238-240) and the expiry timer calls it (lines
    261-264). I reproduced this against a real run: with one connection holding
    a partial frame, the full lifecycle still succeeded (checkpoint, validate,
    and begin all exited 0) and Node unlinked the socket path immediately, but
    the detached `oat review authority-broker` child (pid 83985) was still
    alive at 1s, 3s, and 5s after `begin` returned and exited only once I
    destroyed the squatting connection. `await broker.closed` in
    `packages/cli/src/commands/review/authority-broker.ts:55` therefore never
    returns. The consequence is that the launcher-owned process retains the raw
    HMAC signing key in memory past the run's declared expiry, and each such
    run leaks an orphaned detached process. The reviewer child is the exact
    principal this broker exists to contain and it knows the socket path,
    because the path is passed in its own command argv by `brokerCommands`
    (lines 82-98). The shutdown mechanism predates `ec894c653`, but it was
    unreachable in production until `p02-t50` made the bound lifecycle
    completable, so this is newly exposed by the task under review.
  - Fix: Track live sockets in a `Set` in
    `startPreparedValidationAuthorityBroker`. In the `'connection'` handler,
    apply a bounded read deadline with `socket.setTimeout(...)` that destroys
    the socket and rejects the pending `readSocketJson` promise. In
    `closeBroker`, after `server.close(...)`, destroy every tracked socket
    other than the one whose response is still flushing, and add an absolute
    shutdown timer that invokes `finish()` even if the callback has not fired,
    so `closed` always resolves and the child always exits. Add a regression
    test that holds an unterminated connection across `begin` and asserts the
    broker child exits within the deadline.
  - Requirement: NFR3; newly exposed by `p02-t50`.

### Medium

- **M1: The broker socket is world-connectable at a discoverable shared path**
  (`packages/cli/src/review/validation-authority-broker.ts:280`)
  - Issue: The socket path is
    `join(tmpdir(), 'oat-review-authority-<pid>-<hex>.sock')` (lines 280-283)
    and `server.listen` is called with no mode restriction and no private
    parent directory (lines 170-171 and 253-256). I confirmed with `stat` that
    the live socket is mode `0755`, and the filename is enumerable by any user
    who can list the shared temp directory, so any local user can connect to
    the launcher-owned authority broker. State integrity holds: every
    unauthenticated frame I sent was rejected with
    `validation-authority-broker-request-invalid` before any mutation, and the
    sealed state file stayed byte-identical. The residual exposure is that an
    unauthenticated local peer can probe run existence and expiry, buffer up to
    the 2 MiB `MAX_BROKER_REQUEST_BYTES` per connection, and — combined with
    I1 — pin the broker open. This predates `ec894c653` but is part of the
    trust boundary `p02-t50` completes.
  - Fix: Create a per-run directory with `mkdtemp` under `tmpdir()` (or
    `mkdir` with mode `0o700`), place the socket inside it, and remove that
    directory in `finish()`. Assert the containing directory mode in a test
    alongside the existing socket-path assertions.
  - Requirement: NFR3.
