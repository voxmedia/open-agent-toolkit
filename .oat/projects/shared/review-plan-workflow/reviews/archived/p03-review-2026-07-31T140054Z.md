## Findings

### Critical

- **C1: ReviewPlan validation accepts non-verifiable delegation and an empty or
  fabricated verification boundary**
  (`packages/cli/src/review/plan-validator.ts:330`)
  - Issue: A delegated lane qualifies as the required non-replayed
    deterministic lane solely from `evidenceClass === 'deterministic'` and
    `replay === 'accept-provenance'` (lines 330-345). Its evidence strategy may
    still be `full-file`, so it need not produce provenance-verifiable command
    or inventory evidence. `validateReviewPlan` also never validates
    `verificationBoundary` (lines 410-420): empty `requiredClaims`, a blank
    positive-sampling rationale, and fabricated `positiveCoverage.laneIds` all
    pass. Duplicate classification IDs also pass because only lane IDs are
    registered (lines 217-228), leaving classification-scoped evidence
    ambiguous. `primaryContingency.allowed` may likewise be true for an inline
    lane or an empty subset.
  - Reproduction: An independent `tsx` probe constructed a two-lane delegated
    plan whose only non-replayed lane was
    `{ evidenceClass: "deterministic", strategy: "full-file",
replay: "accept-provenance" }` and whose verification boundary was
    `{ requiredClaims: [], positiveCoverage: { laneIds: ["fabricated"],
rationale: "" } }`. `validateReviewPlan` returned `[]`. A second probe
    supplied two generated classifications with the same ID and no lanes;
    validation again returned `[]`.
  - Impact: A receipt can be issued for a plan that delegates semantic reading
    as supposedly non-replayed deterministic evidence and has no enforceable
    direct-verification or positive-sampling boundary. This defeats the P0
    FR5/FR7 safety package before evidence begins.
  - Fix: Validate unique lane and classification IDs; require the complete,
    duplicate-free direct-claim-kind set; require non-empty, existing
    positive-sampling lane IDs and rationale; and require every
    `accept-provenance`/`nonReplayedLaneIds` lane to use a structurally
    provenance-producing strategy. Reject inline or empty enabled
    contingencies. If “savings exceed cost” is intended to be mechanically
    enforced, replace the current free-text arrays with comparable structured
    estimates or explicitly narrow the contract to prose-only evidence.
  - Requirement: FR3, FR5, FR7, NFR1

- **C2: Worker dossier validation accepts malformed and unbound evidence**
  (`packages/cli/src/review/worker-dossier.ts:96`)
  - Issue: `validateWorkerDossier` never checks `schemaVersion`, does not parse
    the dossier or nested records strictly, permits commands/evidence with
    empty `scopeRefs`, and checks command evidence only for the existence of
    `commandId` (lines 187-210). It does not bind
    `commandResultDigest` to the referenced command result. Partial dossiers
    can also omit uncertainty whenever a missing path or uncovered obligation
    happens to make the first partial check false (lines 256-277).
  - Reproduction: An independent probe passed `schemaVersion: 2`, a partial
    dossier with no uncertainty, a command and command evidence with empty
    scopes, an invalid timestamp, and `commandResultDigest: "wrong"`.
    `validateWorkerDossier` returned `[]`.
  - Impact: Malformed or replayable worker output can be accepted as bounded
    dossier evidence even though its command scope and result provenance are
    not verifiable. This leaves FR6/FR7 enforcement dependent on TypeScript
    annotations at an external worker-data boundary.
  - Fix: Add a strict unknown-to-`WorkerDossierV1` parser and validate
    `schemaVersion`, exact keys, nested command/evidence records, non-empty
    in-lane scopes, timestamp/result discriminants, and canonical command-result
    digest binding. Make partial-state uncertainty and uncovered coverage
    explicit and test malformed nested input, empty scopes, digest mismatch,
    and ambiguous partial outcomes.
  - Requirement: FR6, FR7, NFR1, NFR2

- **C3: The operation-savings fixture encodes the result it claims to prove**
  (`packages/cli/src/review/__fixtures__/large-scope-selective.v1.json:7`)
  - Issue: The candidate fixture directly declares 18 broad reads and 12
    semantic replays, and the test merely feeds those aggregates to
    `compareOperationMetrics` before asserting the same numbers
    (`packages/cli/src/review/operation-metrics.test.ts:17`). No production
    plan, evidence-operation trace, or reviewer contract generates or constrains
    the candidate counts. Any smaller hand-entered values produce
    `improvesBroadReview: true`.
  - Impact: The P0 NFR4 verification can pass without the selective workflow
    reducing a single real operation. It is a tautological fixture, not
    evidence that Phase 3 changes improve the fixed large scope.
  - Fix: Record deterministic operation events from a production-owned
    strategy/evidence executor or derive counts from a validated, non-aggregate
    operation trace. Assert the resulting trace against the fixed baseline, and
    add a negative case where a broad or replay-heavy production strategy fails
    the threshold. Keep wall-clock claims excluded.
  - Requirement: FR4, FR5, NFR4
