### Important

- **Post-adoption notices ignore higher-precedence configuration layers**
  (`packages/cli/src/commands/config/index.ts:2312`)
  - Issue: Each adoption branch derives
    `terminalReviewerNoticesForMatrix()` directly from the workflow object
    written to that one surface (the same pattern appears at lines 2338 and
    2363). It never re-resolves the layered `local > shared > user`
    configuration. For example, `--user` can report the newly adopted Fable
    target even when a shared or local Opus cell is the effective target; the
    inverse can omit the advisory when a higher-precedence Fable cell wins.
    Preserving cells inside the written surface does not make that surface the
    effective post-adoption configuration.
  - Impact: Human and JSON adoption output can make a false access/retention
    disclosure or suppress the required disclosure for the target that runtime
    resolution will actually use. This violates the design's static-versus-
    effective boundary.
  - Fix: After the selected surface is written, resolve the effective layered
    configuration through the existing config-resolution path and derive
    notices from its merged provider matrix. Add shared/user/local precedence
    tests covering both a higher-precedence non-Fable override and a
    higher-precedence Fable override in human and JSON output.

- **Runtime disclosure skips supported bare Cursor Fable targets**
  (`packages/cli/src/commands/project/dispatch-ceiling/index.ts:2232`)
  - Issue: Runtime target extraction falls back to
    `selection.selectedValue` only when `provider === 'claude'`. Supported
    legacy bare provider values and bare tier-cell strings resolve with
    `selection.target === null`, so a Cursor value such as
    `claude-fable-5-thinking-high` receives no advisory even though it is the
    effective reviewer/preflight target. Candidate-ladder entries work because
    they materialize `target.model`, which leaves behavior dependent on config
    shape rather than effective target.
  - Impact: Reviewer and preflight resolutions can launch the constrained Fable
    target without the required model-access and retention-policy advisory on
    documented, still-readable configuration forms.
  - Fix: Centralize effective target extraction and use the selected Cursor
    value when no route target is present, while retaining exact Fable matching.
    Add human/JSON reviewer and preflight tests for bare provider and bare
    tier-cell Cursor Fable values, plus non-Fable controls.
