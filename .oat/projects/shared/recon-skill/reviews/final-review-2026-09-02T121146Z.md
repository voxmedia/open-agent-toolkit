### Important

- **I1: Incorporated review evidence cannot produce a valid, exactly associated packet** (`.agents/skills/recon/scripts/reconcile-ledger.mjs:112`)
  - Issue: For each review, the reconciler treats every disposition claim as affected by every `newEvidence` item, then appends a `context` link to all of them. A two-claim disposable probe linked one semantic evidence record to both claims even though the review format contains no claim/evidence association. A persisted end-to-end probe then failed final validation with `REVIEW_BRIEF_MISMATCH` and `RECONCILIATION_CONTINUITY_MISMATCH`: the final validator requires the prior claim's evidence links to remain byte-identical at `validate-packet.mjs:1276` and binds review briefs against the post-reconciliation claim. Thus p05-t05's in-memory output is not publishable and can also attach evidence to unrelated reviewed claims.
  - Fix: Add a closed, typed claim/evidence association to review results; link evidence only to the named claims; validate exact incorporated additions while preserving continuity for all other links; and bind review dispositions to the immutable pre-review claim. Add a persisted reconcile-then-`compileValidatedRun` positive control plus cross-claim, duplicate/conflicting, unincorporated, and no-new-evidence controls.
  - Requirement: Phase 5 p05-t05; discovery canonical evidence ledger and exact provenance contract.

- **I2: Packet validation accepts completion before launch acceptance** (`.agents/skills/recon/scripts/validate-packet.mjs:727`)
  - Issue: Stage validation parses and orders approval, catalog recheck, and acceptance timestamps, but never reads the completed receipt's `terminalOutcome.completedAt`. The artifact schema only checks that this timestamp is parseable. A disposable packet whose completed receipt was rebound with `completedAt` one second before `acceptedAt` still validated and remained publishable, contradicting the prepared -> approved -> accepted -> completed receipt state machine.
  - Fix: Parse the completed receipt's terminal timestamp and enforce the full causal boundary through `acceptedAt <= completedAt` (and any already-declared earlier timestamp relations) before a stage can count as complete. Add direct negative controls for completion before acceptance and a valid equal/after boundary according to the chosen precision contract.
  - Requirement: Design ValidatedRun receipt topology and Revision 2 terminal receipt-chain binding.

- **I3: Atomic promotion is not bound to the bytes that were rendered and hashed** (`.agents/skills/recon/scripts/render-packet.mjs:217`)
  - Issue: The renderer hashes the temporary pathname and then renames that pathname without retaining or rechecking the temporary file's identity. A disposable promotion probe replaced the temporary path between those operations; rendering returned success while `packet.md` contained the replacement bytes and its digest differed from the returned digest. Root identity checks do not bind the temporary file itself, so the consumer entry point can diverge from the validated run under concurrent replacement.
  - Fix: Create an unpredictable exclusive temporary file, retain its identity through write/hash/promotion, and verify the promoted target is the same rendered object with the returned digest before reporting success. Fail without replacing the last-known-good packet if identity changes. Add a concurrent-replacement negative control and a normal atomic replacement control.
  - Requirement: Design deterministic rendering from immutable ValidatedRun and atomic publication of validated bytes.
