  (`.agents/skills/recon/scripts/reconcile-ledger.mjs:284-291`,

    `claim.status === 'verified'` (line 284). A revision-one `provisional`
    claim (the state `compile` emits per `worker-contract.md:29` and
    `packet-contract.md:173,181-185`) with semantic `affirmed`, adversarial
    `unchallenged`, and coverage `gap` takes none of the earlier branches

    `verified`-only downgrade, and hits `if (!coreComplete) continue;` (line 291) with no transition recorded. The trailing
    `validateArtifactShape(ledger)` then rejects the revision-2 ledger because
    a later-revision `provisional` claim requires a legal incoming transition
    (`contracts.mjs:1303-1315`), and `reconcileLedger` throws for the entire
    run. This is the same failure mode as remote finding I1 (converted to
    `p06-t01`) and the p06 round-1 Important, for the one remaining disposition
    combination. It also violates `packet-contract.md:237-238` ("Accepted
    material gaps require a legal downgrade for every affected claim"): with a
    material coverage finding the contract demands a downgrade and the
    reconciler instead aborts. Direct probes at HEAD on the standard fixture
    with `claim-1` set to `provisional` and the coverage disposition set to
    `gap`: without a material finding →
    `Reconciliation rejects schema-invalid review evidence: INVALID_PROVISIONAL_GENESIS`;
    with a material `coverageFindings` entry bound to `claim-1` → same throw.
    Controls on the same probe: all-affirmed → `provisional:verified`;
    semantic `uncertain` → `provisional:unresolved`; prior `supported` + `gap`
    → stays `supported` (the shipped test case). The shipped test
    "production reconciliation never verifies a claim with a coverage gap
    disposition" (`integrity-contracts.test.mjs:885-912`) only exercises the
    fixture's `supported` prior, so it cannot fail on this path.
  - Fix: Drop the `verified`-only guard and apply the coverage-gap downgrade
    to any claim whose core review is otherwise complete but coverage is
    `gap`, using the existing legality check — for example replace lines
    284-291 with: when `coverageGap && !coreComplete`, set
    `to = materialCoverageGap ? 'contested' : 'unresolved'` and transition
    only if `legalReconciliationTransitions.has(\`${from}:${to}\`)`
(`provisional:contested`, `provisional:unresolved`, `supported:_`, and
`verified:_`are all already legal;`contested`/`unresolved`priors
remain unchanged). Decide explicitly whether a`supported`prior should
also downgrade under a gap and update the`supported`test expectation
accordingly, or keep`supported`exempt and say so in`packet-contract.md`. Add two negative controls modeled on the existing
"transitions uncertain and incomplete provisional claims" test:
`provisional`+ coverage`gap`(no material finding) →`unresolved`and
compiles as a valid`partial`; `provisional`+ material coverage finding
→`contested` and compiles valid. Confirm each test fails against the
    current line 284 before the fix.
  - Requirement: remote I1 / `p06-t01` intent ("publish an honest
