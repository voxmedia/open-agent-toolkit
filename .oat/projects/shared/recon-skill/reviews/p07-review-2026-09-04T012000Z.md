  schema** (`.agents/skills/recon/scripts/lib/contracts.mjs:1631`)

    but never requires each `claims[*].evidence[*].sourceId` to resolve to
    exactly one entry in `brief.sources`. A generated valid verification brief
    remains valid under both `validateReviewBrief` and `validateArtifactShape`
    after replacing `sources` with `[]`. This means the stage-level artifact
    validator can accept and persist a verification brief that does not give the
    verifier the source descriptor needed to reopen evidence; whole-packet
    binding catches the mismatch only later.

    (`.agents/skills/recon/scripts/lib/contracts.mjs:1503`). An empty object is
    accepted, as are incomplete nested capture pairs, despite the contract
    requiring reopenable URL provenance.
  - Fix: in `validateReviewBriefArtifact`, reject duplicate source IDs and
    require every projected evidence `sourceId` to resolve to exactly one
    `brief.sources` entry. In `validateReviewBriefSource`, require a URL source
    to provide either a complete direct capture pair or a non-empty valid
    validator state; validate nested capture pairs and digests and preserve the
    existing exclusive representation rule. Add direct negative controls for
    `sources: []`, unknown/duplicate source IDs, empty validator state, and
    half-specified nested captures.
