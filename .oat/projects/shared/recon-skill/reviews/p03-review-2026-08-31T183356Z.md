### Important

- **Update-all converts a transitive utility lease into direct pack intent** (`packages/cli/src/commands/tools/update/update-tools.ts:162`)
  - Issue: pack-wide update eligibility uses `hasScopedPackPlacementEvidence(before)`. A utility pack installed only because research leases its two dispatch skills therefore becomes an explicit root `update` request. A production-function probe installed only research at user scope and then called `updateTools({ kind: 'all' })`. Before update, utility was `direct: false`, `requiredBy: [research]`, `completeness: partial`, with only the two selected dependency assets present. After update, utility was `direct: true`, `completeness: complete`, and all 10 utility skills were installed. This silently changes user intent and defeats the design's direct-versus-transitive distinction.
  - Fix: select root pack updates from direct intent (plus a narrowly defined legacy full-pack footprint), not from any placement evidence. Let installed direct consumers drive updates of their selected dependencies without creating direct dependency-pack intent. Add a regression test for `update --all` after a research-only install.
  - Requirement: `p03-t01`, `p03-t02`; direct pack intent must remain distinct from `requiredBy` dependency leases.

- **A batch that releases the last two leases leaves orphaned dependency files** (`packages/cli/src/commands/tools/shared/pack-lifecycle.ts:96`)
  - Issue: `reconcilePackLifecycles` plans every expanded request concurrently from the same pre-apply inventory. Each release computes `retainedConsumers` independently at lines 116-132, so two releases for the same dependency owner each see the other consumer and retain the selected assets. A production-function probe used two consumers (`research` and synthetic `brainstorm`) that both leased the utility dispatch skills, then removed both consumers in one batch. Before removal the lease set was `[brainstorm, research]` and both files existed; afterward the lease set was empty but both files still existed and utility inventoried as `legacy-inferred` rather than absent.
  - Fix: coalesce same-owner/scope/root lease transitions and plan against the final post-batch lease set, or re-inventory/re-plan dependency releases after preceding releases. When the final lease is released and there is no direct intent, remove the selected dependency assets. Add a two-consumer batch-removal regression test that asserts empty leases, absent files, and absent inventory.
  - Requirement: `p03-t01`, `p03-t02`; same-scope selected-asset ownership and safe remove semantics.

- **Migration can clear the source root before dependency release fails, making its retry instruction invalid** (`packages/cli/src/commands/tools/migrate/migrate-pack.ts:509`)
  - Issue: source removal is applied first, then `releaseDependencies` runs at line 520. If dependency release fails after root removal, the catch reports `source-removal-failed` and recommends rerunning migration at line 599, but the source pack no longer has direct intent or root assets. A production-function probe injected failure at that boundary after a real project-to-user research migration. The source research inventory became absent while source utility retained `requiredBy: [research]` and both dependency files; calling `planPackMigration` again failed with `Pack research is not installed at project scope`. Destination acquisition correctly occurred first, but source cleanup was not recoverable as promised.
  - Fix: preserve destination-before-source ordering while committing source root removal and dependency release as one recoverable transition. Either retain source direct intent/root state until dependency release succeeds, or persist enough migration state for an idempotent cleanup retry that does not require the source pack to remain installed. Add a failure-injection regression test at this exact boundary and assert that the returned recovery command succeeds.
  - Requirement: `p03-t02`; migration must acquire destination leases before source release and remain safely recoverable on partial failure.
