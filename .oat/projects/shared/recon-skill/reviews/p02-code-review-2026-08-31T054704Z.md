## Findings

### Critical

- **Verified claims do not require validated review artifacts** (`.agents/skills/recon/scripts/validate-packet.mjs:416`)
  - Issue: `deriveAchievedProfile` trusts inline manifest entries whose only relevant facts are `mode` and `status`, and `validateAssurance` treats any three strings in `claim.reviewIds` as independent review evidence (`.agents/skills/recon/scripts/validate-packet.mjs:464`). No code resolves those IDs to hashed `recon.review-result` artifacts, verifies semantic/adversarial/coverage kinds, binds each result to an immutable brief digest, or confirms reconciliation from the reviewed ledger revision. The generic artifact validator compounds this by applying a real schema only to manifests, ledgers, and dossiers; review briefs, review results, stage results, and dispatch receipts receive only kind/version checks (`.agents/skills/recon/scripts/lib/contracts.mjs:340`). A direct probe changed a standard claim's review IDs to `made-up-1`, `made-up-2`, and `made-up-3`; `validatePacket` returned `valid: true`. Another probe removed the required `synthesis` object; validation still returned true, rendering crashed before its cleanup block, and the prior `packet.md` remained published. This defeats the central assurance and structural-publication contracts.
  - Fix: implement closed versioned schemas for every declared artifact kind; validate stage-result fields and hashed artifact membership; require each `reviewId` to resolve to a complete, correctly typed review result whose brief digest and claim disposition match; validate reconciliation input/output revisions and transitions; and encompass document construction in stale-packet cleanup. Add negative tests for nonexistent, duplicated, wrong-kind, wrong-brief, failed, and tampered reviews plus missing canonical ledger sections.

- **Locator reopening can certify stale evidence and a different file than the published locator names** (`.agents/skills/recon/scripts/validate-packet.mjs:246`)
  - Issue: the file-source branch always opens `source.path` and never compares it with `locator.path`. Separately, `reopenEvidence` gives special handling only to `redacted-exact`; evidence declared `stale` or `invalid` proceeds through normal matching and is returned as valid, after which it is inserted into `exactEvidence` (`.agents/skills/recon/scripts/validate-packet.mjs:594`). Direct probes showed both a quick supported claim with `locatorValidation.status = "stale"` and a file locator changed to `/definitely/not/the/source.txt` validate with no errors. The resulting packet can therefore display a false exact locator or rely on evidence its own ledger marks unusable.
  - Fix: reject source/locator identity mismatches for every discriminator; require eligible evidence to be declared `exact` or valid `redacted-exact`; make `stale` and `invalid` categorically ineligible for supported/verified claims; validate timestamps/version tokens where the locator contract carries them; and add negative cases for every locator state and source-kind identity field.

### Important

- **Packet containment is lexical and follows symlink escapes** (`.agents/skills/recon/scripts/validate-packet.mjs:43`)
  - Issue: `containsPath` checks only `path.relative` on unresolved filesystem identities. Artifact hashing and source capture reopening subsequently follow symlinks. A direct probe added `raw/outside-link` as a symlink to a file outside the packet, referenced its correct digest from the manifest, and received `valid: true`. The same pattern affects packet capture paths and repository locator paths, so contract-enforced workers can escape the declared read boundary despite the managed-path claim.
  - Fix: reject symlinks for managed packet artifacts and source paths or compare `realpath` identities against a trusted real root before every read/write/hash; validate parent directories for not-yet-created outputs; and add lexical traversal plus final-component and ancestor-symlink tests.

- **Material coverage gaps cannot produce the designed honest-partial outcome** (`.agents/skills/recon/scripts/validate-packet.mjs:516`)
  - Issue: the validator rejects every `partial` packet whose achieved profile equals the requested profile, while the design explicitly permits partial status when the pass topology completes but material coverage gaps remain. Conversely, `complete` checks only profile equality and never inspects gap materiality. A direct probe with a standard achieved profile and an explicit material coverage gap failed only with `INVALID_PARTIAL_STATUS`.
  - Fix: define and validate gap materiality in the v1 schema, derive publication status from both pass completion and material gaps, accept same-profile partial packets when a material gap remains, and reject `complete` when one exists.

- **The fake end-to-end runner does not exercise the review and reconciliation pipeline it claims to prove** (`.agents/skills/recon/tests/helpers/fake-recon-run.mjs:203`)
  - Issue: standard/thorough runs create verification and adversarial briefs, then write one minimal reconciliation-shaped object. They never create semantic, adversarial, or coverage review results, never feed dispositions into reconciliation, and never derive a new ledger from a provisional predecessor. The imported fixture already contains a `verified` claim and three review-ID strings before the runner starts, yet `workflow.integration.test.mjs:31` calls this the complete deterministic pipeline. This is why the fabricated-review defect passes all workflow scenarios.
  - Fix: make the runner emit and validate every required review result, bind each to the exact brief digest, reconcile a prior provisional/supported ledger into a new revision, and derive stage completion only from those artifacts. Add tamper and missing-result cases that must prevent `verified` publication.

### Medium

- **Contracted locator variants are not actually reopenable** (`.agents/skills/recon/scripts/validate-packet.mjs:164`)
  - Issue: URL sources with an explicit `validatorState` satisfy `sourceHasMinimumProvenance`, but reopening unconditionally reads `source.capturePath` (`.agents/skills/recon/scripts/validate-packet.mjs:257`), so the documented validator-state alternative always fails as `SOURCE_UNAVAILABLE`.   - Fix: either implement deterministic validation for the advertised validator-state branch and whole-file locator form, or remove those variants from the v1 contract and schema. Add positive and drift tests for every retained provenance alternative.
