- **M1: Incorporated review evidence produces a ledger that the final validator rejects** (`.agents/skills/recon/scripts/reconcile-ledger.mjs:142`)
  - Issue: The reconciler appends each review's `newEvidence` and adds a new
    evidence link to every claim named by that review's dispositions. Final
    packet validation still requires every prior claim's `evidence` array to
    remain byte-identical (`.agents/skills/recon/scripts/validate-packet.mjs:1276`),
    and semantic review binding also compares the immutable pre-review brief to
    the current claim evidence. A direct persisted-packet probe therefore
    rejected the p05-t05 output with
    `RECONCILIATION_CONTINUITY_MISMATCH` and `REVIEW_BRIEF_MISMATCH`. The new
    unit test stops after inspecting the in-memory reconciler result
    (`.agents/skills/recon/tests/integrity-contracts.test.mjs:870`) and never
    runs the required final packet boundary, so its green result masks the
    runtime failure. In addition, `newEvidence` has no claim-specific binding;
    using all dispositions as the affected set can attach one evidence record
    to unrelated claims in a multi-claim review.
  - Fix: Add an explicit typed claim/evidence association to review results (or
    another equally exact binding), have reconciliation add links only for
    those claims, and teach final validation to permit exactly those
    incorporated additions while preserving byte continuity for every other
    link. Add an end-to-end persisted packet test that runs `validatePacket`
    after reconciliation, plus negative controls for cross-claim evidence
    smuggling, duplicate/conflicting IDs, unincorporated evidence, and a valid
    no-new-evidence control.
  - Requirement: Remote finding M5 / task p05-t05.

- **M2: The documented controller prevalidation still deletes the packet that p05-t02 intends to preserve** (`.agents/skills/recon/SKILL.md:198`)
  - Issue: p05-t02 changes `renderPacket` to compile with
    `removePublishedOnFailure: false`, so direct renderer validation and
    promotion failures preserve the prior file. The controller contract,
    however, first runs `scripts/validate-packet.mjs` as a separate command;
    that validator defaults to removing `packet.md` on failure
    (`.agents/skills/recon/scripts/validate-packet.mjs:2114`). A direct probe of
    the documented sequence returned `valid: false` and
    `packetExistsAfterDocumentedPrevalidation: false`. Thus the new renderer
    test covers a helper-only route that the actual workflow does not reach
    when prevalidation fails. The shipped packet contract also still says
    structural failure removes a stale packet, while the new renderer test
    requires preservation, leaving publication semantics contradictory.
  - Fix: Choose one authoritative validation/publication entry point and one
    explicit last-known-good policy. If preservation is intended, make the
    controller's prevalidation non-destructive (or remove the duplicate
    prevalidation), distinguish an old validated snapshot from a current
    candidate, and align `packet-contract.md` and `design.md`. Add an
    end-to-end test that executes the same validate-then-render sequence the
    skill instructs. If structural failure must instead withdraw the old
    entry point, narrow p05-t02 to promotion/render-construction failures and
    remove the contradictory validation-preservation assertion.
  - Requirement: Remote finding M2 / task p05-t02.
