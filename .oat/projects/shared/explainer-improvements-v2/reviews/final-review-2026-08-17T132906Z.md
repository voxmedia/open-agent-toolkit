### `publicRootPolicy` contract judgment (item 11)

Verdict: **the addition is correct and I would ship it.**

- **Additivity.** `publish-receipt.v2.schema.json` is `additionalProperties: false`
  at the root, so declaring the field was required. It is added to `properties`
  and deliberately not to `required`, and `publish-receipt/v2` is unreleased on
  this branch. Both presence and absence validate.
- **Emission condition.** `s3-static.mjs:331-334` emits only when
  `privatePublicRootAllowed() && isPrivatePublicHost(new URL(roots.publicBaseUrl).hostname)`.
  That is exactly "the anti-SSRF control was disabled _and_ actually bypassed."
  Opt-in set with a routable root emits nothing (nothing was bypassed); opt-in
  unset with an internal root cannot publish at all
  (`s3-roots.mjs:133-137` throws). `new URL(...)` is inside the short circuit, so
  it is not evaluated on the ordinary path, and `isPrivatePublicHost` handles the
  bracketed IPv6 form WHATWG `hostname` returns (`s3-roots.mjs:258-260`) — the
  same function and spelling the rejection path uses.
- **Ordinary receipts are byte-identical.** Spreading `false` contributes
  nothing, so no key, no ordering change, no hash change. The new test asserts
  `'publicRootPolicy' in receipt === false` for both the opt-in-set-but-routable
  case and the opt-in-unset case.
- **Durability tolerates both.** `verifyPublishEvidence` validates the receipt
  through the same `validateContract('publish-receipt', …)` the connector uses at
  `s3-static.mjs:344`, and the connector throws `E_PUBLISH_VERIFY` on an invalid
  receipt — so the passing test at `s3-static.test.mjs:282-320` is itself proof
  the field schema-validates. Nothing else in the pipeline enumerates receipt
  keys, and the catalog does not carry the field, so no hash is disturbed.
- **Prose matches.** `configuration.md:200-207` describes the field, its
  condition, and the address-literal limitation, all of which hold.

One observation, not a finding: the new test exercises `publicAccess: 'protected'`
with `httpGet: unexpectedHttp`, so the field's emission is proven but the actual
SSRF-shaped path (`public` access plus an internal root plus the opt-in, which
does issue the outbound GET) is not exercised. The emission logic is independent
of `publicAccess`, so this is a coverage nicety rather than a gap.

### Item-13 refutation

merge base and diff head both pinned to that commit returns
