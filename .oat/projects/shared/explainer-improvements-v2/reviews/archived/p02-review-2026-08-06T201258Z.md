## Findings

### Critical

- **Visual corrections are not revalidated before durability** (`.agents/skills/explainer-kit/scripts/run.mjs:521`)
  - Issue: Initial output and internal-reference corrections run through
    `enforceInternalReferenceGate`, but the existing visual-correction branch
    calls `applyVisualCorrection` and proceeds directly to `auditArtifactSet`
    and a second visual review. A focused execution proved that a correction
    introducing `../../missing/index.html` returned `built-not-durable`,
    completed both visual reviews, and invoked durability once. This violates
    the hard-link invariant and the design requirement that every correction
    rerender, revalidate, and re-review.
  - Fix: After `applyVisualCorrection`, run a validation-only reference pass
    before browser/visual review. Because the single correction is already
    consumed, failure must produce `E_INTERNAL_REFERENCE` without invoking
    another correction, critic, durability, or publish callback. Add an
    integration test whose visual correction introduces a missing target.
  - Requirement: p02-t02 hard validation and Design Safety Invariants.

### Important

- **Unused duplicate IDs break supported Markdown diagram output** (`.agents/skills/explainer-kit/scripts/lib/internal-references.mjs:90`)
  - Issue: The validator rejects every repeated `id` while indexing the
    document, even when no fragment references that ID. Two unchanged
    `e2e-recap.test.mjs` cases now fail with
    `E_INTERNAL_REFERENCE/malformed-fragment-target` because repeated Markdown
    diagrams emit repeated inline SVG IDs. These are the two p02-caused
    failures in the broad suite; they are distinct from the 27 pre-existing
    `E_BROWSER_PROBE` failures.
  - Fix: Track ID counts and reject a fragment target only when its referenced
    ID is missing or ambiguous, or namespace renderer-generated SVG IDs per
    diagram. Add a regression covering multiple valid diagram blocks plus
    fragments that target unique and duplicate IDs.
