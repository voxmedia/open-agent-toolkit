### Important

- **The implement profile passes without any phase-review artifacts or passed phase-review rows** (`tools/smoke/evidence/assertions.mjs:471`)
  - Issue: `implementAssertions` sets `requiredReviewScopes` to only `final`.
    It checks that one reviewer dispatch completed per phase, but never binds
    the `p01`, `p02`, and `p03` review artifacts and passed Reviews rows that
    the collector already gathers. As a targeted read-only check, removing all
    three phase-review rows and artifacts from the retained implement bundle
    still produced `9/9` passing assertions. A child process completing is not
    proof that a scoped review artifact exists or passed. This falls short of
    `discovery.md:203-207` and `design.md:79-82`.
  - Fix: Add an implement assertion that, for every expected phase, correlates
    exactly one direct-root reviewer dispatch with a review artifact whose
    scope/type/invocation are correct and a Reviews row whose status and path
    match that artifact. Bind the artifact to committed fixture history (and
    add launcher request linkage if needed for unambiguous correlation). Add
    negative tests that independently remove a row, artifact, passed status,
    or phase scope.

- **The real recovery collector rejects the failed drive state for which it is invoked** (`tools/smoke/runner/drive.mjs:564`)
  - Issue: `run-smoke.mjs:305-323` deliberately invokes collection recovery
    after a drive failure, but the default `collectSmoke` accepts only
    `awaiting-operator` or `completed`. A direct call with a failed drive
    returns `Smoke evidence collection requires a completed drive.` before it
    reads any partial evidence. If that guard is relaxed, the same function
    also throws on a failed assertion at `tools/smoke/runner/drive.mjs:593`;
    normal cleanup then removes the run-local staging directory. The mocked
    lifecycle test therefore proves call ordering, not the real integration.
    This contradicts `design.md:93-98`, `design.md:180-184`, and
    `design.md:299-301`.
  - Fix: Give recovery collection an explicit failed/interrupted mode, collect
    and evaluate all available evidence, and preserve a diagnosable failed-run
    result without publishing it as canonical acceptance evidence. Ensure the
    thrown run error retains the result even when owned worktrees are cleaned.
    Add an integration test that uses the real collector after a failed drive
    and verifies both partial evidence and safe cleanup.

- **Preflight ignores the independent gate runtime when deciding readiness** (`tools/smoke/runner/preflight.mjs:462`)
  - Issue: installation is observed for all harnesses, but authentication is
    run only for the selected drive harness, and `isReady` at
    `tools/smoke/runner/preflight.mjs:392-399` checks only that harness. For
    example, a Codex run with a Cursor gate and an unavailable `cursor-cli`
    runtime still returns `status: "ready"` as long as the Cursor key is
    nonempty. The reciprocal Codex-gate paths have the same gap. This permits
    provisioning and provider work before discovering that the required
    independent gate cannot run, contrary to the fail-fast readiness contract
    in `design.md:72-78`.
  - Fix: Derive the required runtime set from both the selected harness and
    `gateRuntime`; require installation and authentication/credential
    readiness for each distinct runtime, and verify the configured target's
    availability without launching a gate. Add deterministic tests for Codex
    plus missing Cursor, and Claude/Cursor plus missing Codex.
