### Important

- **Provider-sync recovery commands lose the resolved project context**
  (`packages/cli/src/commands/tools/migrate/migrate-pack.ts:352`)
  - Issue: `pendingSyncState()` emits `oat sync --scope ...` and
    `migrationRetry()` emits `oat tools migrate ...` without the resolved cwd or
    scope root. The production adapter deliberately runs the initial sync with
    `--cwd context.cwd`, so `oat --cwd /repo tools migrate ...` is a supported
    invocation even when the caller's shell is outside the repository. If
    source provider sync then fails after canonical files and source intent
    were removed, copying the emitted recovery command resolves project scope
    from the unrelated shell cwd; the migration retry cannot rediscover the
    removed source either. The new typed state is therefore not convergent for
    this supported path.
  - Fix: Carry the resolved project root/cwd into `MigrationPendingSync` and
    every migration retry instruction. Emit a safely escaped command such as
    `oat --cwd <resolved-project-root> sync --scope project ...` whenever the
    affected scope is project (and preserve equivalent context for the
    migration retry). Add destination- and source-sync failure tests invoked
    with global `--cwd` while the process cwd is a different directory, then
    execute the returned command and verify provider convergence without
    repeating canonical removal.
  - Requirement: FR5, FR8, NFR4

### Medium

- **Blocked destination assets are simultaneously classified as additions and conflicts**
  (`packages/cli/src/commands/tools/migrate/migrate-pack.ts:183`)
  - Issue: `additionIds` is derived from every destination reconcile operation
    before newer-asset conflicts are excluded. A newer destination asset
    therefore appears once under `additions` with `destination-reconcile` and
    again under `conflicts` with `newer-destination-asset`. Execution remains
    blocked, but human counts and machine-readable preview categories disagree
    about whether the asset is an executable addition or an unresolved
    conflict.
  - Fix: Exclude conflict asset IDs from `additions` (or build mutually
    exclusive preview categories before composing the blocked plan). Extend
    the human and JSON tests to assert that a newer asset appears only in
    `conflicts` and that blocked previews contain no executable addition for
    that asset.
  - Requirement: FR8, NFR4
