### Critical

- **Manifest-driven pack removal bypasses managed-root containment before deletion** (`packages/cli/src/commands/tools/remove/remove-tools.ts:113`)
  - Issue: `removeManagedPackAssets()` constructs each selected destination and
    passes it directly to recursive file/directory deletion at lines 138-143.
    It never resolves the scope's managed roots or calls the existing
    `validateManagedPath()` containment guard
    (`packages/cli/src/fs/paths.ts:149`). An isolated test against the current
    head demonstrated that a linked path within the managed tree can cause a
    manifest-selected target outside the selected root to be deleted. This can
    remove unowned data and violates NFR1's requirement that destructive
    operations fail closed when a path escapes the selected scope.
  - Fix: Resolve the managed roots once per selected scope and validate every
    deletion target with the existing managed-root/path validator before any
    mutation. Delete and verify only the validated contained target, abort
    before clearing intent on validation failure, and add a safe regression
    test proving an outside sentinel remains unchanged when a managed path is
    linked outside its root.
  - Requirement: NFR1, FR2, FR5
