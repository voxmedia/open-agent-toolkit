## Findings

### Critical

- **The shared reconcile planner and safety executor are dead production abstractions** (`packages/cli/src/commands/tools/shared/apply-pack-reconcile.ts:97`)
  - Issue: A repository-wide non-test search finds `planPackReconcile()` only at
    its definition in `pack-reconcile.ts:133` and `applyPackReconcilePlan()` only
    at this definition. Production install still invokes pack-specific
    installers (`commands/init/tools/index.ts:1003-1238`), update copies paths
    directly (`commands/tools/update/update-tools.ts:230-283`), aggregate scope
    removal deletes paths directly (`commands/init/tools/index.ts:470-487`), and
    `tools remove` has a separate planner/executor. Consequently the production
    paths do not receive the executor's all-target containment preflight,
    post-apply completeness check, intent-after-verification ordering, or exact
    changed-path sync. This is security-relevant for install/update because the
    copy helpers recursively remove and copy destinations without calling the
    managed-root validator (`commands/init/tools/shared/copy-helpers.ts:58-70`,
    `86-95`, `112-121`), so a nested managed-path symlink can redirect writes
    outside the resolved managed root.
  - Fix: Introduce one production lifecycle adapter that inventories, calls
    `planPackReconcile()`, and sends the resulting plan to
    `applyPackReconcilePlan()`. Route aggregate/direct install and pack update
    through it; either route pack removal through it or prove its bounded
    removal adapter preserves every identical safety boundary. Add production
    call-path tests, including nested-symlink rejection before any write and an
    assertion that every filesystem target is validated before mutation.
  - Requirement: FR5, NFR1, NFR2

- **Successful installs can be partial and never record user-scoped pack intent** (`packages/cli/src/commands/init/tools/docs/install-docs.ts:50`)
  - Issue: The canonical docs pack owns two managed user-scope template
    directories (`commands/tools/shared/pack-manifest.ts:197-213`), but the docs
    installer copies only caller-selected skills and the shared script
    (`install-docs.ts:50-93`). Its direct command still exposes per-skill
    selection (`commands/init/tools/docs/index.ts:114-124`); utility and research
    expose the same partial-pack product (`utility/index.ts:129-149`,
    `research/index.ts:118-128`). Aggregate install calls these same installers,
    so a reported-success docs install is immediately partial by canonical
    inventory. Separately, the only production caller of
    `writeScopedPackIntent()` is removal (`commands/tools/remove/index.ts:142`):
    project installs rely on the legacy any-member reconciliation adapter and
    user installs write no intent at all. A fully deleted user install therefore
    loses the evidence required for update repair.
  - Fix: Remove per-member pack selection from pack install commands, materialize
    every applicable manifest-managed asset, inventory to `complete`, then write
    scoped intent. Preserve legacy single-tool operations only as explicitly
    non-pack operations. Add direct and aggregate tests proving every pack is
    complete and declared at project/user/both scope immediately after success,
    including docs directory assets and complete PJM selection.
  - Requirement: FR2, FR3, FR5

- **Aggregate install still performs an unsafe, destructive scope migration** (`packages/cli/src/commands/init/tools/index.ts:934`)
  - Issue: Interactive scope selection is treated as a desired end state and
    stages removals from an existing scope (`index.ts:619-631`, `934-995`). After
    pack-specific installers return, the command deletes the source assets
    (`index.ts:1241-1245`) without re-inventorying the destination or verifying
    canonical completeness. This contradicts the Phase 2 additive-install
    boundary and can delete a complete source after the incomplete docs install
    described above. The confirmation does not supply the required destination
    verification or recovery boundary. In addition, a fresh no-scope install
    outside Git still fails before applying user defaults because project-root
    failure is ignored only for an explicit user scope (`index.ts:844-849`).
  - Fix: Make every install path additive and remove all scope-deletion behavior
    from aggregate install. Preserve existing placement from inventory/intent,
    allow explicit scope only to add placement, and leave narrowing exclusively
    to the Phase 3 migration transaction. Resolve default user installs outside
    Git without requiring a project root.
  - Requirement: FR1, FR5, NFR1

- **Pack update is not a complete or dry-run-equivalent manifest reconciliation** (`packages/cli/src/commands/tools/update/update-tools.ts:77`)
  - Issue: Update rebuilds a local asset split containing only `template` and
    `script` kinds (`update-tools.ts:77-97`), handles skills/agents through a
    separate synthesized `ToolInfo` path, and refreshes core docs through a
    command-level special case that is skipped in dry-run
    (`commands/tools/update/index.ts:162-173`). Managed `directory` assets such
    as the docs pack's user template directories are never updated or restored;
    the returned dry-run plan therefore cannot represent the changes apply will
    make. The command also never adopts inferred user intent, despite p02-t07's
    explicit requirement to persist inferred intent after successful mutation.
  - Fix: Delete the parallel asset split and route pack/all updates through the
    canonical planner/executor. Serialize the exact plan for dry-run, cover every
    asset kind and ownership policy, verify complete post-state, and persist
    inferred intent only after successful verification. Add a real-filesystem
    regression where docs directories and all other managed assets are absent
    but intent remains.
  - Requirement: FR2, FR3, FR5, NFR2

- **Default `has core` and `outdated` commands fail on core's disallowed project scope** (`packages/cli/src/commands/tools/outdated/outdated-tools.ts:61`)
  - Issue: Command context defaults to scope `all`, which expands to project and
    user (`app/command-context.ts:44`, `commands/shared/shared.utils.ts:9-13`).
    `outdated` iterates every manifest pack for every selected scope and calls
    `inventoryScopedPack()` without checking `allowedScopes`
    (`outdated-tools.ts:49-64`), while `has` does the same for the requested pack
    (`commands/tools/has/has-pack.ts:60-68`). Core allows only user scope, and
    inventory rejects core/project (`commands/tools/shared/pack-inventory.ts:207-210`).
    Thus the normal default `oat tools outdated` and `oat tools has core` paths
    error even in a valid Git repository. The 554-test phase suite stays green
    because it does not exercise the real allowed-scope guard through these
    default command paths.
  - Fix: Filter each pack's inspected scopes by its manifest `allowedScopes`;
    represent an explicitly requested disallowed scope as unavailable rather
    than throwing, and add command-level tests using the real inventory contract
    with default `all` scope.
  - Requirement: FR1, FR4, FR5, NFR3

    observations as diagnostics. Add remove-then-inventory tests for each shared
    owner ordering.
