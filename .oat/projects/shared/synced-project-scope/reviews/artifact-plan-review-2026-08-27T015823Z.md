## Findings

### Critical

- **PR creation never establishes the synced-ref state required for current and refreshable links** (`.oat/projects/shared/synced-project-scope/plan.md:1504`)
  - Issue: p04-t05 only inserts `oat project links` into `oat-project-pr-final` and `oat-project-pr-progress`. It does not push newly generated or moved artifacts before rendering links, persist progress-PR status/URL, or push the post-creation state update. `oat project links` reads the project ref, so a summary generated by final-PR preparation can be omitted as stale; progress PRs never establish the `oat_pr_status: open` / `oat_pr_url` state that p03-t03 requires for later push-time refresh; and final-PR state remains local until some unrelated later bookkeeping push. This leaves the P0 FR7 refresh contract incomplete.
  - Fix: Make the synced branches of both PR skills explicit state machines: push pending artifacts before rendering the initial links block; create the PR; persist the open PR status and URL (adding this behavior to progress PR); then push that state so the ref contains the authoritative PR metadata and the push path refreshes the block to the new ref SHA. Add behavioral verification for a newly generated summary and for a progress PR followed by another artifact push.
  - Requirement: FR7

### Important

- **Prune removes only the current nested checkout in a multi-worktree project** (`.oat/projects/shared/synced-project-scope/plan.md:1130`)
  - Issue: p01-t08 deliberately supports one detached project checkout per repository worktree, but p03-t05 calls `removeSyncedCheckout(t)` for only the current `projectPath` before deleting the project ref and record. Any checkout materialized in another linked worktree remains on disk and registered after the project is supposedly pruned; if it is dirty, the command neither protects nor reports it. The p03-t10 dogfood sequence creates exactly this state and then deletes the ref from the primary worktree.
  - Fix: Define and test project-wide prune semantics across all registered checkouts for the slug. Preflight every checkout for dirty/unpushed state, refuse without `--force` when any cannot be safely removed, remove/prune all registrations before deleting the remote/local ref and record, and add a two-parent-worktree integration case. If prune is intentionally current-checkout-only, align FR11 and the command contract instead of reporting project-wide removal.
  - Requirement: FR11

- **Migration rollback still cannot undo failures after the parent commit succeeds** (`.oat/projects/shared/synced-project-scope/plan.md:1166`)
  - Issue: The revised failure test says `commitRecordChange` throws and restores paths with scoped `git reset`/`checkout`, but it does not cover a throw after that helper has created the branch commit or a failure while retargeting `activeProject` in the next step. Those scoped path commands do not move branch HEAD back, so the migration commit can remain while the workflow claims full rollback and retryability. The rollback list also omits a self-healed `.gitignore`, allowing the missing-rule path to remain dirty after failure.
  - Fix: Capture the pre-migration branch HEAD and define rollback for every post-commit failure that restores HEAD and the exact allowlisted paths without disturbing unrelated staged or working-tree changes, including `.gitignore` when self-healed. Add failure injection after the parent commit and during active-project retargeting, then prove the original HEAD/index/worktree state is restored and a retry succeeds.
  - Requirement: FR12, NFR4

### Medium

- **Dogfood cleanup asserts that the entire retained-ref namespace is empty** (`.oat/projects/shared/synced-project-scope/plan.md:1329`)
  - Issue: p03-t10 and p04-t10 both expect `git ls-remote origin 'refs/oat/projects/*'` to be empty after deleting their scratch project. The feature intentionally retains completed project refs and supports concurrent projects, so an unrelated legitimate ref makes these tasks fail even when cleanup is correct.
  - Fix: Assert absence of only `refs/oat/projects/synced-dogfood` and `refs/oat/projects/skill-dogfood`, respectively. Preserve and report unrelated refs instead of treating them as cleanup failures.
