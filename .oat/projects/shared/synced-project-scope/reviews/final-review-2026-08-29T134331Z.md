### Important

- **Archive accepts a descendant path and can mutate a different synced project** (`packages/cli/src/commands/project/archive/push-runner.ts:121`)
  - Issue: The command derives `projectName` from the supplied path's basename,
    while `resolveProjectScope` accepts every descendant beneath a scope root
    (`commands/shared/project-scope.ts:102`). The archive engine consequently
    copies the supplied descendant (`archive-utils.ts:1650`) but resolves the
    synced record/ref and later checkout removal from that basename
    (`archive-utils.ts:1550`, `archive-utils.ts:1786`,
    `archive-utils.ts:1821`). In a real two-project reproduction,
    `project archive .oat/projects/synced/alpha/beta` exited 0, archived
    `alpha/beta/sentinel.txt` as project `beta`, marked `beta` complete, and
    removed the real `beta` checkout. The same broad path acceptance archives
    and deletes an arbitrary descendant for shared/local projects.
  - Fix: Canonicalize the input before dry-run or mutation and require its
    parent to equal exactly one canonical scope root. Recheck that invariant in
    `archiveProjectOnCompletion`, bind the basename to the exact record/target,
    and add shared/local nested-path refusals plus a two-synced-project
    basename-collision integration test.
  - Requirement: FR8, NFR1, NFR4

- **`oat local sync --force` can recursively delete nested synced worktrees** (`packages/cli/src/commands/local/sync.ts:63`)
  - Issue: The guard inspects only `<selected-root>/.git` on the source and
    destination, then recursively removes an existing destination at line 88
    and copies the whole source at line 91. It never checks for `.git` files or
    directories below the selected root. A direct reproduction with
    `localPaths: ['.oat/projects']` and a destination
    `.oat/projects/synced/live/.git` returned `status: copied` and removed the
    nested checkout's unsaved file. Without `--force`, the same ancestor may be
    copied into an absent destination with the nested `.git` pointer and
    project artifacts included. Existing tests cover only a marker at the
    selected root (`local/sync.test.ts:251`).
  - Fix: Before any removal or copy, detect registered worktree overlap and
    nested `.git` markers beneath both trees; skip or refuse the entire entry
    when an overlap exists. Add ancestor tests in both directions, with and
    without `--force`.
  - Requirement: NFR1; design local-path sync guard

- **Documented external absolute project roots fail after synced publication and strand local resources** (`packages/cli/src/commands/project/new/scaffold.ts:570`)
  - Issue: Configuration docs say absolute `projects.root` values remain
    absolute and relocate all three scopes
    (`apps/oat-docs/docs/cli-utilities/configuration.md:79`), while the spec
    requires artifact directories inside the repository (`spec.md:294`). The
    scaffold preserves an outside path, creates and publishes the synced
    checkout at lines 630-710, and only then reaches the allowlisted parent
    record commit. In a real reproduction, creation exited 2 after publishing
    the project content; rollback deleted the remote ref but failed on
    `git reset -- ../external/synced/<slug>.json`, leaving the checkout,
    discovery record, worktree registration, and local custom ref. The error's
    recommended `project prune <slug> --force` also exited 2 because the record
    is outside the parent-branch allowlist. `ensureScopedRootGitignore`
    silently skips an outside root (`commands/init/gitignore.ts:127`).
  - Fix: If inside-repository roots are the intended constraint, reject an
    external synced scope root before gitignore repair or `createSyncedProject`
    and state that constraint in configuration docs. If external synced roots
    are intended, redesign record/active-project durability and rollback so no
    parent pathspec points outside the repository; do not advertise the current
    partially supported state.
  - Requirement: FR1, FR5, FR14, NFR5

### Medium

- **A final prune commit failure leaves no CLI-resolvable retry target** (`packages/cli/src/commands/project/sync/ref-sync.ts:1066`)
  - Issue: Prune deletes the remote ref, removes every checkout, deletes the
    local ref and record at lines 1102-1104, and only then commits the record
    deletion at lines 1105-1113. An injected failure on that final `git commit`
    left the checkout, local ref, remote ref, and record gone, with only the
    staged record deletion remaining. Retrying the public command exited 1
    with `No synced project named prune-fail locally or on origin` because
    target resolution requires a checkout, record, or remote ref
    (`commands/project/sync/resolve-target.ts:147`). The desired destructive
    state is reached, but the promised durable parent lifecycle mutation
    cannot be completed through the CLI.
  - Fix: Persist a partial-prune receipt/tombstone or teach target resolution
    to recognize and finish an exact staged record deletion. At minimum, catch
    this boundary and emit an exact, validated manual commit recovery command.
    Add an injected final-commit failure test that proves retry completion.
  - Requirement: FR11, NFR5

- **Archive retry can silently complete from content older than the retained ref** (`packages/cli/src/commands/project/archive/archive-utils.ts:706`)
  - Issue: Archive metadata records only project name, snapshot name, and scope
    (`archive-utils.ts:211`); retry verifies those fields and, when the archive
    exists, skips the copy at lines 1627-1672. A reproduced first attempt
    failed after copying `# old summary`. The project was then updated to
    `# new summary` and successfully pushed. Retry exited successfully, marked
    the record complete, and removed the checkout, but both the archive and
    durable summary export still contained `# old summary` while the retained
    custom ref contained `# new summary`. The receipt therefore attests a
    snapshot that is not bound to the completed ref state.
  - Fix: Persist the source project-ref SHA or tree hash in archive metadata
    before copying and verify it on every retry. If the current ref differs,
    fail with explicit guidance or create a new transactionally bound snapshot;
    add an intervening-push retry regression.
  - Requirement: FR8, NFR5
