### Important

- **A child identity failure aborts the whole coordination pull instead of remaining isolated to that child** (`packages/cli/src/commands/project/sync/ref-sync.ts:542`)
  - Issue: `pullChildren()` runs `assertCanonicalSyncTargetIdentity()`, record lookup, and the remote probe before the `try` block that converts failures into a `PullChildResult`. The new symlink regression explicitly expects the whole promise to reject. With a parent declaring `alias` followed by `later`, a real-worktree reproduction returned a rejected promise for `alias` with zero Git calls; `later` was never attempted. Through `oat project pull`, that rejection reaches the command-level catch before successful parent/child adoption records can be committed.
  - Impact: mutation safety is preserved, but FR17 requires every failing child to be reported per child without rolling back or preventing the parent and siblings. A corrupt or aliased first child therefore blocks healthy later children and replaces structured per-child diagnostics with a whole-command error.
  - Fix: Move the identity preflight, record lookup, remote probe, and pull into one per-child guarded helper/`try` block. Convert any child-specific failure to an `error` result and continue the loop. Add a real-worktree regression with an aliased first child and a healthy later child that proves the alias receives an error row, the healthy child is pulled/adopted, the sibling target remains unchanged, and pending successful adoption records remain committable.
  - Requirement: FR17
