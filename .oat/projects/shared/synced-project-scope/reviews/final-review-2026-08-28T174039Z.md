### Important

- **Doctor reports the tracked discovery record as a leaked synced artifact and fails on every synced project** (`packages/cli/src/commands/doctor/synced-projects.ts:101`)
  - Issue: The tracked-artifact check runs `git ls-files -- .oat/projects/synced` and treats any output as a failure. The per-project discovery record `.oat/projects/synced/<slug>.json` is tracked by design (FR5), so every repository with at least one committed synced project gets `✗ project:synced_tracked_artifacts - Tracked synced artifact files: .oat/projects/synced/<slug>.json` and `oat doctor --scope project` exits non-zero. Reproduced with the built CLI: `oat project new probe --scope synced` followed by `oat doctor --scope project` fails immediately. The suggested fix, `git rm --cached`, would untrack the record and make the project undiscoverable on other checkouts. This regressed after the p03-t10 dogfood (which recorded doctor passing) when p03-t15/p03-t19 introduced the `ls-files` probe; no test tracks a record file and asserts a pass (`synced-projects.test.ts:96-179` only track files under a slug directory).
  - Fix: Filter the `ls-files` output to entries below a slug directory (`^\.oat/projects/synced/[^/]+/`), or run `git ls-files -- '.oat/projects/synced/*/'`; keep top-level `*.json` records out of the leak set. Add a real-git test that commits `<slug>.json` and asserts no `synced_tracked_artifacts` failure, and keep the existing leak tests.
  - Requirement: FR13 (P1), FR5

- **Completion passes an absolute filesystem path as the FR7 durable-summary line in the PR body** (`.agents/skills/oat-project-complete/SKILL.md:826`)
  - Issue: Step 8.6 forwards `SUMMARY_EXPORT_FILE` verbatim to `oat project links --durable-summary`. That value comes from the archive report's `summaryExportFile`, which `archive-utils.ts:652` builds as `join(repoRoot, summaryExportPath, …)` and `push-runner.ts:300` emits unchanged, so it is absolute (e.g. `/Users/<user>/Code/<repo>/.oat/repo/reference/…`). `render.ts:62-64` prints it verbatim, so the PR body (and the archived PR artifact) carries a machine-local path with the operator's home directory instead of the repository-relative path the design specifies (`design.md` "Rendered block"). The `links` option help says "Repository-relative durable summary path", but nothing relativizes or validates it. `completion-transaction.test.ts` never exercises `--durable-summary`; `review-skill-contracts.test.ts:1381` only asserts the literal argument string.
  - Fix: Relativize in one place — either have `archiveProjectOnCompletion`/the archive JSON report return `summaryExportFile` repo-relative (and update `archive-utils.test.ts:2004,2090` expectations), or have `links/index.ts` resolve `--durable-summary` against the repo root and reject/relativize absolute inputs. Add a `links` test that an absolute input renders repo-relative, and extend the completion transaction matrix with a configured `archive.summaryExportPath` row that asserts the rendered block contains no absolute path.
  - Requirement: FR7 (P0)

- **Non-archive completion retry cannot reach the receipt-recovery surface because Step 5 always dirties the checkout first** (`.agents/skills/oat-project-complete/SKILL.md:500`)
  - Issue: Step 7.5's retry recognition (`SKILL.md:596-667`) invokes `recover-completion-receipts.mjs`, which fails closed on any non-empty `git status --porcelain=v1 -uall` in the checkout (`recover-completion-receipts.mjs:232-241`), and the skill exits on that failure (`SKILL.md:658`). But Step 5 unconditionally runs `oat project complete-state`, which rewrites `oat_project_completed`, `oat_project_state_updated`, and `**Last Updated:**` with the current time on every invocation (`complete-state/index.ts:71-79`, `state-utils.ts:99-123`) and has no unchanged short-circuit; Step 3.7 also re-appends a seal to the project log. A real re-run of the skill after an interruption therefore always arrives at Step 7.5 with a dirty checkout and stops with "Synced project checkout must be clean before receipt recovery", so the p07–p09 recovery contract is exercised only by the test harness (`completion-transaction.test.ts:214-236`), which calls the script against an untouched checkout. Nothing in the skill instructs skipping Steps 3.7/5 on a recognized retry.
  - Fix: Make retry detection precede the lifecycle mutations — probe checkout HEAD/local ref for a `chore(oat): publish final project links` / `attest final project recap` subject before Step 3.7 and Step 5 and skip those steps (or make `complete-state` and the seal append idempotent no-ops when the state already records completion). Add a skill-driven test row that re-runs the skill's ordered steps (not just the script) after each interruption point.
  - Requirement: FR8 (P0), NFR5

### Medium

- **Doctor emits a false "gitignore block does not ignore synced project directories" warning whenever the first record's checkout is absent** (`packages/cli/src/commands/doctor/synced-projects.ts:227`)
  - Issue: The probe is `git check-ignore -q <syncedRoot>/<slug>` with no trailing slash and no `--no-index`. The managed rule `.oat/projects/synced/*/` is directory-only, so git cannot match a path that does not exist on disk (verified: `__probe__` → exit 1, `__probe__/` → exit 0). When the first record's checkout is absent — the exact state doctor separately warns about with "run `oat project pull`" — the repository is told to run `oat tools update` although the rule is present. Reproduced live. The unit test for the absent-checkout case (`synced-projects.test.ts:54-69`) mocks git to return exit 0 for every command, so it cannot catch this.
  - Fix: Use the same probe as `isSyncedRuleApplied` (`gitignore.ts:28-44`): `check-ignore --quiet --no-index '<syncedRelative>/__probe__/'` with the trailing slash. Add a real-git test with a record present, checkout absent, and the managed block applied, asserting no `project:synced_gitignore` check.
  - Requirement: FR13

  - Issue: `pushSynced` returns a valid `sha` for `conflict` (the local commit) and `rejected`, and the command exits 1, but the exit status is lost inside `$(...)`.   - Fix: At every `--json` receipt site require `status` to be `pushed` or `up-to-date` before using `.sha` (mirror the complete skill's `node -e` check or `jq -e 'select(.status=="pushed" or .status=="up-to-date") | .sha'`), and surface the conflict recovery command otherwise. Consider a validator rule in `validation/skills.ts` for `oat project push … --json` receipts.
  - Requirement: FR6, FR3

  - Issue: Step 8.6 states that when `WAS_PR_OPEN_AT_START="true"` "Step 11.5 updates the already-open PR with" the final body, but Step 11.5 (`SKILL.md:1096-1103`) runs only when `SHOULD_ARCHIVE="true"` and lists `SHOULD_ARCHIVE="false"` as a skip condition; Step 11 is also skipped for a tracked open PR (`SKILL.md:207`).   - Fix: Either extend Step 11.5 to run for the non-archive lane (sync the final artifact body) and update the contract test, or correct Step 8.6's prose and document that the PR body is refreshed by push. Decide which pin the PR body should carry and make the test assert that.

- **Recap-evidence commit is a bare `git commit` on the parent branch, and both completion record commits bypass the CLI-owned `commitRecordChange` path the design specifies** (`.agents/skills/oat-project-complete/SKILL.md:1044`)
  - Issue: Step 10.6 runs `git add -- <manifest> <build-record>` followed by `git commit -m "chore(oat): attest final project recap"` with no pathspec/`--only`, so any pre-staged unrelated changes are swept into the evidence commit; the byte-for-byte staged-snapshot check (`SKILL.md:1050-1051`) runs after the commit exists. This commit is new in the range (`origin/main` had only the lifecycle commit). The design assigns the evidence-only commit to `oat project archive` (design.md Archive integration step 5) and says parent-branch index mutations happen only through `commitRecordChange` (design.md Mutation invariants 3), yet the skill states "The archive command does not own this evidence transition" (`SKILL.md:1052`) and the non-archive record completion (`SKILL.md:880-886,943-948`) is also a skill-authored JSON write plus direct `git commit --only`. The implementation is defensible (path-scoped in the record case) but diverges from the design's ownership contract.
  - Fix: Use `git commit --only -- "$EXPORTED_MANIFEST_PATH" "$EXPORTED_BUILD_RECORD_PATH"` (or a CLI surface) for the evidence commit so pre-staged content cannot leak in, and either add a CLI command for non-archive record completion (`oat project archive --no-move`/`oat project complete-record`) or update `design.md` to document the two skill-owned parent-branch commits as the accepted exception.
  - Requirement: NFR4, FR8 (design alignment)
