### Important

- **Synced open still converts remote/system failures into “project not found,” and several p02 commands still force exit 1** (`packages/cli/src/commands/project/open/index.ts:253`)
  - Issue: The bare-slug lookup catches every error from `resolveSyncedTarget`, including the newly corrected exit-2 `ls-remote` transport/authentication failures, and replaces it with `Project not found`. The outer `open` handler then forces exit 1 at line 442. `scope` and `pause` retain the same unconditional exit-1 catch (`scope/index.ts:143`, `pause/index.ts:329`). Human and JSON callers therefore still cannot distinguish actionable absence from filesystem, Git, or remote-system failure, contrary to the phase API contract and the round-one fix objective.
  - Impact: Automation may treat an unavailable or unauthenticated origin as a genuinely absent project and take the wrong recovery action; system failures from scope inspection and synced pause/resume are likewise misclassified.
  - Fix: Catch only the explicit actionable “not found” condition in the lookup and rethrow exit-2/unknown failures unchanged. Convert anticipated user states to `CliError(..., 1)`, and make every p02 command catch preserve `CliError.exitCode` while classifying unknown exceptions as exit 2. Add both human and JSON tests for missing refs, transport/auth failures, and injected exit-2 errors through `open`, `scope`, and synced `pause`.
  - Requirement: FR16; design API/error contract

- **Real coordination-child failures still lose conflict details and collapse every exception to `missing`** (`packages/cli/src/commands/project/sync/ref-sync.ts:475`)
  - Issue: `pullChildren` catches every thrown child failure—missing ref, authentication/DNS failure, malformed record, or filesystem failure—and emits `status: 'missing'`. Successful `pullSynced` conflict/dirty results are spread into `PullChildResult`, but the type has no `conflicts` field and no `message`; human reporting at `pull/index.ts:112` therefore prints `no diagnostic provided` for the real conflict path. The new command test injects a synthetic `message`, so it does not exercise the production result shape.
  - Impact: A partial coordination pull can report a system outage as an absent child with exit 1, and a genuine conflict omits the conflicted files that the operator needs to resolve. This leaves FR17's per-child diagnostic contract and the system-error exit contract incomplete.
  - Fix: Preserve conflict paths on `PullChildResult`, distinguish missing refs from exit-2/system failures, and carry the child failure's exit classification through the aggregate command result while still committing successful adoptions. Add an integration-level human-output test using a real child conflict plus command tests for missing-ref versus transport failure in JSON and human modes.
  - Requirement: FR17

- **An active-pointer write failure after a successful scaffold publication is not resumable** (`packages/cli/src/commands/project/new/scaffold.ts:725`)
  - Issue: The staged recovery boundary ends after the ref, record, and optional parent commit, but `setActiveProject` runs outside it. If that filesystem write fails, the command returns the raw system error even though the project ref and discovery record are already durable. Re-running `project new` then fails with “already exists,” and the emitted error does not name the deterministic recovery (`oat project open <slug>` or an equivalent pointer repair). A temporary-repository injection confirmed this exact sequence: the first run failed with `EISDIR`, and the retry failed because the synced checkout already existed.
  - Impact: Ordinary recovery by retry is impossible after this post-publication failure, violating the scaffold transaction's stated resumability goal and leaving the user without an executable next step.
  - Fix: Include pointer update in the post-publication failure classification (without rolling back the published ref/record), emit a targeted `oat project open '<slug>'` recovery instruction, and make `setActiveProject` injectable so a test proves the durable project is preserved and the emitted command completes recovery.
  - Requirement: FR2, FR5, NFR5

- **Resuming a partial synced split skips the final parent/child ref pushes** (`packages/cli/src/projects/split/finalize.ts:54`)
  - Issue: `finalizeSplit` publishes the coordination parent and all children only when `context.scope === 'synced'`. Fresh execution supplies that field, but `continueSplitResume` calls `seedChildren` and `finalizeSplit` with only `projectsRoot: partial.projectsRoot` (`resume.ts:161-171`). On a synced resume, local state and seeded discovery are updated and the command can report success, yet the parent ref remains without its final `oat_children`/complete state and newly resumed child refs retain their pre-seed scaffold content. No synced split or synced-resume test exists despite p02-t02 explicitly requiring origin-tree assertions.
  - Impact: A later machine pulling the coordination parent or resumed child sees stale artifact state, breaking coordination materialization and creating a silent partial-publication failure.
  - Fix: Derive and pass `scope`/`scopeRoot` from the persisted parent path in the resume path, then publish the parent and every child after all resumed mutations. Add real-bare-origin tests for both a fresh synced split and a missing-child resume, asserting the origin parent contains the full `oat_children` list and each child contains its parent/discovery seed.
  - Requirement: FR17, NFR5
