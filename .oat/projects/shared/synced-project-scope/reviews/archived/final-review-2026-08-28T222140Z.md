## Findings

### Critical

- **Migration rollback can delete a concurrently-created remote project ref** (`packages/cli/src/commands/project/sync/ref-sync.ts:1249`)
  - Issue: `created` becomes true after only the local ref and checkout are
    created (`:1117-1118`). On any later failure, rollback checks only whether
    the remote ref currently exists and then deletes it unconditionally
    (`:1254-1261`). Another actor can publish the same previously absent slug
    after migration's initial collision check; if this migration then conflicts
    or its push is rejected, rollback deletes the other actor's ref even though
    this invocation never published or owned that remote value. This violates
    the design's “if the push had succeeded” rollback condition and creates a
    remote data-loss race.
  - Fix: Track whether this invocation successfully published and the exact SHA
    it published. Delete only that owned SHA with an atomic expected-old-value
    lease/CAS operation; never delete a remote ref merely because it exists.
    Add a bare-origin integration test where a competitor creates the ref
    between preflight and the failed migration push.
  - Requirement: FR12, NFR4

- **Archive retry loses the lifecycle receipt after the lifecycle commit succeeds** (`packages/cli/src/commands/project/archive/archive-utils.ts:1683`)
  - Issue: If checkout removal fails after the lifecycle commit, retry stages
    the already-committed paths, gets `null` from `commitRecordChange` when
    there is no new diff (`ref-sync.ts:842-852`), removes the checkout, and
    returns `lifecycleCommit: null`. The completion skill then requires a full
    lifecycle SHA and exits (`.agents/skills/oat-project-complete/SKILL.md:822`).
    The current retry test explicitly expects null
    (`archive-utils.test.ts:895-901`), so the test codifies a result that cannot
    complete the closeout protocol after the checkout has been removed.
  - Fix: On a no-op retry, recover and return the prior exact lifecycle commit
    only after verifying its subject, path set, record/export contents, and
    relationship to the current branch. Add an executable skill-to-command
    retry test covering failure after lifecycle commit and successful
    re-attestation/closeout on retry.
  - Requirement: FR8, NFR5

### Important

- **`pull --continue` skips adoption records and coordination children** (`packages/cli/src/commands/project/pull/index.ts:197`)
  - Issue: A normal successful pull prepares adoption records and pulls
    children, but the continuation branch explicitly disables children and
    `continueSynced` returns only `{ status, sha }`
    (`sync/ref-sync.ts:798-819`). An adopting pull that conflicts therefore
    remains recordless after a successful continuation, and a coordination
    parent that conflicts never materializes its children. The design requires
    continuation to re-evaluate as pull.
  - Fix: After a successful `rebase --continue`, run the same adoption-record
    preparation, record commit, and child-pull phase as a successful normal
    pull. Add integration tests for adoption-with-conflict and
    coordination-parent-with-conflict through `--continue`.
  - Requirement: FR4, FR16, FR17, NFR5

- **Shared/local archive reads and applies an unrelated same-slug synced record** (`packages/cli/src/commands/project/archive/archive-utils.ts:1449`)
  - Issue: Archive reads `.oat/projects/synced/<slug>.json` before determining
    the project's actual scope and then passes that record's `archiveSnapshot`
    into target resolution regardless of `isSynced` (`:1450-1495`). A malformed
    same-slug synced record can block shared/local archive, while a valid record
    can redirect it to the synced project's retained snapshot identity. This is
    cross-scope coupling in behavior required to remain unchanged.
  - Fix: Resolve scope first and read/use the synced discovery record only when
    the target project is actually synced. Add shared/synced and local/synced
    same-slug tests, including a malformed unrelated synced record.
  - Requirement: NFR1

- **`oat local sync --force` can delete a nested-worktree destination** (`packages/cli/src/commands/local/sync.ts:81`)
  - Issue: The nested `.git` marker guard checks only `sourcePath` (`:63-71`).
    With an overlapping configured `localPaths` entry, an ordinary source and a
    nested-worktree destination, `--force` recursively removes the destination
    and leaves stale Git worktree registration metadata. The new safeguard does
    not protect both ends of the destructive copy.
  - Fix: Check source and destination for `.git` files/directories before any
    remove or copy and skip when either is a nested repository/worktree. Add
    destination-marker tests for `.git` file and directory forms.
  - Requirement: NFR4 safety design

- **First synced archive uses an undated export identity** (`packages/cli/src/commands/project/archive/archive-utils.ts:1501`)
  - Issue: Archive computes a dated `snapshotName` but synced mode replaces the
    export identity with `basename(archivePath)`. The first unused archive path
    is plain `<project>` (`:502-513`), so summary, recap, and S3 outputs become
    `demo.md` / `.../demo` instead of the dated forms required by FR8 and the
    lifecycle docs. The ordinary test confirms `snapshotId === "demo"`
    (`archive-utils.test.ts:588`); only retry fixtures pre-create the base path
    and accidentally exercise a timestamped suffix.
  - Fix: Persist a canonical dated export/snapshot identity on the first run,
    keeping local target selection separate if the local archive directory must
    remain legacy-shaped. Test a first archive with no existing destination and
    a later-date retry for stable dated S3, summary, and recap names.
  - Requirement: FR8, FR14

- **Synced S3 failures block completion despite warning-only parity** (`packages/cli/src/commands/project/archive/archive-utils.ts:1597`)
  - Issue: Completion-mode AWS access deliberately returns warnings when the
    CLI or credentials are unavailable (`:1749-1768`), but synced archive turns
    those warnings and S3 sync failures into `CliError` (`:1597-1601`,
    `:1627-1634`). Shared completion retains warning behavior. This contradicts
    FR8's exact shared parity and the lifecycle documentation that unusable AWS
    configuration does not block closeout.
  - Fix: Preserve warning-only completion behavior for synced projects and
    leave `s3Path` null on failure, or explicitly revise spec/design/docs if
    blocking durability is an intentional product change. Add shared/synced
    parity tests for missing CLI, invalid credentials, and failed `s3 sync`.
  - Requirement: FR8, FR14

- **Completion receipt recovery does not verify completed lifecycle state** (`.agents/skills/oat-project-complete/scripts/recover-completion-receipts.mjs:435`)
  - Issue: Recovery verifies subjects, parentage, exact final-artifact paths,
    link blocks, repository/ref identity, and ref relationships, but for the
    pin-source commit it checks only the subject. It never reads `state.md` or
    validates `oat_lifecycle: complete`; the router then skips `complete-state`,
    project-log, and the other lifecycle mutations
    (`resolve-completion-retry.mjs:89-95`). The executable matrix seeds a
    non-canonical placeholder `state.md` and asserts it remains unchanged
    (`completion-transaction.test.ts:384-407`, `:535-554`). A subject-valid
    chain can therefore be accepted while its lifecycle state is incomplete.
  - Fix: Validate the pin-source tree's canonical completed `state.md` fields
    and required completion-log seal before returning a recovered receipt. Add
    negative repository-backed tests for active/incomplete state and missing or
    unsealed completion log.
  - Requirement: FR8, NFR5

- **Prune fails before it can clean a stale worktree registration** (`packages/cli/src/commands/project/sync/ref-sync.ts:959`)
  - Issue: `pruneSynced` canonicalizes every path returned by `git worktree list
--porcelain` with `realpath` before running any `worktree prune`. A
    registered checkout whose containing parent worktree was removed is
    precisely a missing path, so `realpath` throws and the explicit prune
    command cannot reach its own cleanup/removal flow. The existing stale-path
    coverage exercises pull/removal helpers, not project-wide prune.
  - Fix: Run `git worktree prune` before enumeration or canonicalize registered
    paths without requiring filesystem existence, while retaining containment
    checks for live paths. Add a real-Git test with a prunable nested
    registration left by a removed parent worktree.
  - Requirement: FR11, FR10

- **Doctor omits ref divergence when one side is absent** (`packages/cli/src/commands/doctor/synced-projects.ts:219`)
  - Issue: Doctor warns only when both local and remote SHAs are non-empty and
    unequal. A successful `ls-remote` returning no ref, or a missing local ref,
    produces no ref-sync warning even though the design's local-vs-remote
    diagnostic is divergent. Transport failure is already distinguishable via
    `remote.code !== 0` and should remain a non-blocking offline note.
  - Fix: Treat a successful query with exactly one ref present as divergence,
    while preserving the offline branch for actual transport failure. Add unit
    cases for local-only and remote-only refs.
  - Requirement: FR13
