### Important

- **Active-pointer recovery is not targeted when the slug exists in another scope** (`packages/cli/src/commands/project/new/scaffold.ts:736`)
  - Issue: After a synced scaffold has published its ref and record, an active-pointer write failure now instructs the operator to run `oat project open '<slug>'`. Cross-scope duplicate slugs are supported—creation checks only the selected scope, and `open` deliberately rejects a bare slug when matching projects exist in multiple scopes (`open/index.ts:233`). In that valid state, the emitted recovery command fails with the ambiguity error and does not repair the pointer, so the round-two recovery fix is not always executable.
  - Impact: A system failure after durable publication can still strand `project new`: rerunning creation is forbidden by the existing ref/checkout, while the only emitted recovery command cannot select the newly created synced project.
  - Fix: Emit the shell-quoted scope-correct `projectPath` (for example, `oat project open '.oat/projects/synced/demo'`) instead of the bare slug. Add a test with an existing shared or local project of the same name that injects `setActiveProject` failure and proves the emitted command completes recovery.
  - Requirement: FR2, FR5, NFR5

- **A failed final split push leaves a completed parent that the resume path refuses to retry** (`packages/cli/src/projects/split/finalize.ts:46`)
  - Issue: `finalizeSplit` writes `oat_phase_status: complete` before pushing the parent and each child sequentially. If any later push is rejected or fails due to transport/authentication, earlier refs may already be current while later refs remain at their pre-seed scaffold commits. The command returns failure, but the next `split run --resume` calls `detectPartialSplit`, which unconditionally rejects the now-complete local parent (`resume.ts:121`) before it can republish the incomplete refs. `run.ts:415` also collapses the underlying system failure to exit 1.
  - Impact: A transient failure creates silent partial publication on origin and makes the supported retry command unusable. Another machine can pull a current coordination parent but stale child state, directly breaking FR17 and the terminal fix's resumability objective.
  - Fix: Make final publication resumable as an explicit state: either persist publication progress and allow a matching completed coordination parent to re-enter finalization, or defer/roll back the terminal marker in a way that safely retries all parent/child pushes. Preserve `CliError.exitCode` for transport/system failures. Add an injected mid-sequence failure test that verifies the first run leaves local changes durable, a normal `--resume` republishes every ref, and origin then contains the final parent and every child seed.
  - Requirement: FR17, NFR5
