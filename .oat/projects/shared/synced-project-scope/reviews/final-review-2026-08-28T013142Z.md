### Important

- **An ignored adoption record is mistaken for a committed durable record on retry** (`packages/cli/src/commands/project/sync/ref-sync.ts:120`)
  - Issue: `classifyAdoptionRecord()` treats any readable record with empty `git status --porcelain --untracked-files=all -- <path>` output as durable. Git omits ignored untracked files from that status output. If a repository or user ignore rule covers the exact synced-record path, the initial exact-path `git add` can fail while leaving the record readable; a later pull/open retry then returns `durable` and succeeds without the adoption record being committed. Prior I2 is therefore still open for a plausible legacy/custom-ignore failure mode, contrary to FR16 and NFR5's idempotent recovery contract.
  - Fix: Require proof that the exact record path is tracked in the index/HEAD and clean before returning `durable` (for example, an exact `git ls-files --error-unmatch` check plus the clean-state check). Treat ignored/untracked records as pending or fail with an explicit `git check-ignore` recovery diagnostic. Add pull and open retry tests for an ignored, untracked adoption record.
  - Requirement: FR16, NFR5

### Medium

- **Current workflows packs no longer trigger managed git-file repair through the default reconciler** (`packages/cli/src/commands/tools/update/index.ts:304`)
  - Issue: The merge correctly combines pack reconciliation with `.gitignore` and `.gitattributes` application, but `shouldBackfillWorkflowGitignore()` only inspects `updated`, `current`, and `newer`. With the default `reconcilePacks` dependency, a requested workflows pack that is already current is represented by a reconcile plan with no operations and leaves those three arrays empty. Consequently, rerunning `oat tools update --pack workflows --scope project` does not repair a missing managed `.gitignore` or `.gitattributes` block. Existing config-write tests use the legacy dependency shape and do not cover this merged interaction. This weakens the idempotent managed-file repair promised by FR9/FR15.
  - Fix: Drive the repair decision from the requested workflows project target, or include a matching `result.plans` entry in the predicate. Add a default-dependency/current-pack integration test that asserts both managed-file apply functions run even when reconciliation has no content operations.
  - Requirement: FR9, FR15
