  - Issue: `pullChildren()` builds each child target directly from the parent path and validated slug, reads the child's record, and calls `pullSynced()` without the canonical identity check added to `resolveSyncedTarget`.   - Impact: `oat project pull <coordination-parent>` can mutate durable sibling state under a different child/ref identity. The fix therefore does not yet enforce canonical target identity before every p02 pull mutation, violating FR1, FR4, FR17, and NFR4.

Add a real-worktree regression for `pullChildren()` with an aliased child and assert no Git calls, record write, or sibling HEAD change; cover internally built split-publish targets as well if they retain direct construction.
