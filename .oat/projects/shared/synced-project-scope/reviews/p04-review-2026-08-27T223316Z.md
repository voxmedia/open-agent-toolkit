  - Fix: After the final ref/archive SHA is known, always render `oat project links "$PROJECT_NAME" --format markdown` for a synced completion and insert/replace the delimited block in the body. Make this independent of `projectRecapExport`, and add contract cases for a newly opened PR and an already-open PR with no recap and no configured summary export.
  - Requirement: FR7 / p04-t05

- **`oat-project-next` reports that no projects exist when only synced or local projects are present** (`.agents/skills/oat-project-next/SKILL.md:95`)
  - Issue: When the active pointer is empty or invalid, the router still enumerates only `"$PROJECTS_ROOT"/*/`; the configured root defaults to `.oat/projects/shared`. The CLI now owns all-scope enumeration and `oat-project-progress` correctly uses `oat project list --json`, but `next` can tell a user with a synced-only repository that no projects exist and route them toward creating a new project. p04-t11 made this skill a synced-aware routing entry point, so the fallback is part of the reviewed change.
  - Fix: Replace the shared-root `ls` probe with `oat project list --json`, distinguish an empty list from projects-without-an-active-pointer, and add a contract test with only an absent-checkout synced record plus one with only a local project.
  - Requirement: FR6 / p04-t11

- **Dirty brainstorm fold-back still uses parent-branch Git commands for synced artifacts** (`.agents/skills/oat-brainstorm/SKILL.md:569`)
  - Issue: The clean fold-back path was made scope-aware, but dirty Option A says to commit the existing artifact directly and Option B explicitly runs `git add -- "$ARTIFACT_PATH"` followed by a Git commit (`.agents/skills/oat-brainstorm/SKILL.md:570`). For a synced project the artifact belongs to the nested ref checkout and is ignored by the parent, so these branches either fail or leave the artifact unpushed while the skill proceeds as though it has a handoff commit. The validator misses the prose-only commands.
  - Fix: Carry the resolved scope through the dirty-case picker. For Option A, push the existing artifact state first and then push the fold-back as a second ref commit; for Option B, append and perform one `oat project push --json`, capturing its SHA. Retain the current Git behavior only for non-synced scopes and add contract tests for both dirty branches.
  - Requirement: FR6 / p04-t03

- **A synced summary can leave newly promoted decision records staged but uncommitted** (`.agents/skills/oat-project-summary/SKILL.md:429`)
  - Issue: The synced branch pushes `summary.md` to the project ref, while promoted `DR-*.md` records and their managed index are repository-wide files. The skill instructs agents to stage those files only after the optional ledger commit block (`.agents/skills/oat-project-summary/SKILL.md:451`) and provides no subsequent parent-branch commit. When the ledger is skipped or deduplicated—the common case—the summary reports promoted decisions even though the new records remain merely staged and are not durable. The p04-t10 dogfood deduplicated an existing decision, so it did not cover this branch.
  - Fix: Treat promoted decision paths as explicit parent-branch outputs. Stage and commit the exact created decision records plus managed index in a guarded parent commit, combining them with the ledger commit when one exists and otherwise creating a dedicated commit. Verify the commit paths and preserve unrelated staged state. Add a synced summary test/dogfood case that creates a genuinely new decision with no ledger append.
  - Requirement: FR6 / p04-t03

- **Retro apply has no durable commit path for repository targets when the project is synced** (`.agents/skills/oat-project-retro/references/apply-procedure.md:211`)
  - Issue: Docs, agent-instruction, rule, and decision promotions edit repository files outside the synced project checkout. The procedure still says to include the target and retro writeback in one commit whenever possible, but the only new scope-aware persistence step pushes the retro artifact to its separate project ref (`.agents/skills/oat-project-retro/references/apply-procedure.md:217`). A single commit cannot span the parent branch and project ref, and no synced-specific step commits the repository target first. This can leave an applied target uncommitted or record an `Applied-ref` that does not identify a durable target commit.
  - Fix: Define the synced transaction explicitly: format/verify and commit the exact repository target paths on the parent branch first, capture that commit/path as `Applied-ref`, then write back and push the retro artifact in a separate ref commit. Extend interruption recovery across both commits. Keep the existing single-commit route for shared/local when possible, and add cases for ordinary docs and decision targets under a synced project.
  - Requirement: FR6 / p04-t03
