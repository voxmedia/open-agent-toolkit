For example, `.oat/projects/synced/demo/reviews` is interpreted as slug `reviews`, but the returned target is rebuilt as `.oat/projects/synced/reviews`. If that sibling exists, `push`, `pull`, or a synced `open` transition can operate on it even though the operator named a path inside `demo`.
  - Impact: The new path-capable CLI can silently misidentify durable project state and commit, rebase, or publish the wrong project ref. That violates the standard `.oat/projects/synced/<slug>/` identity and the design's wrong-target mutation boundary.
  - Resolution guidance: Require explicit paths to canonicalize to exactly a direct child of the synced root and reject descendants before deriving the slug or reading its record. Cover both relative and absolute descendant paths, including the case where the basename matches a real sibling checkout.
  - Requirement: FR1, FR3, FR4, NFR4

  - Impact: A routine concurrent update during final parent/child publication leaves partial origin state and an unresolved child rebase. The advertised normal resume path is unsafe, while the error omits the documented recovery commands required by NFR5.
  - Resolution guidance: Make finalization surface target-specific `pull --continue` / `--abort` guidance for conflict state and ensure split resume detects rather than stages a pending rebase. Add a mid-sequence real-conflict integration case that completes recovery and verifies every origin ref.
  - Requirement: FR17, NFR5
