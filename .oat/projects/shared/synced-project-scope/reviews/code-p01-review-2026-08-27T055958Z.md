## Findings

### Critical

- **Duplicate creation can overwrite the only ref to unpushed project history** (`packages/cli/src/commands/project/sync/ref-sync.ts:63`)
  - Issue: `createSyncedProject` creates a new root commit and unconditionally runs `update-ref <ref> <new-commit>` before checking whether the ref, checkout registration, or destination already exists. A retry, race, or mistaken call for an existing slug can therefore replace the only named ref to unpushed artifact commits; if `worktree add` then fails, the function exits after the destructive ref mutation. This violates the repository's destructive-operation safety contract and makes the sync core non-idempotent.
  - Impact: local artifact history can become unreachable or require low-level recovery, and a partially failed create leaves ref and filesystem state inconsistent.
  - Fix: preflight the destination, worktree registration, local ref, and remote ref; refuse an existing slug as an actionable error. Create the ref atomically with an old-value guard such as `git update-ref <ref> <new> 000000...`, and roll back only the newly created ref if worktree creation or the nested-worktree assertion fails. Add tests proving an existing ref's SHA and files remain unchanged and a post-ref failure leaves no partial ref.
  - Requirement: FR1, NFR4

- **Valid Git conflict states escape the resumable conflict flow** (`packages/cli/src/commands/project/sync/ref-sync.ts:102`)
  - Issue: `listConflicts` recognizes only `UU`, `AA`, `DU`, and `UD`. Porcelain v1 also defines `DD`, `AU`, and `UA` as unmerged states. When rebase fails with only one of those omitted states, `listConflicts` returns empty and the callers at lines 174-176 and 249-252 throw a system `CliError` instead of returning `status: 'conflict'` with the affected path.
  - Impact: legitimate add/delete/rename conflict shapes break the P0 pull/push recovery contract, do not provide the required resolution instructions, and cannot be handled uniformly by `--continue` or `--abort` command wiring.
  - Fix: derive conflicted paths from Git's unmerged index (`git diff --name-only --diff-filter=U` or `git ls-files -u`) or cover all seven porcelain unmerged codes. Add integration cases for at least the omitted add/delete/rename conflict classes and exercise both push- and pull-originated rebases.
  - Requirement: FR4, NFR5

### Important

- **Every push transport failure is silently downgraded to a concurrent rejection** (`packages/cli/src/commands/project/sync/ref-sync.ts:191`)
  - Issue: any nonzero `git push` result returns `{status: 'rejected'}` and discards `stderr`. Authentication failures, missing remotes, network failures, server errors, and malformed refspec failures are therefore indistinguishable from the expected non-fast-forward race. This conflicts with the design's error contract, which requires network and external-service errors to retain the Git message and reserves `rejected` for a retryable concurrent advance.
  - Impact: the command layer cannot give a correct recovery instruction; telling users to pull and push again can loop indefinitely while hiding the actual credential, remote, or transport failure.
  - Fix: recognize the bounded non-fast-forward rejection case and return `rejected` only for it. For other failures, throw an actionable `CliError` that preserves the Git diagnostic (or extend the result type with a classified error and diagnostic that the command layer must surface). Add tests for non-fast-forward, auth/remote failure, and network-style failure outputs.

### Medium

- **Discovery records accept remotes other than the v1 `origin` constant** (`packages/cli/src/commands/project/sync/record.ts:29`)
  - Issue: the schema validates `remote` as any non-empty string, while the design's validation rules require it to equal `origin`. The existing tests check scope and ref invariants but omit the remote invariant.
  - Impact: malformed or branch-supplied records can pass validation and create cross-clone inconsistency once record-driven pull/adoption consumes this field; a future caller could also publish artifacts to an unintended configured remote.
  - Fix: use `z.literal(SYNCED_REMOTE)` (or an equivalent refinement), retain the upgrade/corruption diagnostic, and add rejection coverage for any other remote value.

- **Absent checkout removal leaves stale worktree registrations behind** (`packages/cli/src/commands/project/sync/ref-sync.ts:386`)
  - Issue: `removeSyncedCheckout` returns `absent` immediately when the directory is missing and never runs `git worktree prune`. A deleted nested directory can therefore remain registered indefinitely, despite the function's archive/removal contract requiring clean registration removal. `pullSynced` handles this exact stale-registration case, but removal does not.
  - Impact: archive/completion or retry paths can report success while `git worktree list` still contains the removed project, and later materialization may fail until another operation happens to prune it.
  - Fix: prune before returning `absent` (and verify the target registration is gone), or explicitly inspect and remove the stale registration. Add a test that deletes the checkout directory first, calls `removeSyncedCheckout`, and asserts the path is absent from `worktree list --porcelain`.
