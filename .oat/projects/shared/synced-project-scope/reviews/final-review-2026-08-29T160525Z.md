## Summary

The only substantive change since the prior gate review is the `p19-t13` fix
for that review's single Important finding (I1: local sync skipped every
localPath when run from a linked worktree nested under the main checkout). The
fix replaces exact-match exclusion of the source/target roots with
ancestor-or-equal ownership (`worktreeOwnsRoot`), so the main checkout that
contains `.worktrees/<a>` and `.worktrees/<b>` is no longer a protected
boundary for a sync between those two worktrees, while every registration that
does not own the source or target root keeps bidirectional `pathsOverlap`
protection. I traced the default nested layout, main-to-linked, linked-to-main,
and an unrelated registered worktree nested under a localPath entry; each

contains a `.git` boundary. The new real-Git regression exercises the exact
reported layout. Focused suite 21/21, CLI type-check, oxfmt, and

### Minor

- **Configured `localPaths` entries are never validated against `..`
  traversal or absolute paths before force-removal**
  (`packages/cli/src/config/oat-config.ts:1230`,
  `packages/cli/src/commands/local/expand.ts:140`,
  `packages/cli/src/commands/local/sync.ts:241`)
  - Issue: `normalizeOatConfig` keeps any non-empty string, non-glob entries
    are pushed to `resolved` verbatim, and `syncLocalPaths` then joins them
    onto `fromRoot`/`toRoot` and (with `--force`) runs
    `rm(destPath, { recursive: true })`. An entry such as `../shared` in a
    repository's own `.oat/config.json` therefore resolves outside both
    roots. This is pre-existing and not introduced by `p19-t13` (a
    main-checkout source root was already excluded from the registry guard
    before the fix), and it is only reachable through a self-authored config
    entry, so it is hardening rather than a defect in the reviewed change.
    Noted here because the fix deliberately narrows the registry boundary, so
    traversal validation is now the only backstop for entries that escape a
    linked worktree into its owning checkout.
  - Fix: reject entries that are absolute or whose normalized form starts with
    `..` in `normalizeOatConfig` (or fail closed in `syncLocalPaths`
    before the force-removal branch), with a unit test for each shape.
  - Requirement: NFR4 (hardening; out of narrowed range)
