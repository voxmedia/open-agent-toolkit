### High

- **Normal capped reviewer selection bypasses Claude ladder validation** (`packages/cli/src/commands/project/dispatch-ceiling/index.ts:688`)
  - Issue: `resolveProviderCellFromValue` takes `cell.candidates.at(-1)` and routes it without calling `assertCandidateOrder`; that validator is called only by the exact-candidate path at line 1045. A reversed `opus/high` then `opus/medium` ladder exits successfully and chooses the weaker terminal reviewer. An unsupported terminal `sonnet/xhigh` pair also returns a top-level resolved/advisory result with null dispatch arguments instead of the required clear configuration error, while still reporting `effortAxis: selected:xhigh`. The new invalid-ladder tests exercise only `--candidate-model`/`--candidate-effort`, so they do not protect the reviewer path.
  - Fix: Validate every configured ladder before terminal or routed selection, reject unsupported model/effort pairs and nondecreasing-order violations with an error, and derive selected axes only from an enforceable target. Add reviewer-resolution negative controls for both a reversed ladder and an unsupported terminal pair.
  - Requirement: Compatibility and Selection Contract; p01-t01 provider-native pair validation, ordering, deterministic reviewer terminal choice, and evidence/selector agreement.

- **Filtered tool removal leaves managed Claude variants behind** (`packages/cli/src/providers/claude/codec/sync-extension.ts:239`)
  - Issue: `oat tools remove` sends the removed canonical paths through in-process sync, but the Claude extension filters against canonical entries after removal. When no matching entry remains, line 239 returns an empty plan, and partial sync also disables stale cleanup at lines 260-262. A managed `oat-reviewer-claude-opus-high.md` therefore survives removal of its canonical reviewer role. This leaves an executable generated role after the owning pack content is gone and violates the phase's scoped-removal and stale-cleanup contract.
  - Fix: Make removal-filter planning recognize removed supported base-role paths and schedule deletion of managed variants owned by that base role, while retaining ownership checks and preserving unrelated roles. Add an in-process `tools remove` integration test that creates the variants, removes one canonical base role, and proves only its managed variants are deleted.
  - Requirement: p01-t02 managed lifecycle, scoped removal, stale cleanup, and pack-scoped remove integration.

### Medium

- **Human resolver output reports Claude effort as not applicable** (`packages/cli/src/commands/project/dispatch-ceiling/index.ts:2759`)
  - Issue: JSON output correctly reports `effortAxis: selected:<effort>` for an effort-pinned Claude target, but the non-JSON branch unconditionally prints `Effort axis: not-applicable` for every non-Codex provider. A successful Claude `opus/high` resolution therefore gives users contradictory evidence about the selected dispatch control, and the added tests assert only JSON output.
  - Fix: Render the resolved provider's `effortAxis` in human output and reserve `not-applicable` for providers or branches that actually lack an effort axis. Add a human-output assertion for an effort-pinned Claude resolution.

- **Codex role files are skipped by cross-directory collision discovery** (`packages/cli/src/providers/claude/codec/materialize.ts:156`)
  - Issue: `.codex/agents` is declared as a collision-discovery directory, but the scanner accepts only `.md` files. The only cross-directory test creates a Cursor Markdown role, leaving the phase's stated cross-host collision-refusal boundary incomplete.
  - Fix: Associate each discovery directory with its provider-native extension, normalize `.toml` Codex basenames as role names, and refuse a matching unmanaged Codex role. Add a Codex TOML collision test alongside the Cursor case.
