### High

- **Provider capability validation rejects supported Claude effort pairs** (`packages/cli/src/providers/claude/targets.ts:11`)
  - Issue: `CLAUDE_MODEL_EFFORTS` permits only `sonnet/{medium,high}`, `opus/{medium,high,xhigh,max}`, and `fable/{high,xhigh,max}`. The project's retained provider evidence already states that Sonnet 5 supports `low`, `medium`, `high`, `xhigh`, and `max` (`tools/smoke/verification/claude-effort-live.md:35`), and the [current official Claude Code model configuration](https://code.claude.com/docs/en/model-config#adjust-effort-level) lists those five levels for Fable 5.1/5, Opus 5, Sonnet 5, Opus 4.8, and Opus 4.7, with `low`, `medium`, `high`, and `max` for Opus/Sonnet 4.6. A direct source probe confirms that the shipped validator rejects `sonnet/low`, `sonnet/xhigh`, `sonnet/max`, `opus/low`, `fable/low`, and `fable/medium`. Because this shared validator gates candidate resolution and variant naming/materialization, these provider-supported explicit cells fail before they can be selected or launched. This contradicts the plan's requirement to support documented effort labels and to let other supported pairs be configured explicitly (`plan.md:45`, `plan.md:66`). The alias-only static matrix also cannot satisfy the plan's version-awareness rule where `sonnet` resolves to different model versions by provider.
  - Fix: Separate provider capability validation from bundled recommendation and task-routing eligibility. Accept every documented model/version pair that OAT can establish, including the missing low/medium/xhigh/max combinations, and make alias resolution version-aware. When the resolved alias version or provider capability cannot be established, return a clear ambiguity/capability error instead of declaring the pair unsupported. Add resolver and materializer tests for the missing valid pairs and a version-dependent control, such as accepting Sonnet 5 `xhigh` while rejecting Sonnet 4.6 `xhigh` under the project's fail-closed contract.
  - Requirement: SC1, SC2; `plan.md` Compatibility and Selection Contract.
