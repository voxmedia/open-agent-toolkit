### Low

- **Generated Claude variant names repeat the `claude` token for versioned model IDs** (`packages/cli/src/providers/claude/targets.ts:327`)
  - Issue: `buildClaudeEffortVariantName` emits `${agent}-claude-${normalize(model)}-${effort}`. The plan's example (`oat-reviewer-claude-opus-high`) assumed alias models, but recommendation `2026-09-21.1` ships only versioned IDs, so every recommended variant is named `oat-reviewer-claude-claude-opus-5-high` / `oat-phase-implementer-claude-claude-opus-5-high` (verified from resolver output). Deterministic and collision-free, but noisy in dispatch stamps, `.claude/agents/`, and orchestrator prompts.
  - Suggestion: Strip one leading `claude-` from the normalized model slug before composing the name (the existing normalized-name collision refusal in `materializeClaudeAgents` still guards duplicates). Because sync removes stale managed variants, the rename is self-healing; if kept as-is, document the naming shape in `apps/oat-docs/docs/provider-sync/providers.md`.

- **Legacy Claude model-only routes report `effortAxis: not-applicable` while the decision record calls them provider-default effort** (`packages/cli/src/commands/project/dispatch-ceiling/index.ts:2081-2084`)
  - Issue: With a model-only ladder (`opus`), the resolver reports `effortAxis: 'not-applicable'` (verified). `DR-260921-claude-effort-aware-dispatch.md` says legacy candidates "continue to use the native model argument with provider-default effort", and the axis glossary in `.agents/skills/oat-project-implement/references/dispatch-and-dry-run.md:418-422` defines `not-applicable` as "no meaningful per-dispatch concept for that axis" and reserves `provider-default` for Codex. The three surfaces are not contradictory in effect but read inconsistently now that Claude has an effort axis.
  - Suggestion: Either report `provider-default` for Claude model-only targets (and widen the glossary entry beyond Codex), or add a glossary note that Claude model-only launches report `not-applicable` because the per-call Agent API carries no effort. Adjust the tests at `index.test.ts:5817` and `:6289` accordingly if the label changes.

- **Recommendation-version prose attributes unchanged Cursor tiers to `2026-09-21.1`** (`apps/oat-docs/docs/workflows/projects/dispatch-ceiling.md:83-107`)
  - Issue: The paragraph now says version `2026-09-21.1` "also interleaves the Cursor `high` and `frontier` tiers ... also drops `claude-opus-5-thinking-max` and `claude-fable-5-thinking-xhigh`" and closes with "An adopter still on the prior version keeps their existing Cursor tiers untouched". - **Capability-evidence equality relies on `JSON.stringify` key order at three sites** (`packages/cli/src/providers/claude/dispatch-envelope.ts:150`, `:210`; `packages/cli/src/providers/claude/targets.ts:241`)
