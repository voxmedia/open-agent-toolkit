Project Recap

Authored project recap.

Overview

Explainer Kit stopped producing explainers worth reading. This project rebuilt how they are authored.

Note

This recap was generated by the redesigned kit, running against its own project artifacts. It is both the deliverable and the first real test.

Original request

A recap the kit produced for an unrelated project was, in the reviewer's words, "basic AF." The kit had passed every gate it owned while shipping a page nobody wanted to read.

The request was to find out why and fix the cause, not the symptom. Three constraints shaped the work:

  • Recaps can be more structured than decks, but structure must come from guidance rather than rigid schemas.

  • Decks and explainers need genuine artistic freedom.

  • Runs should be recognizably consistent without being replicas. Two runs of the same project may legitimately differ.

Success meant a kit whose output varies with its content instead of with its template.

Key agent decisions

DecisionReasonConsequence
Two authoring paths per artifactOne mode cannot serve both a structured recap and an expressive deckNarrative artifacts render deterministically; artistic ones are composed by the agent
Prose carries quality, schemas carry identityEditorial expectations encoded as schema became shape-checking, which is not qualityRichness is verified by reading output, not by assertion
Guidelines degrade to warningsA floor miss is an editorial signal, not a corruptionSafety and provenance stay hard errors; everything else reports
Recipe policy owns expansionIf authors pick their own freedom level, every author picks the freestCohesion survives without forcing identical output
No content generator shipsBundling one would recreate the rigidity being removedThe calling agent is the author, through a caller-owned seam

The last decision is the load-bearing one. The kit does not write; it renders, validates, and records. A caller that supplies a weak author still gets weak output, and that was accepted deliberately.

As-built architecture

Recipe policy decides how each artifact is authored. The author proposes what the content warrants. Neither side chooses both.

That fence is the run pipeline, and it is deliberately linear: the inline renderer lays nodes out in sequence, so a chain is the shape it represents faithfully. The branching form — where the seam fans out to two renderers and they converge again — is a composed diagram on the artistic path, linked from this page. Choosing the right path per artifact is the redesign in miniature.

The two paths differ in what the agent hands over:

Narrative pathArtistic path
Author returnsMarkdownHTML
Structure fromDeterministic rendererAgent composition
InteractivityNoneHash-pinned shell scripts only
Typical useRecaps, deep divesDecks, diagrams

Markdown is the renderer's actual input, not a provenance record of something already rendered. Tables, alert callouts, fenced timelines, and fenced diagrams survive as structure.

Safety is positional rather than advisory. Artistic artifacts may be composed freely but may only carry scripts whose hashes are pinned, so an agent cannot introduce behavior while composing layout.

Important

Automated tests are not sufficient here, and this run proved it. After the suite above was green, three defects were found by opening the page in a browser: section numerals rendering as body text, diagram labels downscaled to 8px, and wrapped list items splitting into separate lists. The linked process deep-dive records what that implies.

Outcome

Working now: content-driven artifact sets within policy caps, Markdown that renders as structure, an artistic path that cannot smuggle in behavior, warnings that inform instead of blocking, and resumable approval that survives a rejected draft.

Not shipped: automatic render QA. It was built during the revision phase and then removed. It had grown to own a browser dependency and a large share of the test surface, and the published CLI did not ship the driver it imported. The agent generating an explainer reviews it in a browser instead.

The next reader should run the kit on a real project and judge the output by reading it. That is the only test that matters for this change, and it is the test the redesign was built to pass.
