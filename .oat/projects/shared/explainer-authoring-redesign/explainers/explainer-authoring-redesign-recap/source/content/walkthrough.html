Project recap · walkthrough

Explainer Kit stopped producing explainers worth reading

A recap the kit produced was, in the reviewer's words, "basic AF" — while passing every gate the kit owned. This walkthrough covers why, and what changed.

Request → diagnosis

The cause was where quality lived, not how hard it was enforced

  • Before: editorial expectations encoded as schema. Authors filled fixed slots, so every recap had the same shape.
  • Tightening the schema made it worse — the schema described shapes, not quality.
  • After: expectations live in author briefs as prose; schemas define only machine boundaries.

As-built architecture

Two paths, chosen by policy rather than by the author

Decision · trade-off

The load-bearing decision: no content generator ships

  • Bundling a generator would recreate the slot-filling rigidity being removed.
  • The calling agent is the author, reached through a caller-owned seam.
  • Accepted cost: a caller that supplies a weak author still gets weak output, and richness cannot be unit-tested.

Validation

Evidence, and the limits of that evidence

  • Core 224 · adapter 59 · smoke 129 · release 44 — plus lint, type-check, and the real-Chromium visual gate.
  • The anti-regression fixture was verified non-vacuous: breaking the table renderer fails 6 of 8 assertions.
  • But three real defects shipped past all of it and were caught by opening the page in a browser.

Outcome · next

Judge it by reading the output

Run the kit on a real project and read what it produces. That is the only test that matters for this change, and the one the redesign was built to pass.
