### Important

- **The autonomous quality mechanism is still a caller promise, not a shipped authoring path** (`.agents/skills/oat-project-complete/SKILL.md:284`)
  - Issue: Both lifecycle callers only instruct the executing agent to “construct” a brief-aware author seam. There is no concrete provider-backed author driver, module-materialization protocol, or completion-path implementation that can answer the iterative `author-request/v2` calls. The lifecycle test only regex-matches that prose (`.agents/skills/oat-explainer-kit/tests/completion.integration.test.mjs:107`), while the anti-regression test's `richAuthor` returns a checked-in rich fixture (`.agents/skills/explainer-kit/tests/e2e-recap.test.mjs:159`). This proves the renderer can preserve rich input, but not that automated completion can produce that input from project evidence—the original “basic AF” failure mode.
  - Fix: Ship a concrete lifecycle author driver or a precise host-model callback/materialization protocol, then add a behavioral completion → adapter → core test or eval that starts from lifecycle evidence and demonstrates rich authored output without a prewritten recap fixture.
  - Requirement: Discovery success criterion “autonomous recap renders genuinely rich structure without human touch.”

- **Artistic HTML can retain active forms and non-self-contained relative SVG resources** (`.agents/skills/explainer-kit/scripts/lib/html-safety.mjs:505`)
  - Issue: `isUnsafeUrl` returns early for every non-HTTP(S) value, so `form action="mailto:..."`, relative `action`/`formaction`, and relative `image`/`use` resources pass the hard validator. The secondary QA regex only recognizes a subset of quoted HTML `src` attributes and does not cover SVG `<image href>`/`<use href>` (`.agents/skills/explainer-kit/scripts/lib/qa.mjs:19`). Agent-authored output can therefore submit data or depend on unpinned bucket-relative assets despite the self-contained/external-active-content hard boundary.
  - Fix: Reject form submission targets outright (or remove form controls from the allowlist), apply scheme-aware URL policy before the external-URL early return, and require resource elements to use explicitly allowed inline data or same-document fragment references. Add tests for relative, `mailto:`, unquoted, SVG `href`, and `srcset` cases.
  - Requirement: D3 and the hard safety boundary.

- **Normal core and adapter CLI runs have no way to execute render QA** (`.agents/skills/explainer-kit/scripts/run.mjs:236`)
  - Issue: The run only performs browser probes when a caller injects `options.browserProbe`; otherwise it always records the skip warning. The core CLI accepts author/critic/publish/durability modules but no browser-probe module (`.agents/skills/explainer-kit/scripts/run.mjs:1171`), and the adapter ships no runtime implementation. Thus the documented “first-class stage in every mode” is practically skipped on normal CLI/lifecycle paths even where Chromium exists.
  - Fix: Package or resolve a supported probe runtime and expose it through the core/adapter invocation boundary. Attempt runtime launch in normal runs and emit `render-qa-skipped-no-headless-runtime` only after actual capability detection fails.
  - Requirement: Render QA success criterion and design component 6.

- **The probe battery still misclassifies hidden content and misses unreachable or animated content** (`.agents/skills/explainer-kit/scripts/lib/qa.mjs:215`)
  - Issue: The scroll-container exemption suppresses every descendant of any horizontally scrollable ancestor, including content positioned at a negative offset that scrolling can never reveal. The heading probe reports intentionally hidden panels and screen-reader-only headings as unreadable (`.agents/skills/explainer-kit/scripts/lib/qa.mjs:240`). The motion probe checks element styles only and ignores `::before`/`::after`, so a running pseudo-element keyframe reports `animationsDisabled: true` (`.agents/skills/explainer-kit/scripts/lib/qa.mjs:259`). These cases were reproduced in real Chromium during review.
  - Fix: Compute whether an off-viewport element is actually reachable within the ancestor's scroll range; distinguish hidden/`aria-hidden` content and visually-hidden accessibility text from visible headings; and inspect both pseudo-elements for animation/transition state. Pin all cases with real-browser regressions.
  - Requirement: Render QA must detect clipping and active motion without noisy false positives.

- **Markdown and diagram degradation warnings are discarded before the manifest** (`.agents/skills/explainer-kit/scripts/run.mjs:182`)
  - Issue: `renderArtifact` returns section warnings (`.agents/skills/explainer-kit/scripts/lib/render.mjs:79`), including unsupported-diagram, heading-depth, and escaped-raw-HTML findings, but `executeRenderStage` neither returns nor appends them. A real run with `sequenceDiagram` rendered the fallback warning block while its result/manifest omitted `unsupported-diagram`. D7's planned warning is therefore silent.
  - Fix: Aggregate `rendered.warnings` into the render stage and `state.warnings`, deduplicate them, and add end-to-end assertions for unsupported diagram grammar, heading-depth jumps, and raw-HTML escaping.
  - Requirement: D7 and guideline/style findings must persist as warnings.

- **Author provenance is entirely self-asserted by the callback** (`.agents/skills/explainer-kit/scripts/run.mjs:885`)
  - Issue: The v2 schema accepts arbitrary `authorId`, `generatedAt`, and `method` from the author (`.agents/skills/explainer-kit/schemas/author-result.v2.schema.json:20`); the runner validates only shape, artifact identity, and content path, then retains and hash-pins the callback's claim. A callback can impersonate another author or backdate generation, so immutable hashing proves only that the spoofed claim was retained, not that provenance is authentic.
  - Fix: Bind author identity/method through trusted caller configuration and stamp or verify generation time in the core. Treat callback-returned provenance as untrusted metadata unless it matches that trusted context, with mismatch remaining a hard error.
  - Requirement: Provenance integrity remains a hard invariant.

- **Project lifecycle artifacts claim completion while retaining stale in-progress state and placeholders** (`.oat/projects/shared/explainer-authoring-redesign/implementation.md:1`)
  - Issue: `implementation.md` remains `oat_status: in_progress`, uses `oat_current_task_id: complete` instead of `null`, and leaves the required Final Summary as placeholders (`.oat/projects/shared/explainer-authoring-redesign/implementation.md:369`). `state.md` frontmatter says complete while its body still says Phase 1 / 0 of 20 tasks (`.oat/projects/shared/explainer-authoring-redesign/state.md:82`). This is artifact drift, not a code defect, but it makes final-review/closeout state unreliable.
  - Fix: After findings are received, align `implementation.md` and `state.md` with the actual phase, task count, verification, review status, design deltas, and next boundary. Do not mark implementation complete until this review is resolved.

### Medium

- **Declared `maxPerType` expansion limits are never enforced** (`.agents/skills/explainer-kit/scripts/lib/recipes.mjs:166`)
  - Issue: Recipe validation accepts and validates `expansion.limits.maxPerType` (`.agents/skills/explainer-kit/scripts/lib/recipes.mjs:437`), but proposal evaluation checks only per-profile `maxCount` and total `maxArtifacts`. A valid future recipe can therefore declare a finite type cap that the author bypasses through multiple profiles.
  - Fix: Track accepted counts by artifact type, reject over-type-cap proposals with a stable warning/reason, and add synthetic dual-profile coverage.

- **Narrative conversion drops the Markdown lead and permits duplicate section IDs** (`.agents/skills/explainer-kit/scripts/run.mjs:945`)
  - Issue: When any `##` heading exists, `markdownContentModel` slices only from the first such heading onward, silently discarding all prose between the document title and first section. Repeated headings also produce duplicate slug IDs because the run never calls the otherwise-existing content-model duplicate validation. Both behaviors reduce author freedom and can create invalid navigation.
  - Fix: Parse the document once, preserve lead content as a rendered introduction, and reject or deterministically disambiguate duplicate generated section IDs. Add full-run fixtures for both cases.

- **Browser findings emit both stable render-QA IDs and ad hoc `qa-*` duplicates** (`.agents/skills/explainer-kit/scripts/run.mjs:252`)
  - Issue: After mapping browser codes through `renderQaWarningIds`, the runner also prefixes every non-`viewport-*` warning as `qa-*`. Inner overflow, heading readability, motion, keyboard, theme, and deck-layout findings therefore produce two warning vocabularies, contrary to the documented stable IDs and complicating consumers.
  - Fix: Exclude all mapped browser codes from generic structural warning conversion, and assert the exact manifest warning set for an injected browser defect.
