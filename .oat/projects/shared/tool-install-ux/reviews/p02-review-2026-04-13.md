### Medium

- **Both-scope installs still normalize to project on default submit** (`packages/cli/src/commands/init/tools/index.ts:351-364`, `packages/cli/src/commands/init/tools/index.test.ts:406-410`)
  - Issue: `buildUserScopeChoices()` only checks the follow-up checkbox when the existing location is exactly `user`. For packs already installed in both scopes, the label shows `current: project + user`, but the checkbox is left unchecked. Because the prompt text says "unselected go to project scope", pressing Enter without changing that checkbox now removes the existing user-scope install and keeps only the project copy.
  - Impact: This still violates the "prepopulate with current install location" intent for the only state that cannot be represented by the current boolean prompt. More importantly, it creates a silent destructive default for users who are just reinstalling/updating packs and accept the prompt as-is.
  - Fix: Split `both` into an explicit follow-up branch instead of mapping it onto the unchecked project default. The smallest safe fix is a second prompt for `both`-installed packs that asks whether to keep `project`, keep `user`, or leave both alone; alternatively, keep the current checkbox UI but skip migration cleanup when the prior state is `both` and the user does not explicitly change that pack's selection.
