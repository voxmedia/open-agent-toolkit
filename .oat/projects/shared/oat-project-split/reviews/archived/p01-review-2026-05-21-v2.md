## Findings

### Critical

- **Child discovery revalidation gate still misses planned split-created children** (`packages/cli/src/commands/project/complete-discovery/index.ts:111`)
  - Issue: `complete-discovery` validates the updated `discovery.md`, and `validateInheritedContextGate` only fires when that same frontmatter has `oat_parent` (`packages/cli/src/validation/project-state.ts:224`). But the accepted design stores `oat_parent` in child `state.md` (`design.md:418`) and the Phase 2 seeding task says child `discovery.md` frontmatter includes `oat_inherited_context_revalidated: false` while `oat_parent` is written to `state.md` (`plan.md:468` and `plan.md:469`). A child seeded according to the plan can therefore run `oat project complete-discovery` and pass despite `oat_inherited_context_revalidated: false`. The new test covers only a discovery file that also contains `oat_parent`, which the plan does not require.
  - Fix: Make `complete-discovery` validate the child relationship using `state.md` as well as `discovery.md`, or treat the presence of `oat_inherited_context_revalidated: false` in discovery frontmatter as sufficient to block completion. Add a call-site test where `state.md` contains `oat_parent` and `discovery.md` contains only `oat_inherited_context_revalidated: false`, matching `p02-t03`.
  - Requirement: p01-t02

### Important

- **Parent existence checks are still skipped by state write boundaries** (`packages/cli/src/validation/project-state.ts:148`)
  - Issue: Missing-parent validation only runs when `relatedProjects` is supplied. Several real state mutation paths still call `assertValidProjectStateContent` without related project snapshots, including `complete-state` (`packages/cli/src/commands/project/complete-state/index.ts:76`), `open` resume (`packages/cli/src/commands/project/open/index.ts:111`), and `pause` (`packages/cli/src/commands/project/pause/index.ts:152`). Those commands can rewrite a child `state.md` with `oat_parent` pointing at a missing parent without enforcing the p01-t02 rule that `oat_parent` must reference an existing coordination project.
  - Fix: Use the filesystem-aware validator for project state write boundaries that operate on an existing project, passing the project path so sibling/parent snapshots are loaded. Add command-level tests for at least `complete-state` or `pause` rejecting a child state whose `oat_parent` directory is missing.
  - Requirement: p01-t02
