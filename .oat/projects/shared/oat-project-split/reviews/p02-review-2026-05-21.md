### Important

- **Coordination parent discovery omits required split context** (`packages/cli/src/projects/split/write-parent.ts:56`)
  - Issue: `renderParentDiscovery` writes only origin/interactivity, a child slug/description list, and the integration sketch. The discovery/design success criteria require the coordination parent to record split rationale, child list, ordering, sibling/dependency relationships, shared constraints/broad context, and the integration sketch. As written, the durable parent artifact cannot reconstruct why children are ordered or related, and it drops the per-child inherited context that is otherwise only present in child discoveries.
  - Fix: Expand the parent discovery rendering to include ordered children, each child's dependencies/sibling context, inherited/broad context, and any shared constraints available in the `SplitPlanDocument`; add assertions in `write-parent.test.ts` and the integration suite for those sections.
  - Requirement: p02-t02 / discovery success criteria

- **`run` and resume bypass full `SplitPlanDocument` validation** (`packages/cli/src/commands/project/split/run.ts:57`)
  - Issue: `run.ts` accepts any string as `origin` and only shallow-checks the document before executing. `resume.ts` repeats the same shallow check for persisted `references/split-plan.json` and never re-runs `validateChildPlan` on the recovered plan. This conflicts with p02-t07's "reads and validates a `SplitPlanDocument`" contract and p02-t05's requirement that resume validates the persisted document rather than trusting partial state. A mutated partial-run `split-plan.json` can therefore resume with invalid origin metadata or invalid child graph data.
  - Fix: Share/export the document-shape validation from `validate-plan.ts` (including allowed origin enum and `interactive`), normalize `knownDependencies`, and call `validateChildPlan` in both the fresh `run` path and `detectPartialSplit`/`resumeSplit` before writes. Add tests for invalid origin on `run` and invalid dependency/foundation/initial-active values in persisted resume data.
  - Requirement: p02-t05, p02-t07
