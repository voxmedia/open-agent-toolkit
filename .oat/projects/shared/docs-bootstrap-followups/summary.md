# Project Summary: docs-bootstrap-followups

## Overview

This project closed two downstream issues in the OAT docs bootstrap flow. The
first was a consumer-monorepo CI break where a freshly scaffolded Fumadocs app
was pulled into the default root Turbo build and collided with older React/Next
dependencies. The second was silent loss of manual edits to generated
`index.md`, because `oat docs generate-index` rewrites that file on every
`predev` and `prebuild`.

The work shipped in quick mode with two implementation phases and two review-fix
phases. It covered CLI behavior, scaffold assets, skill guidance, release
metadata, review-workflow guidance, and project documentation.

## What Was Implemented

- `oat docs init` now patches compatible root Turbo build scripts in consumer
  repos so default root builds exclude the new docs app, and it adds a
  root-level `build:docs` command for docs-only builds.
- Root-package patching now follows a conservative skip policy for ambiguous
  cases:
  - no `scripts.build`
  - non-Turbo root builds
  - pre-existing user-authored Turbo `--filter` flags
  - composite shell expressions such as `turbo run build && pnpm lint`
- The CLI now exposes the root-patch result cleanly through diff output,
  warnings, manual fallback snippets, `--dry-run`, and `--no-root-patch`.
- `oat docs generate-index` now prepends a stable `AUTOGENERATED` warning to
  generated root `index.md` output, and repeated runs preserve a single correct
  header.
- The Fumadocs scaffold template now ships the same warning so the generated
  file contract is visible before the first regenerate run.
- `oat-docs-bootstrap` now explains the root-build patch rationale, shows the
  diff shape, documents the revert/adjust path, and relays the manual snippet
  when the CLI intentionally skips patching.
- The workflow skills around review execution were hardened so core project
  artifacts are expected to be committed before review boundaries, reducing
  state drift across sessions.
- OAT’s own docs were updated so the command reference and repo bootstrap guide
  reflect the shipped root-patch behavior and generated-index warning contract.

## Key Decisions

- Keep the fix narrow to Turbo-driven root builds rather than trying to support
  arbitrary build systems or shell wrappers.
- Treat ambiguous root build scripts as skip-and-explain cases rather than
  trying to merge semantics automatically.
- Put the generated-file warning in both the generator output and the scaffold
  template so the contract is visible both before and after regeneration.
- Treat bundled assets, scaffold templates, and skill changes as shipped
  functionality and apply the lockstep public package version bump.

## Design Deltas

- The original plan assumed existing Turbo filters might be preserved or
  reconciled. The implementation chose the safer path: skip any user-authored
  filter expression rather than guess how include and exclude filters should
  compose.
- Composite shell expressions were initially under-detected. Final review work
  tightened the safe auto-patch boundary to single-command Turbo builds only.
- The project used quick mode without a dedicated design artifact because the
  request was bounded and the requirements were already concrete.

## Notable Challenges

- The root `package.json` mutation needed to be useful without becoming a
  general shell parser. Most of the review follow-up work came from tightening
  the boundary between “safe to patch” and “must skip”.
- Review bookkeeping drift became part of scope after the project hit repeated
  confusion around uncommitted OAT artifacts between implementation and review
  phases.
- The docs update needed to distinguish between behavior that is now upstream in
  the CLI and behavior that remains capability-gated in the bootstrap skill.

## Tradeoffs Made

- OAT now owns a local unified diff implementation in the root-package patcher
  instead of depending on an external diff library. This keeps the surface local
  but increases owned maintenance code.
- A niche background-operator edge case (`turbo run build & ...`) was explicitly
  deferred after final review because it is low-probability and does not block
  the shipped safety improvements.

## Follow-up Items

- Consider extending composite-shell detection to catch a single `&` background
  operator if that pattern appears in real consumer repos.
- Revisit whether the hand-rolled unified diff helper in
  `root-package.ts` still earns its maintenance cost once the surrounding
  behavior settles.
