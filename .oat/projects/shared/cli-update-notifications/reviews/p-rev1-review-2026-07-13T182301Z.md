- **Accepted updates tell users to rerun an incomplete command** (`packages/cli/src/index.ts:58`)
  - Issue: Bootstrap passes only `formatCommandPath(actionCommand)` to the guard, and that formatter contains Commander node names but no positional arguments or options. Consequently every valid `oat tools update <name>`, `--pack <pack>`, or `--all` invocation is reduced to `oat tools update`, which exits 1 with "Specify a tool name, --pack <pack>, or --all." Scope and behavior flags are also lost for `init` and install variants. This conflicts with the docs and plan's promise to rerun the original command after the old action is cancelled.
  - Fix: Pass a display-safe reconstruction of the normalized user arguments, preserving positional arguments and options, separately from the canonical path used for classification. Add bootstrap/guard tests for named, `--pack`, `--all`, and scoped install/init invocations and assert the success guidance contains a runnable equivalent command.
  - Requirement: Acceptance must stop the old action and ask the user to rerun the original mutation under the updated CLI.

- **The shell-free npm launcher is not portable to Windows** (`packages/cli/src/app/tool-bundle-update-guard.ts:125`)
  - Issue: The accepted path calls `spawn('npm', args, { shell: false })`. Standard Windows Node installations expose npm through `npm.cmd`; Node documents that `.cmd` files cannot execute directly without a command shell. Thus an accepted update fails before npm starts on Windows, even though the feature otherwise claims a portable shell-free argument-array launch. The current injected test verifies only the call shape and cannot detect this runtime failure.
  - Fix: Keep the validated version as a separate argument, but add a platform-aware shell-free launcher. On Windows, resolve npm's JavaScript CLI entrypoint and invoke it with `process.execPath` plus an argument array; on other platforms retain direct executable spawning. Inject platform/executable resolution and add Windows-path coverage that proves no shell or command-string interpolation is used.
  - Requirement: Acceptance must install the exact validated version through a shell-free npm argument array.
