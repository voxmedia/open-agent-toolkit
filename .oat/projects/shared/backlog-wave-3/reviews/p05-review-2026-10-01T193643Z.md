- **M1: Compare the resolved inode after following an AGENTS.md symlink.**
  (`packages/cli/src/commands/instructions/instructions.utils.ts:303`;
  consumer `packages/cli/src/commands/instructions/sync/sync.ts:341`)

  The new preservation check compares device/inode only when AGENTS.md is
  itself regular. Its symlink branch compares realpath strings exclusively.
  If `pkg/AGENTS.md -> ../alias.md` and `alias.md` is a hard link to
  `CLAUDE.md`, both instruction paths resolve to the same file, but their
  realpaths differ. With an independent root AGENTS.md,
  `instructions sync --strategy copy --force` therefore reports
  `update/applied` and replaces the protected CLAUDE.md with root instructions.
  Reads through pkg/AGENTS.md retain the linked instructions, so the previously
  shared instruction sources diverge. Pointer and symlink strategies also
  replace the file. The alias retains the original bytes; this probe does
  not establish total content loss.

  Resolve the symlink endpoint and compare its device/inode with the regular
  CLAUDE.md endpoint, while retaining the fail-closed handling of read errors
  and the distinction for ordinary CLAUDE.md-to-AGENTS.md managed shims.
  Add the combined-link command-boundary regression for all three shim
  strategies: the CLAUDE.md action must be skipped, and its content and inode
  must remain unchanged. Keep the direct-symlink and ordinary-overwrite
  controls. This closes p05-t01's explicit preservation-by-realpath-or-inode
  requirement (`plan.md:1219`); an apply-time relink check is not requested.
