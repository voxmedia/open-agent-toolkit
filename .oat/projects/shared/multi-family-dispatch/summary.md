# Project Summary: multi-family-dispatch

## Overview

This project extended OAT's dispatch policy from a single-family Codex/Claude model to a multi-family routing model that can include Cursor and future model-argument providers. The work covered shared identity primitives, provider-family classification, layered dispatch matrices, family-aware review gate selection, implementation route selection, lifecycle skill guidance, public docs, and release packaging.

The project ran as a quick OAT project with a completed design and plan. Implementation finished through p07, final review and Fable re-review passed, and a post-review audit hardened programmatic execution before PR handoff.

## What Was Implemented

- Added producer identity and provenance primitives, including parseable `Dispatch:` stamps and model-family classification.
- Added sparse provider/tier dispatch matrix config, matrix normalization, source/provenance reporting, validation, doctor checks, and bundled recommendations.
- Registered Cursor as a model-argument provider with availability and current-target probes backed by live binary experiments.
- Changed review-gate target selection to default to same-family avoidance, report achieved diversity, preserve the unknown-producer same-runtime floor, and aggregate producer families for final/range review scopes.
- Added ordered implementation route resolution so managed dispatch can select harness/model/effort targets while preserving dispatch axes.
- Updated lifecycle skills, templates, public docs, generated provider views, bundled assets, and the five public package versions through `0.1.45`.
- Added gate child-process timeouts and structured timeout failure metadata for headless/programmatic review dispatch.

## Key Decisions

- **Dispatch stamps are the producer-identity boundary.** Stamps use single-line key/value grammar so later review gates and lifecycle tools can parse producer, provenance, role, policy, ceiling, and target without brittle prose parsing.
- **Cursor declared identity is high-confidence after validation.** The p01 live experiment showed invalid Cursor model values hard-error rather than silently falling back, so declared Cursor slugs can support high-confidence identity when they pass provider validation.
- **Family diversity is selected before dispatch.** Gates avoid the producer family when known, fall back to the existing same-runtime floor when unknown, and report the achieved diversity outcome instead of silently implying a stronger guarantee.
- **Provider oracles beat curated catalogs.** Validation uses provider-specific availability/model checks where possible instead of shipping a static model catalog that would drift.
- **Routes preserve dispatch axes.** Route resolution keeps harness/model/effort semantics explicit so implementation escalation does not collapse matrix choices into a misleading scalar.
- **Gates V2 remains separate.** Same-target and broader model-level target preference work stayed out of this branch and is tracked separately.

## Design Deltas

- p01 updated the design's Cursor confidence rules after live binary testing proved invalid `--model` values fail rather than silently fall back.
- p03 renamed the dispatch matrix doctor check to `project:dispatch_matrix`, matching the repo's scoped doctor-check convention.
- p06 accepted validation-test file-list drift for the quick-start skill version contract and corrected docs-index verification to target the docs app paths.
- The post-review audit closed the final/range producer-stamp aggregation gap directly instead of leaving it only as a backlog follow-up.

## Notable Challenges

- Repo-local tooling mattered: the global `oat` binary was stale, and Git hooks needed repo-local Node/pnpm resolution to avoid false drift and version-check failures.
- Bundled CLI assets are regenerated by `bundle-assets.sh`; running repo-local CLI commands concurrently can race over `packages/cli/assets`.
- Final review found that same-family gate behavior needed an explicit unknown-producer fallback to avoid regressing below main's same-runtime behavior.
- The final audit exposed that `cursor-agent --version` is not a safe headless availability probe when the keychain is locked.
