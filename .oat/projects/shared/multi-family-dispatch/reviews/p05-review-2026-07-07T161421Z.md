### Important

- **Route target objects collapse model/effort/harness into the wrong dispatch scalar** (`packages/cli/src/commands/project/dispatch-ceiling/index.ts:473`)
  - Issue: p05-t02 requires `(harness, model, effort)` target objects with same-harness dispatch and cross-harness advisory behavior. The resolver currently reduces every target object to `target.model ?? target.effort ?? target.harness`, then compiles that single string through the active provider adapter. That means a same-harness Codex target containing both `model` and `effort` attempts to compile the model as a Codex effort and returns no native dispatch args, while a same-harness harness-only target can become a Cursor `--model cursor` dispatch. This is not an honest same-harness dispatch of the target object.
  - Fix: Resolve adapter-specific dispatch args from the target object instead of first collapsing it to one scalar. For `pinned-variant` providers use `target.effort`; for `model-arg` providers use `target.model`; never use `harness` as the dispatch value. Treat targets without a dispatchable axis as invalid/unresolved or explicit advisory, and add tests for model+effort and harness-only target objects.
  - Requirement: p05-t02

- **Skill guidance can stamp Codex effort variants as declared producer identity** (`.agents/skills/oat-project-implement/SKILL.md:411`)
  - Issue: The new p05-t03 payload-first guidance says concrete `model`, `variant`, or same-harness route args are `declared` producer identity. A Codex pinned `variant` declares the effort axis, not the concrete producer model slug required by the p01 stamp grammar. Following this wording can write `producer=<effort-or-variant> provenance=declared` for Codex subagent dispatches, which corrupts the producer identity used by later same-family gate avoidance.
  - Fix: Clarify that only concrete model args or same-harness route model args declare `producer`. Codex pinned variants should set `effort_axis=selected:<value>` but keep `producer=unknown provenance=unknown` unless an observed or inferred model identity is available. Keep the examples aligned with that rule.
  - Requirement: p05-t03
