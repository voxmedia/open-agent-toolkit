### Important

- **Unknown producer identity can still trigger same-runtime avoidance and block instead of running with a non-claim** (`packages/cli/src/commands/gate/index.ts:829`)
  - Issue: When `--avoid` defaults to `same-family` and the producer identity is not claimable, `listExecTargetCandidates` converts the selection back into same-runtime avoidance (`avoid === 'same-family' && !shouldAvoidSameFamily`). That contradicts the p04 contract that an unknown producer should run with explicit `unknown-producer` metadata rather than claiming or blocking family diversity. In a Cursor/Codex-only environment where the only configured target matches the detected current runtime, this path can return no candidates and error before producing the intended non-claim outcome.
  - Fix: For `avoid === 'same-family'` with an unknown or non-claimable producer, do not synthesize same-runtime filtering. Let the normal candidate walk run, attach `achieved=unknown-producer`, and add a regression where `processEnv` detects the same runtime, only that runtime target is configured, and `--producer-identity unknown:unknown` still executes.
  - Requirement: p04-t03 / p04-t04

- **A target with both `models` and a pinned `--model` can be filtered as one model but execute another** (`packages/cli/src/commands/gate/index.ts:697`)
  - Issue: `targetCandidateModels` prefers `target.models` over a pinned long-form `--model` in `baseCommand`, so selection and diversity filtering can treat the candidate as `models[0]`. Later, `executeTarget` suppresses appending the selected model whenever the base command already contains `--model`, so the child process actually runs the pinned model from `baseCommand` instead. A copied pinned target plus a newly added `models` list can therefore claim `different-family` for one model while executing a same-family pinned model.
  - Fix: Make the configuration unambiguous. Either reject/ignore `models` when `baseCommand` already contains a long-form `--model`, or make pinned `--model` take precedence in `targetCandidateModels` so selection, metadata, and execution all describe the same model. Add a regression for a target with `baseCommand: ['cursor-agent','-p','--model','gpt-5.5']` and `models: ['composer-2.5']`.
  - Requirement: p04-t02 / p04-t03
