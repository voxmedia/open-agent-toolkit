### Important

- **Doctor misses local/user dispatch matrices and cannot report the source layer** (`packages/cli/src/commands/doctor/index.ts:662`)
  - Issue: p03-t06 requires doctor to revalidate configured matrix cells and name the exact cell and config layer. The adopt command defaults `oat config adopt dispatch-matrix` to local config (`packages/cli/src/commands/config/index.ts:1550`), and also supports user config, but doctor reads only shared `.oat/config.json` via `readOatConfig(scopeRoot)` and `collectDispatchMatrixCellRefs` has no layer field. A user who adopts the recommendation with the default command can get no doctor drift warning for stale or unknown local cells.
  - Fix: Build the doctor matrix refs from the effective workflow config layers, or explicitly read user/shared/local configs and tag each ref with its layer. Include that layer in the WARN/PASS message and add tests for default local adoption plus user-level matrix drift.
  - Requirement: p03-t06

### Medium

- **Nested matrix cell keys are accepted but written as bogus provider names** (`packages/cli/src/commands/config/index.ts:744`)
  - Issue: `isDispatchCeilingProviderKey` accepts any suffix after `workflow.dispatchCeiling.providers.`, and `applyWorkflowValue` writes that whole suffix as the provider key. A natural per-tier command such as `oat config set workflow.dispatchCeiling.providers.cursor.high composer-2.5` is saved as `providers: { "cursor.high": "composer-2.5" }` and validated against provider `cursor.high`, not provider `cursor` tier `high`.
  - Fix: Parse provider/tier suffixes explicitly. Support `workflow.dispatchCeiling.providers.<provider>.<tier>` for `economy|balanced|high|frontier` and validate against `<provider>`, or reject nested provider keys with a clear error until per-tier `config set` is implemented.
  - Requirement: p03-t01 / p03-t05
