1. **[important] Data Flow / validator boundaries / closeout refresh — invoking the current summary contract already performs the supposedly later roll-up.**

   Still-loose sentences: “then the owner-controlled prose and summary refresh, then final journal validation before roll-up” (D:101–103), and “Closeout invokes the current summary contract” (D:321). The three named validator modes are a valid correction to round 1, but these two sentences cannot both be implemented literally. Complete invokes the summary skill at Step 3.5; summary Step 6 calls `log rollup`, which writes the summary and can append to the repository ledger. A rejected final journal could therefore already have graduated observations. Also, the disposition “consume the validator at their boundaries” does not say how the existing shared `checkProjectCloseout` remains suitable for complete's early no-write preflight while `complete-state` enforces final validation.

   **Evidence:** `.oat/projects/shared/artifact-cleanup/design.md:98–104`, `:211–219`, `:321–334`, `:406`; `.agents/skills/oat-project-complete/SKILL.md:209–238`, `:569–579`; `.agents/skills/oat-project-summary/SKILL.md:560–589`; `packages/cli/src/commands/project/log/rollup.ts:301–315`; `packages/cli/src/commands/project/closeout-check/index.ts:339–384`; `packages/cli/src/commands/project/complete-state/index.ts:67–98`. Implement's pre-Step-16 call and subsequent header writes are still at `.agents/skills/oat-project-implement/references/completion-and-closeout.md:1269–1305` on this base.

   **Paste-ready replacement:**

   > Keep the existing `closeout-check` contract as the sequence/goal invariant check used by complete's initial no-write preflight. Implement runs that invariant and `journal check --at implement-preflight` before Step 16; review runs `journal check --at review` with an explicit validated phase scope. Complete then performs the owner-controlled terminal prose and summary refresh through an explicit staged summary invocation: author sections and freshness metadata first, suspend before summary Step 6, run `journal check --at completion`, and only after success resume roll-up and downstream publication/commit work. Define that invocation contract in the summary skill and its complete caller; a standalone summary invocation retains its normal behavior. Immediately before its state write, `complete-state` rechecks both the existing closeout invariant and the final journal evaluator. Neither checker requires the lifecycle fields that `complete-state` itself writes to be already terminal. Refusals from the standalone checker and `complete-state` write nothing; a late complete-skill refusal may leave the expressly authorized prose refresh, but must not roll up, seal, archive, or advance lifecycle state.

   This is a correction to the composition of callers, not a fourth validator mode. The public controls should distinguish the early preflight, pre-Step-16 boundary and direct final state command.
