### High

- **H1: Atomically claim a generation before replacing its allocation metadata**

**Location:** packages/cli/src/commands/project/archive/archive-utils.ts:2961-2975; cleanup at 3003-3004 and 3314-3318.

The vacancy decision from evaluateArchiveRetryIdentity is used later with recursive mkdir and an overwriting metadata write. There is no exclusive claim or revalidation tying that write to ownership of the still-pending generation. Two archive calls can both evaluate an unused g2 path. Call B pauses after evaluation; call A completes g2 and removes the active source; B resumes, replaces A's completed metadata with a pending allocation, and clearPendingGeneration deletes A's retained files. B's subsequent source copy fails because A already removed the source, leaving only pending metadata where a successfully completed archive existed.

The root reproduction below exercises the real public archive function. It adds one scheduling barrier to an in-memory derivative of the compiled module, without changing any guard or repository file. A completed g2's state.md disappears and its manifest hash changes after B resumes; g1 remains intact. S3 is disabled and every fixture lives in a removed temporary directory.

**Fix:** Acquire an exclusive allocation claim or lock and re-evaluate identity under that claim. A caller must never overwrite or clear a generation completed by another caller. Keep cleanup tied to the allocation actually owned by this operation. Add a deterministic overlapping-call regression that preserves A's completed g2 and lets B reuse it or refuse without writes.

### Medium

- **M1: Parse the scope-qualified generation names emitted by the archive writer**

**Location:** packages/cli/src/commands/project/archive/archive-utils.ts:469-475; producer at 1470-1475; consumer packages/cli/src/commands/project/archive/sync-runner.ts:253-271.

A cross-scope collision produces a successor named 20261012-demo-g2-local, but parseArchiveSnapshotName recognizes a generation only when -gN ends the local name. It reads this emitted snapshot as projectName=demo-g2-local and generation=1. Consequently, by-name sync demo-local selects the older 20261011-demo-local and omits its newer successor; by-name sync demo also omits that scope-qualified successor. Exact snapshot-name and unnamed sync still reach the snapshot.

The root read-only probe below confirms the parser and selection result. An ordinary demo-g2 control is parsed and included correctly. The separate producer and generation-selection tests pass while this composition fails.

**Fix:** Define one producer/consumer naming contract that includes the originating scope and generation without shortening the hydration directory. Test an actual scope-qualified generation through listing and by-name selection, including the later-date successor case and literal project names containing -gN.

- **M2: Validate plan record uniqueness and phase ownership before accepting journal evidence**

**Location:** packages/cli/src/commands/project/journal-check/rules.ts:351-377; task progress consumer packages/control-plane/src/state/tasks.ts:142-155.
