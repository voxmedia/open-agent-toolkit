    `reviews/adversarial.json` without updating its manifest digest; the other

    `packetXreviews/`, which the prefix/slice calculation normalized to the

    reconciliation candidates from unapproved bytes. This violates p01-t04's

    validation is too late to make consumption of those inputs safe.
  - Fix: Resolve each supplied review path, require exact equality with one
    manifest-declared expected path under a retained canonical packet root,
    reject duplicates, and verify `hashFile(path) === reference.digest` before
    parsing or reconciling. Add negative controls for an altered in-packet
    review and a prefix-collision sibling path, plus an accepted exact-path,
    exact-digest control.
  - Requirement: p01-t04 / Validation Criterion 5.

### Medium

- **Semantically identical reconciliation declarations fail when JSON keys are
  reordered** (`.agents/skills/recon/scripts/lib/contracts.mjs:750`)
  - Issue: The exact declaration check compares
    `JSON.stringify(reconciliation)` with a newly constructed object. JSON
    object key order is not semantic, so a declaration with the same closed
    fields, arrays, and values in another insertion order receives
    `INVALID_RECONCILIATION_PATH`. An independent control reproduced the false
    rejection by reversing only the six declaration keys. This can block a
    valid standard or thorough packet based solely on serializer behavior.
  - Fix: Compare the six required fields and ordered arrays directly, or compare
    canonicalized objects using the repository's canonical JSON helper. Add a
    positive control whose declaration keys are reordered but whose values are
    unchanged.
  - Requirement: p01-t04 / Validation Criterion 5.
