What shipped · correctness fixes

Four writes that can no longer go wrong quietly

The heart of the wave: race conditions, lost updates, and silent data loss on the vault write path — each closed with a regression test proving the old failure.

Lane Why it matters to you
p01 Slack capture idempotency A double-tapped Slack capture or a retried trigger can't create two copies of the same memory — an optional idempotencyKey and a 10-minute dedup table make the write safe to repeat.
p05 Atomic frontmatter edits Two writers touching a note's frontmatter at once can no longer clobber each other — every read-modify-write happens under a single lock, so no update is silently lost.
p03 Tighter path containment The path-safety guard got exact at both call sites: a legitimate ..archive/x.md is admitted while the check is provably not weaker anywhere — verified with a codex cross-model pass that found nothing.
p07 Inbox failure recovery When an inbox AI run crashes mid-flight, its vault side effects are no longer stranded — a post-hoc diff commits the run's own changes, writes a changelog entry, and drops a dead-letter card, while your concurrent edits are never swept.
Why it matters

These are the failure modes you never see until they bite: a duplicated memory, an edit that vanished, a crashed pipeline that half-wrote your vault. After Wave 6 each one fails safe instead of failing silent.

Root cause · completed

The program-long config-revert mystery, solved

Across the whole wave program, .oat/config.json kept losing its 76-line workflow block at boundaries — caught and reverted a dozen times, committed zero. Wave 6's integration gate finally caught it in the act and bisected it to root.

config-revert · trigger → damage → fix 
# the trigger — ran during the integration gate itself
$ pnpm --filter documentation docs:generate
# the stale link: docs app lockfile still resolved oat CLI to 0.1.1
# (PR #156 changed the spec to `latest` but never re-resolved)
# the damage: the stale CLI schema-normalizes config on load
#            → deletes unknown keys (the 76-line workflow block)
# the fix — re-resolve the lockfile, verify the materialized binary
$ pnpm update -r   # → 0.2.6 everywhere; docs:generate verified non-mutating
