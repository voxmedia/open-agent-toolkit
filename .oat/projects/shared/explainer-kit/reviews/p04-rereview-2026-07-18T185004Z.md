  - Root cause: the runner's stdout framing contract differs from the real
    packaged entry's CLI contract, while its tests replace the production
    entry with a non-representative compact-output fixture.
  - Fix: parse the complete JSON document emitted by the real CLI, or define
    and share an explicit machine-output framing contract. Add an integration
    test that feeds a real `buildExplainerRc()` artifact through
    `runExplainerRc()` and asserts request, manifest, receipt, and run-ID
    bindings. Do not substitute a synthetic packaged entry in that test.

- **Wrapper receipt evidence is still not attributable to the packaged run**
  (`tools/release/run-explainer-rc.mjs:365`,
  `tools/release/run-explainer-rc.mjs:437`,
  `tools/release/validate-explainer-acceptance.mjs:289`,
  `.agents/skills/explainer-kit/references/extension-contract.md:52`)
  - Issue: for `scripts/run.mjs`, top-level `--receipt` may name any
    pre-existing JSON object. `readBoundJson()` checks only
    `schemaVersion === "explainer-kit.publish-receipt/v1"` and hashes it; it
    does not validate the receipt contract, compare it with the manifest, or
    require the packaged child to report that output. Acceptance then checks
    that the wrapper repeats the same hash but never reads or semantically
    validates the wrapper receipt. A stale or fabricated receipt therefore
    remains acceptable when all caller-authored hashes agree.
  - The documented sequence is also temporally impossible: it says a wrapper
    can create receipt evidence _after_ the core invocation and declare it
    through top-level `--receipt`, but the runner reads that path immediately
    after the child exits and before returning control to wrapper post-run
    work.
  - Root cause: hash equality is treated as provenance, and core execution
    evidence is being asked to attest wrapper-owned post-run output that does
    not yet exist.
  - Fix: bind only outputs actually reported by the packaged child. Validate
    wrapper-owned post-run evidence separately against the immutable core
    execution record, manifest hash, and core run ID; validate the complete
    receipt contract and its manifest/run relationship. Update the extension
    docs to describe an executable pre/core/post sequence and add a negative
    test where the runner and wrapper repeat the same hash for a foreign
    receipt.
  - Requirement: FR12, FR14, NFR4
