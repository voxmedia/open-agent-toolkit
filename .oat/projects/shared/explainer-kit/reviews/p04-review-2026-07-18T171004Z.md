## Findings

### Critical

- **Acceptance validation hashes a different RC identity than the builder** (`tools/release/validate-explainer-acceptance.mjs:727`)
  - Issue: `build-explainer-rc.mjs` includes `schemaVersion` in the object hashed
    into `rcId`, and `run-explainer-rc.mjs` verifies that same shape. The
    acceptance validator's `candidateIdentity()` omits `schemaVersion`, so every
    real builder-produced RC fails `E_RC_IDENTITY`. The acceptance tests hide
    the defect by generating fixture IDs with the validator's divergent helper
    instead of consuming builder output. An independent real build produced
    `rcId`/builder hash
    `sha256:c35b84ab6a5b460d28de335d3ee685fb82cfa210c752519638fe021d7d6cdca6`
    while the validator formula produced
    `sha256:e9e1cf83b8a2a7528e8f70fe6ed1e8101d7efd615bc7fb89dfb549995df02b4b`.
  - Root cause: three tools duplicate the release-candidate identity shape.
  - Fix: define one shared canonical identity function/schema, include
    `schemaVersion` in acceptance identity and wrapper snapshots, and add an
    integration test that feeds an actual `buildExplainerRc()` record through
    both runner and acceptance validation.
  - Requirement: FR14, NFR4, NFR6

- **RC output can recursively delete the repository or another source directory** (`tools/release/build-explainer-rc.mjs:159`)
  - Issue: `--output` is resolved without safety constraints and then passed to
    `rm(outputRoot, { recursive: true, force: true })`. Supplying `--output .`,
    the repository root, a package directory, or another existing path deletes
    that tree immediately before the staged RC is renamed into its place.
  - Root cause: the atomic staging flow treats an arbitrary caller path as an
    owned disposable RC directory.
  - Fix: reject filesystem roots, the repository root/ancestors, all source and
    candidate roots, symlinks, and non-owned existing destinations. Prefer an
    absent destination or an RC-specific directory carrying an ownership
    marker; atomically swap only previously owned RC output. Add destructive
    path negative tests for `.`, package roots, ancestors, symlinks, and
    unrelated populated directories.
  - Requirement: NFR2, NFR6

- **Dirty-input detection omits most inputs bundled into the CLI tarball** (`tools/release/build-explainer-rc.mjs:29`)
  - Issue: `CANDIDATE_ROOTS` covers the five package directories and only the
    two explainer skills, but `packages/cli/scripts/bundle-assets.sh` also copies
    every bundled skill, bundled agents, OAT templates/scripts, the docs tree,
    migration/config assets, and generated public-package versions. Dirty or
    concurrently changing files in those inputs can enter the retained CLI
    tarball while the RC records a clean `changedCandidates: []` and a commit
    that never contained those bytes.
  - Root cause: the dirty/snapshot inventory is hand-written independently from
    the bundler dependency inventory.
  - Fix: derive one exact bundle-input inventory shared by the bundler and RC
    builder, and apply both pre-build status checks and before/after hashes to
    every input that can affect any retained tarball. Add tracked, untracked,
    and mid-build mutation cases for docs, another bundled skill, agents,
    templates, scripts, and bundle config.
  - Requirement: FR14, NFR4, NFR6

- **Acceptance evidence is not bound to the packaged invocation that supposedly produced it** (`tools/release/run-explainer-rc.mjs:80`)
  - Issue: a packaged execution record contains only RC ID, entry, package,
    verified tarballs, and exit status. It records no request hash, run ID,
    manifest hash, or receipt hash. The acceptance validator then validates the
    execution record and request/manifest/receipt as independent objects. A
    successful packaged run can therefore be paired with a stale or fabricated
    receipt and wrapper result, so `--gate publish`, `--gate wrapper`, or
    `--gate all` does not prove that the frozen RC produced the accepted
    evidence.
  - Root cause: the runner's sanitized execution schema omitted non-secret
    input/output digests needed for provenance.
  - Fix: record canonical hashes for the invoked request and declared output
    evidence (manifest/receipt), plus the core run ID where applicable. Have
    the acceptance validator require those exact bindings and add negative
    tests that reuse a valid execution record with evidence from another run.
    Keep argv values and private content out of the record.
  - Requirement: FR12, FR14, NFR4

- **Public verification accepts stale or incorrect CDN bytes as successfully published** (`.agents/skills/explainer-kit/scripts/lib/s3-static.mjs:201`)
  - Issue: artifact verification checks only HTTP status and content type.
    Unlike the sentinel, it never compares the public response body with the
    manifest SHA-256. A stale cached page—or an existing object whose user
    metadata falsely claims the expected hash—passes and receives the local
    manifest hash in a successful receipt. The current test harness returns an
    empty body for artifact URLs and still passes.
  - Root cause: `defaultHttpGet` returns text and the artifact loop does not
    hash response bytes.
  - Fix: fetch public responses as bytes, compare SHA-256 with each manifest
    artifact hash before writing the receipt, and test a 200 response with the
    expected MIME type but wrong bytes. Preserve exact sentinel body
    verification and support non-text artifacts.
  - Requirement: FR6, FR14, NFR4

- **The release visual matrix never executes a real browser probe** (`.agents/skills/explainer-kit/scripts/render-qa.mjs:109`)
  - Issue: `runReleaseVisualMatrix()` requires a caller-supplied
    `browserProbe`, but Phase 4 supplies no Playwright/Chrome implementation or
    release command. Its tests use canned callbacks that report the expected
    overflow, clipping, motion, keyboard, and deck-layout results. Repository
    search found no other caller, and a direct invocation stops with
    `Release visual QA requires a browser probe callback.` Thus the P0 browser
    QA contract and "release-grade visual" claim are not exercised.
  - Root cause: the matrix orchestration contract was tested, but the real
    browser adapter and release-gate invocation were never implemented.
  - Fix: add a concrete browser driver that serves the rendered cases and
    measures the declared viewports/scenarios, run it from a release validation
    command, fail closed when the browser is unavailable, and retain machine-
    readable results. Keep the structural matrix tests as unit coverage.
  - Requirement: NFR3

### Important

- **AWS metadata verification depends on ambient CLI output configuration and skips transient retries** (`.agents/skills/explainer-kit/scripts/lib/s3-static.mjs:364`)
  - Issue: `head-object` does not force `--output json`, yet both
    `readExistingMetadata()` and `assertMetadata()` unconditionally
    `JSON.parse(stdout)`. A valid AWS profile configured for `text` or `table`
    output makes publishing fail. The pre-upload metadata check also calls the
    raw command seam instead of `runAws`, so transient failures receive none of
    the bounded retries documented for object operations.
  - Fix: force machine-readable JSON on every parsed AWS operation, route
    metadata reads through the bounded retry/error classifier, and add tests
    for ambient non-JSON defaults and transient `head-object` failure.
  - Requirement: FR6, NFR1

- **Credential-bearing public URLs are accepted and persisted in receipts** (`.agents/skills/explainer-kit/scripts/lib/s3-static.mjs:44`)
  - Issue: the schema and normalizer accept URL userinfo. An independent probe
    normalized `https://user:secret@cdn.example.com/root` unchanged, after
    which the secret would appear in receipt roots and every artifact URL.
  - Fix: reject non-empty URL usernames/passwords before network access and
    receipt creation. Prefer rejecting query/fragment-bearing roots rather than
    silently rewriting them, and add a no-secret-persistence test.
  - Requirement: NFR2

### Medium

- **RC artifact discovery relies on an undocumented hard-coded output directory** (`tools/release/run-explainer-rc.mjs:261`)
  - Issue: the builder permits arbitrary independent `--output` and `--record`
    paths, but the runner searches only beside the manifest and
    `<cwd>/dist/explainer-kit-rc`. A valid retained candidate built to another
    directory with its record elsewhere cannot be run without manually moving
    artifacts.
  - Fix: record a safe manifest-relative artifact location, colocate artifacts
    and record by contract, or add an explicit contained `--artifacts-dir`
    argument. Remove the implicit cwd fallback or document and validate it as
    part of the v1 contract.
  - Requirement: FR14
