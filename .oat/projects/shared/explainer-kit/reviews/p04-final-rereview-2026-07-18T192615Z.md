## Final Fix Assessment

### Complete JSON framing

`parseEntryResult()` now parses `String(stdout).trim()` as exactly one JSON
object. It accepts the real core's multiline pretty-printed document and rejects
progress text or line-delimited guessing. The new real integration test uses
`buildExplainerRc()` and the actual packaged `scripts/run.mjs`, rather than a
synthetic entry.

### Wrapper post-run provenance

The runner no longer accepts top-level wrapper receipt assertions. A core
execution record contains `outputs.receipt: null` unless the packaged child
itself reports a receipt. After runner completion, wrapper post-processing
retains:

- `private-wrapper-execution.json`
- `private-wrapper-manifest.json`
- `private-wrapper-publish-receipt.json`
- `private-wrapper-result.json`

Wrapper acceptance verifies the RC/tarballs, canonical request and manifest
hashes, core run ID, exact receipt shape, corresponding roots, every manifest
artifact/hash/destination, run-unique sentinel identity, verification flags,
and sentinel deletion. The receipt hash is necessary but not sufficient.
