## Findings

### Critical

- **Federated lifecycle invocations cannot run against the real core** (`.agents/skills/oat-explainer-kit/scripts/run.mjs:109`)
  - Issue: `runOatExplainer` forwards `coreOptions` unchanged, while normal
    `project-explainer` and `project-recap` bindings are federated and the real
    core requires `options.critic` to be a function. The lifecycle skills invoke
    the adapter without supplying such a callback, and the JSON CLI context
    cannot encode one. A direct probe against the real core returned
    `outcome: failed`, `E_RUN: Federated fact-base processing requires a
provider-neutral critic callback`, and no manifest. The integration test
    uses a fake core that never enforces this contract.
  - Fix: provide a lifecycle-usable, provider-neutral critic execution seam at
    the adapter boundary (for example, a validated module entry point or an
    explicit callback supplied by every in-process lifecycle caller), wire all
    plan/implementation/completion paths to it, and add an adapter integration
    test against the actual bundled core.
  - Requirement: FR3, FR8, FR10

### Important

- **Finalization verification accepts an absent attestation result** (`.agents/skills/oat-explainer-kit/scripts/finalize-tracked-run.mjs:175`)
  - Issue: an empty `attestation: {}` bypasses the consistency condition, after
    which the verifier returns `ok: true` and `pushAllowed: true` with an
    undefined outcome. A direct probe reproduced this. The verifier can
    therefore authorize the evidence commit and push without evidence that core
    durability verification ran.
  - Fix: require `attestation.durable` to be boolean, require the corresponding
    exact terminal outcome, require an errors array, and reject missing or
    unknown attestation shapes. Add negative tests for `{}`, missing
    attestation, and unknown outcomes.
  - Requirement: FR5

- **A later archive-copy failure leaves a committed recap export that blocks retry** (`packages/cli/src/commands/project/archive/archive-utils.ts:826`)
  - Issue: the recap temporary directory is atomically renamed to its final
    tracked destination before the existing project archive copy begins. If the
    subsequent copy at line 833 fails, the active project remains, but the final
    recap destination remains too; retry then fails with “already exists.”
    This breaks the required retry-safe atomic archive behavior.
  - Fix: treat the newly created recap export as part of the archive
    transaction. On any failure before active-project deletion succeeds, remove
    only the export created by that invocation, or defer its final rename until
    all pre-deletion copy work is ready. Add a failure-injection test for the
    second `copyDirectory` call and assert the active project remains and the
    recap destination is absent.
  - Requirement: FR8

- **Archive accepts a partial or empty hash manifest as valid** (`packages/cli/src/commands/project/archive/archive-utils.ts:599`)
  - Issue: `parseProjectRecapManifest` checks only `recipe.id` and that
    `immutableHashes` is an object. It does not require
    `schemaVersion: explainer-kit.manifest/v1`, validate the closed manifest
    shape, or prove that the hash map covers the manifest-declared immutable
    package. An empty map verifies zero files and permits active-tree deletion
    with an unverified tracked recap export.
  - Fix: validate the selected manifest against the v1 contract (including
    cross-record immutable-path coverage) before export, reject empty/incomplete
    hash maps, and add malformed-version, empty-map, and omitted-artifact tests.
  - Requirement: FR5, FR8
