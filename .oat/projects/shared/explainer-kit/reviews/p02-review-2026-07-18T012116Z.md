## Findings

### Critical

- **Rendered and content writes can escape the run root through nested symlinks** (`.agents/skills/explainer-kit/scripts/run.mjs:622`)
  - Issue: `writeText()` creates parent directories and calls `writeFile()` on
    an absolute path without canonical-parent or symlink confinement. The run
    root check only rejects a symlink at the run root itself. A pre-existing
    `<runRoot>/site` or `<runRoot>/source/content` symlink is followed. A direct
    probe pre-created `site -> <outside>`; the core returned
    `built-not-durable` and wrote
    `<outside>/initiatives/demo/index.html`. This violates the explicit
    root-containment and filesystem-safety requirements.
  - Fix: Route every package write through a confined write primitive that
    validates every existing ancestor after `realpath`, rejects symlink
    ancestors/targets, creates missing directories without following
    attacker-controlled links, and atomically replaces the target. Add
    integration tests for `site`, `source/content`, and nested path symlink
    escapes, including an existing slug directory.
  - Requirement: FR1, FR5, NFR2

- **Core execution bypasses recipe source-role cardinality** (`.agents/skills/explainer-kit/scripts/run.mjs:567`)
  - Issue: `validateRecipeSources()` discards all but the first non-critic
    source with `.slice(0, 1)` and fabricates one binding for the recipe's first
    role. Consequently, a `project-recap` federated request with two independent
    project sources succeeds even though the recipe declares `maxBindings: 1`.
    Unit tests prove `validateSourceBindings()` in isolation, but the production
    core does not pass the real invocation bindings to it.
  - Fix: Represent source-role bindings explicitly at the run-request/recipe
    seam, or define and enforce an equivalent unambiguous one-source-set
    contract. Validate every binding and its kind/cardinality before fact-base
    processing. Add an integration test showing `project-recap` rejects two
    project source sets while still allowing multiple documents inside one
    explicitly identified project set.
  - Requirement: FR3

- **Commit durability can certify an incomplete retained package** (`.agents/skills/explainer-kit/scripts/lib/durability.mjs:242`)
  - Issue: Commit evidence requires only built, non-rebuildable rendered
    artifacts. `requiredArtifacts()` excludes the fact base, content Markdown,
    resolved theme, and other immutable package inputs, and content hashes are
    not represented for commit verification. The existing durability test
    commits only `site/index.html` and receives `built-durable`. That contradicts
    the design's requirement that commit evidence identify immutable inputs and
    built artifacts and weakens the claimed retained/reproducible package.
  - Fix: Define the complete immutable evidence set (fact-base JSON/Markdown,
    content models, resolved theme, and required built artifacts), persist
    hashes for each, and require their repository paths and commit blobs to
    match before setting `built-durable`. Keep manifest/build-record excluded
    from the first evidence commit as designed. Add negative tests for omitted
    or mismatched source/content/theme paths.
  - Requirement: FR5, NFR4, NFR5

### Important

- **`user-switchable` output has no user-operable switch** (`.agents/skills/explainer-kit/scripts/lib/render.mjs:65`)
  - Issue: The renderer emits alternate-mode CSS selected by
    `:root[data-theme-mode=...]`, but the final self-contained artifact contains
    no control or script that changes `data-theme-mode`. Tests only assert that
    both attribute strings occur in the HTML. A user cannot actually switch
    modes, so the named render strategy is not functionally exposed.
  - Fix: Add a neutral, keyboard-accessible theme control (or a shared inline
    mechanism in every shell) that toggles the root mode, preserves the selected
    mode where appropriate, and is absent for `default-only`. Exercise the
    interaction through the browser-probe contract in both modes.
  - Requirement: FR4, NFR3

- **No-JS deck CSS removes the required x-axis containment** (`.agents/skills/explainer-kit/templates/deck-shell.html:133`)
  - Issue: The default deck correctly uses horizontal paging and
    `.slide__content { overflow-x: auto }`, but
    `html:not(.js) .slide__content { overflow: visible }` overrides both axes.
    Wide tables/code can therefore expand the page in the no-JS fallback. The
    amended requirement asked for readable vertical flow while retaining
    x-axis inner-content containment; current tests only match independent CSS
    snippets and do not verify their cascade.
  - Fix: Keep vertical document flow while retaining `overflow-x: auto` (and
    only relaxing the vertical constraint) for no-JS output. Add a computed-style
    or browser probe with wide inner content and JavaScript disabled. Keep print
    behavior explicitly tested as a separate cascade.
