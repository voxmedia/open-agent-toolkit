### Important

- **Explicit force-narrow loses to the configured opt-out** (`packages/cli/src/review-remote/narrowing.ts:185`)
  - Issue: `narrowingPreference === false` returns before `forceNarrow` is considered. An invocation with both the persisted opt-out and explicit `--narrow` therefore returns `narrowing-disabled` without selecting a prior review or running the stale-SHA guard. This contradicts discovery's requirement that existing per-invocation narrowing flags remain unaffected and the remote-rail contract that `--narrow` forces narrowing. The focused tests cover `false` and force-narrow independently but omit their precedence.
  - Fix: Give the explicit flag precedence, for example by applying the disabled early return only when `!input.forceNarrow`, and add tests for `forceNarrow: true` with `narrowingPreference: false` covering both a passing guard and a failing guard.
  - Requirement: Default inversion and preserved per-invocation force-narrow behavior.

- **A reporting-only classification failure aborts the review** (`packages/cli/src/review-remote/narrowing.ts:206`)
  - Issue: `classifyRange` awaits `git.changedFiles` without a failure path. If file enumeration rejects, `pickNarrowingTarget` rejects instead of returning a dispatchable narrowing or full-scope result. Classification therefore gates whether a review runs, contrary to the explicit requirement that it is reporting-only and must never skip or prevent review. The tests cover only successful file enumeration.
  - Fix: Handle changed-file enumeration failure conservatively while preserving review dispatch, either by failing open to full scope with an explicit reason or by returning a documented conservative classification. Add a test whose `changedFiles` rejects and assert that resolution still returns a dispatchable result.
  - Requirement: Range classification is reporting-only; unresolved conditions fail open rather than blocking review.
