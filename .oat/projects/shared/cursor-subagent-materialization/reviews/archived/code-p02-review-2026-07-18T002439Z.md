- **Codex public operation serialization now leaks internal envelope fields** (`packages/cli/src/providers/codex/codec/sync-extension.ts:885`)
  - Issue: `toCodexExtensionOperations` spreads shared operations, so serialized output now includes `provider` and, for roles, `entryName`. A direct check produced `[{"provider":"codex",...,"entryName":"r","roleName":"r"}]`, contradicting p02's requirement to preserve existing Codex public result formatting.
  - Fix: Keep provider tagging on internal plans, but explicitly project the legacy Codex public fields in `toCodexExtensionOperations`. Add an exact-equality or JSON-payload regression test; the current command test uses a mock projector and cannot catch this implementation regression.
  - Requirement: `p02-t01`; Codex compatibility.

- **Full user sync can delete managed Cursor roles when bundled canonical bases are unavailable** (`packages/cli/src/providers/cursor/codec/sync-extension.ts:468`)
  - Issue: User targets are collected, but there is no Codex-equivalent fail-closed check for missing `oat-reviewer` or `oat-phase-implementer` canonical definitions before stale cleanup at line 476. With a valid user Cursor target, empty canonical input, and a stale `user-config` role, the computed plan contains a remove operation. A scanner/bundle omission can therefore erase valid user materialization state.
  - Fix: Before full user-scope cleanup, require all supported Cursor base definitions whenever user materialization targets exist; otherwise throw an actionable error and produce no removal plan. Add the Cursor analogue of the Codex missing-base-definition test.
  - Requirement: `p02-t03`; owner-marker/cleanup safety and Codex-compatible fail-closed behavior.

- **Collision detection checks only the expected filename, not declared agent names** (`packages/cli/src/providers/cursor/codec/materialize.ts:145`)
  - Issue: The scan probes only `<directory>/<desiredRoleName>.md`. Cursor definitions have an explicit `name` field, so `different-file.md` can declare the desired materialized role name and remain undetected. A direct check showed the planner still returning `create` for the colliding role.
  - Fix: Enumerate Markdown definitions in all three discovery directories, parse their declared names conservatively, normalize them with the same naming rules, and reject any unmanaged definition whose declared or filename-derived name collides. Preserve the TOML exclusion.
  - Requirement: `p02-t02`; discovery constraint that generated names must not shadow or be shadowed across compatibility directories.

- **Managed symlinks can redirect writes outside the sync scope** (`packages/cli/src/providers/cursor/codec/materialize.ts:149`)
  - Issue: `lstat` is used only as an existence check and `readFile` follows the link. A symlink whose external target contains valid managed markers passes collision and owner checks; `applyCursorProjectExtensionPlan` then follows it with `writeFile` (`packages/cli/src/providers/cursor/codec/sync-extension.ts:564`). A direct check planned `update` and changed the external target. A symlinked `.cursor/agents` directory similarly leaves stale collection and apply paths outside the lexical scope.
  - Fix: Reject symlinked managed definition paths and symlinked agent directories, or validate real parent/target paths within the scope immediately before every update/remove. Add tests for managed external file symlinks and an external `.cursor/agents` directory, not only unmanaged symlink collisions.
  - Requirement: `p02-t03`; symlink-aware collision scans and safe owner-scoped cleanup.
