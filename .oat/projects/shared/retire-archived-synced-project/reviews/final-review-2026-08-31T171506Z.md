## Findings

### Critical

- **Coordination child pull can resurrect a completed project through its inert active alias** (`packages/cli/src/commands/project/sync/ref-sync.ts:843`)
  - Issue: `pullChildren` queries only `refs/oat/projects/<child>` and immediately calls `pullSynced` when that ref exists. It never probes `refs/oat/completed/<child>`. For the explicitly valid `matching-aliases` terminal shape, a coordination parent whose `oat_children` still names the completed child therefore rematerializes the archived checkout and may create a new active discovery record. This bypasses the direct `project pull` terminal guard and contradicts the core contract that completed authority makes a same-SHA active ref inert and non-pullable.
  - Fix: Before classifying adoption or calling `pullSynced`, inspect the child active and completed refs together. Return a terminal child diagnosis without materializing for completed-only or same-SHA aliases, and return the precise mismatch error for differing SHAs. Add a coordination-parent test covering same-SHA aliases, completed-only, and mismatched child refs, asserting no checkout or record is created.
  - Requirement: Discovery decisions 2-3; success criterion that pull and recovery paths agree on terminal classification; p03-t02 terminal guard contract.

### Important

- **Completed-only prune skips checkout and record cleanup but still reports success** (`packages/cli/src/commands/project/prune/index.ts:245`)
  - Issue: The `completed-only` branch bypasses `pruneSynced` and deletes only the completed ref. That is correct only after normal archive sealing has already removed the checkout and record. An interruption after completed-ref creation but before checkout/record removal is also a valid completed-only state; pruning then leaves the nested worktree and tracked active record behind, prints `Pruned synced project`, and removes the terminal ref that identified the state. This conflicts with the documented command contract that prune removes every checkout and the tracked record, and it leaves state that can be republished.
  - Fix: Make completed-only pruning reconcile and remove any remaining checkout, local active ref, and discovery record before deleting the completed ref, while retaining the completed ref if local cleanup cannot safely finish. Add a real fixture for completed-only refs with both a checkout and record present, then assert the command removes those active artifacts, preserves the archive, and remains retryable across failure boundaries.

### Medium

- **List and dashboard treat completed-ref transport failures as authoritative absence** (`packages/cli/src/commands/project/list.ts:347`)
  - Issue: `probeAuthoritativeCompletedRef` returns `null` for every nonzero `git ls-remote --exit-code` result. Code 2 with empty output is the expected absent-ref result, but authentication, network, and remote failures are also collapsed to absence. During an interrupted terminal closeout with a local checkout or legacy record, list/dashboard can consequently present the project as active or pullable instead of preserving a terminal/recovery diagnosis. Other terminal consumers already use `classifyRemoteRefLookup` to distinguish absence from lookup failure.
  - Fix: Use `classifyRemoteRefLookup` and return `null` only for the verified absent result; propagate a precise lookup failure otherwise. Add list and dashboard tests for an unreachable/auth-failing remote so terminal authority never fails open into active guidance.
