## Findings

### Critical

- **Matching-alias prune can delete a concurrently advanced active ref** (`packages/cli/src/commands/project/prune/index.ts:244`)
  - Issue: `inspectTerminalRefs` observes matching active/completed refs at SHA
    A, but `runPrune` then delegates active-ref removal to `pruneSynced` without
    carrying the observed SHA. That primitive deletes the active ref with an
    unleased `git push origin :<active-ref>`
    (`packages/cli/src/commands/project/sync/ref-sync.ts:1518`). If another
    collaborator advances the active ref to SHA B between inspection and
    deletion, prune removes B rather than failing as a terminal mismatch. The
    newly advanced work can lose its only reachability root, while the command
    proceeds with checkout/record cleanup. The new test at
    `packages/cli/src/commands/project/prune/index.test.ts:191` verifies only
    that `pruneSynced` was called, so it does not exercise this race.
  - Fix: make matching-active-alias deletion compare-and-swap against
    `terminal.activeSha` (for example, pass an expected SHA into a leased prune
    primitive or add a dedicated leased active-alias deletion primitive). On
    lease rejection, re-read both refs and retain the advanced ref without
    removing checkouts, records, or completed history. Add a race test that
    advances the active ref after inspection and proves prune fails closed.
  - Requirement: p03-t03 explicit pruning and the p01 hard-mismatch contract.

### Important

- **Local active rows mask authoritative completed refs** (`packages/cli/src/commands/project/list.ts:410`)
  - Issue: materialized synced projects are emitted without any terminal probe,
    and an active discovery record is classified as `recorded-absent` because
    only records carrying `archiveSourceRefSha` are probed. Later,
    `appendRemoteRows` skips every remote slug already represented locally
    (`packages/cli/src/commands/project/list.ts:488`). A stale branch that still
    has an active record or checkout therefore continues to show the project as
    active, including pull/continuation guidance, even when the remote completed
    ref is authoritative and the active ref is absent or a same-SHA alias. The
    dashboard repeats the same behavior by unconditionally rendering
    materialized synced directories and skipping their records
    (`packages/cli/src/commands/state/generate.ts:477` and
    `packages/cli/src/commands/state/generate.ts:499`). Pull/open subsequently
    block the action, but the discovery surfaces still advertise a terminal
    project as active.
  - Fix: reconcile completed-ref state with local synced rows before finalizing
    list/dashboard classification. A completed-only or matching-alias terminal
    identity must override a stale active record/checkout with terminal cleanup
    guidance; differing SHAs must render the recovery mismatch. Add tests for
    both an active record and a materialized checkout on a stale branch against
    completed-only and matching-alias remote states.
  - Requirement: p03-t01 completed-ref authority and terminal
    list/dashboard suppression.
