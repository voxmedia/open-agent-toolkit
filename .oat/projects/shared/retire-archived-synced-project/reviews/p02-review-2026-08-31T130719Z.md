    This directly violates p02-t03's requirement to require the terminal
    archive receipt before clearing the pointer or declaring completion.
  - Fix: Preserve the original pointer through the archive attempt. For the
    synced archive path, clear it and emit the completion declaration only
    after the report has passed all `lifecycleCommit`, `completedRef`, source
    SHA, alias-disposition, and `recordRetired` checks. Add an executable skill
    transaction case proving an S3/archive error leaves the pointer intact.
  - Requirement: p02-t03

- **A retained record makes a post-ref-transition retry call `pull`, which the
  terminal contract must reject**
  (`.agents/skills/oat-project-complete/SKILL.md:69`)
  - Issue: Step 1 calls `oat project pull` whenever the JSON record still
    exists. An interruption after `retireSyncedRef` but before record deletion
    leaves exactly that shape: a bound record plus completed-only or matching
    terminal refs. Under the approved p01 contract and planned p03 guard, pull
    must reject the terminal project, so the completion skill exits before the
    archive command can resume the already-persisted snapshot. The core tests
    exercise this retry by calling `archiveProjectOnCompletion` directly and
    therefore do not cover the failing skill entry path.
  - Fix: Add a read-only completion-entry router for synced archive retries.
    When the record carries the persisted archive identity and the completed
    ref validates that identity, skip pull and route directly through the
    archive-resume path; keep pull only for genuinely active projects. Add an
    executable interruption case after ref retirement and before record
    deletion.
  - Requirement: p02-t02, p02-t03

  archive recovery can use the persisted snapshot**
  (`packages/cli/src/commands/project/archive/push-runner.ts:315`)
  - Issue: `runArchivePushCommand` always verifies `projectRecapRun` beneath
    `target.projectPath`. After checkout and JSON deletion, that path is

    runner test at `push-runner.test.ts:689` mocks a recordless result without a
    selected recap, so it does not prove the direct command-entry recovery case
    required by p02-t03.
  - Fix: For a recordless synced apply retry, resolve and validate the persisted
    archive identity first, then verify the selected recap from that exact
    archive source (or defer the preflight to the archive core). Add a direct
    `runArchivePushCommand` test with an absent checkout/record and a selected
    recap that reuses the original snapshot and lifecycle receipt.
  - Requirement: p02-t02, p02-t03

### Important

- **Recordless identity is not checked against the completed ref before S3
  synchronization**
  (`packages/cli/src/commands/project/archive/archive-utils.ts:1680`)
  - Issue: A recordless run selects the sole local archive metadata candidate

    the later `retireSyncedRef` call at line 1970. If the only local archive is
    stale and the authoritative completed ref names a different SHA, the
    command mutates S3 before returning the mismatch diagnosis. The plan

    completed ref plus persisted metadata before resuming the snapshot.
  - Fix: Introduce a read-only terminal-ref validation before any export or S3
    side effect on the recordless path. Require the completed SHA to equal the
    metadata SHA and use it to disambiguate multiple archived incarnations;
    retain `retireSyncedRef` after durability for the mutating terminal step.
    Test a stale single candidate and multiple candidates with exactly one
    completed-ref SHA match.
