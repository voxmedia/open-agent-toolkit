## Findings

### Critical

- **Separate remote reads can turn a real SHA mismatch into a terminal receipt**
  (`packages/cli/src/commands/project/sync/resolve-target.ts:95`)
  - Issue: `probeSyncedTerminalRefs` launches one `ls-remote` process per ref
    with `Promise.all`, then treats the two independently observed values as one
    state. If the active ref advances after its lookup reports the bound SHA
    while the completed lookup reports the bound SHA, the function returns
    `both`; `retireSyncedRef` then returns `matching-aliases` and p02 may delete
    the active JSON record even though the current refs differ. This violates
    the revised contract's hard mismatch and makes the terminal receipt unsafe
    as a transaction boundary.
  - Fix: Query both exact ref names in one `git ls-remote` invocation, parse at
    most one exact row for each requested ref, reject duplicate/unexpected
    rows, and classify that single advertisement. Add an interleaving test that
    demonstrates the old two-call implementation can observe an expected
    active SHA before a concurrent advance and an expected completed SHA after
    it; the revised one-call probe must not expose that torn-read path.
  - Requirement: p01-t02 mismatch handling and safe terminal receipt for p02.

### Important

- **Explicit completed-ref pruning is not protected by remote or local leases**
  (`packages/cli/src/commands/project/sync/ref-sync.ts:1301`)
  - Issue: The helper observes the completed ref, then deletes it with an
    unconditional push; it also removes the local ref without supplying the
    observed object ID to `update-ref -d`. A concurrent remote or local advance
    between observation and deletion is therefore erased, although the caller
    authorized deletion only of the terminal identity it inspected. Because
    this ref preserves archived commit reachability, the race can destroy newer
    durable history and makes the primitive unsafe for p03-t03.
  - Fix: Parse and retain the observed remote SHA, delete with
    `--force-with-lease=<completed-ref>:<observed-sha>`, and delete the local ref
    with the observed local SHA as the expected old value. Treat a lease
    rejection or local CAS failure as a precise retryable mismatch while
    preserving the advanced ref. Cover both remote and local concurrent-advance
    cases.
