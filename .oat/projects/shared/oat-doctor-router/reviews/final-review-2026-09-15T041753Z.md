### Important

- **The doctor prescribes a repair command that the CLI refuses for two lifecycle pointers** (`.agents/skills/oat-doctor/SKILL.md:111`)
  - Issue: stale `activeProject` and `lastPausedProject` values are reported with `oat config unset <key> --local`. The CLI deliberately rejects `unset` for both keys and tells the caller to use `oat config set <key> ''` (`packages/cli/src/commands/config/index.ts:2853-2856`). The negative control reproduced exit 1 for the doctor's command and exit 0 for `oat config set activeProject ''`. Exact, executable fix guidance is a primary requirement, so the doctor currently fails its core contract on a lifecycle-blocking finding.
  - Fix: use `oat config set activeProject ''` and `oat config set lastPausedProject ''`; retain `unset` only where the CLI supports it, such as `activeIdea`. Add a contract test that executes these state-pointer repairs, not merely each command stem's `--help`.

- **The projection contract test rejects a valid empty result and currently fails CI** (`.agents/skills/oat-doctor/tests/doctor-contract.test.mjs:211-221`)
  - Issue: `hasPath` requires `next.some(...)` for every `[]` path. In CI, `oat tools outdated --json --scope all` correctly returned `tools: []`, so `tools[].name` was reported missing and PR #300's CI failed. The test passes locally only because the operator has outdated user-scope tools, making it environment-dependent.
  - Fix: make the test deterministic. Assert the top-level array exists even when empty, and seed a controlled project/home fixture with an outdated tool before asserting per-item fields, or validate per-item fields only when a deliberately created item exists. Also bind the expected projection list to the skill table so removing a field from the skill cannot leave the duplicated `PROJECTIONS` constant green.

- **A scratch repository does not offer the required docs bootstrap** (`.agents/skills/oat-doctor/SKILL.md:131-134`)
  - Issue: discovery requires verification on a scratch repository with no `.oat/` where every area offers its bootstrap (`discovery.md:105-106`). The docs rules only emit findings when a docs surface already exists or a configured root is missing. The recorded scratch transcript consequently prints `Docs (ok)` and omits docs from the dive prompt (`implementation.md:117-133`) while the next sentence claims every area offered a bootstrap.
  - Fix: add an informational docs finding that offers `oat-docs-bootstrap` for the uninitialized/no-surface case, then rerun the scratch and non-interactive controls and correct the implementation transcript. If empty repositories intentionally should not receive that offer, explicitly revise the discovery success criterion and explain the accepted design change instead.
