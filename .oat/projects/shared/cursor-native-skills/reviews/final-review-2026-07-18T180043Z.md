### Important

- **General user-config writes can erase legacy known-stray choices before migration** (`packages/cli/src/config/oat-config.ts:1205`)
  - Issue: `readUserConfig` deliberately omits the legacy `knownStrays` field,
    and `writeUserConfig` rewrites the normalized object without first invoking
    `resolveUserSyncConfig`. Consequently, any user-level write such as
    `oat config set updateNotifications false --user`, dispatch-matrix
    adoption, or a gate preference update can delete
    `~/.oat/config.json#knownStrays` before `init` or `status` migrates it. A
    direct reproduction starting with one legacy entry produced a rewritten
    general config containing no `knownStrays` and no migration destination.
    This violates the data-preserving migration requirement and the design's
    shared-resolver requirement.
  - Fix: Route every general user-config write through the legacy migration
    helper before normalizing and replacing `~/.oat/config.json` (preferably at
    the shared `writeUserConfig` boundary so all callers, including gate
    configuration, are covered). Add a regression test that seeds a legacy
    entry, performs an unrelated user-config write, and verifies the entry is
    present in `~/.oat/sync/config.json` while unrelated general settings and
    the requested update are preserved.
  - Requirement: Discovery success criterion “Legacy user known-stray settings
    migrate without losing unrelated user configuration”; Design §4,
    configuration ownership and idempotent migration.
