### Medium

- **Routing-unavailable early return skips all remaining validation, not only routing-dependent checks** (`.agents/skills/recon/scripts/validate-packet.mjs:2190`)
  - Issue: When `manifest && ledger && !routing`, `compileValidatedRun` now
    returns immediately after secret-safety validation (`:2190-2205`). `routing`
    is `null` for any `manifestShape` error or a missing approval envelope
    (`:2139-2148`), so every check after the return — `validateDerivedSourceGaps`,
    source identity retention and `reopenEvidence`, `validatePassOutcomes`,
    `resolveTerminalReconciliation`, `validateReviewBindings`,
    `validateReconciliation`, and the `ROOT_IDENTITY_CHANGED` sweep — is skipped
    even though none of them depend on `routing`. Reproduced at the reviewed head
    with the standard fixture: a manifest with one unknown `request` field plus a
    drifted source file returns only `UNKNOWN_FIELD: 1`, while the same drift
    alone returns `SOURCE_DRIFT: 1, CLAIM_ASSURANCE_INVALID: 1`. The packet stays
    correctly `valid: false, publishable: false`, so this is not a fail-open
    defect, but it is broader than the stated scope: `plan.md` `p05-t03` says
    "Stop dependent lane/condition validation when routing cannot be
    normalized", retro RP-01 says "skip dependent checks when routing is
    unavailable", and the prior review's fix guidance named only
    `validateConditionalRouting`, `validateApprovedLanes`, and the
    `collectCompletePasses` path. `design.md:353-356` requires output that
    distinguishes schema, conditional-evidence, and source/evidence errors —
    which this satisfies by suppression rather than by separation — and
    `packet-contract.md:350-356` still lists all of those checks as performed by
    a single run with no mention of schema-first staging. No test pins that the
    suppression is intentional, so a future change could narrow or widen it
    silently.
  - Fix: Either (a) narrow the skip to the routing consumers — guard
    `validateConditionalRouting`, `validateApprovedLanes`, and
    `collectCompletePasses`/`deriveAchievedProfile` behind `routing !== null`
    (passing an empty pass set and `achievedProfile: null` downstream) while
    still running source, locator, review-binding, reconciliation, and
    root-identity checks — and add a control asserting a shape error plus source
    drift reports both codes without any `UNAPPROVED_LANE`/
    `UNKNOWN_CONDITION_OUTCOME`; or (b) keep schema-first staging deliberately and
    document it in `packet-contract.md` § validation and `design.md` § Error
    Handling ("manifest shape errors are reported alone; evidence checks run only
    on a shape-valid manifest"), pin it with a test, and correct the `p05-t03`
    and RP-01 wording from "dependent" to "all downstream" checks.
