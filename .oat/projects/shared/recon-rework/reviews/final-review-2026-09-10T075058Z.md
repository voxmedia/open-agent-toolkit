    profile-specific singleton set and order, exactly one non-conditional final
    reconciliation for standard/thorough, and only condition-bound contradiction

    for out-of-order stages, non-terminal reconciliation, missing/duplicate required
    modes, and unconditional contradiction resolution; retain valid triggered and

### Medium

- **A malformed v2 `execution.waves` value escapes the structured validation contract** (`.agents/skills/recon/scripts/lib/contracts.mjs:487`)
  - Issue: `requiredArray()` correctly records that `waves` is not an array, but
    `validateExecutionV2()` immediately evaluates `(value.waves ?? []).entries()`.
    An object value therefore throws `TypeError: ...entries is not a function`
    instead of returning categorical validation errors. The public packet CLI fails
    closed, but through its exceptional exit-2 path rather than its documented JSON
    validation result, making malformed external manifests harder to diagnose and
    breaking the explicit hostile-input/structured-error intent.
  - Fix: Iterate over `Array.isArray(value.waves) ? value.waves : []` after recording
    the shape error, and add direct `validateArtifactShape()` plus public
    `validate-packet.mjs` controls showing malformed `waves` arrays return stable
    errors without throwing. Apply the same safe iteration to the adjacent v1 path
    if preserving one validator behavior across supported manifest versions.
