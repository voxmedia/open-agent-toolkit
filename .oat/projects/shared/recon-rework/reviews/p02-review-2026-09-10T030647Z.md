### Important

- **The approval preview hides and does not validate the bounded escalation rule** (`.agents/skills/recon/scripts/lib/routing.mjs:333`)
  - Issue: `createRoutingPreview` returns each wave's target, class, lane count, and
    only a boolean `conditional` flag; it does not expose `conditionId`,
    `destinationWaveId`, `afterWaveIds`, `predicate`, `maxActivations`, lane scopes,
    write roots, or execution authority. Its proposal validator also never reads
    `execution.conditions` or applies profile caps. Consequently a draft containing
    `conditions: [null, ...]` and `maxConcurrency: 99` is previewed successfully, and
    Markdown reduces the conditional rule to `yes` at line 397. The fingerprint
    binds hidden values, but the operator cannot inspect the finite trigger/topology
    they are being asked to approve. This violates the p02-t01 requirement to print
    conditions and the design's complete approval-envelope presentation.
  - Fix: Validate the draft's v2 condition bindings/topology and requested-profile
    caps before producing a preview. Include authority, lane scope/write-root
    topology, and every condition field in both JSON and Markdown output. Add direct
    and CLI controls for valid, missing, malformed, and mismatched conditions.
  - Requirement: p02-t01 items 2-3; Discovery success criteria 2-3.

- **Unsupported launcher controls are rejected only after the fixture records approval** (`.agents/skills/recon/tests/helpers/fake-recon-run.mjs:253`)
  - Issue: The integrated harness calls `approveExecution` before its launcher
    capability preflight at lines 263-304. On an unsupported requested axis it then
    persists an `awaiting-approval` manifest that still contains
    `approval.type: explicit-user-approval`. The test named “stop before approval
    acceptance or launch” asserts only status and `launched: false`, so it passes
    while the recorded evidence contradicts the required pre-acceptance ordering.
    This means the p02-t03 integration evidence cannot prove that unsupported
    controls stop before acceptance.
  - Fix: Perform capability binding against the draft target before
    `approveExecution`, or remove/revoke approval on preflight rejection. Strengthen
    the integration test to assert that rejected manifests contain no accepted
    approval evidence while still producing zero launches.
  - Requirement: p02-t03 item 3.

    lane.
