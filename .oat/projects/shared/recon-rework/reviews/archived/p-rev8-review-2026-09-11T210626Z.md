### Minor

- **Absent terminal reconciliation still emits the derivative thorough-ledger
  diagnostic** (`.agents/skills/recon/scripts/validate-packet.mjs:2470`)
  - Issue: The new guard skips `validateThoroughGatherLedgerInputs` only when
    `reconciliationRequired` is true and `priorLedger` is absent. But
    `reconciliationRequired` is derived from the achieved profile after complete
    passes are collected. If the terminal reconciliation artifact is genuinely
    absent, the reconciliation pass is absent too, the achieved profile falls
    below standard, and `reconciliationRequired` becomes false. The guard therefore
    runs the thorough-input check against the final ledger fallback and can still
    add `MISSING_THOROUGH_GATHER_LEDGER_INPUT` beside the primary missing
    reconciliation failure. A production probe using a thorough packet, an exact
    omitted reconciliation lane gap, no reconciliation artifact, and a final
    ledger containing only the prior-ledger reference reproduced
    `MISSING_THOROUGH_GATHER_LEDGER_INPUT` plus
    `MISSING_RECONCILIATION_RESULT`. The added test at
    `.agents/skills/recon/tests/packet-validation.test.mjs:1048` instead retains
    the reconciliation artifact and corrupts its `inputLedger`; it proves the
    unresolvable-prior case, not the absent-terminal case named by the task.
  - Suggestion: Gate the thorough gather-input check on whether the requested
    standard/thorough terminal reconciliation resolves to a usable prior ledger,
    independently of the post-pass achieved-profile downgrade. Add a control that
    removes the reconciliation artifact/reference, records the exact lane outcome
    gap, leaves an otherwise plausible final-ledger fallback, and asserts that the
    derivative gather-input code is absent. Retain the existing malformed
    prior-ledger test and the independent omitted-gather-input test.
  - Requirement: `prev8-t03` Step 2 and the required one-error-per-defect behavior.
