- **The enforced quick-profile lane cap rejects the motivating high-volume topology** (`.agents/skills/recon/scripts/lib/contracts.mjs:77`)
  - Issue: `profileRoutingPolicy.quick.lanes` is `4`, while the validator sums
    lanes from every wave at lines 556-569. The published quick contract allows
    1-4 gather lanes in addition to one map and one compile wave
    (`.agents/skills/recon/references/profiles.md:14`). The source issue's concrete
    target is one map lane, four gather lanes, and one compile lane. Reproducing
    that six-lane topology returns `PROFILE_LANE_CAP_EXCEEDED`, so the new
    validator blocks the exact economical, high-volume quick run that motivated
    this project. The same topology validator also accepts non-profile extra wave
    modes for quick (semantic, adversarial, coverage, redundant, or reconciliation)
    as long as the aggregate count stays under four, which does not match the
    documented statement that quick has no independent semantic pass by design
    (`profiles.md:19`).
  - Fix: Make the profile policy explicit about both allowed wave modes and what
    each lane cap counts. At minimum, permit map + up to four gather lanes +
    compile for quick while rejecting standard/thorough-only wave modes in quick;
    align standard/thorough counting with their documented adaptive ranges. Add
    direct topology and preview tests for the maximum valid quick example and for
    forbidden cross-profile modes.
  - Requirement: Discovery's cheap, high-volume, multi-wave goal and the approved
    profile contract (`discovery.md:14`, `profiles.md:14`).

- **Object-valued `manifest.artifacts` throws before categorical failure and leaves stale output published** (`.agents/skills/recon/scripts/validate-packet.mjs:148`)
  - Issue: `collectReferences()` iterates `manifest.artifacts` before the
    `manifestCoreUsable` array guard at lines 2184-2190. An object-valued JSON
    collection therefore throws `TypeError: object is not iterable`; the public
    CLI exits 2 with no JSON result and never reaches stale `packet.md` withdrawal
    at lines 2367-2369. I reproduced this with a valid standard fixture changed
    only to `artifacts: {}` and a pre-existing `packet.md`; the stale file remained.
    The new tests call only `validateArtifactShape()` across collection fields and
    use the iterable string `"not-an-array"` for the end-to-end artifacts case
    (`.agents/skills/recon/tests/packet-validation.test.mjs:854`,
    `.agents/skills/recon/tests/packet-validation.test.mjs:887`), so 265/265 tests
    pass while missing this hostile shape.
  - Fix: Gate every reference-list iteration with `Array.isArray()` (including
    equivalent ledger collections where applicable), then add public-CLI negative
    controls using object and numeric collection values. Assert exit 1, categorical
    JSON, absence of cascaded pass/reconciliation diagnostics, and withdrawal of a
    seeded stale `packet.md`.
