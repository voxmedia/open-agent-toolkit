### Important

- **The proposal validator accepts an incomplete requested-profile topology** (`.agents/skills/recon/scripts/lib/routing.mjs:348`)
  - Issue: `assertV2ProposalTopology` enforces lane/concurrency/condition caps and
    the single terminal reconciliation rule, but it never requires the waves that
    the requested profile declares mandatory. A direct production-helper probe
    successfully previewed `requestedProfile: standard` with only one
    `reconciliation` wave, even though standard requires map, gather, semantic
    verification, adversarial review, coverage review, and reconciliation. The new
    positive test reinforces the gap by calling a standard draft containing only
    map, conditional contradiction-resolution, and reconciliation a "complete"
    topology at `routing-preview.test.mjs:57`. An operator can therefore approve and
    launch an envelope that cannot produce the requested profile; final packet
    validation catches the missing evidence only after work has run. This leaves the
    complete pre-approval topology requirement unsatisfied.
  - Fix: Define the required wave-mode topology per requested profile in shared
    production policy and make proposal validation reject missing required modes
    before preview/approval. Include direct and CLI negative controls for incomplete
    quick, standard, and thorough envelopes, plus complete accepted controls. Keep
    conditional contradiction-resolution separate from the mandatory terminal
    reconciliation.
  - Requirement: p02-t01 item 2; p02-t03 items 2 and 6; Discovery success criterion 2.

- **Unescaped manifest values can corrupt the human approval preview** (`.agents/skills/recon/scripts/lib/routing.mjs:703`)
  - Issue: Markdown table cells interpolate wave IDs, target axes, selection reasons,
    lane scopes/write roots, and condition IDs/dependencies without escaping pipes or
    line breaks (also lines 716 and 730). The proposal validator accepts those
    characters. A production-helper probe with lane scope
    `visible | hidden\n\n## False limits\n\n- Lanes: 1` broke out of the lane table and injected a false limits section ahead of
    the real limits. Because Markdown is the CLI default, the operator cannot rely on
    the rendered view to show the exact approval-bound topology even though the
    hidden value remains fingerprinted.
  - Fix: Render every manifest-derived Markdown value with a common safe cell/text
    encoder (or reject control characters and use a non-table exact representation).
    Add direct and subprocess CLI controls covering pipes, CR/LF, backticks, and
    other Markdown-significant characters across target, reason, lane, and condition
    fields; assert that no value can create rows, headings, or limit entries.
  - Requirement: p02-t01 items 2 and 6; Discovery success criteria 2-3.
