Wave 1: test and CI containment

Two small defects, a smoke test harness that could hang forever and a release gate that could pass a stale version, were fixed and merged as one wrapper project.

Wave 1 Complete both phases merged
Lanes 2 of 2 run in parallel, merged in order
Definition of done Green 10 gates, every exit code 0
Reviews Passed phase, final and exit gate

What was asked for

Wave 1 of the 2026-08-19 execution program asked for two recently observed, small defects to be closed together as one thin wrapper OAT project. The wrapper owned ordering, worktree isolation, gates, review mapping and bookkeeping. Nothing else.

Each lane kept its entire implementation contract in its own immutable external plan. The wrapper was forbidden from restating, narrowing or overriding any of it, which is what separates the request from the eventual implementation: the request is a routing and safety problem, the implementation lives in the two source plans.

The two lanes and the defects they close
LaneDefectExternal plan
p01 The smoke cleanup SIGTERM regression harness could wait forever on a child that ignored the signal, wedging pnpm test. 2026-08-19-bound-smoke-cleanup-signal-wait.md
p02 A long-lived branch whose lockstep bump had been overtaken by a later release on main still passed CI. 2026-08-19-detect-behind-main-package-versions.md

The constraints the wrapper accepted

  1. Run each source plan's drift check against current HEAD before touching code. A material mismatch stops the lane.
  2. Honour every source-plan STOP condition verbatim. A tripped STOP parks the lane instead of weakening the plan.
  3. Confirm the source plan's own done criteria, then run the full definition of done and capture every exit code explicitly.
  4. Keep reviewed history append-only. Fix rounds land as new commits; no reviewed SHA is amended.
  5. Merge phase branches one at a time in plan order, and do backlog archival once on the integration branch after every merge.

Success meant both plans' done criteria confirmed and recorded, every review row passed, the full definition of done green, and the wave merged to main.

Decisions that shaped the result

Four choices changed what shipped. Each is recorded with the reason it was made and the consequence it carried.

  1. Run both lanes as one parallel group

    Reason
    The wave-boundary drift refresh found an empty write-surface intersection. p01 only touches tools/smoke; p02 only touches tools/release and packages/cli/src/release.
    Consequence
    Two worktrees started from the same base and merged in plan order, p01 first, so the bounded signal harness was already in place for the release lane’s integration test run.

  2. Take a wave-level lockstep bump instead of exempting test paths

    Reason
    Test files under packages/cli/src count as publishable changes, so the repository guardrail demanded a five-package bump that neither lane could make on its own.
    Consequence
    The root bumped 0.2.32 to 0.2.33 once after fan-in, which also exercised the new guard’s green path. Editing versionPolicyIgnorePatterns was rejected as a policy decision outside the plan.

  3. Reconcile the release-guard plan without narrowing it

    Reason
    The plan scopes the strict-greater comparison to check-version-bumps.ts and release-utils.ts, and forbids adding a second competing gate.
    Consequence
    The new errors were appended to the result that already aggregates the merge-base lockstep errors, so one run names every required rebase or re-bump. The separate lockstep pass in release:validate was left alone.

  4. Merge phase branches without rebasing them

    Reason
    The phase branches touched only code and the integration branch touched only .oat/projects, so there was nothing to replay.
    Consequence
    A plain git merge --no-ff in plan order preserved every reviewed SHA that the review chain cites.

How the wave was built

The delivered system is two independent code changes plus the machinery that carried them from the program document to main. The wrapper owns that path. The external plans own what each lane writes.

What the wrapper owns

  • Phase ordering, grouping and the concurrency ceiling
  • Worktree isolation and merge serialisation
  • Wrapper-level gates and the review mapping
  • Commit scope naming and all bookkeeping

What each external plan owns

  • Its drift check and STOP conditions
  • Its implementation steps and embedded verify gates
  • Its done criteria and review focus
  • The files it is allowed to write

Where this leaves the repository

Works now

  • A smoke child that ignores SIGTERM is force-killed, reaped or detached, and reported with its paused stage and captured output. The suite fails in about a minute instead of never.
  • CI rejects a pull request whose public package versions equal or trail origin/main, naming every affected package in one run alongside the existing merge-base errors.
  • Both tracked backlog items are closed, and the repository sits at 0.2.33 across the five public packages.

Did not ship

  • Nothing either source plan required was dropped or narrowed.
  • Three minor findings remain deferred: quote whitespace in the malformed-version diagnostic, regression coverage for the forced and timed-out diagnostic branches, and the zombie-child wording.
  • The documentation for the new strictly-above-main rule was routed to the documentation step rather than deferred.

For the next reader

  • Fetch origin/main before running pnpm release:check-versions locally, or the gate has no current ref to compare against.
  • Any change under packages/cli/src, tests included, triggers the lockstep bump requirement. Plan that bump before a lane starts, not after fan-in.
  • Pick up the deferred minors on the next release-tooling or smoke-harness touch.
  • Waves 2 to 4 baseline their versions on whatever origin/main holds when that wave starts.
