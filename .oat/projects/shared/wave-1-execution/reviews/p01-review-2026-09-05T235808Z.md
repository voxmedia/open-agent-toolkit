### Important

- **Shipped config-write predicate contradicts the plan's `## Current state` negative clause** (`packages/cli/src/commands/docs/index-generate/index.ts:437-443`)
  - Issue: the plan states two overlapping rules. The positive rule — "when
    `documentation.tooling` is `fumadocs` (or `documentation.config` is absent) …
    record the repo-relative output path" — and the negative rule — "When
    `documentation.tooling` is `mkdocs` **or `documentation.config` is set**, never
    call `writeOatConfig`." These conflict on the case `tooling: 'fumadocs'` **and**
    `documentation.config` set. `isFumadocsManifestTransition` resolves it in favor
    of writing: `if (tooling) { return tooling === 'fumadocs'; }` short-circuits
    before the `documentation.config` fallback at `:442`. I confirmed this on the
    real filesystem (probe P6): a repo with
    `{root:'app', tooling:'fumadocs', config:'app/next.config.js', index:'app/docs/index.md'}`
    ran `oat docs generate-index` and `.oat/config.json` was rewritten to
    `index: "app/index.md"`. **This is the live shape of this repository's own
    `.oat/config.json`** (`root: apps/oat-docs`, `tooling: fumadocs`,
    `config: apps/oat-docs/next.config.js`), so the divergent branch is the branch
    OAT itself takes. The case is pinned by no test — `index.test.ts:437-450` pins
    only the adjacent _tooling-undeclared_ + config-set case.
  - Assessment: **the implementation is defensible and I do not recommend changing
    it.** It matches the plan's `## Outcome` ("MkDocs configuration is never
    touched" — not "any config-declaring repo"), matches implementation step 1
    ("the MkDocs branch and the outside-root branch return before it" — naming only
    two early returns), and is required for this repository's own documented
    bootstrap transition (`oat-docs-bootstrap/SKILL.md:906-910`) to keep working.
    The negative clause is the stale artifact.
  - Fix: (a) amend the external plan's `## Current state` negative clause to read
    "when `documentation.tooling` names any tooling other than `fumadocs`, or
    tooling is undeclared and `documentation.config` is set, never call
    `writeOatConfig`", so the plan stops contradicting itself; and (b) add a test
    pinning `tooling: 'fumadocs'` + `documentation.config` set → config **is**
    written, so the deliberate reading is locked in rather than incidental.
  - Requirement: plan `## Current state` final bullet; `## Done criteria` bullet 5.
