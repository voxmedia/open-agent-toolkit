## Findings

### Critical

- **Versioned content comparison rejects freshly materialized bundled skills**
  (`packages/cli/src/commands/tools/shared/pack-inventory.ts:133`)
  - Issue: `canonicalFileMatches` calls `digestFile` without normalizing mode,
    so executable bits participate in equality. The established materializer
    intentionally changes every file beneath a skill's `scripts/` directory to
    `0755` (`packages/cli/src/commands/init/tools/shared/copy-helpers.ts:29` and
    `:66-71`), while several bundled script files are `0644`. A fresh install is
    therefore immediately inventoried as `outdated`, and post-apply verification
    aborts at
    `packages/cli/src/commands/tools/shared/apply-pack-reconcile.ts:128`.
    Running the existing lifecycle acceptance matrix at the reviewed head
    produced 22 failures: fresh project/user installs and subsequent lifecycle
    operations fail for `workflows`, `utility`, and `brainstorm`, with errors
    naming `oat-explainer-kit`, `oat-project-complete`, `explainer-kit`, and
    `oat-brainstorm` as drifted immediately after copy. The new unit fixtures do
    not contain a nested script with the real post-copy mode transformation, so
    the planned focused suite misses the regression.
  - Fix: make the versioned-asset comparison content-aware but mode-insensitive
    (for example, normalize both sides to the same mode when hashing) while
    retaining the current file-type, directory, and symlink checks. Add a
    regression using a same-version bundled skill with a `0644` nested script
    whose installed copy is intentionally `0755`, and require both inventory
    and the lifecycle acceptance matrix to classify the clean materialization as
    current. Content edits must still classify it as outdated.
  - Requirement: p01-t02; discovery success criterion "Same-version but changed
    skill/agent content is reported as drift" without breaking additive install
    behavior.
