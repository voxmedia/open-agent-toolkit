## Findings

### Critical

- **Unscoped sync commit can include unrelated staged changes** (`.agents/skills/oat-worktree-bootstrap-auto/scripts/bootstrap.sh:188`)
  - Issue: Phase 4 correctly removes `-- "${SYNC_STAGE_PATHS[@]}"` from `git commit`, which fixes the empty-provider-directory pathspec failure. But `git commit -m "chore: run sync"` commits the entire current index, not just the paths staged by the preceding scoped `git add -A -- "${SYNC_STAGE_PATHS[@]}"`. If a worktree enters Step 4.5 with unrelated staged changes, line 188 includes those unrelated files in the generated `chore: run sync` commit. This can happen because `git_clean` only sets `HAS_ERROR=true` on dirty state at line 159; the script still continues through sync and Step 4.5 before returning the final error status. Reproduced in a temp repo: with `unrelated/file.txt` staged before the sync block and only `.oat/sync/manifest.json` dirty under sync paths, the current Phase 4 command committed both `.oat/sync/manifest.json` and `unrelated/file.txt`.
  - Fix: Preserve the no-pathspec commit fix for empty directories, but isolate the sync commit from any pre-existing index state. Options include: fail/return before Step 4.5 when strict `git_clean` fails; or save the pre-existing staged set, stage sync paths, commit only the newly staged sync paths using a filtered list of staged files that actually exists in the index; or use a temporary index/worktree-safe commit strategy. After the fix, add a temp-repo verification with an unrelated staged file and assert the `chore: run sync` commit contains only sync-managed paths.
  - Requirement: p04-t01 / imported-plan Goal 1, "The commit only touches sync-managed paths"; review requirement, "scoped staging still limits commit contents."

### Important

- **Docs overstate the safety of scoped staging before an unscoped commit** (`.agents/skills/oat-worktree-bootstrap-auto/SKILL.md:204`)
  - Issue: SKILL.md now says the scoped `git add -A -- "${SYNC_STAGE_PATHS[@]}"` determines what enters the commit and that orchestrators can rely on `chore: run sync` touching only sync-managed paths. That is only true when the index is clean before the sync block. In the dirty-index case above, agents following this prose can commit unrelated staged files with the generated sync commit.
  - Fix: Update the docs alongside the script fix to describe the actual isolation mechanism. If the chosen implementation returns before Step 4.5 on dirty baseline, document that invariant. If it preserves/restores pre-existing index state or derives an exact staged sync file list, document that instead.
