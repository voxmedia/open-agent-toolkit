# Plan: Stop `.oat/sync/manifest.json` from bleeding across OAT workflows

**Date:** 2026-05-13
**Branch:** `fix/oat-sync-manifest-commit`

## Problem

`.oat/sync/manifest.json` (and provider directories under `.claude/`, `.cursor/`, `.codex/`) frequently show up as the only dirty file at the end of OAT workflows. Source traced to:

- `pnpm run worktree:init` (package.json:33) runs `oat sync --scope project` — can dirty manifest.
- `oat-worktree-bootstrap-auto/scripts/bootstrap.sh:160` runs `oat sync --scope all` _after_ its `git_clean` check (line 155) — so even strict bootstraps end with the manifest dirty.
- `oat tools update`, manual `oat sync`, adding a provider — same.

No skill stages the manifest in its explicit commit lists, so it gets left behind and rolls into the next commit on the branch.

## Goals

1. **Root cause:** `oat-worktree-bootstrap-auto` should leave the worktree clean. Sync output is a setup artifact, not workflow churn — commit it.
2. **Defense in depth:** the three project entry skills (`oat-project-new`, `oat-project-quick-start`, `oat-project-import-plan`) should present the inherited git state at the start and offer to commit before scaffolding. Applies broadly, not just to manifest.
3. **Host-agnostic:** preflight must work when `AskUserQuestion` is unavailable (e.g., Codex).

Non-goal: changing CLI sync engine behavior. The engine is already correct (no-op syncs don't dirty the manifest).

## Changes

### Change 1 — `oat-worktree-bootstrap-auto`

**Files:** `.agents/skills/oat-worktree-bootstrap-auto/SKILL.md`, `.agents/skills/oat-worktree-bootstrap-auto/scripts/bootstrap.sh`

- Move the `git_clean` baseline check to **before** sync runs (so it measures the inherited base, not sync output).
- After Step 4 (`oat sync --scope all`), add a **post-sync commit step**:
  - Scope to known provider dirs + manifest: `.oat/sync/manifest.json`, `.claude/`, `.cursor/`, `.codex/`.
  - If anything in that scope is dirty: `git add` those paths and commit as `chore: run sync` (matches existing repo precedent: `6324870e`, `24453589`).
  - Use `git diff --cached --quiet` guard so an empty stage doesn't create an empty commit.
- Add `sync_commit: pass | fail | skip` to the structured status block in Step 5.
- Bump skill `version:` (currently `1.2.2` → `1.3.0`).

**Why autocommit is safe here:** this skill is `user-invocable: false` and `disable-model-invocation: false`, dispatched only by orchestrators (e.g., `oat-project-implement` parallel mode). Orchestrators already accept that this skill mutates the worktree. The commit only touches sync-managed paths, never user code.

### Change 2 — Git State Preflight on project entry skills

**Files:**

- `.agents/skills/oat-project-quick-start/SKILL.md`
- `.agents/skills/oat-project-new/SKILL.md`
- `.agents/skills/oat-project-import-plan/SKILL.md`

Insert a new section (before existing Step 0 / Prerequisites):

```markdown
### Step 0 (Preflight): Inherited Git State

Before scaffolding, surface the working tree state so unrelated changes don't get carried into the project workflow's bookkeeping commits.

1. Run `git status --porcelain`. If empty, continue silently.
2. If non-empty, present the dirty list to the user.
3. If `.oat/sync/manifest.json` or paths under `.claude/`, `.cursor/`, `.codex/` appear in the list, note: "These are generated by `oat sync` (often by `pnpm run worktree:init` or `oat-worktree-bootstrap-auto`) and are typically safe to commit as `chore: run sync`."
4. Offer the user three choices via `AskUserQuestion`:
   - **Commit now** (recommended when only sync output is dirty) — stage and commit. For sync-only diffs, default the message to `chore: run sync`; otherwise ask the user for the message.
   - **Proceed anyway** — start the project workflow with the dirty state acknowledged.
   - **Abort** — exit the skill so the user can clean up manually.

> **Tool availability is not the same as interactivity.** If `AskUserQuestion` is unavailable but chat is available, present the three choices as a plain chat message and wait for the user's reply. Only fall back to "Proceed anyway" when `OAT_NON_INTERACTIVE=1` is set or there is no user-response channel at all.

Do not advance past this gate without an explicit choice.
```

Additional fix in `oat-project-new`: widen `allowed-tools: Bash(pnpm:*)` to `allowed-tools: Bash` — the existing step body already invokes `oat ...` commands, so the current restriction is wrong.

Bump `version:` on each of the three skills.

## Validation

- `pnpm --filter @open-agent-toolkit/cli test` (no CLI source changes, but runs the broader test suite to confirm nothing regressed)
- `pnpm release:validate`
- Manual smoke: in a worktree with intentionally-dirty manifest, invoke `oat-project-quick-start` and verify the preflight surfaces it correctly with and without AskUserQuestion (simulate by setting `OAT_NON_INTERACTIVE=1`).
- Manual smoke: dispatch `oat-worktree-bootstrap-auto` against a base where sync would create new entries, verify the worktree ends clean with the `chore: run sync` commit.

## Out of Scope

- Engine-level guard against no-op `saveManifest` writes — already idempotent in practice; not changing.
- `oat tools update` auto-sync commit — leaves manifest dirty by design; users running that command interactively can commit it themselves. Revisit if it becomes a recurring complaint.
- Updating older skills (`create-oat-skill`, `create-agnostic-skill`) to include manifest in their commit lists — separate follow-up; the preflight in Change 2 covers most of this case for free.

## Risks

- **Autocommit on bootstrap branches:** mitigated by scoping the commit strictly to sync-managed paths.
- **Preflight friction:** users who don't care about the dirty state will see an extra prompt at the start of every project. Mitigated by "Proceed anyway" being a one-click option and the preflight only firing when the tree is dirty.
- **Five-package version bump for a docs-only change:** required by current release policy; flagged in handoff so it's a conscious decision, not a surprise at PR time.
