- **Interactive completion now hard-refuses a closed-unmerged tracked PR, an unrecorded change to the preserved completion contract** (`.agents/skills/oat-project-complete/scripts/prepare-completion-branch.mjs:103-107`)
  - Issue: Step 1.75 runs `observeCompletionPr` on every normal-path completion with a tracked URL. A live `CLOSED` state throws `E_PR_CLOSED` ("resolve its delivery before completion"), so `oat-project-complete` stops before any write. On the integration base (`7e5b5bd3`), interactive completion accepted a closed or stale tracked PR: it used only the stored `oat_pr_status`, set `WAS_PR_OPEN_AT_START` from it, and could even open a new PR. The brief's constraint keeps completion contracts present on the base. The only exception it names is the goal-mode authority rule, and its p02 exit evidence lists only failed, absent, merged and open cases. The journal records no closed-PR decision, the closeout docs (`apps/oat-docs/docs/workflows/projects/closeout/closeout-skills.md`) describe failed-observation and no-URL behavior but not this refusal, and no recovery route exists other than hand-editing `oat_pr_url`. Scenario: a project whose PR was closed (abandoned, or replaced by a PR the project does not track) can no longer be completed or archived through `oat-project-complete`. The autonomous companion already refused closed PRs on the base, so only the interactive path changed.
  - Fix: Operator decision. Either (a) accept the refusal: record it as a phase-local decision or deviation in `implementation.md` and document the stop plus its recovery path (retarget or clear `oat_pr_url`, then rerun) in `closeout-skills.md` and the Step 1.75 prose; or (b) restore the base behavior: treat `CLOSED` as observed-not-open (record `oat_pr_status: closed` with the observation time, `WAS_PR_OPEN_AT_START=false`, no follow-up preparation) and add a closed control to `prepare-completion-branch.test.mjs`. Option (a) is the smaller change and fails safe.

### Low

- **Step 10 follow-up push guard uses `!(`, which zsh rejects as a parse error** (`.agents/skills/oat-project-complete/SKILL.md:1746`)
  - Issue: `[[ "${COMPLETION_FOLLOWUP:-false}" == "true" && !( "$PROJECT_SCOPE" == "synced" && "$SHOULD_ARCHIVE" == "true" ) ]]` evaluates correctly in bash 3.2, but zsh reports `parse error near ')'` and runs none of the block. This machine's agent shell is zsh. On a shared-scope or non-archive follow-up, the snippet would fail loudly instead of pushing `COMPLETION_BRANCH` before Step 11. The failure is visible rather than silent, and the repository's snippet tests run under bash. This is the only `!(` construct in `.agents/skills`.
  - Suggestion: Add a space, `! ( … )`. Verified to parse and evaluate identically in bash 3.2 and zsh. Bump the skill version as the PR-scoped rule requires, unless the PR already carries that bump.
