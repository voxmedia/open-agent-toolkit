  - Issue: Phase 3/design calls the gateability result a non-blocking warning, and the validator now emits `severity: 'warning'` for unknown/non-gateable configured skills. The command path still treats any finding as failure (`result.findings.length > 0`), emits `status: 'failed'`, and sets `process.exitCode = 1`. Update the command-level test that currently expects `status: 'failed'` and exit code 1 for the non-gateable gate case.
