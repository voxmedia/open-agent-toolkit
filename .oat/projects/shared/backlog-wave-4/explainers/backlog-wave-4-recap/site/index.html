Original request

The operator picked this batch through tackle-backlog and approved it as proposed. It shipped as one branch and one PR. The wave aimed at gate and build reliability, plus the review-loop and completion follow-ups that the previous wave surfaced.

The lead request came from the operator's experience in that previous wave. When a review or gate budget runs out, the agent should run a complexity review and present it together with the reasons the loop stopped.

Success criteria

  • Every in-scope acceptance criterion passes, with a failing-first test for each behavior change and a neutralize-and-restore proof for each guard.
  • An empty inventory lookup makes bundle-assets.sh exit non-zero without copying anything.
  • A full-surface gate review gets a thirty-minute default, and a duplicate live gate is rejected.
  • A second oat sync run after a stale entry is restamped changes nothing.
  • Every budget-exhaustion point dispatches the complexity review before the decision message, with a contract pin per point.
  • oat-project-complete-auto refuses to run unless the repository opts in.
  • The full Definition of Done passes and the PR ships at the new lockstep version, with finished items archived and the partial item rewritten.
Fixed constraints

The globally installed CLI and user-scope skills stayed on an older release because the operator did not authorize an update. Gates and lifecycle skills therefore ran older behavior, and new gate behavior was probed with the branch build. Tests of the empty-lookup case had to stop safely and never fill the disk. Docs-bootstrap skills belonged to another session's PR that was still in review, so this wave left them alone.

Key agent decisions

Six choices shaped what shipped. Each pairs the reason with what it changed for users and for later work.

p04

A complexity review at every budget-exhaustion point

Why: a bare "out of attempts" question gave the operator no view of whether the work had grown too complex to converge.

Effect: one read-only reviewer runs before the decision message, using the installed complexity-review skill or a condensed OAT fallback. The operator picks the disposition, including simplify. Agents never pick it themselves, even in autonomous runs, and no automatic early trigger shipped.

p01

One destination rule instead of a growing denylist

Why: every review round found one more path that an OAT_ASSETS_DIR override could overwrite, and every fix added one more entry.

Effect: at the review cap the operator chose simplify. An override now publishes only into an absent or empty directory or an existing bundle. The default destination is exempt because a fresh clone already tracks four files there. In p01 this cut bundle-assets.sh by 36 lines net.

p01

Fix the root cause of the earlier disk fill

Why: bundle-inputs.mjs compared its real module path with the invoked path. Through a symlinked checkout the two differ, every lookup printed nothing, and a source path collapsed to the repository root.

Effect: both sides now compare real paths, and the build refuses an empty, absolute, escaping, or repository-root lookup before it copies anything.

p02

Reject a duplicate gate rather than reuse it

Why: full-surface gate reviews ran out of the old budget, and gate prompts could recurse into nested duplicate runs.

Effect: in p02, artifact gate reviews default to 30 minutes, and a live gate for the same project, review type, and scope is rejected through an atomic hard-linked claim file that is released when the run ends.

p04

Report the quick-start gate record without routing on it

Why: quick plan readiness is already the one routing rule for quick plans, defined once in quick-start and mirrored by the router and dashboard.

Effect: quick-start persists oat_quick_start_gate, whose shape is defined once in a shared doc. Next and progress validate and report it, and routing does not change.

p05

Autonomous completion is an explicit opt-in

Why: wave closeout told autonomous orchestrators to run the interactive completion skill, which they cannot invoke.

Effect: a workflow.autonomousComplete key, off by default, unlocks the oat-project-complete-auto companion. It has a three-layer guard, a recorded pre-merge exception for wave-execute, and a batch mode, and it never creates a PR.

Scope cut at the plan gate

The Codex plan gate blocked on both allowed attempts with real findings. After a complexity review of the plan, the operator chose simplify, then implement. On the operator's request for a recommendation, the agent kept batch completion mode and dropped the gate idle kill and the early-trigger config key. An idle kill cannot serve Codex gates, whose activity is not attributable to the gate child.

As-built architecture

Five delivered paths, one lane per phase that changed runtime behavior. Teal boxes are new commands, skills, or records. Dashed boxes are guards that refuse a bad state.

  • New command, skill, or record
  • Guard that refuses a bad state
  • Existing component

Component boundaries

  • p01 build assets. bundle-assets.sh and bundle-inputs.mjs refuse bad inventory lookups, keep staging outside every recursively copied source, and apply the destination rule only to an OAT_ASSETS_DIR override. Asset-root read failures in assets.ts carry their errno.
  • p02 gate reviews. oat gate review gives artifact reviews a 30-minute default and records the duplicate decision as recursion in its JSON envelope, with unchecked when the marker directory cannot be read.
  • p03 sync. The sync planner and executor restamp stale copy hashes, bridge legacy digests when retiring copies, and plan an error operation for marker-less directories. Skill validation flags a missing SKILL.md in any skill directory.
  • p04 review loop. Implement, quick-start, and review-receive share two docs under .agents/docs: the complexity-review fallback and the gate approval record. Complexity reports live under reviews/archived/ so they never read as unprocessed reviews.
  • p05 completion. oat-project-complete-auto is model-invocable but not user-invocable. It hard-fails unless the repository opts in, then runs the closeout check and the completion tail.
  • p06 small fixes. The recon reconciler keeps a claim unresolved when a thorough-profile review leaves it undisposed. oat-wrap-up resolves its template with oat template resolve, and the dashboard reuses the router's quick-plan readiness reason.

What happened along the way

  • p01 did not converge under review. Each of four root review rounds and two Codex gate attempts found one more path an override could overwrite. The complexity review at the cap traced six of nine findings to one family, and the operator chose simplify plus the root-cause fix.
  • The main branch moved three times. A release PR landed during planning; the reader-first docs restructure and another release landed during closeout. The branch pulled main in twice more, ported its docs into the new site, and bumped the lockstep version again.
  • p04's first gate run was cut short by a host restart. It wrote findings but returned no envelope, so it did not count as an attempt; the root fixed both findings and ran the gate again.
  • p07 absorbed the late findings. The exit gate's first attempt found a newline-only filename that passed the emptiness test and test fixtures that inherited the caller's marker directory. A follow-up review then found that a symlinked destination was not followed. All three were fixed with failing-first tests.
  • The wave-4 setup reused the earlier waves' routes, except that the reviewer target ran GPT-6.1 Sol at the highest reasoning effort.

Outcome

What now works

  • BL-261001-fail-closed-when-bundle-assets is closed: the asset build stops before copying on a bad lookup and can no longer copy the repository into its own staging.
  • Artifact gate reviews get 30 minutes by default, and a duplicate live gate is rejected (p02).
  • A stale copy hash is settled in one sync run, and a marker-less directory is reported instead of rewritten on every run (p03).
  • An exhausted review or gate budget now comes with a complexity review and a simplify option, and quick-start remembers its gate outcome (p04).
  • A repository can opt in to autonomous completion through the new companion skill (p05).
  • The dashboard routes quick plans the way the router does and reads parsed HiLL arrays in every workflow mode (p06, plus the HiLL parsing fix from the final review).

What changes for users

  • Update the CLI together with the skills; the updated skills rely on the new config keys.
  • oat sync --json can report a new error operation.
  • Artifact gate reviews wait twice as long before timing out unless a timeout is set explicitly.
  • Projects whose oat_hill_checkpoints use single-quoted, bare, or block arrays now show pending HiLL gates on the dashboard.
