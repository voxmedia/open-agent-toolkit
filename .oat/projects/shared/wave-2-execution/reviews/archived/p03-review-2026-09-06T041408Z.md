### Minor

- **Widening the intra-token window flips a narrow band of inputs from reject to
  accept** (`.agents/skills/explainer-kit/tests/contracts.test.mjs:846-856`)

  Issue: the positive patterns changed their inter-token filler from `[^.]*` to
  `[\s\S]*`, with sentence splitting now supplying the boundary. Because
  `guardedSentences` splits only on a period followed by whitespace, tokens may
  now span a period inside a token such as `receipts.v1.json`. I ran an explicit
  weaker-anywhere hunt and found exactly one such flip.

  I judged it **not** a safety regression, and the evidence is direct: the same
  drift sentence is **accepted** by the round-1 pattern when it carries no
  dotted token, and rejected only when a dotted token happens to sit between the
  two anchors.

  ```text
  "...a complete legacy record and ignores the `publish-receipt/v2`..."             -> round-1 ACCEPTS
  "...a complete legacy record from `receipts.v1.json` and ignores the ... /v2..."  -> round-1 REJECTS
  ```

  Round 1 was therefore rejecting an artifact of filename punctuation, not a
  drift class it actually guarded. Net direction is a large tightening: B1-B4
  and the separated only/replay case all moved from accept to reject. No input
  that round 1 rejected _for a semantic reason_ is now accepted.

  Suggestion: none required. Optionally note in the comment that the sentence
  splitter deliberately tolerates dotted tokens, so the widening is understood
  as intentional if this is revisited.

- **The docs mirror concentrates all three requirements in one sentence**
  (`apps/oat-docs/docs/workflows/skills/explainer-kit.md:437-440`)

  Issue: I mapped each requirement to the sentence that satisfies it. In the
  canonical copy they are spread across sentences 1, 4, and 6; in the docs
  mirror **all three ride on sentence 1** — the single long semicolon-joined
  sentence. Since `NEGATION_MARKER` disqualifies the whole sentence, adding any
  one of `not`, `never`, `no`, `nor`, `cannot`, `without`, `unless`, `optional`,
  `instead`, or an `n't` contraction anywhere in that sentence would fail all
  three requirements at once, including in an unrelated clause. This fails
  closed, so it is a maintainability hazard rather than a correctness risk, and
  the failure message would name the copy correctly.

  Suggestion: consider splitting the docs sentence at the semicolon so the v1
  replay rule stands alone, matching the canonical copy's distribution. Not
  required for this fan-in.

- **The distance between the v1 token and its only/replay pair is unbounded**
  (`.agents/skills/explainer-kit/tests/contracts.test.mjs:852-854`)

  Issue: the v1 pattern bounds `only` to within 40 characters of `replay`, which
  is what the comment claims and what the separated-pair fixture pins. The
  filler between `publish-receipt/v1` and that pair is `[\s\S]*?`, unbounded
  within the sentence, so a long sentence could satisfy the rule with the
  restriction attached to a different subject than the v1 receipt. The
  separated-pair fixture does not cover this arrangement.

  Suggestion: if this is tightened later, bound the v1-to-pair distance the same
  way and add a fixture; low priority given the sentence boundary already caps
  the span.
