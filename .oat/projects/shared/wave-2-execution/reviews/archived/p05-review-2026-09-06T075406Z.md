## Findings

### Critical

- **`$CAPTURE_SCRIPT` is guarded in one fenced block and used in two others, so a
  miss exits 0 instead of stopping**
  (`.agents/skills/oat-project-implement/references/phase-execution.md:227-241`
  vs `:265-271` and `:298-305`)
  - Issue: step 1's block opens with `set -eu`, resolves `CAPTURE_SCRIPT`, and
    ends with the terminating guard. Steps 3 and 6 are separate fenced `bash`
    blocks that run `node "$CAPTURE_SCRIPT" \ ...` with **no `set -u`, no
    re-resolution, and no `[ -n "$CAPTURE_SCRIPT" ]` guard**, and no prose
    sentence requires the three blocks to run in one shell session. Shell
    variables do not persist across separate tool invocations in mainstream
    agent harnesses, so `$CAPTURE_SCRIPT` is routinely empty at the two call
    sites. `node ""` treats the empty path as "read the program from stdin" and
    **exits 0** at EOF, which is what a non-interactive harness always presents.
    Reproduced end to end against the shipped script:
    - step 6's block verbatim in a fresh shell with `CAPTURE_SCRIPT` unset, run
      against a **tampered** artifact (`printf 'TAMPERED\n' >> worktree.patch`)
      → **exit 0**. The same block with the variable correctly bound exits 5
      with `Artifact file worktree.patch size mismatch: expected 126, found 143`.
      The contract's own gate is "An `artifact-verification-failed` exit is a
      STOP", so exit 0 is read as verification passed and the child proceeds to
      `git apply --index` on an artifact that was never verified.
    - step 3's block verbatim in a fresh shell with `CAPTURE_SCRIPT` unset →
      **exit 0**, no artifact directory created, no JSON emitted. The contract's
      gate is "A nonzero exit is a STOP", so the lifecycle proceeds to step 4
      and restores paths from a `restorePlan` it never received.
    - the round-1 literal-path form in the same missing-script situation threw
      `MODULE_NOT_FOUND` and exited non-zero. Round 2 therefore converted a
      fail-closed miss into a silent success: a previously-rejected input that
      is now accepted.

    Step 1's own prose states the hazard exactly — "The guard terminates; it
    never falls through to an empty command, because `node ""` exits zero and
    would let an unverified artifact through" — and steps 3 and 6 do the thing
    the sentence forbids. The child agent file is **not** affected: its guard
    and its `node "$CAPTURE_SCRIPT" --verify` sit in one block under `set -eu`
    (`.agents/agents/oat-phase-implementer.md:501-522`), which is the shape the
    root contract should copy.

  - Fix: make every `node "$CAPTURE_SCRIPT"` invocation self-contained. Either
    fold the resolve-and-guard lines into the step-3 and step-6 blocks (the
    child's shape), or prepend each with
    `set -u` plus
    `[ -n "${CAPTURE_SCRIPT:-}" ] || { echo "capture-script-unavailable" >&2; exit 1; }`.
    Then strengthen `skills.test.ts` so the guard is required _adjacent to each_
    invocation rather than once per file: the current
    `capture script miss terminates` assertion
    (`packages/cli/src/validation/skills.test.ts:3462-3464`) passes with the
    guard in an unrelated block, and the ordered-chain loop only requires
    `capture-script-unavailable` to appear before the first
    `node "$CAPTURE_SCRIPT"`. Reverting the added guard should fail the test.
