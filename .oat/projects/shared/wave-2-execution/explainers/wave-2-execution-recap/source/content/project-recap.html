Wave 2: making sync version skew visible

A sync manifest remembers which CLI wrote it. Apply used to overwrite that memory before anyone could read it, so a mismatched toolchain looked identical to a healthy one.

What was asked for

Wave 2 of the 2026-08-19 execution program carried a single small defect, so the wrapper OAT project has exactly one lane. oat sync loads a sync manifest that records the CLI version that produced it, and apply restamps that field to the invoking version. The restamp happened silently, which meant the one signal that a different toolchain had last written the manifest was destroyed on the way past.

Before

A manifest written by an older or newer CLI was restamped during apply with no output at all. Nothing in human or JSON mode distinguished it from a manifest the current CLI had written itself.

After

Each scope carries a versionSkew diagnostic. Human mode warns once per skewed scope before the restamp; JSON mode carries the same structured array and stays byte-clean on stderr.

The request was deliberately narrow. Version skew stays advisory: it changes no exit code, no planned-operation count, no apply eligibility and no manifest schema. That narrowness is what let a one-task lane close a defect that had already misled earlier stale-tooling investigations.

The constraints the wrapper accepted

  1. The lane's entire implementation contract is its immutable external plan. The wrapper adds ordering, gates, review mapping and bookkeeping, and restates none of it.
  2. Run the source plan's drift check in the worktree before editing, extended by the plan gate to the release surfaces the plan itself writes.
  3. Honour every source-plan STOP condition verbatim; a tripped STOP parks the lane instead of weakening the plan.
  4. Confirm the source plan's own done criteria, then run the full definition of done, invoking each gate literally and capturing every exit code to a log.
  5. Keep reviewed history append-only: fix rounds land as new commits and no reviewed SHA is amended.

Success meant the source plan's done criteria confirmed and recorded, every review row passed, and the full definition of done green on the wave branch.

Decisions that shaped the result

Four choices changed what shipped or how it got there. Each is recorded with the reason it was made and the consequence it carried.

  1. Derive the apply restamp from the skew diagnostic

    Reason
    The first review round found the same "does the recorded version differ" test written twice: once to build the diagnostic and once to decide whether apply should restamp. Nothing held the two copies in agreement.
    Consequence
    Apply now keys off the diagnostic the warning is built from, so the advisory and the restamp cannot drift apart. Two unreachable empty-string guards were removed to make the derivation bit-for-bit the old predicate, and a desync mutation is now caught by a dedicated coupling test.

  2. Pre-plan the lockstep bump as part of the lane

    Reason
    Wave 1 discovered at fan-in that any change under the CLI source tree, tests included, counts as a publishable change. Here the same rule was applied while planning instead.
    Consequence
    The drift refresh intersected the write surface with the release change-detection roots and stated the 0.2.33 to 0.2.34 bump up front, so the lane carried it rather than the root patching it afterwards.

  3. Extend the in-worktree drift check beyond the source plan

    Reason
    The source plan's drift command omitted two surfaces its own implementation depends on or writes: the shared version constant, and the five public package manifests against a freshly fetched baseline.
    Consequence
    The plan gate added both as a wrapper-level addendum, with a fetch before every release gate run. An advance of the public-package baseline after planning became a STOP rather than a bump from a stale number.

  4. Treat the blocked exit gate as an operator boundary

    Reason
    The configured cross-family exit gate blocked twice: its headless child pushed the gate commands onto background work and ended its turn without writing an artifact.
    Consequence
    Autonomy stopped at the configured attempt cap rather than retrying around it. The operator changed the target selection, and a second generation ran the whole definition of done in the foreground and passed.

How the wave was built

With one lane there is no fan-out to manage, so the interesting structure is vertical: the loops that a change had to survive before it counted as done. Two of them fired, and both are visible in the record.

What the wrapper owns

  • Ordering, the drift-check addendum and the concurrency ceiling
  • The wrapper-level definition-of-done sequence and its captured exit codes
  • Review mapping, gate targets and dispatch policy
  • Commit scope naming, backlog archival and all bookkeeping

What the external plan owns

  • Its drift check and STOP conditions
  • Its implementation steps and embedded verify gates
  • Its done criteria, review focus and test plan
  • The files it is allowed to write

Delivered surfaces

The manifest schema, the manifest loader and the absent-or-invalid manifest semantics were deliberately left untouched; only the loader's test file gained a case.

How it was checked

An advisory that fires after the thing it warns about is worthless, so most of the evidence here is about ordering and about the two places where the advisory could silently stop agreeing with the behaviour it describes.

The finding that mattered was not a bug in the shipped behaviour. It was the duplicated comparison: correct on the day, and free to drift on any later day. The fix removed the duplicate rather than testing it.

Where this leaves the repository

Works now

  • A stale sync manifest announces itself once per affected scope before apply overwrites the evidence, naming both the producing and the invoking version.
  • Machine consumers read the same facts from a structured array present in both the apply and the dry-run envelope, with human text still suppressed in JSON mode.
  • The restamp and the advisory are one decision rather than two agreeing copies, held in place by a coupling test.
  • The five public packages sit at 0.2.34 and the tracked backlog item for this defect is closed.

Did not ship

  • Skew is still only advisory. No exit code, count, eligibility rule or manifest schema changed, exactly as the source plan required.
  • Three sibling commands still restamp the recorded version silently. That was ruled outside the plan's scope and filed as a backlog candidate.
  • A deferred minor: the field the restamp now keys off is optional on its type, so a hand-built plan object that omits it would type-check and skip the restamp. Unreachable through the real construction path.
  • The wave PR has not been opened or merged; the recorded closeout stops at the completed pre-approval steps.

For the next reader

  • The next edit to the sync plan types should make that diagnostic field non-optional; that is the recorded trigger for the deferred minor.
  • Take the three sibling restamp sites together with the "no changes required" message that a restamp-only apply still prints.
  • Generate the project summary before archiving a backlog item, not after; this wave got that order wrong and recorded it as a deviation for the remaining waves.
  • When a configured gate blocks at its attempt cap, that is an operator boundary. Changing the target is a decision, not a retry.
