## Findings

### Critical

- **The recorder can certify `built` with none of the seven required verification checks** (`.agents/skills/explainer-kit/scripts/record.mjs:160`)
  - Issue: `outcomeFromQa` accepts any object or array of checks, treats an empty set as having no failures, and returns `built` solely from `rung: host` plus `visual.verdict: pass` at lines 160-179. It never requires `parse`, `requiredNarrative`, `structure`, `sourceDumping`, `shellScripts`, `ledgerToPage`, and `pageToLedger`, nor validates their exact result shapes. The archive then trusts the resulting manifest outcome. A temporary negative control produced `outcome: built`, a schema-valid manifest, and a valid exact-inventory check from `checks: {}`. The existing test encodes the same weak model by treating a single `structure` check as sufficient (`.agents/skills/explainer-kit/tests/record.test.mjs:107-117`).
  - Fix: Add one structural validator for `qa/result.json` at the recording boundary. Require the exact browser-free check set and valid status/cause shapes; validate rung/visual/reason/screenshot consistency; reject missing or unknown assurance-bearing fields. Add a negative control proving removal of each required check prevents `built`, while a real `verify.mjs` result remains accepted.
  - Requirement: FR4, FR5, NFR1, NFR2.

- **The “exact” package inventory permits any file that lists its own hash** (`.agents/skills/explainer-kit/scripts/lib/package-coverage.mjs:24`)
  - Issue: `permissibleRunPackagePaths` defines the allowlist from every key supplied by `manifest.immutableHashes` (lines 24-35), while `record.mjs` hashes every pre-existing file under the run root (lines 192-218). An extra file therefore becomes declared and passes `enforceRunPackageInventory`; only an undeclared extra is rejected. The checked archive fixture demonstrates this by including and accepting `PROVENANCE.md` in `immutableHashes` (`packages/cli/src/commands/project/archive/fixtures/v2-package/manifest.json:35-43`), even though it is outside the canonical run-package table. The archive copies every resulting permissible path, so arbitrary files can enter the durable export.
  - Fix: Derive permissible paths from the canonical package contract, not from the manifest's claims. Require `immutableHashes` to equal the canonical required set plus only explicitly modeled conditional screenshot paths; make `record.mjs` reject unexpected pre-record files. Move fixture provenance outside the package root or exclude it before recording. Add a control where an extra file and matching immutable hash are still rejected by both the library and archive.
  - Requirement: FR5, NFR2, NFR5.

### Important

- **Reuse trusts a shallow, potentially corrupt manifest and never verifies package bytes** (`.agents/skills/explainer-kit/scripts/bundle.mjs:224`)
  - Issue: `findReusableRun` checks only recipe id/version, satisfied outcome, and input-hash equality (lines 224-245). It does not validate the manifest contract, immutable file hashes, exact inventory, QA binding, or artifact presence. The test reinforces this by constructing an incomplete manifest with only recipe/source/outcome and expecting reuse (`.agents/skills/explainer-kit/tests/bundle.test.mjs:252-262`). A temporary probe confirmed that this invalid manifest returns `reuse: true`, allowing the caller to skip authoring and recording on stale or missing evidence.
  - Fix: Before reuse, validate `manifest`, verify every immutable hash against current bytes, enforce canonical package inventory, and require a satisfied artifact status plus current QA/artifact binding. Replace the incomplete-manifest positive fixture with a real recorded package and add malformed-manifest, missing-artifact, modified-artifact, and extra-file rejection controls.
  - Requirement: FR1, FR5, FR6, NFR2.

- **The project recap source allowlist admits `state.md` and omits `orchestration-log.md`** (`.agents/skills/explainer-kit/scripts/bundle.mjs:32`)
  - Issue: The approved project-recap inputs are summary, implementation, project log, plan, discovery, spec, design, and orchestration log when present. The implementation instead includes `state.md` and has no orchestration-log entry (lines 32-41); the test explicitly expects the unapproved state input (`.agents/skills/explainer-kit/tests/bundle.test.mjs:47-63`). The checked package consequently publishes a `state.md` input hash. This both drops approved execution evidence and permits lifecycle state content into the authored fact bundle.
  - Fix: Remove `state.md`, add conditional `orchestration-log.md`, and add positive/negative allowlist assertions against the exact approved set, including a sentinel secret in `state.md` that must not enter either source files or hashes.
  - Requirement: FR1; design § `bundle.mjs`.

- **Supplied fact-base mode cannot provide valid claim evidence or stable reuse** (`.agents/skills/explainer-kit/scripts/bundle.mjs:295`)
  - Issue: For a supplied fact base, bundling validates the record but builds the ledger from `selectAnchorLedger([], recipe)` (lines 295-304), so its claims index is empty and its only terminology anchor is the recipe id. A normal authored page with facts therefore fails `ledgerToPage` or `pageToLedger`; a temporary end-to-end probe failed claim verification. Independently, bundling computes freshness from the supplied fact-base file hash (lines 284-290), but `record.mjs` rebuilds manifest `inputHashes` from the fact base's internal source list (`record.mjs:82-93`), so later reuse cannot match the original input identity.
  - Fix: Derive the ledger and page-to-ledger index from supplied claims using the same subject/value rules, and preserve the bundle's actual input hash identity through recording without duplicating an existing consumed record. Add a supplied-fact-base `bundle → verify → record → reuse` test with numeric/date/status claims.
  - Requirement: FR1, FR4, FR10.

- **Program wrapper discovery cannot recognize the repository's date-prefixed archive layout** (`.agents/skills/explainer-kit/scripts/bundle.mjs:394`)
  - Issue: Archived wrappers are accepted only when a direct child is named exactly `wave-N-execution` (lines 394-405). The archive command canonically creates `${YYYYMMDD}-${projectName}` snapshots (`packages/cli/src/commands/project/archive/archive-utils.ts:361-365`), so standard wrappers such as `20260909-wave-1-execution` are skipped. The program-input test never supplies an archive root, leaving this branch untested.
  - Fix: Parse canonical archive snapshot names, select the intended/latest wrapper per wave, and extract the specified `implementation.md` Final Summary. Add a fixture using date-prefixed archive directories, duplicate dates, absent wrappers, and a non-wave archive.
  - Requirement: FR1, FR9; design § `bundle.mjs`.

- **`skip/failed_attempt` accepts objects that are not manifests or flow-produced failures** (`.agents/skills/oat-explainer-kit/scripts/check-terminal-outcome.mjs:73`)
  - Issue: The manifest path is parsed and only `.outcome` is retained (lines 73-83), while `isFlowFailure` accepts any three-key object with arbitrary non-empty stage/cause and a parseable date (lines 134-146). Both lifecycle tests deliberately use `{"outcome":"failed"}` as a “manifest” (`.agents/skills/oat-project-complete/tests/check-terminal-outcome.test.mjs:70-79`). This does not prove the NFR2 condition that skip is backed by a failed/incomplete manifest or a failure record from the flow.
  - Fix: Validate a supplied manifest against the v2 contract and require failed/incomplete outcome/artifact consistency. Validate `failure.json` against a closed stage set and bind it to the selected run root or another unforgeable flow invariant. Replace the partial-object positives with outputs produced by `record.mjs` and `writeFailure`.
  - Requirement: FR6, NFR2.

### Medium

- **Pre-record failure sanitization still persists arbitrary absolute paths and environment values** (`.agents/skills/explainer-kit/scripts/bundle.mjs:253`)
  - Issue: Bundle and verify failure writers replace only the current working directory and `/Users/<name>` (bundle lines 253-261; verify lines 315-319). Errors containing `/private/tmp/...`, Linux home paths, Windows paths, or environment values remain intact, contrary to the security contract. These causes are persisted and later surfaced by summary/completion.
  - Fix: Share or mirror the recorder's environment-value redaction and add cross-platform absolute-path normalization. Test bundle containment and verify-crash errors containing temp paths and injected environment secrets.

- **Multiple document roots silently discard files with the same relative locator** (`.agents/skills/explainer-kit/scripts/bundle.mjs:76`)
  - Issue: Each document locator is relative to its own root, then `uniqueByLocator` deduplicates solely on that locator (`bundle.mjs:561-562`). Supplying two directories that each contain `overview.md` drops one source, collides source IDs, and removes its hash and claims without an unresolved-claim record.
  - Fix: Namespace locators/source IDs by declared root (or reject ambiguous collisions explicitly) and test two input roots with identical relative paths and distinct contents.

- **Numbered facts in source headings are excluded from the fact base but extracted from authored headings** (`.agents/skills/explainer-kit/scripts/bundle.mjs:115`)
  - Issue: Source headings update context and are skipped as claims (lines 115-119), whereas rendered headings are scanned for dates and numbers (`.agents/skills/explainer-kit/scripts/verify.mjs:45-70`). A legitimate authored heading such as “Phase 1” or a dated milestone can therefore fail `verify-claim-untraced` even when copied from an approved source heading.
  - Fix: Index factual heading tokens as claims, or exempt purely structural heading tokens using a symmetric documented rule. Add controls for numbered and dated headings.
