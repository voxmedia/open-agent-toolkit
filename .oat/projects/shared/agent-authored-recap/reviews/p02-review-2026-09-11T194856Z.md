## Findings

### Critical

- **Rejected active content is still executed by Chromium** (`.agents/skills/explainer-kit/scripts/verify.mjs:202`)
  - Issue: `verifyRun` computes `structure` and `shellScripts` failures, but
    unconditionally enters the requested browser rung afterward. A
    reproduction using installed Chromium added a foreign inline script that
    set `document.documentElement.style.minWidth = "2000px"`. Verification
    reported `shellScripts: fail`, yet the Playwright result reported
    `viewport-overflow` and `viewport-clipping` at all three widths, proving
    that the rejected script executed. This defeats the shell-script safety
    boundary and can run agent-authored active content derived from untrusted
    project inputs before the failed run is recorded.
  - Fix: Do not launch a browser when parse, structure, or shell-script safety
    checks fail. Record a named `none`-rung reason and clear browser evidence,
    or establish an equally strong browser sandbox that blocks unapproved
    script execution and all external requests. Add a real-Chromium negative
    control whose rejected script would visibly mutate the probe result if it
    executed.
  - Requirement: Design § Security Considerations; FR4

### Important

- **Unavailable/none fallback leaves stale screenshots that prevent recording** (`.agents/skills/explainer-kit/scripts/verify.mjs:340`)
  - Issue: an unavailable Playwright session returns `noneRung(...)` before
    `clearCanonicalScreenshots`; the direct `none` branch at line 219 likewise
    does not clear prior browser evidence. A host-pass followed by a Playwright
    run with `EXPLAINER_KIT_HEADLESS_PROBE=off` correctly returned
    `rung: none` and `disabled-by-configuration`, but `recordRun` then failed
    with `record-qa-invalid: QA screenshot claims do not match the canonical
screenshot files.` Browser fallback therefore does not reliably yield
    `built-needs-review` on a retried run.
  - Fix: Centralize every transition to `rung: none` through an async downgrade
    path that removes `qa/320.png`, `qa/768.png`, and `qa/1440.png`. Add
    host-to-disabled, Playwright-to-disabled, and explicit-none retry controls
    that proceed through `recordRun` and assert `built-needs-review`.
  - Requirement: FR3; NFR3

- **The lifecycle-resume control reuses the in-memory record instead of reading persisted state** (`.agents/skills/explainer-kit/tests/fresh-host.test.mjs:330`)
  - Issue: the test calls `persistIntent`, then passes the original
    `intentRecord` object directly to `resolveIntent` at line 336. It never
    reads `state.md` back through the production state consumer, so it remains
    green if persistence writes nothing or writes an unreadable record. The
    final `ENOENT` assertions only show that authoring never happened in this
    test setup; they do not prove that resumed completion suppressed it because
    of the persisted decision. This is not capable evidence for the declared
    persisted-state resume chain.
  - Fix: Reload `state.md` through the same reader used by resumed completion,
    pass that parsed record into the actual resolution path, and instrument the
    downstream bundle/author step to fail if invoked. If no executable
    completion consumer exists until Phase 3, narrow the claim here and add the
    end-to-end resume proof with that consumer before declaring FR6 covered.
  - Requirement: FR6; p02-t04 assurance contract
