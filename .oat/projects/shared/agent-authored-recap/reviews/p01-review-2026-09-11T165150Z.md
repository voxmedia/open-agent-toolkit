### Important

- **Reuse still accepts an archive-invalid fact-base binding** (`.agents/skills/explainer-kit/scripts/bundle.mjs:250`)
  - Issue: `findReusableRun` validates the manifest, immutable bytes, inventory, QA, artifact hash, and outcome, but the manifest validator does not require `source.factBaseHash === immutableHashes[source.factBasePath]`. Changing only `source.factBaseHash` to another valid SHA-256 leaves reuse accepted, even though the archive rejects that same manifest at `archive-utils.ts:1240-1250`. The independent probe reported `reuse-with-broken-fact-base-binding=ACCEPTED`.
  - Fix: Make the reusable-package check enforce every canonical manifest-to-package binding the archive enforces, including the exact fact-base path/hash. Add wrong fact-base path and wrong fact-base hash controls to `bundle.test.mjs`.
  - Requirement: FR1, FR5, FR6, NFR2.

- **Supplied claims still use incompatible fallback subjects** (`.agents/skills/explainer-kit/scripts/verify.mjs:61`)
  - Issue: Supplied claims without a closed identifier are indexed under `claim.sections[0]` or a citation-derived source path at `bundle.mjs:352-363`; rendered claims without an identifier are keyed under the visible heading text. The design requires the enclosing `<section id>` as the rendered fallback. A valid supplied claim in section `validation-evidence` stating a count of 17 was indexed under `validation-evidence`, while the corresponding authored section was rendered under `Validation evidence`; verification failed with `verify-claim-untraced:Validation evidence:17`. The positive test uses `p01`, which masks the fallback mismatch.
  - Fix: Use one shared subject-normalization rule on both sides, with the enclosing section id as the no-identifier fallback. Add a supplied-fact-base end-to-end control containing numeric, date, and status claims without phase/wave/backlog identifiers.
  - Requirement: FR1, FR4, FR10.

- **The authentic failure vocabulary rejects the designed interrupted stage** (`.agents/skills/explainer-kit/scripts/bundle.mjs:68`)
  - Issue: Both the writer and guard close the stage set to `bundle`, `authoring`, `verify`, and `core`. Design § Error Handling also requires callers to persist `{ stage: 'interrupted' }` when execution stops between steps. `writeFailure(runRoot, 'interrupted', ...)` currently rejects with `Unsupported failure stage: interrupted`, so the resulting attempt cannot produce evidence accepted by `skip/failed_attempt`.
  - Fix: Add `interrupted` to the shared closed stage vocabulary in the writer and guard, and add accepted writer-output plus rejected unknown-stage controls in both lifecycle guard suites.
  - Requirement: FR6.
