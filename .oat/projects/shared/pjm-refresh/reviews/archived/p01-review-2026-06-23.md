### Important

- **`decision new` can leave a record after reporting failure** (`packages/cli/src/commands/decision/new.ts:174`)
  - Issue: `createDecisionRecord` writes the new decision file with `flag: 'wx'` before it validates that `index.md` exists and contains the managed marker pair. If `reference/decisions/index.md` is missing, `regenerateDecisionIndex` fails after the record is already written, so the CLI exits with an error while leaving `dr-*.md` behind and the index stale. I verified this with a temp repo containing `.oat/templates/decision.md` but no decisions index: the command exited `1`, emitted an `ENOENT` JSON error for `index.md`, and left `reference/decisions/dr-260622-no-index.md`.
  - Fix: Preflight the decision scaffold before writing the record. Either initialize/validate `index.md` up front or call a marker-validation helper before `writeFile`; if a later regeneration failure can still occur, roll back the newly created file. The user-facing error should point to `oat decision init` or the exact marker pair instead of raw `ENOENT`.
  - Requirement: FR2, NFR2

- **`decision migrate` is not repeatable and does not preflight target collisions** (`packages/cli/src/commands/decision/migrate.ts:166`)
  - Issue: The migration initializes the decisions directory and then writes each mapped target with `flag: 'wx'` in sequence. A second run against the same legacy source fails with `EEXIST` on the first already-written record instead of short-circuiting as already migrated; similarly, duplicate date/title mappings or pre-existing target records are only discovered after writes begin. This violates the migration repeatability requirement and makes recovery from reruns or partial migrations fragile.
  - Fix: Precompute mappings and validate before any write: reject duplicate target paths, detect existing target files, and either short-circuit successfully when all expected migrated records already exist with matching `legacy_id`/content or fail before writing anything when there is a real conflict. Keep `--delete-legacy` gated on the same verified all-record state.
  - Requirement: NFR2, FR2
