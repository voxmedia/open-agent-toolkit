### Important

- **`decision migrate --delete-legacy` can delete an unparseable legacy file with zero mappings** (`packages/cli/src/commands/decision/migrate.ts:108`)
  - Issue: `assertSafeLegacyDelete` returns successfully when no legacy index IDs are parsed, so a legacy `decision-record.md` that has no parseable ADR/DR sections can still proceed through `--delete-legacy`. I verified this with a temp reference root containing only prose and no ADR/DR headings: the CLI returned `status: ok`, `mappings: []`, `written: []`, created only `decisions/index.md`, and deleted `decision-record.md`. That violates NFR2 and the design requirement that migration parser mismatches stop before destructive operations.
  - Fix: Treat zero parsed sections/mappings as an error for destructive migration, and require an explicit count/content verification path before `rm(legacyPath)`. At minimum, `--delete-legacy` should reject files with no parsed decision sections and reject files where the parsed index IDs cannot verify the parsed sections; then keep the existing migrated-target content verification before deletion.
