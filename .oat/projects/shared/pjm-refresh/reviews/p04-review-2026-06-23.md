### Important

- **`oat decision migrate` is documented as dry-run-by-default but actually
  applies by default** (`apps/oat-docs/docs/cli-utilities/config-and-local-state.md:34`)
  - Issue: The docs state `oat decision migrate` "supports `--dry-run`
    (default)". The live CLI defaults to apply, not dry-run:
    `packages/cli/src/commands/decision/index.ts:247` sets
    `dryRun: options.dryRun ?? false`, so running `oat decision migrate` with no
    flags writes new decision files immediately. This is the opposite of the
    sibling `oat pjm migrate`, which correctly defaults to dry-run
    (`packages/cli/src/commands/pjm/index.ts:263`,
    `apply: options.dryRun ? false : (options.apply ?? false)`). The author
    appears to have conflated the two migration commands' contracts. A user
    relying on the docs would expect a safe no-op preview but would instead
    mutate `reference/decisions/`.
  - Fix: This is artifact (docs) drift, not a code defect — the CLI behavior is
    defensible. Spec FR2 only requires that `oat decision migrate --dry-run`
    writes nothing (the flag must work), and design.md line 181's "defaults to
    dry-run" statement is scoped to `oat pjm migrate`, not `oat decision
migrate`. Correct the docs: change "supports `--dry-run` (default)" to make
    clear `oat decision migrate` applies by default and `--dry-run` must be
    passed explicitly to preview (e.g., "supports `--dry-run` to preview without
    writing, and `--delete-legacy`"). The decision-command help snapshot
    (`help-snapshots.test.ts:147`) already does not claim a dry-run default, so
    only the prose page needs the correction.
  - Requirement: FR2 / NFR2 (migration safety, documentation accuracy)
