### Minor

- **WebSocket auth hardcodes plaintext-HTTP scheme, narrowing an anticipated deployment mode** (`.agents/skills/oat-brainstorm/scripts/server.cjs:311-317`, `.agents/skills/oat-brainstorm/scripts/helper.js:32-35`)
  - Issue: `isAllowedWebSocketOrigin()` only accepts `origin === 'http://' + host`, and the client's `websocketUrl()` hardcodes `'ws://' + window.location.host`. The `server.cjs` comment directly above the key-auth rationale explicitly calls out supporting "loopback, tunnel, and remote binds" as a reason the key (not an Origin allowlist) is the primary gate — but if the companion is fronted by an HTTPS-terminating tunnel/reverse proxy, the browser's real Origin would be `https://...` and browsers block `wss:`-required mixed content from an `https:` page trying `ws://`, so the WS leg would fail even though the session key is valid. This fails closed (no auth bypass), and HTTPS-tunnel support is not a stated success criterion in `discovery.md`, so this is not a regression against any declared requirement — just a latent gap relative to the code's own stated design intent.
  - Fix: If tunnel/remote-bind support is intended to extend to the WebSocket leg in a later phase, derive the scheme from `window.location.protocol` (`wss:` when `https:`) in `helper.js`, and accept both `http://`+host and `https://`+host origins (or drop the scheme from the comparison) in `isAllowedWebSocketOrigin()`. No action needed for p01 sign-off.

- **Vestigial dead-code block carried through the rewrite** (`.agents/skills/oat-brainstorm/scripts/start-server.sh:185-190`)
  - Issue: The "Kill any existing server" block checks `[[ -f "$PID_FILE" ]]` where `PID_FILE="${SESSION_DIR}/state/server.pid"` and `SESSION_DIR` is always a freshly-generated, never-before-seen directory (`SESSION_ID="$$-$(date +%s)"`, `mkdir -p "${SESSION_DIR}/content" "$STATE_DIR"` runs immediately before). This condition can never be true, so the block is unreachable. Confirmed via diff against the pre-port baseline (`cff2146f`) that this exact dead block already existed before this task — it is not a new regression — but p01-t03 substantially rewrote this file around it and left it in place. (Actual restart/port-reuse safety is correctly handled elsewhere, via `server.cjs`'s `EADDRINUSE` fallback logic that avoids clobbering a still-live prior session's persisted port/token — verified by reading; this dead block has no bearing on that correctness.)
  - Suggestion: Remove the block (or replace the comment) in a future pass touching this file, to avoid misleading future readers into thinking it does something.
