### Medium

- **M1: Fragment checks disagree with the actual Markdown renderer in both directions** (`packages/cli/src/commands/docs/nav/fumadocs.ts:53`)

  Issue: `anchorsOf` derives slugs from raw ATX-heading lines rather than parsed heading text; `apps/oat-docs/scripts/validate.ts:72` independently duplicates the same approximation. For ordinary Markdown `## [Guide](https://example.com)`, installed MDX produces `#guide`, but both validators reject that valid fragment and accept nonexistent `#guidehttpsexamplecom`. A Setext heading `Setext Heading` followed by `--------------` renders `#setext-heading` but is absent from both validators. Thus source-only checking can block valid authoring while blessing links that cannot reach their rendered heading. Existing tests exercise simple ATX headings and cannot expose this disagreement.

  Fix: Derive headings and slug collision handling from parsed Markdown with renderer-compatible semantics, retaining source-only/no-output behavior. Align both validators rather than maintaining two approximate slug implementations. Add installed-renderer controls that accept the actual linked/Setext heading fragments and reject the raw-syntax phantom fragment.

  Requirement: p01-t01 unresolved-fragment checks; p01-t02 source-route/anchor validation and real-consumer proof.

- **M2: Nested asset-only directories become mandatory content sections** (`packages/cli/src/commands/docs/nav/fumadocs.ts:83`)

  Issue: `hasPages` becomes true merely because an entry is a directory. Adding only `docs/assets/icons/logo.svg` to an otherwise valid app therefore makes `docs/assets` a content directory and fails generation/validate-only at missing `docs/assets/index.md`. No Markdown exists anywhere under that asset tree. Since new app/scaffold prebuild hooks require this compiler, organizing images in nested directories now blocks an otherwise valid build. The canonical authoring contract explicitly exempts asset-only directories (`.agents/skills/oat-docs-authoring/references/oat-fumadocs-contract.md:70`).

  Fix: Classify directories from actual Markdown descendants, not the existence of arbitrary subdirectories; preserve the index/ownership requirement for real content sections and all current symlink safeguards. Add a nested asset-only accepted control and a genuinely content-bearing missing-index rejected control.

  Requirement: p01-t02 first-build integration; p01-t03 alignment with the existing content-directory contract.

- **M3: A sibling page and folder with the same stem silently duplicate folder traversal** (`packages/cli/src/commands/docs/nav/fumadocs.ts:162`)

  Issue: Owned `topic.md` and `topic/index.md` are different source paths and each can have exactly one correctly labelled parent entry, yet both become native identifier `topic`. Validation and generation succeed with `pages: ["index", "page", "topic", "topic"]`. In the real installed loader, both identifiers resolve to the folder: the flattened tree contains the Topic Folder and Child twice, while the existing `/topic` leaf is absent from traversal. The loader also distinguishes the folder landing as `/topic/index`, which reinforces that raw source ownership alone is not sufficient proof of a faithful projection.

  Fix: Detect ambiguous native identifiers before writes and provide a rename diagnostic, or use a demonstrably supported unambiguous native representation. Do not invent custom routes or patch the loader. Add a real-loader fixture with a sibling leaf/folder stem collision and require either fail-closed prevalidation or exactly one occurrence of every owned destination with correct neighbours.

  Requirement: p01-t01 native ownership, deterministic projection and duplicate detection; p01-t02 installed-loader traversal/landing-once proof.

### Low

- **L1: Unsupported separator entries are silently discarded instead of diagnosed** (`packages/cli/src/commands/docs/nav/fumadocs.ts:113`)

  Issue: The new compiler delegates to `parseIndexContents`, which filters out every non-link line (`packages/cli/src/commands/docs/nav/contents.ts:58`). A valid Contents block plus `- --- Extra Group ---` therefore passes source validation and generation, silently omitting the requested group. The phase design and new user guidance promise actionable diagnostics for unsupported separator syntax, not successful reinterpretation as nothing.

  Suggestion: Add a Fumadocs-specific unsupported-navigation-entry check before projection, preserving allowed descriptions, whitespace and fenced examples and leaving the MkDocs default unchanged. Cover a mixed valid-links/separator case; do not implement a separator DSL.
