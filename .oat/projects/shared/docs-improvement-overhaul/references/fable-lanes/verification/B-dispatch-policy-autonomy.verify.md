## Verdicts on (a)–(f)

- **(a) Explicit config overrides `state.md`: CONFIRMED.** `resolveCeilingValue` uses `configCeiling ?? projectCeiling` (`index.ts:2558`), and preflight reporting follows the same order (`2322-2324`). The test `index.test.ts:529` asserts it. Nuances: (1) "explicit" means a non-default source with `mode=inherit`, or `mode=managed` plus a valid `policy` (`1443-1509`); (2) a legacy bare `providers.<provider>` scalar also overrides it (`1511-1576`); (3) the per-invocation `--ceiling-tier` overrides both for implementer calls (`2563-2583`); (4) ladder **cells** go the other way: project-state cells win over config cells (`index.ts:796`).
- **(b) Reviews on the strongest candidate of the top tier: PARTLY TRUE.** True for the per-phase and final code reviews that `oat-project-implement` dispatches. They use the cap tier's **last** candidate (`index.ts:751`), which is not necessarily the strongest across models (`950-995`). A higher tier does raise the cost of those reviews. False for planning-artifact reviews (they inherit the parent) and for external gates (`gates.execTargets`). Uncapped and Inherit reviewers falling back to the provider default: **CONFIRMED** (`index.ts:1854-1873`, `1831`; DR-260706-reviewer-targets-only-capped; `dispatch-and-dry-run.md:461-463,497-498`).
- **(c) Non-interactive with no policy stops before implementation: CONFIRMED.** The resolver blocks on `--non-interactive`, `OAT_NON_INTERACTIVE=1`, or preflight with neither interactive nor JSON (`index.ts:2483-2494`). The skill reruns with `--non-interactive` and stops (`dispatch-and-dry-run.md:298-305`). Planning also blocks readiness (`plan/SKILL.md:466-468`).
- **(d) `config set workflow.dispatchCeiling.preset` overwrites ladder columns and then blocks exact selection: CONFIRMED.** It writes scalar `codex`/`claude` into that scope's `providers` (`commands/config/index.ts:1949-1967`); Cursor is untouched. A scalar at a layer also wipes lower-layer tier cells for that provider (`index.ts:856-858`). With the legacy scalar winning, exact candidates are refused (`2594-2599`). If a `dispatchPolicy` at the same or higher scope wins instead (`1570-1575`), the exact candidate is still "not present in the configured … ladders" (`1163-1165`), or preflight reports the ladder missing. Either way exact selection breaks for Codex and Claude.
- **(e) Cursor is not merely advisory, but may substitute a model: CONFIRMED.** The Cursor adapter has `supportsCeiling: true` and `pinned-variant` (`registry.ts:202-224`), and the resolver reports `enforced` when dispatch args compile (`index.ts:2062-2069`). Silent fallback is documented at `dispatch-ceiling.md:437-456`. The variant is advisory if the candidate has no pin mapping.
- **(f) Autonomy never chooses a policy and ignores `workflow.hillCheckpointDefault` on first run: CONFIRMED.** For policy: QS-09, LITE-07, PLAN-06, IMPORT-06 and IMPLEMENT-09 are all "preserve explicit/configured; unresolved non-interactive blocks" (`boundary:repository-policy-approval`). For checkpoints: the autonomous branch runs before the workflow-preference check and skips it (`plan-and-resume.md:144-169`). It writes `[final]` regardless of a configured `every`, and also forces `oat_auto_review_at_hill_checkpoints: true`. Existing valid values (`[]` or a list) are preserved. Note: `autonomy.md:123-124` says it "takes the existing `workflow.hillCheckpointDefault: final` path", which reads as if the config is honored. That wording should be clarified.

## Jargon to define (junior-to-mid readability)

A newcomer could follow the overall shape, because root, subagent, ladder, candidate and tier are defined up front. These terms are used without definition:

- **cap / ceiling:** the highest tier allowed; "dispatch ceiling" is the old name.
- **matrix:** a synonym for ladder; say so once.
- **role / pinned role / variant:** a generated agent definition fixed to one model and effort.
- **provider / host / harness:** Codex, Claude Code, Cursor.
- **preflight:** the check before implementation starts.
- **HiLL / checkpoint:** a human-in-the-loop stop after a phase.
- **scope:** user, repo-local, shared.
- **gate, `onFailure`, `execTargets`.**
- **"Dispatch Profile"**
- **"host-managed routing", "short alias", "advisory", "chaining"**
- **`disable-model-invocation`**
- **"terminal"/"last candidate"**
- **"model access"**

Sentences that assume insider knowledge: "Preflight blocks if `agents.max_depth` is present but below 1" (say what `agents.max_depth` is and where it lives: `.codex/config.toml`); "Pruned task classes become unreachable" (define task class); "shared only where policy allows".
