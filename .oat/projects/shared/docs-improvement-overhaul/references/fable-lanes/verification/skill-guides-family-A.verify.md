The page's "does not universally require" understates the agreed correction, which is that repository and direct runs with a supplied fact base do not need a project. See the findings above.
- **oat-wrap-up** (none): the page agrees. Its "An OAT repository with local project summaries" suggests summaries are required, but the contract only warns. With no summaries in the window, the report is built from merged PRs alone (S/oat-wrap-up/SKILL.md:378-382).
- **oat-brainstorm** (optional): the page agrees.
- **recon** (none, borderline): the page agrees, and the pre-existing destination section covers the caller-supplied project directory.
- All other skills (none): the pages agree. analyze, compare, deep-research, skeptic, synthesize, oat-repo-improve, oat-repo-maintainability-review, oat-repo-knowledge-index, oat-doctor, explainer-kit, and create-agnostic-skill all say no project is required.

## Usefulness (junior to mid developer, no OAT background)

- **research.md:** good. The opening paragraph routes to the right skill, and each section is runnable. Weak spots: `deep-research` "schema" and "repository research / user research" destinations are undefined.
- **repo-improve.md:** the new per-skill sections are runnable, but they point back to a pre-existing Orchestration section dense with Tier, lane, and PJM jargon that is never defined. A newcomer could run maintainability-review → repo-improve from this page, but could not tell what "managed delegation capabilities" means or how to get them (the `utility` pack is never named in the new text).
- **session-closeout.md:** clear and runnable. It overstates de-duplication and completeness filtering, so a reader would trust the draft too much.
- **brainstorm.md:** thin. It does not say what the reader gets (an inline summary, a doc, an idea, a backlog item, a project) in concrete terms, and it omits the commit and push side effects.
- **diagnostics.md:** runnable. It does not explain the interactive dive loop, and the "ask by name" claim may fail.
- **recon.md:** the new section is a helpful on-ramp to a very jargon-heavy page ("wave", "lane", "class floor", and "assurance" are undefined for newcomers). A reader can run it, but cannot predict the approval prompt.
- **explainer-kit.md:** the core section's worked example would mislead a reader into expecting a code tour from a source directory. The adapter section has no concrete output path and no recipe choice.
- **contributing/skills.md:** runnable. It misses the `create-oat-skill` redirect that most OAT contributors need.

**Weakest three sections**

1. **explainer-kit (core).** The worked example is false: source files are dropped without a warning. Its relative paths resolve against the skill directory, and the Node prerequisite is missing.
2. **oat-explainer-kit.** The prerequisites are hedged ("not universally"), the active-project requirement is understated, and there is no output path, no recipe guidance, and no mention of the `state.md` write. A newcomer could not predict what happens or where the output lands.
3. **oat-brainstorm.** The expected output is abstract, the example has no outcome, and it does not disclose that fold-back commits (and, for synced projects, pushes).
