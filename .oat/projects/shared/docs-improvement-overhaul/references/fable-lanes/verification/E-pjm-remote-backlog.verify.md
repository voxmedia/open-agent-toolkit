## Verdicts on (a)–(f)

- **(a) Confirmed, with nuances.** The pack installer never writes `pjm.initialized` (`init/tools/project-management/index.ts:101,115`; `init/tools/index.ts:2030`). `oat pjm init` writes it (`init.ts:224-231`). Unadopted backlog and decision writes refuse (`backlog/index.ts:102-119`, `decision/index.ts:102-119`). Remote refuses everything (`remote/index.ts:557-574`). Run: `backlog new` exit 1; `pjm remote intake` exit 2. The nuances: remote uses exit 2, not 1, and refuses reads too; and `inferred-legacy` counts as adopted. `oat decision migrate` and `oat backlog generate-id` are not gated (`decision/index.ts:301-330`).
- **(b) Confirmed for fields, incomplete overall.** Publish creates `purposes: ['planning']` (`service.ts:2851`); intake creates `['source']` (`:3620`). Their field directions are set in `purpose-policy.ts:46-69`. Outbound requires `outbound` in the purpose (`service.ts:5671-5674`). Priority goes outbound only with priority mapping (`:5701`). Omissions: `source` bindings still allow closeout annotate and transition, and intake always imports the remote body.
- **(c) Partly refuted.** Confirmed parts:
  - The default is `read-only` (config describe: `pjm.remote.policy.authority.default` default `read-only`; fallback at `service.ts:2709-2712`).
  - `user-approved` requires an interactive instruction naming the same operation and target, plus approval of the exact preview digest no older than 300 000 ms (`authority.ts:227-272`, `preview.ts:146-177`, `service.ts:2841,3233`).
  - delete, recreate, relink and detach are floored at `user-approved` (`authority.ts:332-370`).
  - A hand-edited unknown value becomes `read-only` (`oat-config.ts:1092-1117`, `authority.ts:509-519`).

  Refuted: **replace-mode updates are not floored**, only replace-mode creates (see the first blocking finding).

- **(d) Confirmed.** Provider authority replaces the repository result and can widen it (`authority.ts:429-448`). Provider description replaces the repository value (`authority.ts:502`). Caps still apply (`:370`). Extra subtlety: a provider `default` overrides repository per-operation entries. Also, `config describe` lists the provider `description` default as `none`, but in code an unset provider description inherits the repository value (`authority.ts:488-502`). The draft's "Default: unset" is the correct reading.
- **(e) Partly refuted.**
  - Confirmed: `oat config set` refuses `shared` (run: exit 1 with "direct config set is blocked").
  - Confirmed: the preview text is "Sanitized remote content and operation journals will enter Git history." (`service.ts:2249`), and the path is not gitignored.
  - Confirmed: records are not moved (`shared-storage.ts:158`, `movedRecords: false`).
  - Refuted: "only" through the command, since a hand edit works.
  - Refuted: "approve within 5 minutes", since `approvedAt` is set to now and no window exists.
  - Refuted: "stops local-scope projects", since the production store never takes a project target.
  - Refuted: "`<project>/remote/state/`", since production uses only `.oat/repo/pjm/remote/state`.
- **(f) Confirmed, reproduced.** `initializeRepoReference` writes `{...config, pjm: {initialized, schemaVersion}}` (`init.ts:224-231`). `writeOatConfig` normalizes and orders, but does not merge with what is on disk (`oat-config.ts:2324-2340`). No init test covers `pjm.remote` preservation (`grep remote init.test.ts` found nothing). `oat pjm migrate --apply` reaches the same code (`migrate.ts:548`). The effect: authority and description fall back to safe defaults, and `shared` storage reverts to `local`, which hides journals already written to `.oat/repo/pjm/remote/state`.

## Jargon a junior-to-mid developer would trip on

These terms are undefined or assume insider knowledge:

- "intake" and "publish", used as verbs
- "purpose `source`/`planning`"
- "digest-stamped"
- "operation journals" and "snapshots"
- "`<fingerprint>`" and "repository fingerprint"
- "instruction evidence", "workflow evidence" and "the target's current revision"
- "caller authority evidence", which never appears in the draft yet is required
- "capability evidence" and "host agent", which are also absent yet required for every command
- "local-scope, shared and synced projects" and "linked worktrees"
- "hard floor" and "cap"
- "closeout"
- "the `OAT-MANAGED` marker comments"
- "uncertain create"
- "`inferred-legacy`"

Two sentences assume insider knowledge:

- "Works under read-only policy". Say which commands work: intake, refresh, discussion and doctor.
- "It is not background sync". Say instead: "OAT never writes unless an agent runs a command in a workflow step."
