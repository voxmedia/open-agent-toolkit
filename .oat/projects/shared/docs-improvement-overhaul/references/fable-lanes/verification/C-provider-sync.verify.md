# Verification: C-provider-sync.md

**Verdict: ACCEPT WITH CHANGES.** Every stated default is correct, and so is almost every consequence. One recommendation is a blocking problem: "use `copy` for Windows/CI" steers teams into permanent churn across checkouts. Several should-fix omissions concern interactive prompts, folder aliases and stale copies.

## Method

- The worktree is in the middle of a merge. `packages/cli/package.json` has conflict markers, so `pnpm -s run cli:source` fails with `ERR_INVALID_PACKAGE_CONFIG`. I copied the working-tree `packages/cli/src`, `assets` and `tsconfig.json` plus the root `tsconfig.json` into the scratchpad (`scratchpad/oatcli`). For three files I used the HEAD versions instead: `package.json`, and the two conflicted, unrelated files `commands/docs/nav/{sync,fumadocs}.ts`. I symlinked the repo's `node_modules` and ran the CLI with the repo's `tsx`.
- Every behavior probe ran in a `mktemp -d` git repo under the scratchpad, with `HOME` set to a separate `mktemp -d`, using `--cwd <tmp>`. Nothing was written inside the repository or the real home directory.
- All citations were checked against the working tree, not HEAD. `fs/io.ts` differs between them.

## Verdicts on (a) to (g)

- **(a) Confirmed, observed.** With no config and no provider folders: `No changes required`. With `.claude/` created: claude became active, with a warning (`unset: claude`). With `--enabled claude,cursor,copilot,codex,gemini` and no folders, the views were written. After `--disabled claude`, `.claude/skills/foo` and `.claude/agents/bar.md` stayed on disk, and `status` said `No managed entries found`. Nuance: interactive sync re-offers detected providers pre-checked (see findings).
- **(b) Confirmed, observed.** `sync --help` and `status --help` both show `default: "all"`. A bare `oat sync` printed `Scope: project` and then `Scope: user`, and wrote `$HOME/.claude/skills/mine` (a symlink to `~/.agents/skills/mine`) and `$HOME/.oat/sync/manifest.json`. With an empty home it created nothing. `oat providers set` defaults to `project`.
- **(c) Confirmed.** `auto` produced per-entry `create_symlink`, observed. Under `copy`, hand edits showed `⚠ drifted:modified` and the next sync planned `update_copy` and removed them (`grep -c HAND` = 0), observed. The explicit-`symlink` fallback to copy is **verified by reading only**: `resolveStrategy` returns `symlink` for both `auto` and `symlink` (`compute-plan.ts:131-150`), and `createSymlink` copies on any `symlink()` error with no callback (`io.ts:127-139`; `execute-plan.ts:264-269`). I could not force the OS to refuse a symlink on macOS.
- **(d) Confirmed, observed.** `providers set --help` offers only `--scope`, `--enabled` and `--disabled`. `config get` reports `Unknown config key` for `sync.defaultStrategy`, `defaultStrategy` and `providers.claude.strategy`, and `config set sync.defaultStrategy copy` does the same. `config describe` nonetheless lists `owningCommand: "oat providers set --scope project"` for `sync.defaultStrategy` and `sync.providers.<name>.strategy`.
- **(e) Confirmed, observed.** `config get instructions.claude.shims` → `none`. The `--strategy` choices are `none`, `pointer`, `symlink` and `copy`. Under `copy`, after editing `AGENTS.md`: `content_mismatch`, `skip CLAUDE.md (content mismatch requires --force)`, exit 1. Then `--force` gave `updated=1` and the files were identical.
- **(f) Confirmed, by reading.** Keep is offered only for skill mappings with `nativeRead` and `adoptionSourceDirs`, which means Cursor (`.cursor/skills`) and Copilot (`.github/skills`, `~/.copilot/skills`) (`native-skill-disposition.ts:31-58`). Other strays go to an adopt-only multi-select (`status/index.ts:1432-1450`). Keep is blocked on a duplicate canonical name (`:87-115`). Observed: hand-adding `.claude/skills/cstray` to `knownStrays` removed it from `status`. The interactive prompts themselves were not exercised (no TTY).
- **(g) Confirmed, observed.** With all five providers enabled, no `.gemini/`, `.cursor/skills` or `.github/skills` was created. Mappings: `gemini/paths.ts` (all `nativeRead: true`) and the cursor/copilot skill mappings `nativeRead: true`. Codex also reads skills natively, but writes `.codex/agents/*.toml` and `.codex/config.toml` (observed).

## Verdicts on the claimed doc contradictions

1. `configuration.md:27,896` and catalog `owningCommand` say `oat providers set` sets strategy. **Confirmed** for the catalog, where it is explicit at `config/index.ts:1134,1170` and shows in `describe` output. For `configuration.md:27`/`:896` it is **implied**: the table lists `oat providers set` as the primary CLI surface for a file whose contents include "sync strategy", and line 896 says it is used "to mutate sync/provider settings".
2. `configuration.md:47` uses a provider named `github`. **Confirmed.** `oat config describe sync.providers.github.enabled` resolves through the `<name>` wildcard (exit 0), but `oat providers set --enabled github` → `Unknown providers: github. Known providers: claude, cursor, codex, copilot, gemini`.
3. `providers.md:218` calls `--scope all` explicit. **Refuted** as a contradiction (see findings).
4. Docs imply only `auto` falls back. **Refuted as worded.** The docs are silent on the fallback for every mode.
5. Docs omit that disabling leaves views. **Partly confirmed.** It is documented for collection aliases only.

## Jargon and insider assumptions for a junior-to-mid reader

- Not defined: "folder alias" / "whole-folder link", "per-entry", "fans it out", "shim", "pointer" (say "a one-line `CLAUDE.md` containing `@AGENTS.md`"), "Copilot markers" (list them: `.copilot/`, `.github/copilot-instructions.md`, `.github/agents`, `.github/skills`, `.github/instructions`), "packs", "fresh worktree", "unresolved", "unmaintained", "exits 1".
- `instructionFiles: claude-md` and "current Claude Code with defaults" assume the reader knows Claude Code's built-in `agents-md` support and its setting. Name it and say it is a user/managed setting.
- DR IDs (DR-260216 and others) mean nothing to outside readers. Link them or describe them.
- The `user` row's "Rules and repo views" needs to say that rules are project-only.
- The `false` row's "You give up: Updates" is vague. Say "OAT stops creating, updating or removing that tool's files".
- The tables pack three ideas into each cell. The "In practice" cells for `auto` and `none` are dense enough to need a sentence each outside the table.

## What I could not verify

- Behavior when the OS refuses a symlink (Windows, or restricted filesystems). The fallback was verified only by reading.
- Windows and CI git handling of committed symlinks.
- Interactive TTY prompts (the stray keep/adopt prompt and the mismatch prompt). Verified by reading only.
- Whether gitignoring provider views is a supported setup, as an alternative to committing `copy` views.
- Stated rationale for the `auto` and `all` defaults. No DR found. The draft labels these as inferred, which is acceptable.
