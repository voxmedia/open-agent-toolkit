## Verdicts on "Docs that contradict the code"

1. **`hill-checkpoints.md:25` example includes `spec`: CONFIRMED.** New projects are created with `['discovery', 'design']` (`scaffold.ts:154`). `oat-project-next/SKILL.md:226` (HEAD) says `spec` appears only in legacy projects. The line is unchanged on `origin/main`, where the file is `workflows/projects/hill-checkpoints.md:25`. Fix: change the example to `['discovery', 'design']`, and optionally note that older projects may list `spec`.
2. **`lifecycle.md:510` lists an `env` layer for workflow preferences: CONFIRMED**, with two clarifications.
   - `ENV_OVERRIDE_MAP` (`resolve.ts:156-160`) covers only `projects.root`, `projects.defaultScope` and `worktrees.root`.
   - The same sentence calls a five-element chain "three-layer".
   - `configuration.md:783` already states it correctly (`local > shared > user > default`).
   - The fix must not say that design mode has no environment override. `OAT_DESIGN_MODE` is read by the design skills (`oat-project-design/SKILL.md:95`), not by the CLI resolver, so `oat config get` never reports it.
   - On `origin/main` this is line 516.
3. **`lifecycle.md:220` is an empty heading, with its paragraph at line 261: CONFIRMED** at HEAD, and present on `origin/main` too (lines 226 and 267). The misplaced paragraph also says "Disabled by default". The code default is _unset_, and the skill then asks with "no" as the default answer (`config/index.ts:979-985`, `plan-and-resume.md:223-228`). Replace it with "Unset by default; the skill asks, and the default answer is no."
4. **DR-260706 gives `important` as the `exit_nonzero_on` default, while the skill uses `high`: REFUTED as a contradiction.**
   - `important` is the name used before severities were renamed, and the code still maps it to `high` (`packages/cli/src/commands/gate/index.ts:458-465`; `plan-and-resume.md:289`). The two defaults behave the same.
   - The DR (`DR-260706-phase-review-gate-is-non.md:26`) is a dated historical record, not shipped docs, and this key is outside draft A's area.
   - At most, add a reader note to the DR; do not count it as a docs fix.

## Jargon to define for a junior-to-mid reader

- **Autonomous run.** Started by `oat-project-autonomous`, which sets `OAT_AUTONOMOUS=1`. It is used throughout sections 3 and 4 and never defined.
- **Non-interactive run.** `OAT_NON_INTERACTIVE=1`, or no way for the user to reply.
- **Lifecycle review, per-phase review ("Tier 1"), final review and phase review gate.** Section 4 depends on the difference between them.
- **Closeout.** Used in "stops once before closeout".
- **Spec-driven, `spec.md`, discovery.** These need a one-line description of each artifact.
- **Promote, scaffold, frontmatter.** Say that `state.md` and `plan.md` frontmatter is the YAML block at the top of the file.
- **"Proof commands" and "batched interview"** (lite).
- **"Utility-only".** Comes from choose-workflow.md: provider sync or a single CLI command.
- **Routine and risky sections, and "grounding"** (selective mode).
- **"Findings are handled"** (auto-disposition: what happens to Low and Medium findings).
- **`--user`, `--shared`, `--local` and their precedence.** The recommendations use these flags without explaining them.

Sentences that assume insider knowledge:

- "`[]` means every phase, never 'none'." This needs the reason: lite is the only mode with no checkpoints.
- "The phase review gate and `workflow.autoArtifactReview.plan` … are separate settings; link to their pages." This is an editor's note left in the reader-facing text.
- "Lite never pauses here." The word "here" has no clear referent.
