# Verification: D. Workflow gates and automated reviews

**Verdict: ACCEPT WITH CHANGES.** Most defaults are right: no gate by default, `--layer user`, local > shared > user precedence, `onFailure` required, `maxAttempts` 2, `same-family`, built-in priorities, threshold `high`, the timeout defaults, `autoArtifactReview` on, and HiLL unset. Four statements are factually wrong and must change before publishing:

- the `same-runtime` "hard guarantee" recommendation;
- "a timeout ... never a pass";
- contradiction 3, which is refuted, plus the timeout section's missing `OAT_GATE_EXEC_TIMEOUT_MS`;
- "fixes and reruns up to `maxAttempts` times", which overcounts by one.

Several scoping fixes are also needed.

Basis: branch `amphipod` at `a080dfbef`. The working tree was read only.

## Verdicts on (a)-(h)

- **(a) Confirmed.** `DEFAULT_WORKFLOW_CONFIG` has no `gates` key (`resolve.ts:114-154`). `parseLayer` defaults to `'user'` (`gate/index.ts:825-833`). Gate resolution is local > shared > user, first declaring layer wins, and a `null` entry disables (`resolve.ts:266-287`). The per-project off switch is `oat_skill_gate_overrides` in `state.md`, valid only for skills that declare `oat_gateable` (`workflow-gates.md:71-89`). Missing from the draft: shared overrides user, and `--disable --layer local` works as a per-machine opt-out.
- **(b) Mostly confirmed.**
  - `onFailure` has no default.
  - `oat gate set` throws without it (`gate/index.ts:862-867`, `:1133`), except with `--disable`.
  - An invalid stored gate is dropped with no warning (`oat-config.ts:509-516` and `normalizeRecordMap` at `:610-614`). The next lower layer then decides.
  - "Stays blocked under `warn`" holds for implement, lite and the docs, but the plan, quick-start and import-plan contracts are ambiguous.
  - "Timeouts" must be read as "timeouts with no recovered artifact".
- **(c) Confirmed for `same-family`.**
  - The default `same-family` is set at `gate/index.ts:838`.
  - When no diverse candidate is available, it reruns selection with `'none'` (same runtime allowed) and adds the warning (`:1882-1897`, `:1686-1698`).
  - `none` uses the highest-priority available target. Ties break alphabetically, so `claude-default` sorts before `codex-default` (`:1325-1333`).
  - **Refuted as a guarantee for `same-runtime`.** It refuses only when a host runtime is detected; on an undetected host it filters nothing (`:1754-1757`).
- **(d) Confirmed.** `codex-default` and `claude-default` have priority 100 and `cursor-default` has 70 (`oat-config.ts:357-399`). Planning offers the phase gate only for targets that are `explicitlyConfigured` + `enabled` + `available` (`plan-writing/SKILL.md:316-330`); built-ins report `explicitlyConfigured: false` (`resolve.ts:~331`). It can still be enabled by editing `plan.md`.
- **(e) Confirmed.** `parseReviewGateThreshold` defaults to `high` and maps `important`→`high` and `minor`→`low` (`gate/index.ts:461-465`, `:847-860`). The phase gate default is `high` (`plan-and-resume.md:289`). The rationale is labelled as inferred.
- **(f) Defaults confirmed.**
  - Code reviews at final, pNN or pNN-pMM scope get 1,800,000 ms. Task scope, artifact reviews and untyped commands get 900,000 ms (`gate/index.ts:998-1015`).
  - The precedence is not stated, and `OAT_GATE_EXEC_TIMEOUT_MS` is missing.
  - Not mentioned: the defaults depend on the command's flags.
- **(g) Confirmed.**
  - Both default to `true` (`resolve.ts:123-126`; config describe `defaultValue: 'true'`). Only a boolean `false` disables, because non-boolean values are dropped (`oat-config.ts:766-776`; `plan-writing/SKILL.md:527-529`).
  - The retry default is 2 (`:532-535`).
  - "Same session" is broadly right: the reviewer inherits the planning parent. The exception is a parent below the ceiling, which dispatches a resolver-pinned target (`:537-540`).
  - The 0-5 range is prose only; the CLI has no enforcement (no `orchestration_retry_limit` match in `packages/cli/src`).
- **(h) Confirmed.**
  - The default is `null` (`resolve.ts:121`). Legacy shared `autoReviewAtCheckpoints` is used only when it is set (`:230-239`).
  - When unset, the skill asks, with "no (default)" (`plan-and-resume.md:224-228`).
  - `OAT_AUTONOMOUS=1` writes `true` (`:153-157`).
  - Missing caveats: lite projects force `false`, and the value is stored in `plan.md` on the first run.

## Verdicts on the claimed doc contradictions

1. **review-flavors.md "fail closed": confirmed.** Lines 69-70, 106-110 and 118-120 say an unavailable independent target blocks the gate. The default `same-family` falls back to any available target (`gate/index.ts:1882-1897`), and `workflow-gates.md:1056-1060` agrees with the code.
2. **review-flavors.md:67 "plan/spec/design": confirmed.** Only `plan` and `analysis` loops exist (`plan-writing/SKILL.md:521-522`; config keys at `oat-config.ts:232-235`). Spec and discovery offer a manual review only (`oat-project-spec/SKILL.md:378`, `oat-project-discover/SKILL.md:415`), and design has no loop.
3. **`GATE_EXEC_TIMEOUT_MS`: refuted.** Line 933 of `workflow-gates.md` says "legacy `GATE_EXEC_TIMEOUT_MS` behavior". That is the 15-minute internal constant (`gate/index.ts:478`, used at `:1015`), not a claim about an environment variable. The real environment variable `OAT_GATE_EXEC_TIMEOUT_MS` is listed at line 931 and read at `:986`. At most this is insider wording.
4. **reviews/index.md:137 "disabled by default": partly confirmed.** The value is unset, and the skill prompts with "no" suggested, so accepting the prompt gives "disabled". The doc omits the prompt and the forced-on behaviour under autonomous runs. Treat it as an omission, not a hard contradiction.
5. **"Superseded" decision records: partly confirmed.**
   - DR-260621's `same-runtime` default is outdated.
   - DR-260706's `important` still works as an alias.
   - Neither record is superseded; both are `accepted`.
6. **New: the plan, quick-start and import-plan skill contracts disagree with the docs and the implement and lite skills.** Their step 6 sends every nonzero exit to `onFailure` (`warn` = continue). The docs and the other two skills say operational failures stay blocked regardless. The same three skills also still say the dispatcher "avoid[s] the same runtime" (`oat-project-plan/SKILL.md:658-661`), which is stale: the default is `same-family`.

## Jargon to define for a junior-to-mid reader

Terms to define:

- **gate**: defined, but tie it to "an extra review after the skill's own work".
- **exec target**: "a saved command OAT uses to start a reviewer CLI, such as `claude -p` or `codex exec`".
- **runtime**: "the agent CLI: Claude Code, Codex or Cursor".
- **family**: "the model maker or line, for example Claude versus GPT; Cursor can run several".
- **HiLL**: defined only in section 9; move it to the definitions.
- **artifact review**: defined.
- **same-session**: "the same agent conversation that wrote the plan".
- **closeout**: "the end of `oat-project-implement`".
- **phase** and **phase-range** (pNN, pNN-pMM).
- **received** / **receive**: "processed by `oat-project-review-receive` into fixes or deferrals".
- **`review_failed`**.
- **headless**.
- **bypass flags**.
- **layers** (`shared` = committed `.oat/config.json`, `local` = `.oat/config.local.json`, `user` = `~/.oat/config.json`).
- **`state.md`** and **`plan.md`** frontmatter.
- **"high-risk repo"**.

Sentences that assume insider knowledge:

- "It is usually `oat --json gate review`, which ... turns findings into pass/fail."
- "Implement closeout rejects stored commands that include it."
- "The retry bound is `oat_orchestration_retry_limit` in `state.md`."
- "Only the standard per-phase reviewer runs."
- "DR-260621 records the earlier runtime-only design."
