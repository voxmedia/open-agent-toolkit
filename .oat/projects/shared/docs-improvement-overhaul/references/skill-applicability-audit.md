## Uncertain or contradictory

- **oat-explainer-kit:** The `project-explainer` and `project-recap` recipes clearly need an active project (`resolve-paths.mjs:46-47`). For `program-recap`, the contract routes output to the repo (`config-contract.md:40`, `lifecycle-contract.md:123`), and repository invocation takes a supplied fact base (`bind-project-sources.mjs:98-105`). However, `bindProjectSources` still requires a `projectRoot` for `program-recap` (`bind-project-sources.mjs:36-38`), and SKILL.md defines no direct front door. I classified the skill `required`. A program-recap run may not need an _active_ project.
- **Naming hazard:** Several skills say "project level" when they mean repo-scoped OAT. This applies to `.oat/` in `analyze`, `compare`, and `deep-research`, and to `.oat/ideas` in the idea skills. Neither use means an OAT project; do not read it as a project requirement.

- **oat-project-clear-active**: it only acts on an active project, but with none set it prints "No active project is currently set." and exits 0 (:36-38). I classed it `required` because it stops. `optional` is also defensible.
- **oat-project-lite / -import-plan / -autonomous**: all three are entry points that create a project when none exists, so they are classed `none`. Each also resumes or reuses the active project, so `optional` is arguable.
- **oat-project-implement**: argument-hint advertises `--retry-limit <N>` (:5), but no step parses it. The retry limit is read from `oat_orchestration_retry_limit` in state (references/phase-execution.md:786).
- **oat-project-discover**: the prerequisite says "Required for model invocation" (:19), but Step 1 stops on direct user invocation too (:116-120).
